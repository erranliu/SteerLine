# 认识 SteerLine

SteerLine 是一款面向工程 AGI 的研究型软件开发工具，以 roadmap 连接产品目标、任务依赖、AI 开发执行和 PR 交付。它希望让人能够持续组织复杂软件项目的开发，把具体实现交给 AI，并掌握目标、关键决策和合并结果。

## SteerLine 与开发项目

开发项目拥有自己的产品目标、代码仓库、技术栈和验证方式。SteerLine 围绕这些项目组织开发工作：把确认的需求落实为任务，跟踪任务之间的依赖，连接 AI 执行过程，并核验实际交付。

项目通过 Spec 说明要实现什么、边界在哪里以及怎样算通过，通过 Plan 安排实现和验证，通过 roadmap 表达任务及推进顺序。测试入口、清单和报告让执行者能够找到验证方法，也让人能够检查实际结果。这些项目材料为 SteerLine 和 AI 提供共同的工作依据。

SteerLine 提供通用项目规范，项目维护自己的流程与执行材料。SteerLine 自身也是一个采用这些规范的开发项目。具体目录和维护边界见[受管理项目规范](project-standards.md)。

## SteerLine 怎样工作

一个典型的开发闭环从人的目标开始，以经过核验的交付结束：

1. **规划与确认。** 人与 AI 讨论目标，拆分任务，准备 Spec、Plan 和验证安排，确认正式 roadmap 的范围及依赖。当前规划主要在 Codex 中进行。
2. **建立任务关系。** 确认的任务进入 SteerLine 的任务 DAG（有向无环依赖图）。DAG 表达哪些任务需要等待前置交付，哪些任务具备独立开展的条件。
3. **执行开发。** SteerLine 固定任务材料与执行配置，通过独立的 SteerRunner 连接 AI worker。worker 在对应工作区中按 Spec/Plan 实现、测试、修复、提交代码并创建 PR；SteerRunner 管理工作区、原生会话和具体执行流程。
4. **反馈与决策。** SteerLine 展示执行进展和待处理问题，把人的反馈送回对应执行会话。人处理产品取舍、权限和需要人工判断的事项，审阅成果并决定是否合并 PR。
5. **核验与继续。** PR 实际合并后，SteerLine 核验交付身份和合并事实，记录任务交付并释放满足依赖条件的后继任务。执行和验证结果为下一轮规划提供依据。

过程中，人决定目标和授权范围；SteerLine 维护任务、依赖和交付事实；SteerRunner 与 worker 完成具体执行。任务完成以核验过的交付为依据，测试通过以实际测试报告为依据。

SteerLine 目前尚未发布，正逐步完善从规划到交付的流程。上述闭环说明产品的工作方式，具体接入能力和可用范围以对应版本的实现及验收记录为准。
