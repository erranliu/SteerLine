# 开发项目规范

本目录维护供 SteerLine 所开发项目采用的通用工程规范，SteerLine 自身也直接采用。规范按主题维护，与仓库根目录的 `docs/` 并列；`docs/` 继续保存 SteerLine 产品自身的设计、实现、任务、测试清单及验收证据。

| 主题 | 规范 | 内容 |
| --- | --- | --- |
| 测试 | [测试架构规范](testing-architecture.md) | L1–L4 定义、L3 正交与并行设计、测试内容清单、职责归属和最小必要验证。 |

## 目录与内容边界

- 本目录保存可跨项目复用的规则、必要解释和明确标为示例的内容。按主题使用稳定文件名；目前直接放在根目录，主题增多后再按领域分目录。
- 项目特有的技术栈、命令、路径、模型、环境、场景 ID、实施缺口和验收结果由各项目自己的文档维护。通用规范链接这些项目落地文档，不吸收其运行状态。
- 同一条通用规则只在本目录维护一份；项目文档引用规则并补充本项目的选择、差异和现状。SteerLine 的落地入口为 [测试指南](../docs/testing.md)。
- 新增规范须明确适用范围、规则、项目落地要求，必要时给最小示例，并更新本索引。不要为尚未形成共识的主题预建空规范。

## 项目采用方式

项目在自己的 `AGENTS.md` 或文档入口声明采用的规范，并在本项目文档中维护执行入口、清单和未落实项。已有项目可以逐步对齐；采用规范不等于现有实现已经全部符合。

同仓项目直接使用相对链接。跨仓项目采用时记录规范来源及固定 Git commit，或保存带来源 commit 的副本；升级时核对差异，避免依赖另一个仓库工作区的本机绝对路径，也不在多处独立修改同一规则。
