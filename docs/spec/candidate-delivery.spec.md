# Spec：PR 胜出与落选候选对账

任务 ID：27；任务名称：PR 胜出与落选候选对账；目标：`PHASE1-CANDIDATES`。配套 [Plan](candidate-delivery.plan.md)。状态：待实现与验收。一个独立实现 PR 交付。

## 范围与前置

硬前置：#26。依赖[多候选模型](task-candidates.spec.md)，遵守[共同约束](phase1-delivery-constraints.md)。交付每候选独立 PR、唯一 TaskDelivery、落选后在途执行结算与冲突记录，替换 #26 的 multiple 发布/交付能力拒绝；不自动合并 PR、比较代码优劣或拼接候选成果。

## 发布和胜出

每候选只能绑定一个精确 PR；同请求丢回执按原发布 Operation 查同一 PR，不另建。PR 平台/仓库/目标分支/head、发布 revision、verify/review 结果 ID 均属于原候选，兄弟候选不能复用；一个 PR 不能被多个候选或 Task 绑定。候选在自己的步骤门槛满足时独立提 PR，人决定合并哪个。

中心在选定前核对本 Task 全部已绑定候选 PR 和未结算发布 Operation。已知一个有效候选真实合并，其他已知 PR 确认未合并且不存在无法排除另一 PR 的发布未知时，方可写入 TaskDelivery；无法读取相关 PR 或发布不确定时保持待核实，不能凭最先到达的回执判断胜出。没有发布行为的活动 implement 不阻止胜出，但提交瞬间必须阻断它后续发布。

平台读取在事务外；提交事务重新核验 Task/候选/发布集合版本、固定选用证据和依赖资格。以 Task 唯一交付约束仲裁竞争，原请求重放返回同一结果。Task closed、唯一 TaskDelivery、获胜 WorkflowRun completed 和其他候选“禁止继续推进”标记同事务提交；后继只从该已提交交付派生就绪，资源清理可以继续但不得伪称已停止。

多个候选在选定前均已真实合并时记录 delivery_conflict，禁止自动选一个并放行后继，交人工核实；首版没有强制选中/抹去冲突的入口。选定后发现另一 PR 合并时追加冲突事件并显示异常，不覆盖原 TaskDelivery、不伪造 Git 回退，也不自动撤销已放行后继。平台与 SQLite 不存在跨系统事务，不承诺阻止中心之外的人工合并。

## 落选执行与恢复

候选是否仍有交付资格与真实资源状态分开：落选表示不得再启动步骤、回答以推进流程、重试或发布；不表示 worker 已退出。新步骤、续跑、回答应用和发布发起事务均核该资格，和在途启动/发布意图竞争时只保留已经持久化的原操作对账。迟到结果存为原执行事实，不能再驱动下一步骤或 TaskDelivery。

胜出后为其他候选持久化精确待办：本机只用已认证的 Stop；受监管 Orca 不支持取消则保留运行/unknown 和人工处置说明；已创建开放 PR 按固定身份请求关闭，关闭未知继续对账。保留分支/worktree/日志供审阅，不自动删除工作成果。PR 关闭回执不能证明没有其他未结算发布动作，资源占用只在精确退出/释放证明后消除。

Task closed 后仍持续恢复落选候选的待办、原发布 Operation 和迟到合并观察。查询区分 Task 已交付与候选资源未结算，不能因任务从活动列表消失而遗失监督。新的 start_candidate 与交付事务竞争时，交付先提交则拒绝启动；启动先提交则新候选纳入冻结及对账集合。

扩展 #26 的任务级安全变更：本次领取的候选均已精确结算、没有未知 Operation/Decision，且所有历史已知 PR 均经原平台核验为 closed_unmerged 时，允许受控 reopen、补前置并重置或 discard；开放 PR 先由操作者关闭再核验，本入口不隐式关闭。任一 merged/unknown/发布身份不完整均拒绝。查询在事务外、候选/PR 集合与 Task 版本复核在提交事务内，沿用原命令幂等和安全结算规则。

重开/丢弃后仍保留并核对历史 PR；历史候选 PR 被外部重新打开或迟到合并时记录冲突，冻结当前未交付 Task 的新候选、下一步骤、发布和交付，交人工核实，不把历史 abandoned 候选改为当前获胜者。若已有当前 TaskDelivery，则保留交付并记录迟到冲突。历史 PR 观测不因 Task 重开或丢弃而消失。

仅重新打开而未合并的历史 PR 经人关闭后，可提交带原 Task/冲突版本和 request_id 的核实命令；中心重新核对全部历史 PR、当前候选和未知副作用，确认全部 closed_unmerged 后只解除这一临时阻塞，保留冲突事件。任何历史已合并事实不走该解除路径；不同阻塞原因不得被一并清除。

## 验收

| 编号 | 通过条件 |
| --- | --- |
| CD1 | 两候选各自满足门槛并发布不同 PR；任一有效 PR 人工合并后，中心只写一份交付并使后继就绪 |
| CD2 | 错 head/分支/平台、跨候选验证证据、PR 复用、未合并关闭均不能交付；发布回执丢失不重复建 PR |
| CD3 | 交付与新候选/下一步骤/回答/发布竞争时，旧意图只对账，新动作被禁止；事务失败及重启无部分关闭 |
| CD4 | 多合并和无法核实的发布按规则阻断；选定后的迟到合并只追加冲突，不覆盖 Delivery 或重放后继 |
| CD5 | 胜出后本机停止、远端 unsupported、开放 PR 关闭失败均保持真实资源状态；closed Task 重启仍继续对账 |
| CD6 | single 原交付路径与 #26 读/命令接口回归通过，取消 multiple 发布拒绝后无越步发布入口 |
| CD7 | 全部候选已结算且 PR 均 closed_unmerged 时可重置/补边/丢弃；任一 merged/unknown 拒绝；重开后的历史 PR 重新打开或迟到合并会冻结当前未交付流程且不覆盖交付证据 |

采用平台替身和故障注入验证 CD1–CD7；真实多候选合并及资源证明归 #29。证据路径为 docs/validation/candidate-delivery/。
