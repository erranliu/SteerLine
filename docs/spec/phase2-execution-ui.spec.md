# Spec：执行与待处理原生界面

任务 ID：50；任务名称：执行与待处理原生界面；目标：`PHASE2`。配套 [Plan](phase2-execution-ui.plan.md)。状态：待实现与验收，一个独立实现 PR 交付。

## 范围与前置

硬前置：#44 [WinUI 基座](phase2-winui-foundation.spec.md)、#45 [本机客户端协议](phase2-local-api.spec.md)，传递包含 #36 [持续 worker](../archive/spec/completed/worker-flow.spec.md)。遵守[第二阶段共同约束](phase2-constraints.md)。只交付真实中心状态、会话、反馈和 PR 的原生界面，不新增状态机或后端规则；多候选能力未提供时明确 unsupported。

## 展示与反馈

展示待执行、执行中、待决策、待合并、已完成，另有历史/明确丢弃筛选。失败、部分提交、连接未知及资源残留放在所属任务详情中，不再创建独立“需处理”业务阶段。主状态和计数来自中心 DTO。

会话区保留真实 turn/phase、完整最终回复、过程折叠、正文分页和阅读位置；缺来源能力时显示缺口，不推断轮次。用户始终看到反馈将发往哪个任务的原会话。

统一输入支持选项、任意文字及选项加备注。提交前持久保存原命令信封，双击、回执丢失、重开和服务切换按原请求对账；目标变化时保留草稿并提示，不发到另一会话。区分已保存、平台接受和轮次开始，不展示或要求 agent 业务应用证明。

允许的开始、派发/服务控制及明确丢弃沿同一 API 的资格显示；没有专用 retry/mark-stopped/resolve-command 页面。原会话无法继续时展示中心原因和未发送输入，不由客户端创建替代 worker。宿主权限提示仍在真实平台处理。

打开精确 PR 链接由用户合并；真实 merged 和 TaskDelivery 来自中心。UI 关闭、换项目、浏览器返回不改变执行或交付。离线可读历史但不据缓存发命令。

## 验收

| 编号 | 通过条件 |
| --- | --- |
| EX1 | 五个主阶段、交互原因和计数与真实服务一致，任务/运行不重复 |
| EX2 | 真实会话折叠、最终回复、缺口和正文阅读通过，用户选择/滚动保持 |
| EX3 | 纯文字/选项/选项加备注完整送到原会话；双击、超时、重启和旧目标不重复或串线 |
| EX4 | 部分提交/编译失败/连接异常都在同一待决策入口展示，不新增恢复状态机或强制重派按钮 |
| EX5 | PR 建立、未合并关闭和真实合并由中心状态驱动；UI 不自行决定完成 |
| EX6 | Windows 中文/多行输入、窄窗口、跨项目迟到消息、服务窗口关闭和离线历史真实验证 |

证据保存在 `docs/validation/phase2-execution-ui/`。先验页面/协议与原生构建，变更 Go 接线时回归对应领域；完整产品链由 [二期验收活动](../acceptance/phase2.md) 验收。
