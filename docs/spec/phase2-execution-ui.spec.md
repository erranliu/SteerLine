# Spec：执行与待处理原生界面

任务 ID：21；任务名称：执行与待处理原生界面；目标：`PHASE2`。状态：规格已编写，尚未实现或验收。配套 [Plan](phase2-execution-ui.plan.md)。本任务由一个独立实现 PR 交付。

## 范围与前置

硬前置：#15、#16。依赖 [WinUI 基座](phase2-winui-foundation.spec.md)和[本机客户端协议](phase2-local-api.spec.md)，遵守[共同约束](phase2-constraints.md)、[执行控制台](pr-04-console.spec.md)、[人工决策](pr-05-intervention.spec.md)与[会话契约](pr-04b-conversation-events.spec.md)的当前语义。
本任务交付原生执行与待处理页面；不重写执行资格、回答仲裁、PR 核验或资源结算。#3/#4/#6 的未通过能力在本任务中显示不可用，完整双后端交付由最终集成任务承担。

## 观察与会话

提供 Ready、运行中、待决策、待合并、需处理、历史筛选，任务/运行去重与选择规则沿用中心 DTO。详情可见精确 Task/WorkflowRun/Execution/Attempt、执行后端/目标、阶段、能力、最后可信采样及阻塞原因。全局待处理计数从服务查询得到，不由本地弹窗数计算。

会话区使用真实 turn/phase，过程可折叠、最终回复完整可读；无精确来源能力时显示执行级内容和缺口，不推断 turn。错误、未解决问题和 outcome_unknown 保持可见；用户展开/历史阅读不被新输出重置。正文按服务引用分页读取，不访问 Codex/Orca 私有日志。

## 操作和恢复

服务允许时提供开始任务、派发控制、回答、原操作核实和既有恢复入口；每个动作提交固定目标/expected_version/request_id，按钮禁用只是交互辅助。界面保存完整信封后发送；双击、超时、页面切换和重启先查原结果，当前项目权威明确 command_not_found 时允许按共同契约补交原信封，已有记录则只对账。不得换 ID、自动刷新 expected_version 或直接重放外部动作。版本冲突保留用户答案草稿并显示当前问题状态，不能改答另一个 attempt。

决策答案保存、平台接受、轮次开始及应用证明分别显示。宿主登录/权限提示与业务问题分开，原生 UI 不自动代答。未知执行的卡片保留原身份、最后可信阶段与资源可能仍在运行的原因；只开放中心允许的核实动作。远端取消不提供可执行入口，不能借中断 UI 会话去 stop worker。

PR 操作打开精确 URL，由用户合并；只显示中心已核验的 merge 与交付状态，UI 不据浏览器关闭或点击链接宣告完成。关闭 UI 或切项目不提交 stop；关闭服务窗口后改为离线历史，禁止依缓存 Ready 发命令。
