# PR 4 Spec：执行控制台 TUI

状态：待实现。依赖：PR 1–3。对应 [Plan](pr-04-console.plan.md)。

## 目标

把现有查看器升级为日常执行入口。用户在一个终端界面中切换项目、启动/连接服务、选择 ready 任务开始执行、控制派发并查看运行详情。UI 通过共享客户端发指令，业务校验和状态变更由服务完成。

## U1：入口与项目

- `steerline console` 枚举 `<STEERLINE_HOME>/etc/*.json`；`-config <path>` 只打开显式配置的项目，即使该配置不在 etc。
- `-run-id <run-id|task-id>` 在所选项目中定位已有运行；找不到时显示提示，不静默聚焦另一个任务并暗示匹配成功。
- 无配置时显示配置目录和建立配置的说明。某一配置损坏时保留项目行及错误，其他有效项目正常可用。
- 多项目切换只改变观察/操作目标；后台服务独立运行。项目显示服务状态、当前执行、待决策数和需人工处理数。
- 控制台按配置路径和 run_dir 保存视图身份，控制指令按实际 repository identity 与实例定位。不同配置指向同一仓库时显示关联/冲突，不能借此绕过单仓库服务锁。
- 后台刷新、命令结果、决策弹窗都携带项目与目标身份；换项目后到达的响应不能更新新项目的视图。

## U2：信息布局

默认宽屏布局示意（精确颜色、边框不是契约）：

```text
SteerLine  项目 A | 服务已连接 | 手动 | 派发正常 | 最近更新 1s
项目          Ready / 运行中 / 待决策 / 待合并 / 需处理 / 历史
 A  1决策     任务/运行列表                  详情 / 活动 / 尝试记录
 B  离线      ID     标题       当前阶段     task、run、attempt 身份
              ...                           执行 / 交付 / 任务状态
                                            PR、工作目录、错误与摘要
                                            当前对象可用操作与原因
状态：开始 B 的请求已提交，等待服务确认
快捷键提示：随当前焦点、模式和对象变化
```

- Ready 是提供方候选，run 列表是执行记录，不能把从未启动的任务伪造为 pending run。
- 待决策、需处理和运行中有清晰计数。错误/unknown 不因为有旧的 succeeded 字段而显示完成。
- run 详情分别显示 execution、finish、外部任务状态与最后核验时间。外部任务镜像注明是最近观察；不把它显示成实时 Beads 全量对账结果。
- 展示 PR 状态、queried_at 和 query_error，保留 PR 链接；只有 completed 才显示整体完成。
- activity 展示所选 attempt；历史尝试可从现有 previous-run.json 和 attempt 路径中读取，标明缺失资料。切换历史不会改变当前执行目标。
- 无日志、服务离线、候选查询失败、没有 ready 任务和执行槽被保留使用不同空态。
- 窄屏采用可切换的单面板，能读完整详情和操作说明；不能像当前 viewer 一样只剩列表而失去详情入口。

## U3：动作与反馈

| UI 动作 | 请求/行为 | 可用条件 |
| --- | --- | --- |
| 启动服务 | PR 3 StartService，初始 manual | 明确离线/未启动，配置可解析 |
| 连接/刷新 | 只读连接和快照刷新 | 项目可读取 |
| 开始所选任务 | start_task | 服务兼容、manual、未暂停、无槽阻塞、选中 ready 候选 |
| 切换手动/自动 | set_dispatch_mode | 服务兼容，显示切到 auto 后可能开始领取 |
| 暂停/恢复派发 | pause_dispatch / resume_dispatch | 服务兼容；当前模式保留 |
| 停止服务 | stop_service | 有可定位实例，显示对当前 worker 的 shutdown 后果 |
| 退出控制台 | 仅退出 UI | 始终可用 |

- 开始、切自动和停止使用显式动作键/命令面板；Enter 默认打开详情。只有停止可能中断 worker 的动作需要展示影响并确认，普通选中/浏览不产生执行。
- 点击开始后立即显示 task_id 和 request_id，并禁止同一视图重复提交；直到确定结果前继续跟踪原请求，不能因为 UI 超时再生成新 ID。
- 展示 submitted、applying、applied、rejected、failed、indeterminate。start applied 时跳转/提供导航到对应 run；worker 随后失败时展示 run 的真实状态。
- 回执丢失或超时显示“结果待确认”，允许按原 ID 查询。stale_revision 说明状态已变化，刷新并让用户重新选择，不自动重发有副作用动作。
- 服务不在线时已有 runs/日志仍可看；启动按钮显示其可用性理由。重连后不自动提交离线期间尚未确认的任务动作。
- 键盘焦点明确：列表、详情、日志、动作面板各自处理按键。输入控件内字符不触发全局开始/停止快捷键。

## U4：刷新与性能

- 前台项目状态/回执目标刷新间隔约 700ms–1s，后台项目摘要约 5s；以可注入计时器实现，慢请求不得堆叠。
- 候选任务直接读服务的 tasks 快照；UI 不以高频轮询调用 Beads。实例不同、查询报错或距最后成功查询超过 `max(3 × task_poll, 30s)` 时视为不可操作的缓存，禁用依赖候选的操作并显示刷新原因。
- 使用 PR 1 的选择/cursor/generation 规则；各项目恢复自己上次选择、筛选和日志跟随状态。
- 错误不通过刷新被瞬间清空；区分当前持续错误和已经结束的动作结果。切换项目后仍能回到原项目查到原 request_id。
- UI 退出无需等待后台任务结束；它等待的只应是自身必要的终端清理。

## U5：决策的阶段性兼容

- 保留现有待决策入口与选项/备注提交能力，提交前重新读取 run 并携带明确 decision_id，不能再把弹窗保存的 Run 指针作为最新状态。
- 本 PR 的兼容回答仍走现有答案文件通道；显示“答案已保存，等待服务应用”，服务不在线时明确说明这一点。
- 多轮留档、答案不可覆盖、完整可滚动决策页和统一在线恢复在 PR 5 交付。PR 4 的新开始/模式/停止功能始终使用 PR 2 指令协议。

## U6：CLI 与批处理兼容

- TTY 下普通 `watch` 进入同一控制台；其显式流式参数继续按 PR 1 路由。
- 新增 `console.bat`；`viewer.bat` 调用同一控制台入口。`projects` 菜单增加 console，并保留现有 action 别名。
- `projects/run/stop` 的原调用方式保持可用；菜单文字明确 run 是自动调度，而 console 启动新服务是手动模式。
- 控制台使用当前项目实际状态，不因从 watch/viewer 别名进入而改变服务模式。

## 验收标准

| ID | 场景与结果 |
| --- | --- |
| U-A1 | 零配置、一个配置、多个配置及部分配置损坏都能进入正确页面 |
| U-A2 | 空状态项目可在 UI 启动服务、看到 ready、选 B 并启动，A 不被领取 |
| U-A3 | start 提交后连按按键、超时、刷新和重开 UI，都不会重复提交新执行 |
| U-A4 | 多项目快速切换和乱序响应不串日志、不串回执、不向错项目发动作 |
| U-A5 | 分别展示 waiting_decision、waiting_pr_merge、unknown、failed/blocked 和 completed |
| U-A6 | pause 不停当前 worker，stop 有明确后果，q 退出不停止服务 |
| U-A7 | 大小终端、Unicode 标题与长错误下，详情和所有动作可通过键盘到达 |
| U-A8 | watch 管道/JSON/raw/显式流式参数保持兼容；旧 launcher 别名进入新控制台 |
| U-A9 | 离线日志可看，候选缓存不被显示为实时 ready，答案保存与续跑区分 |

## 范围限制

本轮不添加任务创建/编辑、DAG 编辑、批量排队、终端自由发消息或 PR 合并。外部宿主终端可用于只读诊断；控制台的任务操作始终通过服务状态机。
