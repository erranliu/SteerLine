# Spec：多候选本机与远端真机验收

任务 ID：29；任务名称：多候选本机与远端真机验收；目标：`PHASE1-CANDIDATES`。配套 [Plan](candidate-native-acceptance.plan.md)。状态：待实现与验收。一个独立实现 PR 交付。

## 范围与前置

硬前置：#28、#3、#4、#6。#28 传递包含 #26/#27。依赖[候选界面](candidate-console.spec.md)、[交付仲裁](candidate-delivery.spec.md)、[人工决策](pr-05-intervention.spec.md)、[远端协议](01-orca-remote-protocol.md)及[远程闭环](03-remote-execution-and-viewer.md)，遵守[共同约束](phase1-delivery-constraints.md)。交付可重跑验收入口、真实证据和本链路所需的集成修复；不能用本任务声明上游未交付门槛通过。

2026-09-28 的生产远端目标为台式机64g（远端 Orca 1.4.215），已有探测因 Smart App Control 拒绝 worker 调用未签名 orca.exe 而失败。执行时须重新读取实际配置、版本和能力，先通过平台允许的方式解决运行前提并取得认证；本任务不自动修改系统安全策略。此前 home 的结果只证明 home，不能用于新主机。目标变更时记录替代目标及其全套证据，不沿用原结论。

## 真实链路

使用隔离原生项目、独立托管测试仓库和当前格式 SQLite。分别完成本机 Codex 执行链（可由已认证本机 Orca 承载）与受监管 Orca 远端执行链；本机成功不表示直接 local_process Codex 续跑能力可用。每条链至少一个 multiple Task 同时有两个真实候选，各自完成准备、实现、验证、审查和发布，生成不同 PR。记录重叠执行窗口、不同 worktree/branch、固定共同 base、全部 Dispatch/Attempt 与结果绑定。

每条链至少让两个候选各自提出可区分的业务问题，分别回答并取得原 Decision/Attempt 的应用证明；只在精确绑定的候选推进。人合并其中一个 PR 后，由中心核验唯一 TaskDelivery。设置一个后继 Task，证明合并前不就绪、交付后新领取 base 包含胜出 merge commit；后继也须经过真实 PR 合并完成，不能用模拟 closed 替代。

另建一组同 Task 混合后端候选：一个使用本机已认证配置，一个使用当前认证远端配置，二者重叠运行且各提出独立问题。两者等待时重启中心，核验各自原终端/Dispatch、worktree、配置、问题和输出恢复；错误候选/后端的答案须被拒绝。分别走到不同 PR，由人合并一个，核对另一后端候选的推进冻结与真实资源结算。此组不要求重复后继链，但必须有同一 Task 跨后端的身份及交付证据，不能用前两条同类后端链替代。

胜出后跟踪落选候选的原 PR 与资源至已结算，或明确保留平台不支持取消的人工处置记录。正常链通过要求最终完成精确结算，不能留下未解释的占用。人工停止/PR 处置逐项记录；不要求系统实现远端取消。

## 故障证明

另建隔离任务覆盖：同请求重复启动；已产生外部执行后的启动回执丢失；两个候选都在等待时中心重启；答案回执丢失；已建 PR 后发布回执丢失；一个候选交付时兄弟仍在途；选定前多 PR 已合并和选定后迟到合并。异常任务可以正确阻塞作为通过结果，不伪造成功交付。

回执丢失通过真实适配器边界上的定点注入完成，保留原平台记录和 SQLite；不能用两份人工编辑 JSON 冒充原链路恢复。双合并破坏性样本只在隔离仓库执行并由人合并，不引入生产回退。自动化保存复现参数和清理清单，不自动批准业务答案或合并 PR。
