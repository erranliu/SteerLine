# Spec：多候选本机验收

任务 ID：39；任务名称：多候选本机验收；目标：`PHASE1-CANDIDATES`。配套 [Plan](candidate-native-acceptance.plan.md)。状态：本机验收与协调复审完成；实现合入状态见 [PR #216](https://github.com/erranliu/SteerLine/pull/216)。

## 范围与前置

硬前置：#38 的实现合入（传递包含 #37/#36）；候选 TUI 使用当前源码和[操作/证据入口](../validation/candidate-console/README.md)。#38 CC5 已由用户人工确认通过，不豁免本任务的本机 CN1–CN8 条件。遵守[第一阶段共同约束](phase1-delivery-constraints.md)。复用已有单会话基础证据，交付本机多候选新增的真实竞争、反馈隔离、唯一交付与残留观察证明；不重建五步或 applied 验收矩阵。

当前原生路径只接受worker发布：实际提交/推送/创建PR由原worker完成，中心仅查询/核验和交付。不同方案的权限、发布能力及原配置各自准入；不使用中心代发布fixture或下发中心凭据。场景只调用产品端口，采集/证据适配器核验原生身份，UI/产品结果从规范数据库读取，原始日志只用于诊断及原生证据。

本任务只验当前受支持的本地 Codex 与本机 Orca。用同 Task 的一组本机双候选覆盖两种后端和不同冻结配置；所有执行资源都在本机。本机不等于同一 backend，不为每种配置另建完整矩阵。

用户明确将 #39 收缩为本机验收：远端新 worker 准入、远端双候选、本机/远端混合以及相应候选场景/manifest 门槛不在本任务范围，也不作为其开工、验收或合入阻塞，不列为 #39 待补验。远端流程跑通后另行规划，不能把本机结果记为远端通过；既有生产远端准入规则不因本任务收缩而改变。

## 与解耦任务并行

#73–#82 不是本任务新增硬前置，本任务等待 #38 实现合入与场景所需实际能力。CC5 的人工确认记录由原入口保留，不新增本任务前置。可以在独立 worktree/固定构建、配置、home、仓库与平台现场上，与解耦线并行验收；报告记录精确 commit/构建和入口/场景/证据映射，不在运行中替换 executable、配置或宿主。

迁移之后按实际影响复核：纯包名/import 改动且行为/接线不变可复用本机原生证据，仍需当前构建的受控接线通过；目标/配置/身份、PR 交付、恢复/反馈、协议/启动/权限/宿主实际变化时，对受影响 CN 场景定向重验。#77 在 #38 后完整迁移产品/TUI，#78 迁 adapter/资源，#80 迁服务构造，分别交接入口和证据影响。不能用迁移前证据覆盖已改变的行为，不重跑无影响平台组合。

## 真实链路

使用隔离原生项目、当前格式数据库和测试托管仓库，记录实际构建、执行目标/版本与认证。同 Task 的本地 Codex 与本机 Orca 至少两个候选重叠工作，使用共同 base、独立 session/worktree/分支，各自提出可区分的反馈请求并继续原会话，创建不同真实 PR。

人合并其中一个，中心写入唯一 Delivery。后继在合并前不可开始，交付后从包含胜出 merge commit 的 base 启动并完成真实 PR 交付。落选会话/PR 保留可追溯信息，不能因 Task 完成而伪造已停止；资源处置使用实际支持的操作。

在这组本机不同后端候选等待反馈时重启中心，恢复原会话并分别送达完整选项和文字。对一个本机候选制造一例连接故障，另一候选继续可观察和交互。既有单会话证据可复用，平台或接线改变的部分须定向重验，不再创建远端/混合远端现场。

复用这组本机现场，合并前人工放弃一个候选，核对其立即退出实验、不影响兄弟反馈；停止支持/不支持/待核实按实际能力记录，原历史和资源不删除。允许沿原领取/base人工新增本机替代实验，不等待旧worker停止，记录新配置与原停止事实。合并后实际提交放弃并核验拒绝，不仅检查按钮。控制台不宣称物理并发永远不超过五个。

反馈/环境阻断与晚到副作用的完整故障边界复用 #37受控证据，只在真实候选接线改变的部分补验；环境阻断不能被当作需要agent回答的新Decision，也不能自动补发旧输入。停止与放弃分别报告原命令/Operation回执，不把命令accepted写成worker已经停止。
