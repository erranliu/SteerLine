# Spec：多候选本机与远端真机验收

任务 ID：39；任务名称：多候选本机与远端真机验收；目标：`PHASE1-CANDIDATES`。配套 [Plan](candidate-native-acceptance.plan.md)。状态：待实现与验收，一个独立实现 PR 交付。

## 范围与前置

硬前置：#38 [候选观察界面](candidate-console.spec.md)，传递包含 #37/#36。遵守[第一阶段共同约束](phase1-delivery-constraints.md)。复用 #36 的单会话基础证据，交付多候选新增的真实竞争、反馈隔离、唯一交付与残留观察证明；不重建五步或 applied 验收矩阵。

## 真实链路

使用隔离原生项目、当前格式数据库和测试托管仓库，记录实际构建、执行目标/版本与认证。分别在本机和当前受支持远端运行实验Task：至少两个候选重叠工作，使用共同base、独立session/worktree/分支，各自提出可区分的反馈请求并继续原会话，创建不同PR。

人合并其中一个，中心写入唯一 Delivery。后继在合并前不可开始，交付后从包含胜出 merge commit 的 base 启动并完成真实 PR 交付。落选会话/PR 保留可追溯信息，不能因 Task 完成而伪造已停止；资源处置使用实际支持的操作。

另运行同 Task 本机/远端混合候选，在两者等待反馈时重启中心，恢复原会话并分别送达完整选项和文字。对一个候选断连，另一候选继续可观察和交互。既有单会话证据可复用，平台或接线改变的部分须定向重验。

在一组已有混合配置现场中，合并前人工放弃一个候选，核对其立即退出实验、不影响兄弟反馈；停止支持/不支持/待核实按实际能力记录，原历史和资源不删除。允许沿原领取/base人工新增替代实验，不等待旧worker停止，记录新配置与原停止事实。合并后实际提交放弃并核验拒绝，不仅检查按钮。控制台不宣称物理并发永远不超过五个。

## 故障与验收

| 编号 | 通过条件 |
| --- | --- |
| CN1 | 本机和远端各有双候选重叠执行、独立原会话反馈、不同真实 PR |
| CN2 | 一份真实合并形成唯一 Delivery，后继 base 和真实交付正确，重复轮询不重复完成 |
| CN3 | 反馈回执丢失、候选列表变化和迟到轮次不串线、不新建替代 worker |
| CN4 | 一候选连接故障不影响兄弟候选；中心重启重接原会话和原请求 |
| CN5 | 隔离故障样本中的多 PR 合并/未知状态按统一待决策或冲突记录处理，不覆盖既有 Delivery |
| CN6 | 获胜后落选在途输出/PR 仍有归属，停止不支持或结果不明按实记录；不验证中心不可能保证的“阻止在途发布” |
| CN7 | 同Task不同执行配置、混合后端、两份反馈和重启恢复真实通过，冻结配置与版本/会话/消息/PR证据齐全 |
| CN8 | 合并前真实放弃退出实验并保留资源状态，不阻断兄弟/人工新增；合并后放弃被拒绝，未知停止不假称成功 |

测试 PR 由操作者合并，不使用生产任务或人工编辑数据库代验。证据及重跑入口保存 `docs/validation/candidate-native-acceptance/`。只修复本链新增集成缺陷；长期运行与版本组合归 #42。五个数量边界在 #37 的受控测试验，不为数量启动五个真实模型，也不穷举不同配置组合。
