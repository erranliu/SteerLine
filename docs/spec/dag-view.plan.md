# Plan：任务关系视图与只读导出

任务：`DAG-VIEW`。唯一执行依据：[Spec](dag-view.spec.md)，共同要求见 [原生任务共同约束](native-task-constraints.md)。前置为 Beads 退出任务已合入、固定 DAG 的关系读模型及控制台查询边界已交付；本 Plan 只实现关系展示与导出。

## 基线确认

核对 native-tasks/v1 的 database_revision、graph_revision、分页与阻塞语义，复用已交付的 TaskDetail/关系查询。固定图过滤与 native-task-graph/v1 导出契约；原生任务的状态判断和算法保持由前置服务提供。核对控制台稳定选择、阅读位置及离线查询规则，不改业务写入路径。

## 实施步骤

1. 基于固定 DAG 前置的关系 DTO 实现项目/状态/任务邻域查询，完成 version/cursor、过滤边界、深度和数量限制；在同一数据库采样事务读取节点、边与交付，不拼接不同版本的查询。
2. 控制台增加任务前置/后继、具体阻塞、规格与交付来源详情，保持稳定 task_id 选择、离线时间及历史来源区别。复用 CONSOLE 查询入口，不按每个节点调用 Beads 或平台。
3. 实现 JSON 快照和 DOT 导出，明确它们不可作为任务发布输入。添加纯文本转义、边界提示、超限错误、临时文件原子发布及显式 overwrite，失败保留已有输出。
4. 可选调用 Graphviz dot 生成 SVG，参数数组和 stdin 传入，固定 30 秒/20 MiB 限制；阻塞操作在查询/渲染客户端或独立工作单元进行，不进入调度服务循环。缺工具仅阻塞 SVG；不增加 Web 服务和交互编辑器。
5. 用 100/500/1000 节点链/汇合/不连通图、中文长标题和恶意文本样本生成并人工查看 SVG；核验布局、箭头、截断/过滤信息、时间版本及运行详情一致。记录 dot 版本、耗时、体积；失败预算路径也须验证。
6. 发布关系查询和导出用法及可复现样例，把真实导出样本与验证报告链接起来；不将静态图标成实时调度结果。

## 验证与完成

本任务验收：NT18–NT20、NT21-VIEW。重点验证图/列表同一读取版本、游标失效与过滤边界、中文长标题、100/500/1000 节点图、转义/文件覆盖、30 秒与 20 MiB 渲染预算、缺工具降级及调度不被阻塞；先运行针对性测试，再按 [共同约束](native-task-constraints.md) 的验证原则运行完整 Go 测试、静态检查及差异检查。

证据保存在 `docs/validation/dag-view/`，逐项列出验收编号、输入摘要、工具/协议版本、命令、实际结果与证据位置。未运行项不得以 skipped/fake 记为完成。当前文档调整不代表实现验收通过。

本 Plan 的所有实施步骤构成同一个任务，由一个独立实现 PR 交付；不与前置或后继任务合并，也不把内部步骤各自当成独立交付 PR。完成自己的全部验收、兼容回归和文档更新后再交付，不代替后继任务验收。
