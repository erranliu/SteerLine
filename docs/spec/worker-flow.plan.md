# Plan：单 worker 持续执行与统一待决策

任务 ID：36；任务名称：单 worker 持续执行与统一待决策。唯一执行依据：[Spec](worker-flow.spec.md)。无未完成硬前置，一个独立实现 PR 交付。

## 1. 固定替换范围与接口

对照 Spec §2、§6，盘点 `domain.go`、`minimal_step.go`、`native_retry.go`、`decision.go`、`task_execution.go`、`native_service.go`、执行适配器和 UI 的生产入口。列出保留的任务/交付事务与要删除的步骤规则、项目验证、修复轮次、恢复按钮和应用证明要求，避免仅换显示文字。

必要的执行上下文、会话路由和单写职责随本任务完成；复用当前已存在的组件，不先提取将被删除的五步规则。向 #37/#41/#45 提供窄接口并串行集成共享改动，不承担全面 SQL 搬包。

固定新的配置/执行协议和持久格式标识、五个主阶段及消息 DTO。复用 Task、WorkflowRun、Execution、Decision、Operation 和会话正文权威；删去不再有生产用途的步骤状态更新，定义所有 UI 状态从中心事实派生的规则。

## 2. 先验证原会话持续交互能力

分别验证 local、Orca 本机和受监管远端的创建会话、完整输出、轮次结束、输入等待、向原会话发任意反馈与重接能力。记录逻辑 session/worker 身份和平台回执；明确进程重启与逻辑会话替换的区别。

本机旧 `codex exec` 一次性启动、步骤结束自动关闭 PTY，以及受监管步骤完成后释放 Dispatch 的路径不能原样承担持续交互。选用真实支持同会话续聊的原生接口接入已有适配器，不引入第二套会话服务，不从标题/路径猜测身份。不可用能力在首次派发前拒绝。WF2/WF9/WF12 的能力证据不足时不宣告实现完成。

## 3. 接入简化主流程与反馈

保留首次准备、领取和 worker 关联；按 Spec §3 实现一个中心事件处理路径。项目内部阶段只记录进度。轮次停下时处理原会话输出、PR 线索和待决策记录；重复/迟到事件以固定会话和轮次去重。

复用反馈命令与持久化操作，打通选项、纯文本和选项加备注的完整传递。答案保存、送达和工作轮次开始分别作为事实展示，不要求 agent 回传应用摘要。重启与超时沿同一个请求 ID 对账；既有会话不能恢复时保留反馈与原因，首启未完成则对账原启动意图。

用可控后端完成 WF2–WF6/WF9/WF10：包含部分提交后继续、`.meta` 改动、编译错误、重复点击、发送前退出、发送回执丢失、平台重启、同任务旧轮次迟到和不同任务交错。

## 4. PR 观察、完成事务与清理

将 PR 关联入口从 publish_pr 步骤解开，使用原会话线索及 provider 查询，绑定任务/仓库/base/执行分支。移除 `validateNativeDeliveryGates` 对步骤回执链、verified/reviewed revision 的要求；保留真实合并、唯一交付和任务/DAG 事务核验。

覆盖链接查询失败、不同任务 PR、同一 PR 后续推送、关闭未合并后继续、多个线索需选择、真实合并与迟到 worker 消息。已完成/丢弃后保留外部资源事实，不能通过主状态隐去仍运行的现场。完成 WF7/WF8/WF10。

## 5. 配置、控制台与旧路径删除

配置仅保留任务/后端/agent/目标等必要信息；删除新流程不再消费的 `project_steps`、工作流检查/修复门槛、dirty 忽略规则及其兼容分支。给 worker 的输入固定任务 Spec/Plan 和实现、提交、PR 职责，不注入项目验证阶段或文件忽略政策。

TUI/CLI 显示五个主阶段，所有需用户输入的停下状态进入统一待决策；移除用户侧专用重试/恢复按钮，保留基础服务控制、原请求查询及丢弃能力。复用会话折叠、完整正文、PR 链接和离线标识。更新 `docs/data-contract.md`、`docs/decisions.md`、运行说明和受影响 Spec 的当前协议说明，向 #45/#50/#38 交接 DTO。

按 Spec §8 拒绝不支持的旧配置/状态并保留现场，不做旧 17/18/19 自动转换或补造 worker。WF1/WF11 必须包含旧格式负例和新格式重启正例。

## 6. 验证与交付

先完成针对性回归，再执行 Spec §9 的完整 Go 测试、vet 和双平台构建。使用隔离项目在所有要求的执行路径完成至少三轮同会话反馈；本机/远端分别由操作者合并测试 PR，核验原中心交付和后继启动。记录终端/进程重建时逻辑会话保持的证据，不能只比较工作树路径。

在 `docs/validation/worker-flow/` 建立 WF1–WF12 的证据索引、旧入口删除清单和剩余限制。真实平台未通过项如实保留，不以替身测试代替。交付仅更新本任务范围与实际完成状态；既有中心 Task/依赖的规划冲突按固定契约规则处理，不顺手改写生产数据库或关闭外部 PR。
