# 第一阶段交付共同约束

本文只定义 #26–#32 共用的身份、交接和证据规则；每项任务仍以自己的独立 Spec/Plan 和实现 PR 交付。本组文档是待执行规格，不表示中心任务已创建或平台验收已通过。

## 权威与交付

复用[原生任务共同约束](native-task-constraints.md)、[中心执行模型](02-execution-model-and-adapter.md)、[执行架构](execution-architecture.spec.md)、[人工决策](pr-05-intervention.spec.md)、[远程闭环](03-remote-execution-and-viewer.md)与[服务生命周期](pr-03-service-lifecycle.spec.md)。SQLite 是任务、执行、决策和交付的唯一权威；运行配置与版本选择文件不复制业务状态。

本组显式扩展原生任务共同约束中“一个权威活动 WorkflowRun”的默认边界：新建且契约明确允许多候选的 Task 可有多个候选 WorkflowRun；每个 WorkflowRun 仍只有一个活动 Execution。原 single 契约及既有任务不自动获得多候选资格。TaskDelivery 仍唯一，必须由中心核验选用候选的步骤门槛、精确 PR 及真实合并事实；agent 退出或 worker_done 不关闭 Task。

一个实现任务对应一份 Spec/Plan 和一个最终交付 PR。产品中的多候选可各有竞争 PR，但只选用一个经核验的 PR 作为任务交付；其余 PR 和资源保留各自事实。改变已创建任务的执行契约不属于本组范围。已支持的[追加前置](native-task-add-predecessors.spec.md)只改变执行资格。#26 保留尚未领取 multiple Task 的补边/丢弃，并实现全部候选安全结算且未发布时的重开、补边和丢弃；#27 扩展到各 PR 均确认未合并关闭的场景。未知或活动候选必须阻止重置，不能只处理最后一个候选。

## 重构边界与交接

结构重构由 #33 的纯执行规则、#34 的显式执行上下文、#35 的中心/SQLite 包边界独立交付。#26 负责精确候选身份、投影与事务准入，#27 负责交付资格及结算，#28 消费同一查询和命令接口；#30 收敛版本选择和运行身份，#31 接入维护屏障。结构任务的拟追加前置以中心回执生效，既有 TaskContract 保持。复用现有按 WorkflowRun 管理的 worker、Query/Command 和 SQLite 事务；拆分以这些职责为界，不另建候选权威、worker 管理器或通用策略框架。

各任务在验证记录中列出所改动作入口、固定目标、意图写入事务和对应验收项，覆盖 CLI、控制台、自动推进与恢复路径。候选资格和维护屏障的最终检查与新的外部动作意图在同一项目事务中提交；可复用小范围的事务内检查函数，具体动作仍核验自己的版本、能力和业务证据。原请求重放与已持久化 Operation 的观察、回执入库、资源结算沿用原身份；这些路径不能因禁止新动作而丢失，也不能借“恢复”创建替代执行。#26/#27 与 #31 涉及同一动作入口时，由后集成方核对两种约束都生效并补齐组合竞态回归，不增加两条任务链之间的开工硬前置。

这些细化解释各任务既有范围与验收项。已创建 Task 的执行依据仍是中心契约固定的 Spec/Plan 提交和摘要；修改文档路径下的当前内容不会更新该绑定。执行前核对所选文档与固定契约，超出固定要求的新增交付范围须另行形成执行依据，不能通过文档编辑或追加依赖替换原契约。

## 状态格式与部署

默认不兼容此前开发格式。为保留现有项目 DAG，本组唯一明确要求的升级是 #26 从原生数据库 schema 5 到其发布的多候选新格式的受控转换：保留 Task ID、原 single 契约、依赖、Command/Operation、Decision、WorkflowRun/Execution/Attempt、PR 和外部绑定；转换前停服、取得原仓库锁、备份并验证，未知或不支持的输入拒绝写入。#26 必须固定源格式样本、目标 schema 与明确的旧/新摘要模式；不得试遍摘要算法或以清空状态代替升级。该具体转换不扩大为通用迁移框架；其他格式变化必须在所属 Spec 中明确，#31 的提升入口默认拒绝未认证的格式组合。

stable/dev 使用不同 home 和不同测试仓库，不要求同时操作同一仓库。原仓库身份锁仍跨 home 生效，不能因 channel 不同让同一仓库出现两个写者。当前格式内的重启、同身份恢复和副作用对账必须保留；不自动恢复旧数据库快照或回退已合并代码。

## 验证与证据

每任务在 docs/validation/<对应文件名前缀>/ 保存命令、构建摘要、数据库/项目身份、平台版本与目标、请求/执行/PR 身份、实际结果和未通过项。生产改动先跑针对性回归，再运行 `go test ./... -count=1 -timeout=45m -p 1 -parallel 1`、`go vet ./...` 和 Windows/Linux Go 构建；本组将原生共同约束的全套测试上限明确改为 45 分钟。仅文档编写检查身份、链接、引用方向、依赖与语义，不运行实现测试。替身/编译通过不证明原生平台通过；长跑未完成必须如实记录。

真机任务不得共享生产活动工作区。远端能力按实际目标和版本认证；既有 home 样本不能认证台式机64g。未知外部结果保留原身份和占用，远端取消仍按已测能力标为 unsupported；终止中心监督不代表 worker 已退出。PR 合并由人完成，验收脚本只核验。
