# L2/L3 测试依赖边界

生产程序与生产包不得直接或间接依赖 E2E 场景、测试 runner、fixture 或测试进程管理包。L2/L3 保持同仓独立 Go 包，不拆 module，不增加生产 API。

测试侧依赖集中于三层：driver 使用现有产品控制/查询接口；native 适配原生工具发现、CLI 返回及执行配置；evidence 使用现有实现 codec 验证原执行身份，并返回测试自有的模型、会话、权限和回合证据。testenv 与场景不直接导入生产 facade 或 Codex/Orca 实现包，只消费这些测试适配层及 contracts/task 数据合同。

抽取不得改变权限、会话绑定、模型、usage、清理或场景选择语义，不复制生产 codec，不绕过身份校验，不创建兼容路径。L1 固定入口包含依赖边界检查，检查生产依赖闭包和启用 e2e tag 的场景/环境导入方向。

最小验证：边界检查能拒绝传递依赖和场景直接依赖实现；evidence 正常解码与错误身份拒绝；受控 L2 交付和 L3 恢复保持现有断言；真实场景只做编译，不重复模型请求。
