# Spec：任务图规则拆包与测试分层

任务 ID：13；任务名称：任务图规则拆包与测试分层；目标：`REFACTOR`。状态：待实施。配套 [Plan](taskgraph-modules.plan.md)。本任务由一个独立实现 PR 交付。

## M1：目标与前置

硬前置：[#12](beads-path-removal.spec.md) 合入；使用 [#11](test-feedback.spec.md) 的测量工具与夹具基线。在单一原生路径上建立可单独测试的任务图规则包，并将 CLI 进程集成测试移出核心包。遵守[原生任务共同约束](native-task-constraints.md)、[固定 DAG](task-dag.spec.md)和[关系视图](dag-view.spec.md)。

本任务固定交付下述模块边界；测量只用于选择夹具优化和安全并行范围，不扩大为整个 Service、SQLite、会话和执行后端的一次性重写。保留 Go 单一 module；这里的拆分指 Go package。

## M2：任务图规则包

建立 `internal/steerline/taskgraph`，承接当前散布在 `task_dag.go`、`task_graph_query.go` 的纯规则：确定性环检测、数字任务 ID 排序与稳定就绪顺序、邻域遍历和深度/节点/边界截断计算。相关用例与规则同包测试。

- 包只接受调用方传入的节点、依赖、已核验资格和过滤值，返回确定性结果；不访问 SQLite、文件、时钟、Git、OS 进程或后端，也不反向导入父包。
- QueryService/CommandService 继续从同一中心事务/读取快照取得事实。任务资格、交付有效性、版本检查、权限和事务提交保持在当前权威边界；图算法不能成为第二套 ready 状态来源。
- 只定义算法必要的最小输入/结果类型。父包保留持久化模型和对外 DTO，使用薄转换调用；不保留两份算法、不引入泛型仓储或通用依赖注入框架，也不把整个 Runtime 搬入公共 model 包。
- 现有 `native-task-graph/v1`、分页游标、数据库/图版本、边方向、稳定排序、丢弃前置阻塞、500 节点/边界边与深度上限保持不变；JSON 文件发布和覆盖保护仍在 I/O 层。

## M3：测试归属与独立入口

1. 纯图算法测试归 `taskgraph`，只构造内存数据。保留分支汇合、不连通图、环、数字排序、截断和边界计数等行为；大输入矩阵集中在此验证，不在每层重复全部组合。
2. 核心包保留事务/CAS、交付资格、同快照读取、游标失效与权威绑定测试。为转换接线保留少量有代表性的跨层场景，确保纯函数输出实际接入命令和查询。
3. 建立 `internal/steerline/integration` 包，经实际 CLI 进程和现有公开入口验证行为。至少迁入当前 `cli_test.go` 的旧来源拒绝场景，并从现有 CLI/服务测试迁入一个原生命令成功场景，验证两者的退出结果与持久化/无副作用事实。本次运行只构建一次当前 CLI，各场景独立状态；不为测试导出私有 Service 字段或增加生产调试 API。
4. 默认 `go test ./...` 自动覆盖所有上述确定性测试，不增加默认关闭的 integration 标签、名称白名单或环境开关。已有真实平台验收仍用原开关运行并单独报告。
5. 日常规则修改可单独运行 `go test ./internal/steerline/taskgraph`；改变跨包接线、持久化或 CLI 时运行相应消费者/集成包。完整无缓存回归仍是合入门槛，不能因定向测试成功就宣称全套通过。

## M4：并发、性能与依赖检查

只为无共享可变状态的规则/fixture 用例引入有界并行。使用进程级环境变量、工作目录、真实宿主窗口或共享平台资源的用例保持串行；真实并发写者测试继续验证业务仲裁。测试并行不能改变生产单 Execution 策略。

使用 #11 工具比较 #12 合入基线与本任务最终版本，列出按包/全量耗时、构建成本及测试迁移映射。规则包独立命令必须不执行核心/集成测试，也不启动子进程或建数据库；移入的 CLI 场景只在 integration 包拥有一份测试。完整套件不得遗漏原有行为或引入未解决耗时回归。若并发未改善实测耗时或导致不稳定，保持串行并给出数据，不以开更多进程作为完成条件。

通过 `go list` 核验 `taskgraph` 依赖不含父包、SQLite、UI、网络/平台适配。移出规则在父包只保留必要接线；测试清单逐项说明迁移、合并或删除原因。包路径和测试入口写入开发文档。

## M5：集成关系与验收

与 #6 的远端协议独立样例可并行；涉及 Query/Command、Task DTO、原生 Service 接线或同一测试夹具时串行集成，后集成方运行受影响双方回归。#3 的真实交互验收继续使用固定版本和隔离资源。本任务不修改现有运行时任务的固定依赖。
