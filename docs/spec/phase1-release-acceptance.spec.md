# Spec：第一阶段集成验收

任务 ID：32；任务名称：第一阶段集成验收；目标：`PHASE1-DELIVERY`。配套 [Plan](phase1-release-acceptance.plan.md)。状态：待实现与验收。一个独立实现 PR 交付。

## 范围与前置

硬前置：#29、#31。#29 传递汇合 #3/#4/#6/#26/#27/#28，#31 传递汇合 #30。依赖[多候选真机验收](candidate-native-acceptance.spec.md)、[环境隔离与提升](runtime-isolation-promotion.spec.md)，遵守[共同约束](phase1-delivery-constraints.md)。

本任务给出第一阶段可持续使用版本的交付判定，交付集成验收脚本/记录、运行入口说明、未结算资源清单和维护指引。只修复组合运行的接线缺陷；候选模型、远端基础能力、版本管理或平台权限的缺失实现仍归原任务。第一阶段采用 CLI/TUI；WinUI 和主 agent 规划闭环仍归第二阶段。

## 固定验收基线

选择包含全部前置实现的干净 commit 和 manifest，固定本机/远端 agent、Orca 目标/版本、测试仓库与 home。逐项核对前置交付及原生证据；来源文件、目标或构建变化时重跑受影响部分，不能将旧 home 能力标到新主机。尚未解决的管理员/UAC、精确 turn/final、生产提示启动或新主机回传问题必须由所属前置明确结算，不能在本任务改写为 passed。

## 组合闭环与持续运行

在真实 Windows stable 入口上完成一条本机和一条当前认证远端的原生依赖链。每条链包含 multiple Task：两个候选独立问答、步骤及 PR；由人合并一个后，中心唯一结项并从含合并成果的 base 执行后继。复用 #29 脚本，但要在本次组合构建和固定入口上重跑关键链路；保留全部 PR 与资源处置证据。

stable 在固定 build/home 下连续至少 24 小时真实运行，其间交付至少五个原生任务：上述两条依赖链共四个任务，加一个独立 single 策略任务；并覆盖无人操作的空闲期、待问题/待合并期。此处承接 #6 不承担的长期无人值守与跨任务资源稳定性矩阵；#6 的功能、故障安全和真实交付仍须先独立通过。并行使用 dev 独立仓库做构建、调试、退出重开、dev select 和入口重生成。24 小时必须来自真实墙钟及进程/日志证据，不快进时间；中途更换 stable build 或异常失去监督则修复后重新计时。持续运行不代替 PR 合并交付。

每 60 秒采样 stable 中心进程的 PID/启动身份、心跳、Private Bytes、句柄数、goroutine 数，以及 Task/候选/未结算待办和错误；agent 子进程、文件日志及 SQLite 业务历史增长单列，不混入中心内存指标。采样覆盖率须不低于 99%，任一间断不得超过 180 秒。先预热一小时，在无活动 worker/未知动作/等待合并的同等空闲负载下取初始连续 30 分钟样本；全部任务及资源结算后，在末尾再取同等负载连续 30 分钟样本。

以两窗口中位数比较：Private Bytes 增量不得超过 max(64 MiB, 初始值的 20%)；句柄增量不得超过 32；goroutine 增量不得超过 10。平台已明确结算且无需人工动作的清理待办须在 5 分钟内清零，任一候选残余 worker/句柄需能追溯。阈值不满足或缺同等负载窗口即未通过，需定位修复后重跑；正常持久日志/数据库增长按新增任务和事件量解释，不要求磁盘文件回到初始大小。通过还要求无未解释退出、任务/问题丢失、重复派发/PR、串线或假释放。这只是本次有限时段的回归门槛，不宣称证明永不泄漏。人工干预逐项记录；手动 Enter 才启动的运行不计为无人值守启动通过。

持续运行窗口之外做一次受控 stable 提升与一次当前格式重启：提升到另一个已验收固定构建，确认旧服务退出、原库恢复、Task/DAG、等待合并 PR 和请求身份保留。活跃/unknown 外部执行只验证提升被拒绝，不强制绕过 #31 门槛。重启后的原请求/PR 对账不得生成替代 worker、重复 PR 或第二份 TaskDelivery。
