# Spec：第一阶段集成验收

任务 ID：42；任务名称：第一阶段集成验收；目标：`PHASE1-DELIVERY`。配套 [Plan](phase1-release-acceptance.plan.md)。状态：待实现与验收。一个独立实现 PR 交付。

## 范围与前置

硬前置：#39、#41。#39 传递包含 #38/#37/#36，#41 传递汇合 #40。依赖[多候选真机验收](candidate-native-acceptance.spec.md)、[环境隔离与提升](runtime-isolation-promotion.spec.md)，遵守[共同约束](phase1-delivery-constraints.md)。

本任务给出第一阶段可持续使用版本的交付判定，交付集成验收脚本/记录、运行入口说明、未结算资源清单和维护指引。第一阶段统一只包含本地 Codex 与本机 Orca，不包含远端准入、派发、反馈、恢复、取消或远端组合验收，也不把远端列作本任务阻塞/待补验。只修复本机组合运行的接线缺陷；版本管理或本机权限的缺失实现仍归原任务。第一阶段采用 CLI/TUI；WinUI 和主 agent 规划闭环仍归第二阶段，远端流程另行规划。

## 固定验收基线

选择包含全部前置实现的干净 commit 和本机 manifest，固定本地 Codex/本机 Orca 的 agent、版本、测试仓库与 home，不要求远端目标或远端权限回执。逐项核对本机前置交付及原生证据；来源文件、目标或构建变化时重跑受影响部分。尚未解决的本机管理员/UAC、精确 turn/final 或业务提示启动问题必须由所属前置明确结算，不能在本任务改写为 passed。

## 组合闭环与持续运行

在真实 Windows stable 入口上完成两条本机原生依赖链，覆盖本地 Codex 与本机 Orca。每条链包含一个双候选实验 Task 与一个后继 Task：两个候选独立原会话反馈及 PR；由人合并一个后，中心唯一结项并从含合并成果的 base 执行后继。两条链的后继分别使用本地 Codex 和本机 Orca。复用 #39 的本机多候选证据和夹具，在本次组合构建及固定入口重跑必要集成链，不重复完整配置矩阵、旧五步或业务应用证明；保留全部 PR 与资源处置证据。

stable 在固定 build/home 下连续至少 24 小时真实运行，其间交付至少五个本机原生任务：上述两条依赖链共四个任务，加一个独立 single 策略任务；并覆盖无人操作的空闲期、待问题/待合并期。本次只验证当前本机范围的长期无人值守与跨任务资源稳定性，不引入旧远端任务或旧试验的先行验收链。并行使用 dev 独立仓库做构建、调试、退出重开、dev select 和入口重生成。24 小时必须来自真实墙钟及进程/日志证据，不快进时间；中途更换 stable build 或异常失去监督则修复后重新计时。持续运行不代替 PR 合并交付。

每 60 秒采样 stable 中心进程的 PID/启动身份、心跳、Private Bytes、句柄数、goroutine 数，以及 Task/候选/未结算待办和错误；agent 子进程、文件日志及 SQLite 业务历史增长单列，不混入中心内存指标。采样覆盖率须不低于 99%，任一间断不得超过 180 秒。先预热一小时，在无活动工作轮次/未知动作/等待合并的同等空闲负载下取初始连续 30 分钟样本；全部任务及资源结算后，在末尾再取同等负载连续 30 分钟样本。

以两窗口中位数比较：Private Bytes 增量不得超过 max(64 MiB, 初始值的 20%)；句柄增量不得超过 32；goroutine 增量不得超过 10。平台已明确结算且无需人工动作的清理待办须在 5 分钟内清零，任一候选残余 worker/句柄需能追溯。阈值不满足或缺同等负载窗口即未通过，需定位修复后重跑；正常持久日志/数据库增长按新增任务和事件量解释，不要求磁盘文件回到初始大小。通过还要求无未解释退出、任务/问题丢失、重复派发/PR、串线或假释放。这只是本次有限时段的回归门槛，不宣称证明永不泄漏。人工干预逐项记录；手动 Enter 才启动的运行不计为无人值守启动通过。

持续运行窗口之外做一次受控 stable 提升与一次当前格式重启：提升到另一个已验收固定构建，确认旧服务退出、原库恢复、Task/DAG、等待合并 PR 和请求身份保留。活动工作轮次/未知外部动作只验证提升被拒绝，空闲可恢复原会话须验证可以提升后继续，不强制绕过 #41 门槛。重启后的原请求/PR 对账不得生成替代 worker、重复 PR 或第二份 TaskDelivery。
