# Spec：第一阶段集成验收

任务 ID：42；任务名称：第一阶段集成验收；目标：`PHASE1-DELIVERY`。配套 [Plan](phase1-release-acceptance.plan.md)。状态：待实现与验收。一个独立实现 PR 交付。

## 范围与前置

硬前置：#39、#83。#39 传递包含 #38/#37/#36；#83 提供本机安装与调试路径隔离。复用已交付的[本机多候选证据](../validation/candidate-native-acceptance/README.md)，依赖[本机安装与调试路径隔离](local-runtime-isolation.spec.md)，遵守[共同约束](phase1-delivery-constraints.md)。#40/#41 延后，不是本任务或 #53 的传递前置。

本任务给出第一阶段单安装版可持续使用的交付判定，交付集成验收脚本/记录、运行入口说明、未结算资源清单和维护指引。第一阶段统一只包含本地 Codex 与本机 Orca，不包含远端准入、派发、反馈、恢复、取消或远端组合验收，也不把远端列作阻塞/待补验。只修复本机组合运行的接线缺陷；安装/调试入口和隔离缺陷归 #83。第一阶段采用 CLI/TUI；WinUI 和主 agent 规划闭环归第二阶段。双 channel、dev select、受控提升、跨构建活动状态接管和旧格式兼容不在本任务范围。

本次修订是仓库中的新执行规划。实施前核对中心 Task 的固定 commit/摘要/依赖；已创建的旧契约不能被本文件覆盖。若中心仍固定旧版本范围，须经受控替换并同步任务身份和消费者依赖后再执行，不能仅删去文档前置宣告 Ready。

## 固定验收基线

选择包含全部前置实现的干净 commit，记录安装 exe 的绝对路径、SHA-256、源码 commit、home、配置及本地 Codex/本机 Orca 的 agent、版本和测试仓库。基线清单只是本次验收输入，不是产品版本 manifest 或选择记录。逐项核对本机前置交付及原生证据；来源文件、目标或构建变化时重跑受影响部分。尚未解决的本机管理员/UAC、精确 turn/final 或业务提示启动问题必须由所属前置明确结算，不能在本任务改写为 passed。

已有 L2/L3 提供真实交付、当前格式恢复和候选证据，按本次构建及接线影响复用，不重复完整上游矩阵。但 runner 临时构建通过不等于安装入口通过；本任务组合链及重启必须使用上述精确安装产物，启动前后核对摘要。所需测试环境能力沿现有适配层扩展。

## 组合闭环与持续运行

在真实 Windows 安装入口上完成两条本机原生依赖链，覆盖本地 Codex 与本机 Orca。每条链包含一个双候选实验 Task 与一个后继 Task：两个候选独立原会话反馈及 PR；由人合并一个后，中心唯一结项并从含合并成果的 base 执行后继。两条链的后继分别使用本地 Codex 和本机 Orca。复用 #39 的本机多候选证据和夹具，在本次安装构建重跑必要集成链，不重复完整配置矩阵、旧五步或业务应用证明；保留全部 PR 与资源处置证据。

安装版在固定 exe/home 下连续至少 24 小时真实运行，其间交付至少五个本机原生任务：上述两条依赖链共四个任务，加一个独立 single 策略任务；覆盖无人操作的空闲期、待问题/待合并期。并行在独立测试 clone/home 中构建、调试及停启源码版本一次，安装摘要、实例及任务事实保持；复用 #83 的路径与隔离断言，不做版本选择或提升。24 小时必须来自真实墙钟及进程/日志证据，不快进时间；中途替换安装 exe 或异常失去监督则修复后重新计时。短时 E2E 不替代本次持续运行，持续运行不代替 PR 合并交付。该窗口只阻塞本任务最终交付，不阻塞 #43/#44/#45/#50 的按前置研发。

每 60 秒采样安装版中心进程的 PID/启动身份、心跳、Private Bytes、句柄数、goroutine 数，以及 Task/候选/未结算待办和错误；agent 子进程、文件日志及 SQLite 业务历史增长单列，不混入中心内存指标。采样覆盖率须不低于 99%，任一间断不得超过 180 秒。先预热一小时，在无活动工作轮次/未知动作/等待合并的同等空闲负载下取初始连续 30 分钟样本；全部任务及资源结算后，在末尾再取同等负载连续 30 分钟样本。

以两窗口中位数比较：Private Bytes 增量不得超过 max(64 MiB, 初始值的 20%)；句柄增量不得超过 32；goroutine 增量不得超过 10。平台已明确结算且无需人工动作的清理待办须在 5 分钟内清零，任一候选残余 worker/句柄需能追溯。阈值不满足或缺同等负载窗口即未通过，需定位修复后重跑；正常持久日志/数据库增长按新增任务和事件量解释，不要求磁盘文件回到初始大小。通过还要求无未解释退出、任务/问题丢失、重复派发/PR、串线或假释放。这只是本次有限时段的回归门槛，不宣称证明永不泄漏。人工干预逐项记录；手动 Enter 才启动的运行不计为无人值守启动通过。

持续运行窗口之外，使用同一个安装 exe 做一次等待合并状态的当前格式服务重启：确认旧服务退出、新服务实例可识别，原库、Task/DAG、Workflow/Execution、原会话、请求及等待合并 PR 保留，随后正常核验交付。新服务实例不意味着新的 worker；原请求/PR 对账不得生成替代 worker、重复 PR 或第二份 TaskDelivery。不替换构建，不验跨版本恢复或活动/unknown 提升门槛。
