# Spec：候选观察界面

任务 ID：38；任务名称：候选观察界面；目标：`PHASE1-CANDIDATES`。配套 [Plan](candidate-console.plan.md)。状态：实现 PR 待独立复审；CC1–CC4/真实接线已有证据，CC5 原生终端输入验收未通过，不能宣称任务完成。证据见[验收记录](../validation/candidate-console/README.md)。

## 范围与前置

硬前置：#37 已交付，传递包含 #36；需要核对接口时查当前产品合同、投影和候选服务源码，不追读已交付 Spec/历史验收链。遵守[第一阶段共同约束](phase1-delivery-constraints.md)。一期只增加用于人工方案实验的候选列表、选择、反馈和放弃，复用原TUI与统一待决策；不建设评分、排名、融合或实验调度工作台。

## 展示与操作

每Task一条主行，详情按workflow_run_id列出当前与历史候选。显示实际冻结配置、主状态、开始/采样与耗时、最终回复、PR/差异定位、获胜/落选/放弃/冲突和资源事实。未支持指标显示缺口，不把Task已完成或候选已放弃显示为worker已停止。

新增候选先选一套已支持执行配置，再提交 #37 的精确目标、版本与原request_id。当前参与数达到5个时显示开始限制及原因；服务仍只做开始时检查，不显示严格五名额、排队、自动补位或资源容量保证。偶尔超额如实列出，不隐藏或自动停止。

候选正文、输入草稿、请求与阅读位置按Task/WorkflowRun/Execution/session隔离。分页、重排、迟到消息和重开保持ID选择；统一反馈支持文字/选项/备注，保存、送达与轮次开始按真实回执显示。

会话、正文、raw与活动只消费当前产品查询返回的已提交规范记录，不按候选直接打开/检测原生日志或借日志补画；缺口明确显示。环境blocker与agent业务Decision分别展示，阻断时保留本地未发送草稿、显示服务拒绝原因，不保存客户端自动补投队列。原终端/重新检查动作绑定所选候选、blocker/turn、版本和实例，切换候选不改投递目标，解除阻断后仍需人重新提交。

人工放弃入口明确候选和配置、退出实验的不可撤销语义、worker可能仍运行。按 #37 的服务资格提交abandon_candidate，不直接kill进程、不丢弃Task或删除资源。放弃回执后该候选归历史/退出实验，不再反馈；停止待核实可继续查看。已知PR合并后关闭放弃入口，提交时服务重检；待核实不能伪装为已放弃成功。

PR链接由人选择并合并，中心核验后显示唯一交付。放弃历史和落选资源保留定位；多个PR冲突通过原待决策入口解释，不增加强制胜出或自动清理按钮。

## 与解耦任务并行

#73 可与本任务并行：本任务拥有候选交互/视图和产品 fixture，#73 拥有纯类型归属/import 与构造迁移；共享产品定义/app 接线先由 #73 顺序集成，本任务随已集成契约更新，不同时改同一段。#74 改选择/结果业务边界时保持本任务的精确目标、资格原因与原回执语义，共同 DTO/工厂段约定单个修改所有者。

本任务不等待全面解耦；#77 产品/控制台迁移以本任务整体交付为硬前置，随后完整迁移本任务实际消费者和测试。原 Windows 输入证据只在输入/渲染实现未变时复用；构造/公开 DTO 变化必须重验受影响 CC 接线。路径迁移同次更新本 Spec/Plan 的实际命令，不新增产品功能或把契约草案当交付。
