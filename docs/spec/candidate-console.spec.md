# Spec：候选观察界面

任务 ID：38；任务名称：候选观察界面；目标：`PHASE1-CANDIDATES`。配套 [Plan](candidate-console.plan.md)。状态：待实现与验收，一个独立实现 PR 交付。

## 范围与前置

硬前置：#37 [多候选会话与唯一交付](candidate-workers.spec.md)，传递包含 #36。遵守[第一阶段共同约束](phase1-delivery-constraints.md)。本任务只增加 TUI/CLI 的候选列表、选择和精确反馈定位；复用 #36 的五个主阶段、会话展示与统一待决策，不建设专用恢复或项目验证界面。

## 展示与操作

每 Task 一条主行，详情按 workflow_run_id 列出当前与历史候选。候选各自显示原会话、主状态、最近回复、PR、获胜/落选/冲突及资源事实。Task 已交付时仍可从历史详情查看落选会话和未结算资源，不将落选等同于停止。

分页、列表重排、迟到消息和重开后按精确 ID 保持选择、展开和阅读位置。候选正文、输入草稿及请求按 Task/WorkflowRun/Execution/session 隔离，不自动把另一候选的回复或答案切过来。

multiple Task 提供“新增候选”，通过 #37 的同一命令提交精确任务版本/图版本、配置和请求 ID。所选候选使用原会话的反馈输入，支持纯文字、选项和选项加备注；保存、送达与工作轮次开始按真实回执显示，不要求应用证明。single 不显示新增候选能力。

PR 打开精确关联链接，由用户合并；中心确认实际合并后才显示交付。停服、明确丢弃和平台不支持的操作沿既有资格展示；不新加 retry/mark-stopped/强制胜出按钮。多个 PR 冲突通过原待决策详情解释，不在 UI 改写交付。

## 验收

| 编号 | 通过条件 |
| --- | --- |
| CC1 | 三候选仅一 Task 主行，候选分页和状态/会话/PR 与同一服务快照一致 |
| CC2 | 切换、重排、迟到输出与重启不串正文或草稿，保持阅读位置 |
| CC3 | 新增候选及反馈绑定精确身份，重复点击/丢回执沿原请求，不重复启动/发送 |
| CC4 | 已交付 Task 的落选资源和迟到 PR 可定位，错误事实不伪装为新主状态或已停止 |
| CC5 | Windows TUI 的中文输入、选项加备注、键盘导航、窄窗口及滚动真实通过 |

CC1–CC4 使用真实中心与可控后端，CC5 使用真实 Windows 终端；证据保存 `docs/validation/candidate-console/`。真实多候选合并与跨主机竞争归 #39。
