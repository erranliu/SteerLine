# Spec：解除 Beads 依赖与原生接入

任务 ID：9；任务名称：解除 Beads 依赖与原生接入；目标：`BEADS-EXIT`。状态：待实施。配套 [Plan](beads-exit.plan.md)。本任务由一个独立实现 PR 交付。

## B1：范围与前置

前置：[固定 DAG Spec](task-dag.spec.md) 完整验收并合入；复用[原生任务模型](task-core.spec.md)和[原生任务共同约束](native-task-constraints.md)。本任务使原生任务成为可实际接入的项目来源，完成配置、预检、worker 上下文、步骤技能、PR 核验与交付闭环。不再实现 DAG 算法、任务拆分或回退。

项目尚未上线，不提供 Beads 数据导出、旧项目导入、旧运行迁移或同时维持两种生产任务来源。现有 Beads 代码可作为重构输入，原生接入完成后不作为产品兼容路径。发现旧 Beads 状态或仍可能活跃的外部执行时拒绝自动接管；人先核实现场，再使用干净状态目录接入。

## B2：原生项目接入

- 配置和 `check` 不要求 bd/bv、Beads 目录或数据库；配置显式选择 native，中心数据库是任务和交付的唯一权威。当前状态与配置不符时拒绝启动有副作用动作，不因改配置创建另一份权威。
- 创建、丢弃、ready、claim、详情、恢复和关闭复用中心任务服务。worker 只接收 `native-task/v1` 固定上下文：project/task/contract、run/execution/attempt、仓库/分支/base 与当前步骤输入。执行端核对真实工作区与契约摘要，不从 Beads 环境变量推断身份。
- 项目提供已提交的 `project_steps`，分别实现 implement、verify、按配置 review 和 publish_pr；技能或脚本只返回本步事实，不领取任务、不写中心数据库、不调用 bd/bv 或额外结项回调。预检须发现仍依赖旧 start/finish、completion 或 Beads 的入口并拒绝执行。
- PR 由人合并。中心按[固定 DAG Spec D3](task-dag.spec.md)核验平台事实并在事务中记录 TaskDelivery、关闭任务和释放后继，不运行 Beads close、BV 刷新或旧 completion。
- 对已丢弃任务，生产接线按中心保存的固定执行、PR 和工作区身份处理 `cleanup_pending`：本机仅使用已验证的 Stop 能力，远端不支持取消时保留资源并交人工；开放 PR 与工作区分别清理并持久化回执，结果未知不伪称完成。若丢弃后的 PR 仍合并，复用中心冲突对账，不补写正常 TaskDelivery。
- 本机 Codex 与已支持的 Orca 后端共用执行契约。远端 worker 不安装 SteerLine 服务、不访问中心 SQLite；版本、消息上限和取消限制沿用[远程闭环 Spec](03-remote-execution-and-viewer.md)，不能因原生接入放宽。

## B3：启动与恢复

新原生项目从干净状态目录初始化，默认 manual 且 paused；用户完成配置检查后显式开启派发。当前格式内的命令、领取、步骤回执和交付事实按中心事务恢复。旧状态、未知 schema、旧项目数据库或不明外部资源不触发导入、转换或自动清理，显示具体阻塞原因。只读诊断不把旧状态伪装成原生任务。

配置文件更新失败不回滚已提交的数据库事实；下一次启动若配置与已存权威冲突则拒绝派发，并说明如何核对当前项目。外部 PR 查询失败、合并未证实、结果回执丢失或远端状态不明时保留原身份和资源约束，不重复创建任务或 worker。
