# Spec 主包隔离守卫与测试归位

任务 ID：67；任务名称：主包隔离守卫与测试归位；目标：`CORE-IMPLEMENTATION-DECOUPLING`。配套 [Plan](core-decoupling-06-boundary.plan.md)。硬前置：#66 整体交付，一个实现 PR 完成。

## 目标与范围

完成主包直属测试去平台化，建立主包外的持续隔离守卫，并证明新增中性实现无需修改主包生产代码。

遵守[共同约束](core-decoupling-constraints.md)，承接当前执行隔离及恢复修复，不回写历史 Spec。迁移输入：root 含平台名称的测试及 acceptance helpers、fixture、cmd/test-feedback 最小入口、所有实际生产目录/依赖和外层集成入口；生产搬迁必须已由 #62–#66 完成。

## 验收产物与覆盖归属

| 方向/所有者 | 输入或输出 | 固定语义 |
| --- | --- | --- |
| 实现包 | 原生单元覆盖 | 协议、命令、codec、版本与原身份 fixture 归实现，中心规则不重复。 |
| 主包 | 中性业务覆盖 | 单写者、提交失败、资格、重启人工门槛、唯一交付等中性 fixture，源文件无平台文本。 |
| 外层集成 | 产品与原生覆盖 | 现有平台 live/跨层 fixture 经过应用构造和产品端口，保留原证据条件，不以导出私有中心写接口迁移。 |
| 最小入口 | 隔离和扩展证明 | 守卫扫描全部直属源码/文件名和全 OS 依赖，第三实现使用同一目录；实际命中与旧到新映射作为结果交付。 |

## 必须交付的契约与消费者

1. 每个 root 平台测试按职责归位：原生 codec/命令/身份协议 unit 移到对应实现，跨产品真实平台用例移到外层集成包，中心 Decision/Operation/事务/恢复门槛改用中性 fake。不能仅改测试名字、删失败测试或为外层测试导出任意 Service/Store 写接口。

2. 最终扫描 root 直属全部 Go 文件（含 _test.go、不同 OS 文件和文件名）大小写不敏感 codex|orca 必须零命中，无例外。守卫自身和具体 fixture 在外层，构造输入中的动态实现名称允许按数据传递。

3. 结构守卫解析实际生产 import 并检查全体平台文件的直接/传递依赖，禁止 root 经 contracts/helper 重新导入平台、组装或集成包，禁止平台反向导入 root；平台含 Service 代用品的可写端口须人工审阅拒绝。守卫接到现有最小入口；AST 扫描全部构建标签下的源码，生产传递依赖至少采样 Windows/Linux，额外项目内 import 边用完整源码图核对。主包生产零命中由 #66 已交付，最终守卫加入直属测试；不依赖默认 OS 排除另平台源码。

4. 在外层定义一个名字中性的第三实现，使用现有目录/codec 和通用端口完成配置受理、固定目标、started/question/answer/settlement、原输入对账及恢复授权。采用目录注入已有基础，不补产品能力；首个实例运行中保存固定输入，重建服务和来源后只读对账，再经新人工确认恢复。核验原身份、去重及唯一交付边界；root 生产源码无需增加 key/switch/case；fake 的准入与不支持能力必须显式声明，不伪造真实权限证据或构建动态插件系统。

5. 核对全部旧到新测试映射和 fixture 去重，保留 platform live acceptance 的原工具/版本/证据要求。quick 调整只覆盖真实必要包和少量集成代表用例，防止正则零命中、漏移用例或把 mock 视为权限认证。

## 删除与剩余所有者

删除 root 的平台测试文件及遗留 acceptance helpers（由对应所有者承接，非删除覆盖）、无消费者测试工具和重复镜像矩阵。若仍有生产平台命中则回到 #66 范围修复，不把未完成生产搬迁包装为最终清理。

不重做全量或双机/原生能力认证；远程权限证据仍单独列缺口。文件名零命中和关键词零命中不能代替结构依赖及行为验收。

## 开工与集成

#66 整体交付后才完整开工。准备性阅读不构成提前领取资格。共享 execution/contracts、主包配置/Service/事务接线及原生 fixture 的变更串行处理；本任务当场删除已切换消费者的原实现，不交付双路或空接口。
