# Spec：多候选会话与唯一PR交付

任务 ID：37；任务名称：多候选会话与唯一PR交付；目标：`PHASE1-CANDIDATES`。配套 [Plan](candidate-workers.plan.md)。状态：待实现与验收，一个独立实现 PR 交付。

## 范围与前置

硬前置：#36 [持续 worker 流程](worker-flow.spec.md)。遵守[第一阶段共同约束](phase1-delivery-constraints.md)。一期认为外部提供的roadmap和任务契约已稳定，不引入主agent、审核或正式roadmap准入机制。

本任务支持同Task不同执行方案的人工对比实验。默认启动一个候选，人逐个新增、选择原会话反馈或放弃候选；每个候选复用 #36 的持续worker、主阶段与PR观察。候选创建、单候选放弃、完整运行及唯一交付一起交付；TUI增量归 #38，真实混合方案增量验收归 #39。

Task就是实验组，WorkflowRun就是候选，不新增可写Candidate或Experiment权威。中心只提供方案、状态、耗时、最终回复及PR/差异定位，质量与合并选择由人判断，不增加自动评分、排名、淘汰、成果融合、实验队列或自动补位。worker依据同一Spec/Plan实现、验证、提交和创建PR，中心不增加项目验证或审查门槛。

## 身份与启动

默认开始只创建首个WorkflowRun并完成Task claim。后续人工start_candidate沿用原领取、固定任务契约、共同base、目标仓库和base分支，只新增WorkflowRun、Execution及启动意图，不重复领取或重开Task。单候选是没有新增候选的普通路径，不另设single/multiple模式或模式切换。

各候选可选择不同的已支持执行配置，分别冻结profile及摘要、backend、agent、模型/推理强度、权限与目标。每个执行端独立核验能取得共同base，各自使用独立worktree、分支、session、消息和PR。原候选不允许就地改配置；需要新方案时放弃旧候选并创建新身份。继续原会话或按现有授权恢复不算新增候选。

start_candidate携带task_id、request_id、当前任务/图版本和选定配置；除下面的宽松数量检查外，复用原身份、资格、能力、版本与幂等校验。事务保存候选和启动intent，提交后才调用后端。相同请求取回原记录，异内容拒绝；未知启动结果只对账原请求，不用新ID补派。

每次人工开始时，读取该Task当前参与实验的候选数量；已经达到5个就返回candidate_limit_reached。未放弃且仍参与实验的准备中、执行中、等待决策或等待合并候选计入；已放弃、获胜或历史终态不计入。数量依据中心记录，不依据进程数或瞬时turn状态。

原request_id的查询与幂等重放先于数量检查；已经受理的原请求在参与数后来达到5个时仍返回原记录，不被数量限制改写为拒绝。数量只约束新的开始动作。

这只是开始时的用户操作限制，不是资源硬上限：不设置名额预留、数量专用CAS、槽位记录、队列或自动补位，不为数量等待停止确认。保留普通业务事务与请求幂等，接受并发请求偶尔超出5个；不要求制造超额、不因超额回滚已受理启动或自动停止候选。不同任务的人工作业并行仍沿原规则，不增加项目级上限。

自动派发只启动未领取Task的首个候选，不自行创建竞争候选。所有候选放弃后Task仍保留原领取、契约与base；未合并且资格满足时可人工新增，不因没有参与候选而重新领取或自动重开。

## 单候选放弃

人工abandon_candidate绑定明确workflow_run_id、Task及候选版本、原request_id和发起者。放弃不可撤销：持久记录退出实验与原因，立即禁止该候选新增推进/反馈、不再计入开始检查，不修改Task状态、不撤销兄弟候选、不删除原记录。其回执只证明退出实验，不证明worker停止或资源已清理。

对已知关联PR先核验合并事实，并在业务提交内重检Task/候选及PR关联前值。该Task任一已知关联PR已确认merged，或已经正式交付时，拒绝候选放弃；PR合并状态无法核实时沿原请求保持待核实，不能凭缓存或用户文字认定未合并。已知合并后的新增候选也拒绝，转入交付核验。中心不宣称知道尚未报告的外部PR。

候选退出实验后，可按已有后端能力和原身份请求停止；停止不支持、失败或结果未知如实显示，不回滚退出实验，也不阻塞新增候选。只沿原停止请求对账，不重复kill或扩大到兄弟资源。worktree、PR和必要来源观察保留，停止与清理各用原有生命周期规则，不建立实验专用资源结算状态机。

放弃与PR实际合并跨系统无法原子互斥。先完成放弃后才发现该候选PR已合并，记录明确冲突并进入既有人工处置，不悄悄恢复候选资格、选择它获胜或覆盖交付。Task已交付后仍记录迟到输出/合并及资源事实，但不再提供候选新增或放弃；实际停止/清理与交付事实分开。

## 查询、交互与恢复

Task查询返回当前与历史候选集合。执行命令、正文、游标、草稿和反馈绑定workflow_run_id、Execution与原session；不能按task_id猜最后一个运行，目标不唯一返回ambiguous_execution。分页、重排和重启保持精确选择与database revision。

候选DTO提供冻结配置、实际执行身份/版本、主阶段、当前轮次、决策、开始/结束采样与耗时语义、最终回复、PR定位、放弃及真实资源状态。缺指标或能力如实标明，不伪造统一成本。候选结果不复制为Task级权威。

复用原Command/Operation、事件/正文、消息去重与当前格式恢复。一个候选等待输入、放弃或断连，不停止其他候选。已放弃候选重启后不能复活或重新发送，未结算停止和迟到消息仍核验原身份；不能因5个检查、退出实验或中心重启建立替代worker。

## PR关联与唯一交付

每个候选沿 #36 核验真实PR的仓库/base/执行分支；一个PR不能被不同Task/候选重复绑定。未合并关闭的旧PR保留历史，原会话可关联新PR，所有已知关联继续可查。

中心核验包含已放弃候选在内的已知PR集合。只有一个仍具交付资格的候选PR确认merged，且其他已知PR没有合并冲突或查询歧义时，才原子提交唯一TaskDelivery、Task.closed与后继资格；事务内复核Task、候选资格及PR集合前值。新增、放弃和交付竞争保留现有版本仲裁，不为宽松数量限制放宽这些边界。

已放弃候选PR合并、首次交付前多个PR合并或状态未知，通过既有待决策/冲突入口解释，不随机选胜者。交付后其他候选/历史PR迟到合并，只追加事实，不覆盖原Delivery、不再次解锁后继，不自动回退代码。

获胜后禁止该Task中心新增推进消息；在途worker仍可能执行或发布。继续保存来源输出、PR和资源事实，不能把落选或已放弃显示为已停止，不自动关闭落选PR或删除worktree。

## 任务变更与格式

尚未领取且无候选的Task沿既有补前置与丢弃规则。丢弃整个Task与放弃单候选是不同命令；整体丢弃必须核验包括已放弃候选在内的全部已知PR与未结算动作，已合并拒绝，历史/资源保留、后继仍阻塞。不新增reopen、删边、改绑或候选复活。

内部格式确需改变时明确版本并拒绝旧格式，不做single/multiple旧摘要试算、迁移、双写或回退。当前支持格式的重启、原消息对账、原领取/候选绑定和唯一交付继续成立。

## 最小验收

| 编号 | 通过条件 |
| --- | --- |
| MC1 | 首个候选领取一次，人工新增达到5个参与候选；不同配置分别冻结，共同base且session/worktree/分支独立；单候选普通路径保持 |
| MC2 | 重复请求、异内容/旧版本、启动回执丢失、错误目标/base/工作区不产生重复claim或worker |
| MC3 | 两候选交错反馈、重排、迟到消息和重启不串线，一个待决策不阻断兄弟 |
| MC4 | 各候选按同一任务要求产出不同PR，错误归属/重复绑定不交付，无自动评分或额外中心验证门槛 |
| MC5 | 人合并一个有效PR后仅一份Delivery、一次关闭与后继解锁；新增/放弃/交付竞争及回滚保留身份与资格 |
| MC6 | 多合并、已放弃PR合并或未知状态保持待决策/冲突；交付后迟到事实不覆盖Delivery、不假称落选停止 |
| MC7 | 整体丢弃核验完整集合，全部候选放弃不重开Task；当前格式重启及原候选普通路径保持，旧格式拒绝 |
| MC8 | 合并前单候选放弃立即退出实验、停止未知不回滚、不阻断兄弟或人工新增；重复放弃/回执丢失/重启沿原请求；已知PR合并后拒绝放弃 |
| MC9 | 串行观察到5个时第6次新增拒绝；放弃后可新增；并发数量检查无专用预留/占槽，偶尔超出不强制纠正，普通版本与幂等仍成立 |

MC1–MC9复用临时SQLite、可控后端/provider及现有恢复/提交代表断言，不穷举五候选交错或配置笛卡尔积。证据保存于`docs/validation/candidate-workers/`；真实混合配置与放弃能力由 #39验收。
