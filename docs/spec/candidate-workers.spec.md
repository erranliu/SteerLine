# Spec：多候选会话与唯一PR交付

任务 ID：37；任务名称：多候选会话与唯一PR交付；目标：`PHASE1-CANDIDATES`。配套 [Plan](candidate-workers.plan.md)。状态：待实现与验收，一个独立实现 PR 交付。

## 范围与前置

硬前置：#36 [持续 worker 流程](worker-flow.spec.md)。遵守[第一阶段共同约束](phase1-delivery-constraints.md)。在同一个 Task 下支持多个独立候选，每个候选复用 #36 的一条持续 worker 会话、五个主阶段、用户反馈和 PR 观察。候选创建、完整运行、PR 关联和唯一交付在本任务一起交付；界面增量归 #38，跨后端竞争验收归 #39。

worker 依据任务 Spec/Plan 实现、提交和创建 PR。中心不比较代码优劣，不设置项目验证/审查门槛，不限制候选先运行却不得提 PR。一个 Task 最终只有一份 TaskDelivery，所选结果来自用户实际合并的候选 PR。

## 身份与启动

Task 创建时固定 execution_policy=single/multiple，缺省为 single；创建后不能在同一契约上修改策略。采用本任务明确版本的新契约，不增加 legacy 摘要试算或旧 minimal-v1 转换。每个候选直接以 workflow_run_id 标识，不另建可写 Candidate 权威；该候选有自己的 Execution、原 worker session、worktree、分支、消息和 PR。

首个候选完成 Task claim；后续候选只增加 WorkflowRun，不重复领取、重开 Task 或更改任务 Spec/Plan。当前领取下的所有候选固定共同 base、目标仓库/base 分支和任务契约，每个执行端独立核验能取得该 base。工作目录、执行分支与会话不能复用兄弟候选的绑定。后续反馈只继续所选候选的原会话。

人工显式 start_candidate 绑定 task_id、request_id、当前任务/图版本、选定执行配置；事务复核 single/multiple、前置交付、无已交付/丢弃/维护冲突后保存候选及启动意图，再在事务外启动。相同请求返回原记录，异内容拒绝；并发旧版本拒绝，不自动更新版本重发。后端尚不支持持续会话时启动前拒绝，不能降级为一次性步骤 worker。

不设置候选数量的业务常数上限。自动派发只启动未领取 Task 的首个候选；不会自行增加竞争候选。同 Task 一个候选等待决策或连接异常，不停止其他候选的观察和原会话交互。

## 查询、交互与恢复

Task 查询返回候选集合，所有执行级命令与正文请求绑定 workflow_run_id、Execution 和原会话。不能按 task_id 猜“最后一个运行”；无法唯一定位时返回 ambiguous_execution。列表保留稳定分页、database_revision、游标失效和原选择；Task 级汇总不成为执行事实来源。

候选 DTO 包含精确身份、版本、五阶段主状态、原会话/当前轮次、待决策、PR 关联及资源事实。当前领取与历史候选明确区分，历史消息不驱动当前候选。仍复用原 Command/Operation、事件/正文和服务单写者。

各候选均使用 #36 的完整文字/选项反馈路径，不增加候选专用重试或业务答案应用证明。反馈重复、回执丢失和中心重启沿原消息/会话恢复，不漏候选、不新建替代 worker。一个候选全部工作未完成并停下时进入待决策，用户可以继续原会话或明确丢弃任务，不要求不断添加候选。

## PR 关联与唯一交付

每个候选按 #36 从原会话或用户指定的线索关联真实 PR，核对仓库、目标分支及执行分支归属；一个 PR 不能被不同 Task/候选重复绑定。没有中心项目验证回执也能关联和进入待合并。已关闭未合并的旧 PR 留作历史，再按原会话输出关联新 PR；所有已知关联都继续可查。

中心轮询当前 Task 已关联的 PR 集合：无合并时各候选继续按自身状态运行；仅一个有效关联 PR 确认 merged 且其他已知 PR 查询无歧义时，复用唯一 TaskDelivery 事务提交获胜 WorkflowRun、Task.closed 和后继资格。平台查询在事务外，事务内复核 Task/候选/PR 集合版本。与 start_candidate 竞争时只允许一方在同一版本提交。

多个已知 PR 在首次交付前已合并，或已知 PR 状态无法核实时，通过同一待决策入口展示冲突/缺失事实，不随机选择、不伪造未合并。交付后发现其他候选或历史 PR 迟到合并，只追加冲突记录，不覆盖原 Delivery、不再次释放后继、不自动回退已合并代码。中心只对已绑定和后续发现的关联负责，不宣称能证明不存在任何尚未报告的外部 PR。

获胜后拒绝同 Task 的新增候选和中心新增推进消息；在途 worker 可能继续执行或发布，不能依靠中心标记保证其停止。继续保存原会话输出、PR 和真实资源状态。已有明确授权且后端支持的停止操作可沿原身份执行；远端取消不支持时交用户处置，不自动关闭落选 PR 或删除工作树。Task 已完成后相关资源和迟到 PR 仍可从历史详情定位。

## 任务变更与格式

尚未领取、无候选的 open Task 继续支持既有补前置和丢弃。已领取 multiple Task 的普通反馈不重置候选或任务；本任务不新增通用 reopen/删边/改绑流程。明确丢弃按现有 Task 命令核验全部候选的已知 PR 与未结算动作，拒绝已合并交付，保留所有历史/资源和后继阻塞，不以某一候选停止代替全部事实。

采用当前实现明确的配置/数据库协议版本，旧或未知格式拒绝有副作用启动；不自动升级历史 minimal-v1、重建库或清除外部绑定。当前格式重启、消息对账、唯一交付及单候选路径必须继续通过。

## 验收

| 编号 | 通过条件 |
| --- | --- |
| MC1 | multiple Task 创建三个独立候选，同一领取/共同 base、各自 session/worktree/分支；single 拒绝第二候选；无数量常数限制 |
| MC2 | 首次领取、重复请求、旧版本竞争和启动回执丢失不重复 claim/worker；错误目标/base/工作区在副作用前拒绝 |
| MC3 | 两候选多轮反馈、同 Task 列表重排、历史轮次迟到和重启恢复不串线；一个待决策不阻断其他候选 |
| MC4 | worker 可自行创建不同 PR，无中心五步或检查门槛；错误归属、PR 重复绑定和未合并关闭不交付 |
| MC5 | 人工合并一个有效 PR后仅一份 Delivery、一次 Task.closed、一次后继解锁；交付/启动竞争及事务中断保持一致 |
| MC6 | 交付前多合并/查询不明进入统一待决策；交付后迟到合并保留冲突；不能假称落选 worker 已停止或保证禁止在途发布 |
| MC7 | 明确丢弃核对整个候选集合，历史/资源可追踪；旧或损坏格式拒绝，新格式重启和 single 回归通过 |

MC1–MC7 使用真实临时 SQLite、可控后端与 PR provider 故障注入；证据保存在 `docs/validation/candidate-workers/`。生产接线按共同约束测试，双后端真实竞争由 #39 验收。
