# Spec：执行应用用例归包

任务 ID：76；任务名称：执行应用用例归包；目标：`TASK-EXECUTION-CONSOLE-DECOUPLING`。配套 [Plan](three-line-04-execution-usecases.plan.md)。一个独立实现 PR 交付。

## 范围与前置

硬前置：#74。把派发/容量、冻结方案、候选/会话/反馈、决策/恢复、PR 集合核验/唯一交付和执行清理用例迁到 `internal/execution`，保留唯一 actor 和提交屏障。

实际盘点起点：主包 `worker_*.go`、`candidate_workers.go`、`candidate_pr.go`、`service_commit.go`、`lifecycle_*.go`、`conversation_service.go`、`execution_requirements.go` 与恢复/决策/发布用例；#74 文件级清单限定职责。开工时按实际消费者核对路径；前置迁移已发生的部分只承接其唯一实现，不重建。

## 实现要求

1. 执行依赖 execution/model/backend、任务小端口/task/model 和必需 storage/ports，不能导入 task 应用实现、具体 adapter/SQL、app/console。任务输入到 worker 提示转换归执行应用，后端只收冻结输入。

2. 唯一 actor、私有工作状态、提交后公开视图及异步单步结果通道保留；先 intent，后一个动作，绑定/receipt 提交后再下一步或 ack。事件/正文/cursor 原子提交与心跳元数据分开，不新增第二写者。

3. Task 只有一个领取，各 WorkflowRun 配置/Execution/session/工作区/PR 独立；按精确 ID 反馈，不能以 Task 猜最新候选。开始时参与数达到五个拒绝，允许竞态偶尔超出；放弃退出实验不等于停止、不等待停止再新增。

4. 未知启动/回复/停止保持原 Operation/request/target/generation 只读对账，恢复人工门槛不自动解除。结果经 #74 任务端口应用，历史 PR 与迟到合并保留且不能覆盖唯一 Delivery。

5. 应用本阶段注入现有 adapter/backend 及任务端口；保留 host 所需调度小端口，把循环/心跳/控制传输留给 #80 的唯一旧宿主。规划会话不复用 worker 授权/派发，远端权限不足拒绝不变。

## 共同执行约束

遵守 [三线解耦共同实现约束](three-line-constraints.spec.md) 的最终依赖矩阵与跨域提交规则；本阶段负责实际启用自己迁移部分的守卫。

保持当前任务/DAG、持续 worker、人工并行/自动派发、原会话反馈、恢复授权、唯一交付和 UI 生命周期。失败、轮次结束、最终回复、交付、任务关闭与资源停止分别表达。具体实现无业务写权，状态仍由唯一业务写者经窄声明提交；同数据库查询保持同读快照。

同仓库、同 go.mod、同 SQLite 和服务部署方式；不引入新进程协议、后端、严格候选名额、评分/融合或规划实现。纯结构迁移保持数据格式；确需调整格式时由唯一所有者统一支持版本与拒绝边界，不新增旧版读取、迁移、双写或回退。各步切换真实消费者/构造/测试并当场删除迁出定义，保持可构建，不留永久兼容门面。

完整实施须硬前置整体交付；只读盘点可提前。共享定义、Service/Config/组装/runner 段先确定一个修改所有者并顺序集成，禁止多条线独立重写共同文件。与 #38/#39 并行使用隔离 worktree/构建/配置/测试资源；#39 记录固定构建，不在运行中替换现场。迁移后按实际接线/行为影响决定证据复用或定向重验，远端权限缺口、零命中、skip 或 mock 都不能代表原生通过。
