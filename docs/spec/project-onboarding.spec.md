## 1. 目标与范围

2026-10-20 审查后共用边界（仍未实现）：初始化准备复用[项目维护 Spec](project-maintenance.spec.md)的输入快照/窄材料规则；PS-01–PS-07 完整结构核验、预纳管候选及应用级记录仍由本批补齐，不把全部纳管建设提前给维护批次。相同路径/blob/格式检查只实现一次；本批保留外部提示词、确认登记/建库及初始化旁路关闭。预纳管只人工准备/只读核验，不启动内置生成。正式材料采用配置远端目标已提交版本，testing 固定路径遵循维护设计。PON 验收保留，公共规则通过不能替代登记证明。

在当前项目切换器中增加“添加项目”流程：输入本机已有 Git 仓库与目标 → 复制准备提示词 → 用户自行在 Codex 准备文档 → Go 服务只读核验 → 用户确认 → 服务正式登记，必要时初始化原生项目数据库。核验通过前不纳管、不为该候选建库。

规范唯一正文：[项目管理](../product-design/project-management.md)、[结构核验 PS-01–PS-07](../product-design/project-structure.md)、[准备提示词](../product-design/project-onboarding-prompt.md)。本 Spec 固定交付边界，不复制第二套路径/内容规则。清单采用 `steerline-project/v1`、提示词采用 `project-prepare/v1`；实施遇到规则变化需显式更新这些文档及本规格，不能静默放宽。

本任务不实现仓库克隆/远端创建、Web 调度 Codex、自动修仓库、自动安装工具/执行环境、推送/合并、项目删除/迁移或旧格式数据兼容。TUI 不增加该功能。添加项目不创建 Task/DAG，不自动启动项目服务或派发，worker 流程与原执行权限不变。

## 2. Go 所有权与入口

复用前置应用服务及单端口 Web，不在 Web 新建项目目录、检查器或数据库。Go 应用层提供准备文本、结构/参数核验、最终登记和原请求查询，Web 仅提交输入、显示逐项结果及确认摘要。

候选输入来自用户的仓库路径、显示名、remote、目标分支与发布目标。服务自己规范化并解析 common-dir；路径属于服务机器。先前已配置项目与正式纳管状态明确区分，不把配置文件存在、Codex 报告或浏览器 passed 当成证明。

在统一宿主的 `steerline-application/v2` 下增加准备、核验、登记及原请求查询契约；不复用一个伪项目的 commands：

| 入口 | 约束 |
| --- | --- |
| 准备提示词 | 返回填写明确输入的完整文本及版本；缺关键输入明确列出，不启动代理、不写仓库 |
| 只读核验 | 执行 PS-01–PS-07，保存应用级结果/依据；不调用项目初始化入口 |
| 确认登记 | 应用级命令包含固定 request ID、home 身份、validation ID、输入/版本摘要；连接核验当前应用实例，最终重新核验后才提交 |
| 查询原请求 | 返回原登记事实及阶段/失败原因；断线不能推定失败或新建替代请求 |

具体 DTO/路由在实施中先固定成独立应用契约并测试消费者，不改变原生项目 commands 的项目/实例语义。原生应用认证沿用前置；浏览器登记要求同源 CSRF，不能把任意宿主命令放进准备清单执行。

## 3. 准备与核验行为

用户可以跳过复制提示词，直接核验已准备好的仓库。Codex 只在用户自己的会话中调查并准备文档；完整模板包含实际要求和边界，不能只返回用户环境无法访问的产品源码链接。未完成提交/合入必须如实报告。

服务读取选定目标分支的固定 commit、清单和普通 blob，采用已有文档角色映射，不要求复制相同正文。分支之外的文件、未提交内容、symlink/submodule、越界/缺失引用、错误格式或超限内容按 PS 规则返回原因。只读核验不运行仓库脚本、模型、测试、hooks、依赖安装或初始化数据库。

返回结构、纳管参数及执行就绪三个维度；只读解析/账户不可用不能伪装成必需文件缺失。所有机器内容检查仅证明格式/结构，不能声称文档语义真实或测试已通过。分支、commit、清单/文档摘要、参数、规则版本或仓库身份变化后，原结果不可用于最终登记。

## 4. 登记、并发及已有状态

应用服务是项目登记唯一写者，正式成员记录发布后才在目录标为“已纳管”。候选/核验记录放应用级目录，不能放进未通过核验的项目数据库或破坏现有严格运行目录。后续批次收紧当前目录的成员判定，不保留“新建 etc 文件即自动纳管”的旁路。

前置批次列出的存量项目不被自动盖上结构通过标记。它们可供选择并显示“待核验”，按本流程显式核验登记；当前格式的原数据库可在身份、remote、branch 及归属匹配时明确复用，不清空原任务。未正式纳管的新候选禁止新库初始化、新任务/新候选等新业务入口；所有 CLI/宿主初始化入口复用同一服务准入，不只检查 Web 按钮。

既有运行服务和已接受执行不因上述目录状态变化被停止或重写；原执行的事实查询、回执、反馈及资源操作仍按原资格办理，不借此启动替代任务。复用一个本 home 当前格式数据库时，只读核对既有权威并提交应用登记，不争夺已有项目服务的数据库写者。全新数据库初始化才取得原仓库/运行目录互斥并采用原 `InitializeProject` 的 manual/paused 初值。其他 home 的写者、错误身份、旧格式及陌生半成品均明确阻断，不隐式迁移或接管。

最终提交顺序为“重新核验 → 核对/初始化原生权威 → 原子发布正式登记 → 回执”。核验与提交间发生变化、并发同仓库或重复 request ID 必须核对原事实。数据库与文件发布不伪装为跨介质事务：保存最小原请求事实，初始化成功但登记/回执失败时只补齐同一操作，不删除重建或换 ID。取消尚未提交的添加面板不删仓库/数据库；提交之后关闭页面只影响观察，保留原请求查询。

应用重启后查询原请求只读，不自动续补。需要继续原登记时由当前会话显式提交同一 ID/固定正文，服务先识别原记录，再复核当前身份与 PS-06；受理应用实例只作为原事实保留，不把该操作改为另一 home 或另一仓库。已完成请求直接返回原结果，失败的旧输入不凭新实例获得绕过核验的权限。这是应用级登记契约，不改变原生项目命令的实例绑定规则。

## 5. 验收要求

要求与结果分离，归[专属验收](../acceptance/project-onboarding.md)。

| ID | 必须达到的行为 |
| --- | --- |
| PON-A1 | 准备提示词的完整输入、版本和内容边界正确；用户自行执行，Web/服务不启动代理或写仓库；TUI 无添加功能 |
| PON-A2 | PS-01–PS-07 正反例命中，合法已有文档映射通过；固定版本、路径/对象、正文/链接/限额及冲突准确，核验前后无项目库/状态写入 |
| PON-A3 | 最终重新核验、唯一登记、重复/并发同仓与 stale 输入守卫；旧格式/异主库拒绝，当前格式明确复用；未纳管初始化旁路关闭 |
| PON-A4 | 登记提交/回执故障按原 ID 对账，自己的初始化半成品准确识别并补齐，不删库重建；失败不标纳管，既有执行事实不被重写 |
| PON-A5 | 新独立包 Edge 完成实际未准备→失败、外部准备夹具→通过、确认→纳管/建库、切换；零项目首添与既有项目并存，关闭页面/重复提交无重复项目，完整清理 |

PON-M1：自动场景通过后，用户把实际生成提示词交给自己的 Codex 准备一个隔离项目，再返回核验，体验提示词可理解性与修复反馈；窗口待安排，可后置。机器夹具不宣称验证了 Codex 的语义质量或用户体验。
