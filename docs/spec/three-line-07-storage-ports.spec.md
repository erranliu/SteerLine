# Spec：存储目录与消费者端口收口

任务 ID：79；任务名称：存储目录与消费者端口收口；目标：`TASK-EXECUTION-CONSOLE-DECOUPLING`。配套 [Plan](three-line-07-storage-ports.plan.md)。一个独立实现 PR 交付。

## 范围与前置

硬前置：#75、#76、#77。将唯一 sqlite 实现迁到 `internal/storage/sqlite`，在 #73 storage/ports 基础上按任务、执行、产品实际消费者收窄读写端口，消除整包 Domain/可写聚合泄漏。

实际盘点起点：`internal/steerline/sqlite`、#73 的 `storage/ports`、任务/执行/产品消费者及 app 连接工厂；原连接/schema/SQL 已唯一，不重新建设持久层。开工时按实际消费者核对路径；前置迁移已发生的部分只承接其唯一实现，不重建。

## 实现要求

1. 仅 sqlite 拥有连接/schema/SQL/读写事务、CAS/原身份和唯一约束；不导入任务/执行应用、adapter 或 app。仅可复用 product/query 的纯模型/API 投影，不调用其读取/命令用例或 I/O；投影自身无具体 SQL 依赖。服务工作状态重建归 execution/model，不通过产品页面投影恢复。

2. task 只持任务图、固定契约、任务意图和规范结果相关窄端口；执行只持自己声明提交/读取，产品持只读同快照端口。跨记录原子提交在存储的窄声明中完成，任务不能因此获得任意执行记录写权限。

3. 消除业务全量 Domain 读取和可写 Runtime 泄漏，按用例提供有界事实/前值。应用可组合多个端口管理一个连接，但不把组合 Connection/Factory 交给业务消费者。

4. 保持唯一 Reader、同快照数据库版本、原子回滚、WAL/锁/关闭与只读不建库；当前格式恢复保留。纯路径变更不升级 schema；确需记录形状变化由本存储所有者一次处理支持版本和拒绝边界，不迁移旧开发数据。

5. 本阶段切换 app 实际工厂和消费者，删除旧 sqlite/persistence 路径中的迁出定义；不等 #80 修编译，不以扩大端口或两套 SQL 作过渡。

## 共同执行约束

遵守 [三线解耦共同实现约束](three-line-constraints.spec.md) 的最终依赖矩阵与跨域提交规则；本阶段负责实际启用自己迁移部分的守卫。

保持当前任务/DAG、持续 worker、人工并行/自动派发、原会话反馈、恢复授权、唯一交付和 UI 生命周期。失败、轮次结束、最终回复、交付、任务关闭与资源停止分别表达。具体实现无业务写权，状态仍由唯一业务写者经窄声明提交；同数据库查询保持同读快照。

同仓库、同 go.mod、同 SQLite 和服务部署方式；不引入新进程协议、后端、严格候选名额、评分/融合或规划实现。纯结构迁移保持数据格式；确需调整格式时由唯一所有者统一支持版本与拒绝边界，不新增旧版读取、迁移、双写或回退。各步切换真实消费者/构造/测试并当场删除迁出定义，保持可构建，不留永久兼容门面。

完整实施须硬前置整体交付；只读盘点可提前。共享定义、Service/Config/组装/runner 段先确定一个修改所有者并顺序集成，禁止多条线独立重写共同文件。与 #38/#39 并行使用隔离 worktree/构建/配置/测试资源；#39 记录固定构建，不在运行中替换现场。迁移后按实际接线/行为影响决定证据复用或定向重验，远端权限缺口、零命中、skip 或 mock 都不能代表原生通过。
