# Spec：Worker 原始状态与控制台精简

本次命名增量以[状态命名 Spec](state-naming.spec.md)为准：候选快照与活动的业务字段改为 workflow_stage/workflow_status，内部领域步骤保持；原布局和事件事务保持；当前主干阶段变化只显示流程消息，阶段不变才显示状态消息，字段改名不恢复旧双消息规则。

用户直接授权；普通开发，不新增 roadmap 任务。配套 [Plan](console-worker-state.plan.md)、[验收](../acceptance/console-worker-state.md)。保留前一项[三轮流程恢复](worker-prompt-convergence.spec.md)。

本文记录原始状态保留的首轮实现；用户后续确认的列表单行与流程/状态投影，以[可读性收敛 Spec](console-flow-state-readability.spec.md) 为当前展示契约，原持久化字段及事务规则不变。

控制台主界面保留三窗格：列表选择 Task，右上显示当前候选及原始 step_id/status/execution_status，右下显示原问题、短结果与最近状态变化。原始值不缩写、不替换，宽度不足先省中文映射再换行；未知值原样显示。中文和颜色以字段与确切枚举值固定映射，不根据描述文字猜测状态，不增加新的状态集合。

任务列表每项用标题/Task 原状态和 worker 步骤/状态两行（必要时换行），替代拥挤的多列。右上保留所选候选、冻结方案的一行摘要、已有 PR、一个原诊断与一个下一步；不常驻权限说明或重复错误。右下优先问题和原操作回执，结果正文最多三行，完整内容按 f/d/F8 阅读。状态变化在问题和终态下仍可读；最新在前，最近五条。上下文快捷键压缩显示，完整键位仍在 ?。不改变目标、命令资格、输入提交门槛或候选编号。

变化来自服务已提交事实：比较步骤、业务状态、原生执行/资源状态、输入版本、原轮次、恢复和环境原因。在既有 Activity 中保存 from/to 原始字段、时间及已有原诊断，随 worker 提交同事务写入；初始领取和唯一真实交付也在所属事务记录。失败提交不发布变化，重复提交不重复记录。原执行/资源查询映射复用唯一纯函数，不维护第二个状态机或存储表。

RecentActivity 在同一读事务读取原项目/WorkflowRun/Execution/Attempt 的五条变化与十条其他活动，共用原字节预算并优先保留变化正文；工具活动不能挤掉变化。复用活动索引并为状态类型增加部分索引。界面只读，不从轮询差异或自然语言制造历史；重复刷新不累计，迟到响应不能跨目标/Attempt，新活动不抢焦点或滚动。离线保留最后快照并注明采样，不推断进程停止。

最小自动验收 CSC-A1–A4 见专属记录，不新增 live 模型验收或旧数据迁移。
