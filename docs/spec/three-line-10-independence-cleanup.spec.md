# Spec：独立开发证明与最终清理

任务 ID：82；任务名称：独立开发证明与最终清理；目标：`TASK-EXECUTION-CONSOLE-DECOUPLING`。配套 [Plan](three-line-10-independence-cleanup.plan.md)。一个独立实现 PR 交付。

## 范围与前置

硬前置：#81。按最终消费者删除残留无用辅助、别名/转发，完成任务/执行/控制台各自独立改动证明与最小产品交付/恢复组合，更新实际架构/构建/测试索引。

实际盘点起点：最终 `internal/{task,execution,product,console,storage,app,testkit}`、`cmd`、`tests/integration`、`tests/e2e` 与构建/安装及架构文档；仅有实际消费者依据的残留清理。开工时按实际消费者核对路径；前置迁移已发生的部分只承接其唯一实现，不重建。

## 实现要求

1. 任务优先级/挑选代表改动只涉及 task 与对应测试；执行既有容量/恢复代表改动只涉及 execution 与对应测试；console 导航/输入/展示代表改动只涉及 console 与产品 fixture。共同产品语义变化不伪称无需契约协同。

2. 证明走真实生产入口或其注入端口，记录修改范围、规则改变前后结果与实际命中证据；可复用本轮已完成的真实改动。若无足够实例，在隔离验证补丁上做最小探针，运行后撤回，不提交用户未要求的永久功能。

3. 依赖矩阵成立：task 不含 PR/session/派发，execution 不拿 task 内部写权，console 无 Domain/Runtime/默认业务 I/O，存储不反向依赖应用/平台，host 不承载业务状态机。

4. 完成一次 L1、已注册 delivery.basic 与 recovery.waiting-merge-restart 受控场景，保持同快照、当前格式恢复、原身份/请求/回执和唯一交付/DAG 解锁；不把受控场景宣称为 #39 真机验收。

5. 清理按实际消费者和 #81 断言映射，不以名称老旧为理由删除行为；全源码、Windows/Linux 依赖、launcher/runner 及公开类型索引同步实际结构，未交付远端/规划/UI 能力如实保留限制。

## 共同执行约束

遵守 [三线解耦共同实现约束](three-line-constraints.spec.md) 的最终依赖矩阵与跨域提交规则；本阶段负责实际启用自己迁移部分的守卫。

保持当前任务/DAG、持续 worker、人工并行/自动派发、原会话反馈、恢复授权、唯一交付和 UI 生命周期。失败、轮次结束、最终回复、交付、任务关闭与资源停止分别表达。具体实现无业务写权，状态仍由唯一业务写者经窄声明提交；同数据库查询保持同读快照。

同仓库、同 go.mod、同 SQLite 和服务部署方式；不引入新进程协议、后端、严格候选名额、评分/融合或规划实现。纯结构迁移保持数据格式；确需调整格式时由唯一所有者统一支持版本与拒绝边界，不新增旧版读取、迁移、双写或回退。各步切换真实消费者/构造/测试并当场删除迁出定义，保持可构建，不留永久兼容门面。

完整实施须硬前置整体交付；只读盘点可提前。共享定义、Service/Config/组装/runner 段先确定一个修改所有者并顺序集成，禁止多条线独立重写共同文件。与 #38/#39 并行使用隔离 worktree/构建/配置/测试资源；#39 记录固定构建，不在运行中替换现场。迁移后按实际接线/行为影响决定证据复用或定向重验，零命中、skip 或 mock 都不能代表本机原生通过；远端流程不纳入一期验收。
