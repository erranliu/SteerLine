# Spec：三窗主界面操作与控制台可读性优化

目标：`CONSOLE-PRIMARY-WORKSPACE`。状态：实现及定向/终端验证完成，草稿交付 [PR #234](https://github.com/erranliu/SteerLine/pull/234)，未分配 Task ID；[实施 Plan](console-primary-workspace.plan.md)。固定 L1 超时不完整，缺失项定向补跑通过；范围和限制见[验证记录](../validation/console-primary-workspace/README.md)。依据：2026-10-07 用户确认的控制台体验建议，要求日常操作尽量在一级界面三个窗口完成，详细阅读才进入详情，并增强颜色、加粗和焦点表示。

参考源码基线：`172cea6c6530b6693b742324a9c1d4f9aeb17b6d`。功能前置：[精简候选控制台与会话阅读](product-simplification-01-console.spec.md)的三窗、最近活动、内嵌回答与最小持久化能力；实施 Plan 固定包含这些能力的实际基线。本任务不依赖产品精简第二、三批。

## 目标与覆盖关系

主界面完成“选任务 → 判断情况 → 日常操作 → 查看结果”。三窗固定为左侧任务列表、右上只读候选与执行概要、右下运行与反馈工作区。详情用于长正文、完整背景、历史记录和深入诊断，不作为开始、回答、放弃及日常核验的必经入口。

本 Spec 替代第一批 Spec 中普通 Enter 打开详情、整页方案选择、完整只读核验必须切页，以及右下只包含运行/回答/回执三种显示状态的界面要求；保留其最近最多 10 条规范活动、完整最终回复只读入口、草稿和原请求对账要求。与[控制台规划约束](../roadmap/console-constraints.md)中的过程折叠、阅读位置保持等旧展示要求冲突时，按第一批精简边界和本 Spec 执行，不恢复完整过程阅读器。其他业务约束继续适用。

不改变任务资格、派发策略、不同任务人工并行、多候选开始检查、权限模式、冻结方案、原会话反馈、唯一 TaskDelivery 与后继解锁。候选退出、任务完成、执行成功、worker 停止及 PR 合并分别表达；当前执行支持与原生验收范围仍为本地 Codex、本机 Orca，保留既有远端路径和拒绝原因，不新增远端能力或宣称其已通过验收。

SQLite 与既有服务读模型继续提供业务事实，UI 不从终端文字推断状态或授权。沿用原 intent/receipt/ack、请求身份、版本和资格核验；未知结果只对账原请求，不重发或新建替代会话。不新增旧开发版本兼容、迁移、双写或回退路径。

## 三窗信息与布局

### 左侧：选择任务

1. 每 Task 保留一条主行，显示稳定任务编号、任务名称、任务状态和执行状态；额外显示一个简短待处理提示，如“待回答”“环境受阻”“待合并”。任务状态和执行状态不合并成一个模糊的状态字段。
2. 待处理提示按已知事实突出最需要人关注的原因：阻断/失败/未核实优先，其次待回答，再次待合并；完整原因与其他并存状态在右侧表达。多个候选时按该 Task 的候选事实汇总，必要时带 P 编号或数量，不把兄弟候选的待回答标到所选候选上。沿用当前历史失败排除规则：已结算的退出/落选/已关闭任务中的历史失败不自动升级为当前需处理；仍活动或状态未知的 worker、当前阻断和 PR 冲突仍需提示。
3. 保留现有筛选、稳定选择及有界列表；刷新或状态变化不自动重排到另一个任务，不抢焦点、不改选候选。列表失焦后仍能看见当前选中任务。
4. 宽度不足时缩短待处理提示和辅助列，任务编号、可辨认的名称与关键状态优先；长名称和原因在右侧换行展示。截断显式使用省略标记，不让空白或截断暗示没有问题。

### 右上：判断当前候选与下一步

1. 固定展示 Task 编号/名称、候选切换条、当前冻结方案、任务与执行/业务状态，以及“下一步”。候选条使用稳定 P1/P2 编号，区分当前选中、仍参与、退出与历史候选；确认没有候选时显示“暂无候选”。原所选候选暂不在快照中或读取失败时保留原选择，显示“原候选暂不可读取/未核实”，禁止静默改选或声称没有候选；F6/F7 可显式选择已读取候选。候选较多时以所选候选为中心显示有界窗口，提示未显示/未加载数量或缺口，不把部分列表当作完整候选集合。
2. 冻结方案使用已冻结的产品可读名称与宿主/Agent 概要，不用当前项目配置替换历史方案。概要及方案选择区还须展示已有读模型提供的模型、推理强度、权限模式等影响方案比较/启动核对的产品字段；未适用/由 Agent 决定/未核实按原事实表达，不解析原始配置封套猜测。不相关的完整实现配置、codec 标识和路径留在详情，缺失事实明确标记未核实。
3. 环境阻断、关键错误或 PR 查询失败优先于正常 PR 信息显示；仍能看到并存的待回答/待合并状态。“下一步”取自当前目标的既有资格与能力，显示主要可用动作；不可用时显示具体原因，不只显示一个灰色快捷键。
4. 正常时显示 PR 简称和已核实状态；完整 URL、原生资源定位及完整 ID 留在详情。耗时、采样、session 等降为辅助信息。离线、陈旧快照、采集失败或状态未核实时，其真实性提示优先于一般辅助信息，不因高度不足隐藏，也不把旧快照当作可执行授权。
5. 取消概要最多 9 行的机械截断。按信息优先级与右下当前模式分配高度：先去掉普通辅助字段，再压缩概要；关键原因与下一步至少在概要或右下可见。普通运行时保留概要与活动，回答/选择/确认时优先保证目标、问题或操作内容、预览和关键提示。

### 右下：完成操作与查看结果

同一工作区承载下表模式，不创建独立整页操作页面或第二套回答编辑器。右上始终表示当前选中目标；操作头和预览还须显示本次绑定目标。

| 模式 | 主界面必须可见的内容 | 进入与退出 |
| --- | --- | --- |
| 运行/浏览 | 当前状态、最近最多 10 条已提交规范活动、采样或缺口提示 | 默认；↑↓/PgUp/PgDn 简单滚动 |
| 方案选择 | 开始首候选或新增候选的区别、Task、选中方案产品概要及关键比较字段、可用性/不可用原因及确认提示 | s 开始首候选、b 新增；Enter 明确确认，Esc 取消 |
| 待回答/编辑 | 原问题、选项、当前选项必要说明、文字输入、绑定目标和提交预览 | a 或待回答时 Enter 激活；F2 提交，Esc 保存草稿并退出编辑 |
| 放弃确认 | Task/P 编号、方案概要、不可撤销退出实验的影响、worker 停止须独立核实及确认提示 | z 激活；Enter 显式确认，Esc 取消 |
| 异常/核验 | 原因、主要可用操作、核验进度/结论/采样与当前操作回执 | 异常默认突出；u 获取既有只读核验摘要，Ctrl+E 重查环境，Ctrl+O 原终端 |
| 结果摘要 | 已采集最终回复摘要或明确标注的有界正文预览、已有验证信息、PR 状态与下一步 | 无更优先待处理项时展示；f 读取完整最终回复 |

没有显式交互模式时，右下优先展示当前阻断/失败/未核实，再展示原待回答问题；其余情况按当前执行事实选择运行活动或结果摘要。当前准备/执行/新业务轮次已开始时显示运行活动，上一轮 final 只能作为带轮次标识的辅助摘要，不能遮住新轮次动态。当前业务轮次已确认结束且有结果可读时显示结果摘要；无 final 时显示结束事实及采集缺口，不沿用上一轮冒充本轮结果。

当前目标未决请求、保存/提交失败和结果未知以有界回执提示保持可见，和问题/运行内容共存，不用永久独占模式遮住问题或活动。已终态回执显示最近一项，确认后续事实（如新轮次启动）后降为辅助信息；重开只恢复原请求对账，不恢复已终态回执的独占展示。异常与问题并存时保留问题提示和 a 草稿入口；环境受阻不丢草稿，是否可提交继续按原资格判断。用户已进入的编辑/选择/确认不被新活动替换，关键异常以可见提示表达；拒绝/失败的迟到回执也不能在用户已转到列表后自动重新打开编辑并抢焦点。

回答编辑、方案选择、放弃确认、只读核验摘要为互斥的右下交互模式。s/b/z/u/x 等模式动作仅在普通浏览、核验摘要或回答的列表焦点下处理；回答选项焦点和已激活的方案选择/放弃确认不接受嵌套模式动作，须先 Esc 退出。切入另一模式前，原回答按原目标保存草稿并退出，原选择/确认取消，保存失败则留在原模式并显示原因。文字输入中的普通字母仍作为文本。只读核验摘要是用户显式进入的浏览模式，Esc 返回自动运行/问题视图，r 在右下焦点重读同一原目标的核验报告，列表焦点 r 仅刷新项目；不能将项目刷新误写为报告已更新。Tab 可以返回列表而不退出同目标报告。

方案选择和放弃确认允许 Tab 返回任务列表。选择别的 Task、项目或候选时，取消原临时选择/确认，不带到新目标，不发出操作；答案编辑先按原规则保存草稿并退出。返回原目标需要显式重新进入选择/确认，重新核验。

已激活模式在身份、实例、问题或版本变化时，不更新绑定目标后继续提交；拒绝原操作并显示原因。绑定范围按既有请求契约固定：开始/新增锁定项目、Task、服务实例及控制版本、Task/图版本和选中方案 ID/摘要；放弃锁定原 Task/WorkflowRun、Task/候选版本及服务实例/控制版本；回答与环境动作沿用原 Decision/Execution/Attempt/session、blocker/turn/instance 及各自版本。方案可以在列表内显式切换，但确认前显示的选中方案须与最终请求的 ID/摘要一致；刷新改变选中方案内容或相关核验版本时需退出后重新进入，不根据同名/索引换绑。纯采样时间推进和无关候选更新不使原操作自动失效。

普通刷新、迟到摘要或核验回执不能改变目标。核验摘要取自原只读报告的各项事实、错误和采样，不推断综合“可安全恢复”；报告与当前目标/实例/相关版本不一致时标记已过期，只能重新核验，不能作为当前操作可用的证明。完整核验报告仍可按需阅读，u 先在右下提供有界结论与下一步，不能直接切成整页。

### 回答、回执与结果摘要

1. 复用现有 Unicode 多行、自由文字、选项加备注、草稿及请求提交实现。浏览问题时展示选项标签；选项焦点移动时显示当前选项的原始必要说明，可换行/简单滚动。长背景和长选项以 F8 完整读取，截断不冒充完整内容。
2. 预览同时显示 Task/候选、选择和答复内容。继续区分已保存、已送达、新轮次已开始与结果待核实等真实投递事实，不推断“已落实”；开始、放弃、环境动作也把对应目标的最新未决回执或最近结果放在右下，不展示兄弟候选回执。
3. 结果摘要只使用已采集且归属当前候选、已确认业务轮次的 final。优先使用具有明确 final/轮次来源的既有摘要；没有这种摘要但有已采集规范 final 正文时，可通过既有 Body 读取提供最多 800 字符/6 行的确定性前缀预览，明确标注“最终回复预览（截断）”及轮次，不将前缀称为完整摘要。读取遵守原正文身份/版本、单页大小与完整性约束，不为主界面无界读取历史/全文。CandidateSummary.Summary 或最后消息若不能证明 final 与轮次归属，不作为该来源。准备轮、commentary、工具输出和未知阶段不冒充最终回复。缺少可确认 final、正文或归属证据时显示相应缺口和 f 完整读取入口，不自动调用模型生成摘要，不从原始日志拼接。
4. 验证信息只展示已有明确事实。worker 在 final 中报告的测试结果标为“最终回复报告”，不能当作服务独立确认的“验证通过”；工作目录/身份核验成功、执行 succeeded、工具退出码或 PR 创建均不等于产品测试通过。当前读模型没有可核实的测试结果字段时不新增绿色通过标记，也不为此建设测试证据采集系统。执行完成、PR 创建和已合并分别表达，任务完成只能依据真实交付事实。存在待回答/阻断时，结果摘要不能覆盖待处理内容。
5. 保留 f 完整最终回复、[ / ] 历史已确认最终回复及 v 历史决策的按需阅读能力；历史正文不自动替换主界面的当前轮次摘要。返回仍是原候选、原草稿/操作目标，期间已失效的操作保持失效。

## 键盘与详情入口

| 所在模式/焦点 | Enter | Tab / Shift+Tab | Esc |
| --- | --- | --- | --- |
| 普通任务列表 | 转到右下；当前可回答的问题激活原地编辑；不会打开详情、开始任务或放弃候选 | 列表与右下浏览区循环 | 按现有普通浏览规则 |
| 普通右下浏览 | 保持浏览；只有当前待回答问题可激活编辑，不自动执行其他副作用 | 返回列表 | 回列表 |
| 已激活方案选择/放弃确认 | 仅右下操作焦点且可见目标、方案/影响、确认提示时确认；列表焦点下只返回原操作区 | 列表与右下操作区循环 | 取消临时操作 |
| 回答编辑 | 列表焦点回原草稿；选项焦点转输入；输入焦点换行 | 列表 → 选项 → 输入；无选项时跳过选项 | 保存草稿并退出编辑 |
| 按需详情阅读 | d/f/v 普通阅读返回主界面；F8 背景/操作全文中不确认，只负责阅读 | 不切换成其他任务/操作目标 | 返回原主界面上下文 |

F2 是唯一答案提交键，只对已激活的原草稿生效；方案选择和放弃确认使用明确的 Enter 确认语义。窄屏下列表焦点或预览不可见时，F2 只返回草稿预览，需再次显式 F2 才能提交；选择/确认同样不能执行不可见操作。所有外发继续先保存原请求，保存失败不发送，重复按键或回执丢失只沿原 ID 核验。

所有内嵌选择/确认共用同一焦点与可见性核验，删除旧 y 直接确认旁路，n 可仅作取消；全局停服确认也须可见原服务实例、停止影响与确认提示后显式 Enter，不能利用全局快捷键确认隐藏操作。只有显式进入相应右下选择/确认或全局停服确认后，Enter 才可能发送相应请求。

普通 Enter 不再进入详情。d 进入完整候选详情；F8 阅读回答背景/选项或当前内嵌操作的完整信息；f 阅读完整最终回复；v 阅读历史决策。u 的右下核验摘要提供 F8 完整报告入口。详情保留已有 Esc/d/Enter 返回行为，F8 阅读保留 F8/Esc 返回；进入/返回方式在当前底部提示中明确。

详情与 F8 阅读独占按键处理：只允许当前阅读的滚动、合法章节/历史回复切换、刷新、返回与退出，不向主界面动作分派继续落入；F2、s/b/z/a/u/x/m、Ctrl+E/Ctrl+O 和项目/候选切换在阅读中不执行操作，返回主界面后才能使用。[ / ] 只在最终回复阅读上下文切历史，文字输入中为普通字符。进入 F8 保留原模式、焦点、选项和草稿；返回恢复其上下文并重新检查目标/版本，失效则显示拒绝原因，下一次确认不能沿用旧资格。d/f/v 仅在可用浏览上下文作为阅读动作，文字输入中仍是正文；从原地操作进入全文统一使用 F8。

F6/F7 切候选、s/b/z、r 刷新及已有派发控制沿用当前产品语义。输入焦点的普通文字键作为文本，不能触发 s/b/z/d 等操作；Ctrl+E/Ctrl+O 等已存在的显式环境动作继续按能力和原身份核验。停止服务保留明确的全局确认，可用主界面上的小型确认覆盖层承载，不进入候选详情；停止与候选放弃分别表达。

底部快捷键随焦点/模式变化，突出当前主要动作，最多两行；其他操作通过 ? 查看，减少重复铺满所有快捷键。回答编辑中准确区分“Enter 转输入”和“Enter 换行”。服务/连接/派发属于全局栏，完整 ID、路径和配置属于详情，不在多处重复。

## 焦点、颜色与文字层次

### 焦点表示

1. 活动窗口使用高对比双线边框，标题前显示 ▶，标题加粗；非活动窗口为普通细线。右上为只读概要，不新增 Tab 停靠点。
2. 列表选中行保持底色/反显和左侧选择标记；列表失焦后降低强调，但不消失。当前候选使用独立的选中标记，不能借状态颜色表示选中。
3. 右下内部区分浏览/操作、选项与输入焦点。选项焦点高亮当前操作行；输入焦点突出输入边界并显示明确光标；切回列表时保留草稿内容，输入不再呈现为当前接收键盘的位置。
4. 去掉 [焦点]、[列表焦点]、[选项焦点]、[输入焦点] 作为主要提示的实现，依靠边框、标题标记、操作行及光标共同表达。新问题/异常突出状态和待处理数量，不自动抢焦点、不自动切任务或打开编辑。
5. 单色或不支持双线字形的终端保留等价的线框/反显、▶ 或 ASCII 标记、加粗与光标区别。焦点与选择必须在无颜色时仍可辨认；不靠闪烁或动画提示焦点。

### 颜色与加粗

| 含义 | 样式 |
| --- | --- |
| 执行中 | 蓝色 + ● / 执行中文字 |
| 待人工处理、待回答、待合并 | 黄色 + ? / ↗ 或对应文字 |
| 已确认成功、完成或送达事实 | 绿色 + ✓ 或对应事实文字 |
| 失败、阻断、核验错误 | 红色 + ! 或对应原因文字 |
| 未核实、离线或陈旧快照 | 黄色提示 + 明确“未核实/离线/缓存”文字；不能显示为成功 |
| 焦点 | 固定青色或终端等价高对比色，与状态独立 |

颜色只用于关键状态、原因、主操作与焦点，不给每个候选、每行活动或完整正文分别上色。状态始终有文字/符号，不只依赖色相。主题采用适合终端明暗背景的语义样式，自动遵守终端颜色能力及无颜色配置，不要求用户建立新主题配置。

任务标题、窗口标题、问题、关键原因和主要操作加粗；普通内容正常字重；时间、完整 ID、路径及辅助说明使用次要样式，但仍清晰可读。次要样式不能用于唯一的阻断原因、提交预览或确认影响。状态样式不能把“执行成功”渲染成“任务已完成”，未知回执不能呈现为绿色成功。

ANSI 样式纳入显示宽度和中文换行处理。外部内容继续通过现有终端文本清洗，业务正文不能注入 ANSI、伪造焦点/按钮或改变全局样式。

## 小窗口与状态保留

参考宽屏为 120×32、紧凑宽屏为 100×28（终端列×行）；这些是布局验收尺寸，不是新的业务门槛。空间足够时三窗同时可见，左侧参考占 40%，保证右侧问题/输入可读，实施 Plan 可按显示列宽微调。辅助字段先压缩，边框和底部提示计入尺寸，不产生横向溢出。

80×24 等窄屏沿用按焦点切换列表与右侧的降级方式，三个窗口仍为同一主界面上下文，不创建独立编辑页面。120×18 等短屏优先显示右下的操作目标、关键原因/问题、选择/输入、预览和提交/取消提示；右上可压缩或暂时收起，并把必要身份放在右下。长正文简单滚动并明确尚有未显示内容。

极小窗口无法展示操作核对信息时显示“窗口过小，请调整后操作”，保持只读/取消/返回可达，不允许确认开始、放弃、提交答案等不可见动作。发送前必须同屏可见的最小信息为：原项目/Task/候选或服务目标、关键阻断/不可用原因、当前选中方案的关键比较字段或放弃/停服影响、回答的选项与有界内容预览，以及确认/提交和取消提示。长问题/选项/答复可以有界预览并明确截断，通过 F8 完整阅读；不要求整个长正文同时显示，也不把它误判为窗口过小。全文阅读本身不产生“已确认”，返回后仍需在可见操作区显式确认。详细阅读继续可达，边框/辅助字段不能挤掉上述最小信息。

不新增布局、焦点、滚动、主题、临时选择/确认或活动缓冲的持久化。重开默认布局，只恢复既有目标绑定草稿和请求对账信息；主界面模式不承担自动发送职责。异步摘要、核验、回执均隔离到原项目/Task/候选/Execution/Attempt 或原请求，切换后拒绝旧响应覆盖当前视图。

## 实施范围与交付

主要修改 [console](../../internal/console/) 的三窗渲染、布局、键盘导航、方案选择/确认、内嵌回答、核验及摘要呈现；优先复用已有 product/query/client 读模型，必要时只补充对应摘要字段，不建立第二套查询权威、通用窗口框架、主题系统或反馈协议。

保留最多 10 条规范活动摘要、有界读取和简单滚动，不恢复 transcript 时间线、工具正文展开、历史活动翻页、跨重启阅读位置或全量日志导出。不开自动摘要模型、不增 PR 自动合并、资源清理、恢复重试/替代 worker 或平台无能力的“打开原终端”。PR 审阅合并仍由用户在提供方完成；保留已有入口，没有能力则显示可核实定位，不为本任务新建通用启动器。

后续一份实施 Plan、一个独立实现 PR，先完成焦点/信息优先级/Enter，再完成原地选择/确认、核验与结果摘要；上述全部行为属于本任务交付，不以先完成样式作为整个任务完成。同步更新 README/操作说明、快捷键帮助和受影响 fixture，删除被替代的整页操作渲染与专属接线，不保留两套选择/确认/回答实现。

## 最小验收

| ID | 场景与通过条件 |
| --- | --- |
| CPW-01 | 一个任务多个候选，含兄弟待回答、当前执行中、环境受阻与待合并代表状态；左侧汇总和右侧所选目标正确；已结算历史失败不冒充当前需处理，原候选缺失保留选择；刷新、新问题及迟到回执不抢焦点/自动重开编辑，不串目标 |
| CPW-02 | 从主界面完成首候选/新增候选方案选择、放弃确认和回答；普通 Enter 不进详情、不产生副作用；切模式/目标时草稿保存或临时确认取消；同名方案不同关键配置可区分，方案摘要/Task/相关版本变化拒绝旧确认；重复按键/未知结果沿原请求，复用保存失败断言 |
| CPW-03 | u/r 核验、Ctrl+E 环境重查及回执在右下正确呈现，旧核验不能证明当前资格；未决回执与问题共存，旧终态回执/上一轮 final 不遮住新轮次运行；无来源的通用 Summary 不冒充 final，有界正文预览与缺口正确，worker 自报验证与独立事实区分；f/F8/v/d 全文入口、历史与返回正确 |
| CPW-04 | 宽屏/紧凑宽屏与窄/短屏覆盖焦点窗口、失焦选中行、候选选中、选项焦点和输入光标；颜色与无颜色均可辨认；中文/ANSI 安全/换行不溢出；长内容预览可达，不因正文过长禁发，极小窗口缺少最小核对信息禁发；y 无确认旁路，停服同样核验可见性 |
| CPW-05 | 一次隔离 Windows 原生终端或 PTY 定向检查 Tab/Shift+Tab、Enter、F2、Esc、F6/F7、多行中文和宽/窄布局；编辑切候选保留原草稿；F8 返回保留模式/焦点，阅读中按操作键不产生请求、不能确认隐藏操作；重开只恢复草稿/原请求，不恢复临时确认、不自动发送 |

CPW-01–04优先复用现有 console fixture 和最小真实 app/可控后端接线，只为新增界面行为补必要断言，不穷举业务状态机与交错。CPW-05验证实际修改的终端布局/输入，保留截图或 ANSI/PTY 输出及操作结果；PTY 不作为物理 IME 或所有终端配色兼容验收的证明。

实施 Plan 必须有“测试计划”，按[测试指南](../testing.md)和 [E2E 约定](../../tests/e2e/README.md)列最小必要级别、组/场景 ID、环境、命令、执行时点、通过条件及证据位置；新增场景/环境能力同时规划。默认一次 L1、console/接线定向回归及上述一次 Windows 终端检查，不默认 Full、完整 L2 或 L3/live；未选交付/恢复组说明本任务未改变原生交付/恢复协议。实际修改这些边界时再补对应最小场景，不能以界面测试声称其已通过。

实现证据根目录约定为 `docs/validation/console-primary-workspace/`，具体测试名称和命令由实施 Plan 按实际新增/复用场景固定。文档静态检查与实现验收分别记录，Spec 本身不替代实现证据。
