# 模块重构共同约束

本文是 #33–#35 的共同接口与验证约束。每项任务仍由自己的独立 Spec/Plan 和一个实现 PR 交付。

## 职责与依赖

复用[原生任务共同约束](native-task-constraints.md)、[执行架构](execution-architecture.spec.md)与[第一阶段交付共同约束](phase1-delivery-constraints.md)。保留一个 Go module、一个中心业务权威和现有单写者事件循环。

| 归属 | 拥有的职责与状态 | 允许的依赖与交接 |
| --- | --- | --- |
| #33：`internal/steerline/workflow` | 无副作用的步骤结果、转换与交付证据规则；不拥有可变运行状态 | 仅使用必要的值类型和标准库；不依赖根 `steerline`、center、平台实现、数据库、UI 或进程工具 |
| #34：执行上下文与协调层 | 固定执行上下文、worker 观察者登记、事件分发和生命周期 | 消费 workflow 规则、既有执行后端和中心命令；业务状态仍经同一写者提交 |
| #35：`internal/steerline/center` | 中心命令/查询、事务、不变量、持久化和可重建投影 | 可依赖 workflow 与既有纯规则包、SQLite 驱动；不依赖根 Service、console 或具体后端；外部证据通过窄接口或值对象输入 |
| 既有平台与表现层 | 本机/Orca 平台调用、协议事实；CLI/TUI 输入和展示 | 调用中心与执行接口，不绕过中心写业务表或自行判定任务交付 |

公开类型以消费者真正需要的命令、查询、证据和错误为界。不得为避免 import cycle 把数据库连接、事务、Service 或全部状态字段公开，也不把互相依赖的代码集中到 `common`/`utils` 大包。接口由使用方按实际能力需求定义；只有一种实现且不需要替换的内部组件可以直接使用具体类型。目录移动或新增接口数量不作为完成标准。

## 语义与状态

重构保持前置交付时的行为、命令与结果协议、持久格式、契约摘要算法、错误码、精确执行身份和恢复语义。#33/#34 不实现 #26 的多候选模型或格式转换；#35 消费 #26/#27 已交付的当前格式。包迁移不引入数据库迁移、双写、旧版本读取或新调度策略。

纯规则只评价给定证据，不能以缓存结论替代事务内的版本与资格复核。外部证据取得和平台动作位于事务外；动作意图、命令幂等、CAS、事件和业务状态仍按原原子边界提交。超时/unknown 保留原 Operation 与资源占用；TaskDelivery 必须继续核验固定 PR 的真实合并事实。

组合快照和查询结果不能把可变中心对象借给调用方。固定上下文中的 map/slice 按所有权复制或只读封装，禁止通过别名改变其他运行。重构不能增加第二个任务、执行、会话或交付权威。

## 执行顺序与集成

#33 无未完成硬前置，#34 等待 #33；拟通过原生追加前置命令建立 #34 → #26。#35 等待 #27，拟追加 #35 → #28 与 #35 → #16；原有 #26 → #27、#27 → #28、#26 → #16 均保留。这些边须以中心回执确认，文档不能自行重置已领取任务或使拟追加边生效。

若 #26 已领取，只能在既有安全重置能力核验原运行后再追加；不支持的后端、活跃/unknown、未决问题、发布不确定或已合并均不能靠人工声明清除。无法满足时保留原执行与待处理的补边意图，不自动改成 #26 → #33，也不对原 TaskContract 换绑。

#30/#31 的版本模块化仍归原任务。涉及 Service、启动/恢复、SQLite 或维护准入的共享修改串行集成，后合入方保留并回归此前已交付的维护、候选和平台边界；不因此增加 #30/#31 与本组的开工硬前置。#3/#4/#6 的真机证据按实际触及路径复验，不以重构测试关闭原剩余验收。

## 验证与交付

每项实现 PR 在自己的 `docs/validation/<任务前缀>/` 记录：原调用点到新模块的映射、状态所有者、公开接口、`go list -deps -json` 的实际依赖检查、行为样例及验证命令。依赖检查落实为可重复的脚本或测试，断言不允许的 import 与公共入口没有重新泄露存储/Service；禁止只凭文件已搬迁判定解耦完成。

针对性测试后运行 `go test ./... -count=1 -timeout=45m -p 1 -parallel 1`、`go vet ./...`、Windows/Linux Go 构建及 `git diff --check`。沿用已有测试反馈工具；纯规则测试不启动外部进程，事务测试使用临时真实 SQLite，执行协调测试用可控后端注入事件。有 goroutine/事件所有权变更时运行受影响并发测试，并在可用平台运行 race；不可用如实记载。

改变真实后端调用、身份映射或恢复接线时，在隔离资源复验受影响的本机/Orca 原生路径；报告明确构建、目标及覆盖范围。生产活动资源不得用于夹具或故障注入。纯文档规划只检查身份、链接、依赖、引用方向与语义，不运行实现验收。
