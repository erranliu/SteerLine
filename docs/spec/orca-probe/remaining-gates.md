# Spec 01 remaining gates

The [remote report](remote-capability-report-2026-09-23.json) covers Orca 1.4.209 on a Windows center and a paired Windows execution host. All further probes use the isolated SteerlineTest repository and a new test Task/Dispatch. Preserve the existing Run and worktree identities; do not use Beads or create a PR.

P06 passed in the [transient transport probe](samples/p06-transient-2026-09-24.json): liveness changed from `live` to `unverifiable/host_unavailable` and back to exact-worker `live` on the original Dispatch, with the same question Delivery and no replacement worker or worktree.

P03 passed in the [output probe](samples/p03-output-2026-09-24.json): retained messages paged without duplicates, bounded-history omission was marked, and a terminal cursor returned `source_changed` after release switched the read to transcript.

P07 passed in the [center restart probe](samples/p07-center-restarts-2026-09-24.json): the home runtime recovered the original Dispatch after interruption at dispatch, message and answer checkpoints. An in-flight worker-start request remained `pending`, but its accepted IDs and execution-host observation enabled explicit reconciliation without a second worker. P08 passed in the [response-loss probe](samples/p08-response-loss-2026-09-24.json): saved request IDs recovered completed or pending mutations, while a caller-discarded response with no request ID was reconciled through read-only Run and Task enumeration.

P11 passed as a tested [file-backed no-agent composition](samples/p11-file-receipt-2026-09-24.json): Orca returned exit 7, a structured receipt survived a home Orca restart, and a new no-agent terminal read it. Built-in terminal stdout still disappears after exit; Spec 03 must implement the file-backed adapter if it uses direct script steps.

A [remote-runtime restart probe](samples/remote-runtime-restart-2026-09-24.json) recovered the same exact worker and question after the remote Orca runtime ID changed. A [disconnected stop probe](samples/disconnected-stop-2026-09-24.json) then exposed a blocking cleanup gap: `stop_unknown` persisted after the execution host verified the worker live, while Orca refused a new stop or follow-up to the original Dispatch. With explicit user authorization, the exact test terminal was manually closed, exit verified, and the Dispatch abandoned as failed. The platform-managed recovery path remains unsupported.

The user selected a production scope with remote cancellation unavailable. Spec 02/03 may implement and test this fail-closed boundary; no new disconnected-stop probe is needed to claim cancellation support, because support is explicitly absent.
