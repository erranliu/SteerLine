# 原生任务共同约束

本文是可被独立任务 Spec 引用的共同约束，不是一份执行 Spec，不承担任务、实现计划或多个 PR 的验收清单。每个任务必须有自己的独立 Spec、可选独立 Plan 和一个独立实现 PR。

## 业务边界

- 发布前的任务草稿可以编辑；发布后固定范围、规格、验收、优先级和外部依赖。本版不提供编辑已发布任务的业务入口。
- 系统不提供拆分、撤销、重新打开、任务回退、执行中依赖修改、级联补偿或动态重规划。不实现父子任务、聚合节点、拆分状态、聚合验收或通用强制写入/整图替换命令。
- 拆分与回退是用户行为。尚未交付任务无论是否在执行，都可由用户通过 Codex 分析并人工拆分；人工拆分应保持原对外交付承诺、不让后继提前执行。已交付任务需改变交付事实时按人工回退处置，不作为普通拆分对象。
- 用户自行决定代码、PR、任务记录、依赖及运行现场的处置方式；各任务均不实现该流程，也不承诺自动识别、修复任意人工改动。人工处置不受产品是否提供按钮或命令的限制。
- 故障恢复、断线对账、原任务契约下的重试和人工问答继续沿用执行模型。暂停派发不代表 worker 已停止，执行失败不自动重开、释放 claim 或修改依赖。
- 只支持同项目硬前置：`A → B` 表示 A 交付后 B 才能领取，多个前置为 AND。不提供条件/OR 边、部分交付放行、跨项目依赖或接口提前满足的特殊门槛。
- 任务 DAG 只管任务之间的资格；实现/验证/审查/发布与重试仍由 WorkflowRun/Execution/StepAttempt 管理。保持既有执行槽策略，不增加并行选择器、资源锁系统或自动合并。

## 身份、权威与执行层

复用 [中心执行模型](02-execution-model-and-adapter.md) 的 SQLite、项目身份、仓库锁、QueryService/CommandService、事件及 Operation/outbox；[共同执行约束](execution-architecture.spec.md)、[双后端](pr-04a-execution-backends.spec.md) 与 [会话契约](pr-04b-conversation-events.spec.md) 继续适用。不得建立第二个 TaskStore、状态机、会话模型或业务写者。

任务、WorkflowRun、Execution、StepAttempt、Decision 和外部身份分开。一个任务可以有重试及历史运行，但只有一个权威活动 WorkflowRun；同任务候选与重试不混同，不增加限制未来多个 Execution 的唯一键。旧尝试的迟到消息不推进新尝试。

任务发布前已有的仓库规划数字 ID 属于外部追踪身份，可在发布时通过 ExternalTaskRef 与原生 Task 一对一关联；它不替代中心生成的不透明 task_id，也不参与 DAG 边、调度排序或业务状态。没有规划 ID 的任务仍可发布。中心不读取规划文档作为任务契约或状态权威。

任务级别的范围、唯一 Spec 和可选配套 Plan 固定在契约中；可另外引用共同约束或协议，但不能以 common_refs 夹带其他任务的执行 Spec 或计划。UI/CLI/worker 只使用查询、受控命令或既有结果通道，不直接写业务表。图算法和渲染器均不是权威来源。

Beads 项目在显式迁移前保持原权威；native 项目由中心任务/交付事务维护。任务源与 backend、工作流版本分开，不因 local/Orca 或 UI 入口改变任务源。中心模型已建立的内部 Task ID 和历史运行关联必须复用，不能再次迁移一套执行模型。

## 恢复、远端与版本

外部动作的意图、回执及不确定性按现有 Operation 契约持久化；事务不跨越网络请求或 worker 启动。未知结果不等于失败或已停止，不能重派或释放占用。数据库事务失败回滚是存储原子性，不是产品任务回退。

原生任务不以整个 [远程闭环](03-remote-execution-and-viewer.md) 完成为前置；启用受监管远端时仍须满足其版本、消息大小和取消能力门槛。worker 不连接中心数据库，不要求远端安装 SteerLine 服务；目标路径和现场事实由对应执行适配器核验，不能转交本机文件 API。

沿用实际前置的数据库/命令版本，扩展不兼容结构时分配未使用版本。runtime/候选投影只是可重建读模型，记录 database revision、生成时间和导出错误；数据库提交后投影失败不回滚任务事实。旧读者拒绝不兼容格式，旧 beads_status 不改名伪装成原生历史。

所有命令遵循既有目标身份、expected_version、幂等键、发起者、期限与回执规则。客户端超时按原 request_id 查询。错误为 code、message 和相关 ID/字段，客户端按 code 分支，不解析自然语言。接口协议的精确版本由拥有该接口的独立 Spec 定义。

契约和命令的规范摘要统一使用规范化 JSON（对象键排序、UTF-8、无格式空白，数组顺序保留）的 SHA-256；解析拒绝重复键。文件引用的内容摘要仍使用对应 Git blob 字节的 SHA-256。规范化库与样例由原生任务模型任务固定，后继直接复用，不各自生成不同的 payload_digest。

任务身份、契约、交付、PR 绑定、来源映射及历史运行均保留；删除展示条目不删除业务事实。本组任务不实现历史清理。

## 验证原则

每个任务只验收自己 Spec 的条件，并回归其触及的既有 Beads、执行/会话和控制路径。按任务目录保存输入摘要、命令、工具版本、身份、实际结果与证据。fake、skipped 或文档完成不能代替要求的真实平台证据。

实现任务运行针对性检查后执行 `go test ./... -count=1 -timeout 10m`、`go vet ./...`、`git diff --check`，适用时补充 race 和原生构建。纯文档调整只检查链接、引用方向和规格一致性，不宣称实现验收已通过。
