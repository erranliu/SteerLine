# Spec：收敛执行与反馈产品流程

依据：用户明确授权环境阻断简化、会话来源统一、执行动作统一并明确发布责任，完成后另提 PR。基线 #199 合入后的 `7eb02bb`。

本 Spec 取代原解耦约束中 DeferredDecision/DeferredFeedback 与混合发布责任的要求，以及产品日志自动回退的要求；其余单写者、身份、资格、当前格式恢复、intent/receipt/ack 屏障和真实唯一交付继续成立。历史 Spec 不回写。

## 行为

1. 环境阻断是 Execution 的独立事实，不创建、替换或隐藏 agent 的业务 Decision。阻断期间新业务反馈在受理或消费前明确拒绝，不保存后台待投递队列；UI 保留草稿。已有原请求只对账，不重发。打开原终端/重新检查是独立中心命令，绑定项目、服务实例、Run/Execution/Attempt、blocker/turn 和版本；不能以按钮状态代替中心重检。准备 nonce/deadline、晚到结果的人工门槛保留。
2. 产品会话、正文、原始证据和活动页面只消费数据库中已提交的规范记录。平台采集器仍可读取原生历史/日志并保留 raw 证据；UI 不尾随或检测日志格式，不自动用原始日志补画。不完整/尚未采集明确显示缺口，不能伪装完整。诊断文件保留，可手动查看。
3. 生命周期副作用统一通过现有 Service actor 的单步调度：持久 intent → 后台 Execute/Reconcile → 带原请求身份的结果 → actor 核验并提交 receipt → 才授权下一步。启动、反馈、宿主动作、ack/清理共用调用交接；禁止绕过原生问题路由、自动重发未知输入或合并跨提交屏障的动作。不新增第二引擎或平台反向中心依赖。命令先受理，最终状态由回执确认。
4. 当前产品固定 worker-only 发布：worker 提交、推送、创建 PR；中心只核验 PR/合并、提交唯一 TaskDelivery 和授权清理。不接受 host_service 或 execution_profile 发布责任，不默默改成 worker；删除中心发布执行、动态发布工具和责任组合分支。执行环境必须提供发布能力与凭据，准入仍按真实能力拒绝不支持的路径。
5. 修改持久结构时升级受影响版本，旧开发格式明确拒绝并保留现场；不迁移、双写或回退。所有公开入口、组装、测试 fixture 和代表断言当场切换。

## 最小验收

- 环境阻断保留原业务决策，拒绝新反馈且无排队；解除阻断不自动发送。旧 blocker/实例/Attempt 拒绝，重放查原回执。
- 产品页面只读规范数据库，raw 诊断文件不是备用产品数据源；正文/游标/历史身份和缺口保持。
- 控制 actor 不被慢副作用阻塞；每步 intent/receipt/ack 屏障、原身份、过期结果及提交失败保持，未知动作只读对账。
- worker-only 实际创建 PR，中心无 commit/push/create；provider 真合并前不能交付，重复观察只有一个 TaskDelivery。
