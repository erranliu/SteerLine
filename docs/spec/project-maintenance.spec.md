# Spec：项目基线与材料统一维护

状态：2026-10-21 按用户授权实施；验证结果以专属验收为准。配套 [Plan](../plans/project-maintenance.plan.md)、[专属验收](../acceptance/project-maintenance.md)，统一行为正文见[项目维护设计](../product-design/project-maintenance.md)。普通开发，不占 Task ID 或修改 roadmap。

## 目标与现状

初始化、基线更新和局部更新共用维护服务，主动提示远端变化；生成可审阅、显式应用，Task 首次启动固定远端最新代码与同 commit 材料。

| 当前能力/缺口 | 本次整合 |
| --- | --- |
| BaseResolver 首次启动 fetch、后续候选共用 base 已有 | 保留目标获取/祖先/前置检查，首次同时解析材料；已有快照不重新取最新材料 |
| Task 登记固定 contract，启动新代码仍读旧 Spec/Plan | 最近确认内容与首次执行契约分开，沿原 Task version/CAS，不新增任务修订编号 |

## 范围与复用

一个 Go 维护服务，统一“输入快照→影响评估→人工核对或单项生成→审阅/应用→远端核验”。初始化只选择全范围，基线更新选择受影响范围，局部更新选择指定材料及必要依赖；无关项不强制执行。无基准时做当前支持材料的全范围检查，不推定全仓文档或语义覆盖已通过。

首版材料仅为测试规范/清单、Task 原 refs、Plan 测试安排；复用普通 blob/规范路径/UTF-8/大小及严格 JSON 检查。初始化模式调用同一规则，无 Plan 时不造任务/安排。预纳管只人工准备及只读核验，服务适配可测试但不开放新的未纳管项目 Web/CLI 或持久候选库；正式登记/PS-01–PS-07 扩展继续由项目添加批次消费公共能力。

远端与工作区草稿使用同一输入快照，分别标明完整 commit 或基准 HEAD+实际字节；纯检查不依赖 Runner/profile。唯一模型生成目标是一个 Plan 的 .tests.json，读取完整 Plan、docs/testing.md、docs/testing/test-list.json。规范、清单和长期文档由用户维护；不生成测试程序或自动重规划。

材料依据按完整实际输入/输出及规则版本判断。三个生成输入任一个变化须重核，可人工采用有效现有安排而不调用模型；原依据缺失也可经人工核对建立。依赖比较统一文本 CRLF 为 LF，原请求/Task blob SHA及写入条件仍按真实字节，避免草稿合入后的换行差异造成永久待更新。生成输出不作为自身输入，commit 改变本身不触发再生成。

仅源码/测试入口/构建/未知路径变化而材料输入未变时显示适用性核对提示，语义质量由代码审查负责；不要求每次普通代码交付都完成人工回执才能释放后继。必要文件缺失/无效、实际材料变化未复核、Task 内容变化未确认才阻断相关首次启动，无关 Plan 待办不阻断。

## 观察与首次版本冻结

在线项目装载后及每五分钟检查，支持手动检查，合并在途读取，有界 fetch/超时。首版只检测、提示用户通过正常 Git 流程 pull/处理脏工作区、分叉或历史改写，不实现产品同步按钮或通用 Git 写命令。检查不改本地分支/工作区、不调用模型；失败保留上次成功时间，不把缓存称为最新。

Task 的 repository/remote/目标分支固定；材料确认可在没有任何候选预留前按 Task version CAS 更新路径/内容依据，不能变更目标身份、范围、依赖或交付。

所有首次启动入口共用以下规则：原请求已预留先返回原事实；否则本次成功 fetch，读取该 commit 的所有 Spec/Plan/common/acceptance Git 引用及测试规范/清单/安排，核验相关材料依据和前置合并，构造完整执行契约。事务内重核 Task/authority/graph、配置目标及实际消费的材料确认，原子固定唯一 Task 执行快照、共同 base、测试快照、候选和原提交意图。事务前已知远端目标前进则重新评估；不在数据库事务内联网/生成，不以轮询时间或无关 Plan 版本制造冲突。

“最新”仅指本次成功 fetch 的 commit，冻结后新提交不改变执行；不声称 Git/数据库跨系统原子性。失败/缺必要材料时零派发，不用本地 HEAD 或旧缓存代替。Task 最近确认的内容未变可在新 commit 固定，内容变化需先审阅确认。有效空安排与 Plan 无自动测试说明允许，不要求测试通过，不增加 PR/Delivery 门禁。

首次预留后含 Runner 未受理、拒绝/未知、候选退出都保持冻结。后续候选先取原执行快照，不重新读最新材料；仍核验原目标/图/前置、祖先关系、profile 和 Runner 资格。远端历史改写导致原 base 不在目标分支时拒绝新候选并明确诊断，不换 base；原请求对账/原执行反馈保持。换基线使用新任务，无旧库迁移、历史回填或 Task 重开。

## 生成控制与产品入口

维护清单可包含多项，但首版每次生成一个 Plan、一次 generate/1、一个输出文件。一个动作显示固定来源、输入、目标/profile，先持久原意图再调用 Runner；复用原 Generation，不另套通用任务/批量调度或提交日志。每个操作无自动重试，unknown 只查原请求；明确拒绝或原调用终态且资源/停止义务允许后才可显式新尝试。

结果严格校验后只供审阅。单文件显式应用绑定输出摘要、HEAD/分支、实际输入与目标原字节，意图先保存，条件满足才原子替换。源码来自远端但本地输入不匹配时先提示更新，不覆盖到错误现场。审阅后条件变化拒绝旧应用；重新评估并审阅后可用新应用请求复用仍适用的输出，不改原 Runner 信封或重新生成。多项独立应用，无多文件事务/回滚/批量继续机制。

取消和应用意图在唯一 owner 下串行：先取消则不许应用；先提交应用意图则原在途写入可完成，只核实实际事实。丢回执/重启按原条件判定未写/已写/冲突，查询不补写；未取消时显式重用原应用命令可续原动作，取消后不能用旧号新开写入，须重新审阅/新操作。已写事实不被取消抹去。原生成停止/迟到 Run/资源结算沿共享 Runner，不新增原生恢复。生成、应用与启动授权分开，后台/查询/重启均零自动副作用。

应用/草稿不计远端就绪。用户正常提交/推送/合入，重新 fetch 后由服务核对输入/输出真实 blob 与新增影响，沿用或建立该范围依据；生成合入不自触发循环。空模型结果不自动覆盖，明确确认无测试且 Plan 有说明时允许空安排。

Web 仅一个维护面板：检查/Git 更新提示、影响清单、人工核对、单项生成/diff/应用及待提交状态；启动待办直达对应范围。沿既有应用 v2 认证/项目路由增加必要 DTO/命令，服务端核对原项目/范围/版本/摘要，不信 passed 布尔值，切项目不转移授权。首版不建 project maintenance 通用 CLI。既有 tests generate/generation/stop-generation 消费共用服务；新增 `tests apply -project <id> -generation-id <id> -request-id <new-id> -expected-revision <n> -review-digest <sha256>`。预览只读返回这些参数；review_digest覆盖项目/原生成/路径/输出及本地HEAD/分支、实际输入、目标原字节，应用时服务重算比对，不能只有输出摘要。重新审阅返回新摘要，不改原请求；Task确认先由维护面板/API提供，不新增独立修订CLI。

已配置项目的材料确认与冻结由同一项目库/actor 持有；初始化仅复用规则。应用层只装配/路由/观察，不用应用级文件的版本与项目 SQLite 伪造跨库事务。所有旧生成入口切换为待审阅，无自动保存旁路。W/E/V 仍归[生命周期](../product-design/worker-lifecycle.md)，不增加 Runner 状态机。

## 验收要求

自动项对应当前实现，安排见 Plan，实际结果只进[专属验收](../acceptance/project-maintenance.md)。

| ID | 必须达到的行为 |
| --- | --- |
| PM-A01 | 周期/手动观察、首次 fresh fetch、在途合并、失败及目标删除/非快进诊断正确；只提示 Git 更新，零本地分支/工作区/模型副作用 |
| PM-A02 | 三入口只改变范围/来源，复用窄规则；无基准/增删改/完整输入摘要、换行继承及范围隔离正确，无生成自失效；无全套纳管门槛/提前建库 |
| PM-A03 | 人工采用/Task 内容确认有实际摘要及 CAS；目标身份不可借确认改变；源码适用性仅提示，必要待办才阻断；人工材料无须先调用模型 |
| PM-A04 | 单 Plan/单次调用，完整快照/profile/原信封固定，新旧生成入口待审阅；草稿与 commit 来源正确，零隐式写入/测试/提交/启动 |
| PM-A05 | 单文件显式应用的输出/HEAD/分支/输入/目标及路径检查正确；取消先后序、丢回执/重启和旧输出显式复用可控，草稿/应用不冒充远端就绪 |
| PM-A06 | unknown/取消/迟到仅按原请求及停止义务核验，明确失败新尝试先检查资源资格；重启零自动生成/应用，复用原共享围栏，不为预纳管虚构生成 |
| PM-A07 | 各首次启动入口固定最新同 commit 全引用/快照，相关依据/Task/图/目标竞态零派发，无关观察不制造冲突；后续候选/拒绝后重放及非快进边界保持原版本，Delivery 不变 |
| PM-A08 | 隔离真实 Go/Web 浏览器闭环覆盖三入口范围、更新提示、生成/审阅/应用、合入核验与首次冻结/PlanTests；跨项目不串授权，一次真实 Runner/Codex 共用路径及资源清理有证据 |

PM-M01：自动验证后人工检查提示、diff 和启动待办可理解性，可后置，仅阻塞体验签收。本批实施与验证使用独立调试包，不使用安装现场。
