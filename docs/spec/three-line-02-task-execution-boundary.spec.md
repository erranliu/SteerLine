# Spec：任务选择与执行结果边界

任务 ID：74；任务名称：任务选择与执行结果边界；目标：`TASK-EXECUTION-CONSOLE-DECOUPLING`。配套 [Plan](three-line-02-task-execution-boundary.plan.md)。一个独立实现 PR 交付。

## 范围与前置

硬前置：#73。在当前实际启动、领取、候选新增、交付和丢弃路径接通任务工作端口与规范化结果应用，移出任务中的执行模式/容量、会话与 PR 核验责任。

实际盘点起点：`task/readiness.go`、`task/delivery_gate.go`、`task/delivery.go`；主包 `native_claim_command.go`、`native_delivery_command.go`、`native_discard_command.go`、`candidate_workers.go`、`service_workers.go`、`worker_completion.go`、`write_ports.go` 与对应 sqlite 提交。开工时按实际消费者核对路径；前置迁移已发生的部分只承接其唯一实现，不重建。

## 实现要求

1. 任务端口提供依赖已满足的固定工作、优先级排序及领取前值；暂停、auto 占槽、权限/配置准入、宽松五候选检查归执行。首次候选以 Task 为粒度领取，后续候选复用原领取/base/契约，不重新挑选或增加另一可写 Candidate 权威。

2. task/model 定义规范化结果输入：项目/任务/固定契约身份、领取归属、预期任务与集合版本、唯一结果/原请求 ID、结果关联及结论。任务不解释 PR URL、session、后端状态或不透明执行载荷；需要保存的 PR 明细归执行记录，查询可组合关联。结果应用小端口只由 app 注入执行用例，不暴露给产品或具体后端；关闭声明须在同一提交边界关联执行已核验的唯一交付记录，不接受任意 success 布尔值作为授权。

3. 执行侧核验候选与历史 PR 集合、真实 repository/head/base/merge 及交付资格，决定可关闭/待决策/冲突。失败、放弃、轮次结束、最终回复和停止未知都不是可关闭结果；多个合并/事实不明不释放后继，迟到事实不覆盖 Delivery。

4. 领取涉及任务与新执行记录时仍通过同一 SQLite 提交重检；交付涉及唯一结果、任务关闭与 DAG 修订时仍一次事务。应用接口不拆成先改任务再存执行的两步，不暴露任意 SQL/事务，也不把全能事务端口交给任务消费者。

5. 丢弃由任务记录意图；执行提供可丢弃事实并负责停止/清理。交付与丢弃、新增候选与结项在同一提交边界核对原版本。建立 Service/CommandService/Config 字段及函数到 #75/#76/#77/#80 的文件级清单，先拆共享协调段，保证后继无需同时重写同一文件。

## 共同执行约束

遵守 [三线解耦共同实现约束](three-line-constraints.spec.md) 的最终依赖矩阵与跨域提交规则；本阶段负责实际启用自己迁移部分的守卫。

保持当前任务/DAG、持续 worker、人工并行/自动派发、原会话反馈、恢复授权、唯一交付和 UI 生命周期。失败、轮次结束、最终回复、交付、任务关闭与资源停止分别表达。具体实现无业务写权，状态仍由唯一业务写者经窄声明提交；同数据库查询保持同读快照。

同仓库、同 go.mod、同 SQLite 和服务部署方式；不引入新进程协议、后端、严格候选名额、评分/融合或规划实现。纯结构迁移保持数据格式；确需调整格式时由唯一所有者统一支持版本与拒绝边界，不新增旧版读取、迁移、双写或回退。各步切换真实消费者/构造/测试并当场删除迁出定义，保持可构建，不留永久兼容门面。

完整实施须硬前置整体交付；只读盘点可提前。共享定义、Service/Config/组装/runner 段先确定一个修改所有者并顺序集成，禁止多条线独立重写共同文件。与 #38/#39 并行使用隔离 worktree/构建/配置/测试资源；#39 记录固定构建，不在运行中替换现场。迁移后按实际接线/行为影响决定证据复用或定向重验，远端权限缺口、零命中、skip 或 mock 都不能代表原生通过。
