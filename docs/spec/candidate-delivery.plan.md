# Plan：PR 胜出与落选候选对账

任务 ID：27；任务名称：PR 胜出与落选候选对账。唯一执行依据：[Spec](candidate-delivery.spec.md)。硬前置：#26，一个实现 PR 交付。

1. 基于 #26 的精确运行身份、DTO 和意图入口清单，实现逐候选发布及 PR 唯一绑定。保留临时发布拒绝，直至本任务的资格检查和交付仲裁已完整接通，再统一移除，覆盖直接命令、步骤自动推进与恢复入口。
2. 复用当前 PR provider 与步骤证据核验；事务外读取全部候选 PR/未决发布的固定证据，提交事务重新核对 Task、候选和发布集合版本。唯一 Delivery、Task closed、胜出与落选资格在同一事务提交，随后按原身份继续结算资源。
3. 在启动、下一步骤、回答续跑、重试与发布的意图写入事务中复用候选资格检查，保留各动作自己的精确身份和版本检查。区分新意图与原 Operation 对账，迟到结果可入库但不再推进落选候选；用持久待办接原本机 Stop/PR 关闭及远端不支持分支。
4. 将资源结算和历史 PR 观察按持久候选/待办加载，避免依赖 Task 仍为 in_progress；Task closed 后仍恢复全部未结算候选。扩展全部 PR 确认 closed_unmerged 后的安全任务变更，持续核对 abandoned/discarded 的历史 PR，沿用 #26 查询补齐 delivery_role、待办与冲突信息。
5. 按 CD1–CD7 注入交付与追加候选/步骤/回答/发布的事务竞争、回执丢失、并发双合并及重置后的历史 PR 重开/迟到合并；验证 closed Task 重启仍能定位并对账落选资源。运行共同约束回归并保存记录；若 #31 已集成，同步回归维护屏障与这些入口的组合。
