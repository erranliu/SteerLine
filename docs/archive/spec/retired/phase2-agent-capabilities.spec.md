## 探测契约

使用隔离的本机测试仓库和专用 Codex 配置目录，不修改用户全局配置。记录 CLI 路径、实际版本、配置摘要、Windows 版本、方法/schema 摘要、进程/thread/turn 身份、正文与回执。文档方法只能作为候选，交付报告须固定一套真正通过的版本及配置。

分别验证 thread 新建、按固定 ID 恢复、只读历史、轮次流、最终回复与轮次结束、工具审批、追加输入/中断。新 thread 不 fork、不注入旧摘要，却能读取同一目录既有草稿；thread/resume 不能被当作重发上次 turn。断开 stdio、终止宿主、轮次发送响应丢失后，确认能否只读重认原动作；不能唯一核实时报告 unknown，不启动第二轮。

权限试验分别覆盖仓库代码、正式 Markdown、.git 与共享 refs、草稿目录直写、目录联接/符号链接逃逸、脚本/测试执行、通用 shell、子 agent 和外部配置注入。只读文件系统仍可能允许执行工具，必须独立证明通用执行工具被禁止或在执行前被可靠拒绝。全仓读取通过服务只读工具也可实现，不得为读取开放任意命令执行。测试由宿主控制，在临时哨兵文件上证实越界副作用未发生，不能只查最终 diff。

比较客户端动态工具与本机 MCP 中可验证的受控写通道，最终只选择一种；最小服务样例只接预先分配的 Markdown file_id、expected_version 和正文，不能收任意路径/命令。模型可调用保存草稿，不得调用 reserve、publish、create、start 等人工产品命令；服务校验来源身份，不能仅依靠工具描述隐藏。该样例不承担正式提案存储。

## 结果与下游门槛

报告每项为 passed/failed/not_tested，给出复现命令与受支持方法字段。关键能力全通过才能声明本任务交付并供规划会话任务依赖。若不能代码化禁止执行/越界，保留失败报告与现场并阻塞任务；不能以“探测完成”冒充可用能力。允许不提供“编辑已发送消息并重跑”；本任务不承诺对话回退即文件回退。
