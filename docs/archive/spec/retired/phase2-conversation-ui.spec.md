## 页面与输入

使用基座原生输入，发送、追加当前轮、排队意图与中断按真实服务能力标注。初版仅提供已经验证的开始/steer/interrupt；没有服务队列支持时不展示排队动作。输入发送状态引用 InputReceipt，服务 accepted 不显示为 agent 已读。

session 列表绑定项目和 workspace。新 session 操作前显示固定 worktree、草稿/文档版本和当前 owner，说明保留文件、清空对话；新 thread 的输入草稿为空。旧轮次活动时允许创建/阅读新 session，禁用开始写轮次并显示等待原因。只允许通过服务中断原轮次，不能换 thread 绕过 guard。

对话明确显示用户输入、过程、工具、完整最终回复、错误及权限等待。工具正文按需折叠，读历史不强制跟随；路径、任务、proposal 和文档版本链接统一导航。主 agent 的建议卡片不是创建任务回执；本任务可以链接受控草稿预览，但不自行 reserve/publish/create。没有人已授权的提案时仅讨论，不能先造草稿槽；本任务的独立验收可由服务命令预先注册 workspace 和授权提案，完整 UI 入口由审阅界面任务交付。

## 生命周期

UI 重启从原 session/thread 和持久游标补读；未发送草稿按 session 保存，已提交意图持久保存完整信封并按原 ID 核实。服务明确 command_not_found 时按共同契约补交同一输入/审批命令；服务已登记的未知 turn 只对账，不因补交重发 app-server turn/start。服务断线保留历史、未知输入和审批目标；错误项目/服务实例禁止写。Codex 审批准确展示原请求且只允许服务已准入的选项，禁止通过批准 shell 等方式越过主 agent 边界。
