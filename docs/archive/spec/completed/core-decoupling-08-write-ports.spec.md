# Spec 中心写入端口收窄

任务 ID：69；任务名称：中心写入端口收窄；目标：`CORE-IMPLEMENTATION-DECOUPLING`。配套 [Plan](core-decoupling-08-write-ports.plan.md)。硬前置：#68 [重构后代码清理](core-decoupling-07-cleanup.spec.md)整体交付；一个实现 PR。

## 目标与范围

遵守[后续维护共同约束](core-maintenance-constraints.md)。让 CommandService、Service 及任务/会话实际消费者通过小写端口提交，不再依赖具体 SQLiteStore 或共享全能 DomainTx。端口按完整业务提交边界划分，业务规则仍归中心，现有 SQL 实现在本任务继续唯一保留，整体搬迁由 #70 完成。

开工时盘点 query_command、native_* 命令、service_commit/worker_commit、绑定/回执附件、conversation_store、checkpoint 与命令消费；文件名按 #68 的实际交付映射，不重新引入已删平台接线。

## 提交契约与消费者

| 消费者 | 必须接通的能力 | 原子边界 |
| --- | --- | --- |
| 命令受理/消费 | 保存/读取命令、幂等查询、接受答案、更新处理结果 | 原请求与答案/状态的既有事务，身份和内容冲突重检 |
| worker 协调 | 加载权威前值、提交声明写集合、固定绑定和回执附件 | Before/After、控制/权威版本、当前 Attempt、业务记录/附件/checkpoint 同事务 |
| 任务/DAG/交付 | 创建批次、领取、追加前置、丢弃和唯一交付的提交与所需读取 | 任务/合同/依赖/执行固定记录/回执及对应权威版本，不逐表独立提交 |
| 会话采集/服务元数据 | 提交事件/正文/source cursor、读取恢复数据、保存 checkpoint/heartbeat | 会话使用独立内容事务；heartbeat 不能写业务记录 |

1. 共享请求/结果和消费者接口放在纯契约所有者，类型化表达固定目标、前值、预期版本、幂等键与必要证据。只返回该消费者所需记录或回执，不以整份可写 Domain/Runtime、任意表名/SQL/any payload 替代宽接口。
2. 端口以操作为单位保持事务。若保留事务回调，回调只见该用例需要的窄接口，且不同写集合仍由同一个底层事务承载；不得通过多个小事务拼出原业务操作。请求声明与业务转换由中心生成，存储保证并发前置和关系约束。
3. 将嵌在 native_* 等消费者内的 SQL/扫描移入现有唯一存储实现；事务外资格检查仍留业务用例，事务内权威重检由执行器保留。中心规则不复制到客户端，存储实现不调用平台工具。所有生产写消费者当场切换，不能只将 Store 字段改成同样宽的 interface。
4. 旧 DomainTx/DomainStore 和具体 Store 依赖按实际消费者消除；确属连接所有者的构造/关闭留应用接线，业务消费者不承担具体连接。worker 提交失败仍恢复私有候选，会话失败不推进 mapper 已提交状态或 cursor。
5. 注入现有 SQLite 实现并接通 Service、CommandService、任务与会话路径；中性测试通过端口验证请求/拒绝，事务正确性复用实际 SQLite 代表用例。不得交付第二条持久实现或任意测试写入口。

## 并行与后继

可与 #71/#72 并行，拥有写端口纯类型、中心提交消费者及现有 Store 写实现；不改变产品客户端 DTO/语义。共享 contracts 字段或组装构造变更集中集成，客户端保持应用 Query/Command 接口。#70 只消费本项已接通的窄接口，不能代补遗漏消费者。
