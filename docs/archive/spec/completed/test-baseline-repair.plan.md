# Plan：测试设计审计与基线修复

日期：2026-10-01。状态：已完成设计审计和基线修复，完整回归通过，待 PR 评审。依据：用户要求先审计测试设计，再修复[当前失败基线](../../../validation/tiered-e2e-testing/baseline-2026-10-01/README.md)。本计划补充现有分级测试实现，沿用 PR #180，不创建中心任务。

## 审计结论与修复边界

1. 分级入口、显式 E2E tag、真实 Git/SQLite 与受控外部组件的边界合理；已验证的 L2/L3 无需扩展成完整故障矩阵。默认回归与真实平台验收必须继续分列。
2. 通用 service/config/console 夹具未完整跟随当前 execution/publication 契约。生命周期测试在 publisher/host/provider 组合校验处失败，无法检验进程身份、锁和启动回执；配置负例先因缺少其他必需字段失败，出现错误原因遮蔽。先修共享合法基线，保留原业务断言，并核对负例实际命中目标错误。
3. app-server、停止和恢复测试人工补写 session/process/workspace，却遗漏冻结的 PolicyResources。需要原生 I/O 的用例应从真实隔离 worktree 和资源绑定入口建立当前记录；纯规则/回执单测复用合法当前类型化资源 receipt，明确不是原生权限证据。不能绕过生产权限检查。
4. 当前运行模型区分服务拥有的 domain/runs 与只读 Runtime 投影。部分夹具继续写旧视图，或在提交/刷新后断言已失效的指针。应在正式提交后重新取得权威记录/公开投影，保留幂等、迟到回执及身份不变断言。
5. Decision format version、固定执行快照和 PR repository 等人工记录缺少当前必需字段。修正输入使测试到达真正要验证的业务边界；不恢复旧格式、不新增迁移或兼容读取。
6. 针对某个报错文案片段的断言脆弱；有类型化错误码时优先核对错误码、固定身份和外部调用次数。冻结配置与当前默认配置的语义按现行契约核对，不能沿用已经被新契约替代的拒绝预期。

上述是根据日志和代码的设计审计，尚不宣称所有失败都是夹具问题。每组修复前核对现行消费者和已有 Spec；若合法当前夹具仍复现错误，则修复产品缺陷并增加能保护其业务边界的最小断言。不得删测试、改成默认 skip、扩大超时或削弱身份/持久化检查以取得通过。

## 实施

先修共享配置与生命周期夹具，再修合法资源/当前 Decision/交付记录及投影断言。按失败簇定向运行，记录“原失败 → 根因 → 修复 → 保留断言”的映射。只对确认过时的预期改写语义，不批量替换错误字符串。
