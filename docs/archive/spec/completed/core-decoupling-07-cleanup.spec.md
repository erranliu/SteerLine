# Spec 主包解耦重构后代码清理

任务 ID：68；任务名称：主包解耦重构后代码清理；目标：`CORE-IMPLEMENTATION-DECOUPLING`。配套 [Plan](core-decoupling-07-cleanup.plan.md)。硬前置：#67 [主包隔离守卫与测试归位](core-decoupling-06-boundary.spec.md)整体交付；一个实现 PR。

## 目标与范围

遵守[后续维护共同约束](core-maintenance-constraints.md)。按 #63–#67 交付后的最终调用关系，删除能够证明无人消费的 helper、转发/别名、重复规则、空分支、无用测试辅助和重复 fixture；同步当前模块说明、源码索引及验证入口。实际删除项以开工后的调用清单为准，不预先承诺删除仍有消费者的文件。

#64–#67 的完整消费者迁移、临时 codec 视图删除、生产清零及测试归位仍属于各自任务，不能延期至本项。发现未达标内容先修复原边界，不能以本项清理完成掩盖前置未交付。

## 必须交付

1. 建立候选删除清单，逐项记录原职责、最终所有者、生产/测试/脚本/嵌入资源消费者、所有 OS/构建标签和删除依据。平台命名、缺少直接引用或仅在失败路径出现均不单独作为删除依据。
2. 删除无消费者的桥接层和重复实现；重复规则保留唯一所有者并切换全部实际调用。仍承担稳定公共或协议入口的包装保留并说明用途，不为达到数量目标删接口。
3. 保留当前格式故障对账、未知结果、恢复人工门槛、intent/receipt/ack 屏障及唯一交付。旧格式拒绝样本、原生支持证据和没有认证的新执行拒绝路径不删除。测试去重按断言归属，不能仅凭测试名或 fixture 相似删覆盖。
4. 同步主包/纯契约/实现/组装/集成的简短职责说明、当前架构源码索引及代表测试映射。修正因删除失效的 quick/守卫引用，不引入新的完整矩阵或维护已交付任务活动状态。

## 所有者与边界

仅清理前置交付后的现有模块，不新建执行、存储或客户端引擎。存储写端口留 #69，SQL 搬迁留 #70，客户端适配和 TUI 消费留 #71/#72。后继收到可构建、守卫有效且没有第二实现的基线。
