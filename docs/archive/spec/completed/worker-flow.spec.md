维护说明：本页保留原交付/试验契约与证据定位。当前第一阶段只验本地 Codex/本机 Orca，远端相关历史条目不构成当前一期研发或验收前置；活动任务范围见[一期共同约束](../../../spec/phase1-delivery-constraints.md)。

适用说明（2026-09-30）：停服后的执行输入、原 worker 终止后的新 Attempt 与显式新会话选择，按[停服恢复 Spec](../../../spec/worker-service-recovery.spec.md)执行；本文普通反馈仍使用当前可核实的原会话。

任务 ID：36；任务名称：单 worker 持续执行与统一待决策；目标：`WORKER-FLOW`。配套 [Plan](worker-flow.plan.md)。状态：local Codex 实现候选，PR #121；发布前人工合并链及列明的延期项仍未验收。日期：2026-09-29。

## 1. 目标与职责

SteerLine 围绕同一 worker 会话管理任务的启动、观察、用户反馈和 PR 交付。worker 负责实现任务、提交代码、创建 PR；是否需要测试、修复、审查以及具体方法，由任务绑定的 Spec、Plan 和项目指令约定。中心不确定这些工作阶段，不审查 worker 是否按中心预设的检查清单完成了项目工作。

用户与 worker 的继续交互使用同一待决策入口：可以选择建议选项、输入任意文字，或同时提供选项与补充说明。部分完成、编译错误、执行失败及无法自动恢复的异常都是停下原因，不分别产生一套用户恢复流程。

中心保留原生 Task/DAG、领取事务、执行身份、会话记录、外部动作回执、重启对账以及真实 PR 合并核验。一个任务在本 Spec 范围内仍只有一个权威活动 WorkflowRun/worker 会话；不同任务的人工并行与自动派发资格沿用既有约束。

## 3. 单一主状态

复用中心 WorkflowRun 的权威阶段；Task 的 open/in_progress/discarded/closed 继续管理领取与最终交付。UI 的主状态由中心投影，不新增独立可写的“恢复状态机”。

| 主状态 | 含义 |
| --- | --- |
| `queued` 待执行 | 任务已预留，正在准备或等待首次启动 |
| `executing` 执行中 | 原 worker 正在处理任务或一轮用户反馈 |
| `waiting_decision` 待决策 | 未完成流程停下，需要用户输入；包括 agent 提问和中心观察到的无法自动推进 |
| `waiting_pr_merge` 待合并 | worker 本轮已停下，任务关联 PR 已由平台查询确认存在且尚未合并 |
| `completed` 已完成 | 中心确认真实 PR 合并，并原子写入 TaskDelivery、关闭 Task |

明确丢弃继续使用既有 Task.discarded 终态；不映射成普通决策答案或完成。业务主链不保留 failed、blocked、unknown、completing 等独立可恢复阶段；错误、外部结果不明、正在提交交付事务等事实保存在原事件/操作记录中。

| 已核实事件 | 中心行为 |
| --- | --- |
| 首次 worker 工作轮次开始 | queued → executing，保留固定会话和工作区关联 |
| worker 提出需要回答的问题 | executing → waiting_decision，保留其问题/选项及完整上下文 |
| worker 一轮结束/失败，未发现已关联的有效交付 PR | executing → waiting_decision；无结构化问题时展示最后回复和停下原因，始终可输入文字 |
| 用户反馈已保存，但未证实送达/开始执行 | 保持 waiting_decision，展示送达进度或错误，不新增业务阶段 |
| 原会话已接受反馈且该轮开始 | waiting_decision → executing |
| 本轮结束且关联 PR 已存在、未合并 | → waiting_pr_merge；PR 提前出现时可先记录链接，worker 仍工作则保持 executing |
| PR 关闭未合并，或待合并阶段用户主动反馈要求继续 | 无活动轮次时 → waiting_decision；正在工作的原会话保持 executing 并记录 PR 变化。反馈送达后继续原会话，PR 关联仍保留 |
| 对应 PR 真实合并 | 通过交付事务转 completed，并按现有 DAG 规则释放后继 |
| 首次准备失败、会话无法连接、输出不足以判断等无法自动处理 | → waiting_decision，展示实际原因和能否投递反馈 |

观察超时不是“worker 已停下”的证明。可自动重连时继续对账；无法自动推进时用同一待决策入口展示连接问题。平台仍在运行、未知或已退出的事实不因主状态为待决策而被改写。服务离线/数据库不可用是连接事实，UI 不伪造已持久化的 Decision。

日志中的测试失败或错误文本本身不触发待决策；worker 仍在自行处理时保持执行中。worker 明确提出的未回答问题优先于“已有开放 PR”的等待合并展示；只有问题已处理且本轮停下才转待合并。真实 PR 合并/明确 Task 丢弃是终态事实，其优先级高于待处理反馈，未投递消息保留为未执行记录。

重复或迟到事件不能将较新工作轮次退回待决策，也不能将已完成/丢弃任务恢复为执行中。重新查询到 PR 或补齐事实可自动收敛状态；有新工作轮次或未投递反馈时，不依据旧轮次结果误进入待合并。

## 4. worker 会话与工作区

一个 Execution 绑定任务、工作区、执行端和稳定的 agent 会话身份。“同一个 worker”指同一可继续对话的逻辑会话，不要求 PID 永远不变。适配器恢复进程时必须证明接回原会话；不能用保留 worktree、相同标题或复制摘要的新会话冒充续聊。

正常轮次结束保留会话、worktree 和分支。不因实现完成、测试失败、用户提问或 PR 已建立而自动销毁会话，也不为这些事件创建另一条执行会话。项目内部阶段可作为 worker 进度展示，不能驱动中心按步骤换 worker。

回复默认发送到已绑定的原会话。首次 worker 尚未创建时，中心完成初始启动；已有会话无法恢复时明确显示不可投递并保留反馈，不能自动创建替代 worker。显式替换执行端属于后续单独授权范围，不在本任务新增通用重开命令。

工作区身份、目标仓库和初始 base 仍需在准备时核对。开始后，用户与 worker 决定当前代码、提交和文件内容；用户回答不会触发中心 reset、清理未提交改动、强制返回旧输入 commit 或 cherry-pick。部分提交后继续使用当前原工作区。

本次仅交付 local Codex 执行路径的开始、观察、向原会话发送消息和重接语义。Orca 本机与受监管远端的已有适配代码和平台证据保留，中心功能交付及验收均推迟；这两种目标在本次首次派发前明确拒绝，不能降级为每轮新 worker。后续交付时仍须实测所采用的平台原生接口；既有一次性步骤能力报告不构成持续会话能力证明。

本机 Orca 的实施范围由[本机 Orca 原生编排 Spec](../../../spec/worker-flow-orca-native.spec.md)与[Plan](../../../spec/worker-flow-orca-native.plan.md)固定，平台连续对话、隔离 SQLite 回归和中心真机双轮探针已在该 Spec 记录；公共反馈入口、恢复故障与 PR 交付等验收仍待完成。该补充不改变本文件对 #36 已交付范围的说明，也不解除受监管远端的延期边界。

## 5. 用户反馈与统一待决策

复用 Decision、Command、Operation 和会话正文存储，不增加专用恢复指令族。Decision 是待处理交互记录，可来自 worker 的问题，也可由中心在本轮停下后创建；来源和原因只影响展示。

- 一次明确停下事件只产生一个待处理记录；重启、重复观察和迟到消息按原身份去重。已回答记录保留，新一轮再次停下建立新的记录。
- 选项是 worker 提供或界面给出的快捷反馈；任意文字可以独立提交，也可以附在选项后。不得因为选了选项而丢掉补充文字；中心保存并传递完整用户输入，不解释“继续”为重新派发某个技术步骤。
- 每条提交有固定消息/命令 ID。相同请求重交返回已有记录，不重复发送；新的用户反馈使用新的消息 ID。目标轮次已变化时保留输入草稿并提示当前状态，不把旧答案静默发送给另一执行。
- 中心只记录已保存、平台接受、对应轮次开始等传输事实，不要求 agent 回传 applied_decision_id/answer_sha256 等“业务答案已应用”证明，也不展示未经证实的“已落实”。
- 停下原因和技术证据完整可读，但默认操作仍是同一个反馈输入。现有 retry_run、mark_stopped、resolve_command 等专用恢复入口从新业务流程移除；其必要的原操作对账在传输/适配器内部完成。
- 任意文字是发给 worker 的内容，不能直接改中心 Task 状态、标记 PR 已合并或绕过工作区/接收者身份。
- 宿主登录、权限或原生确认仍由平台对应入口处理。待决策展示入口和原始信息，不把文字反馈当作 UAC 批准或外部操作成功。

同一会话正在工作时追加的信息按平台已有能力投递或排队，并记录真实结果；不能为了投递追加信息新建会话。缺少可判断轮次状态的输出时说明观察能力不足，不通过几秒静默猜测轮次已完成。

## 6. 删除中心项目工作门槛

从新流程移除以下生产入口、配置和状态推进条件：

- `minimal-v1` 固定 implement/verify/review/publish_pr 顺序、每步独立派发和 StepGateResult/StepAttempt 前置结果链。
- 项目 `project_steps` 验证脚本、required_checks、review_required、max_repair_rounds，以及由中心选择修复步骤/轮数。
- 候选 verified_revision/reviewed_revision 链、强制干净工作树门槛及 workspace_dirty_ignore 配置。
- PR 发布/交付依赖中心认可的测试、审查或项目步骤回执；worker 提前发布 PR 被视为越步的规则。

保留 agent/model/sandbox/后端/目标仓库/PR provider 等必要运行配置及任务固定 Spec/Plan。worker 初始指令只要求遵循固定任务契约，实现、提交并创建 PR；不注入统一测试、审查阶段或 `.meta` 忽略提示。中心可收集检查与 Git 状态作为可选诊断，但其成功、失败或文件类型不直接阻止反馈和 PR 状态流转。

`.meta` 与其他文件是否进入 PR 由实际提交决定，中心不自动添加、删除、恢复、忽略 Git 文件或变更候选 commit。有关脏目录过滤的未交付改动不是本任务前置；若届时已合入，应在本任务删除新流程不再使用的门槛和配置，不维持两套业务路径。

## 7. PR 关联与最终交付

worker 的消息、可信结构化输出或用户明确提供的链接可提供 PR 线索。中心通过配置的 provider 查询它是否真实存在，匹配目标仓库、base 分支和当前任务的执行分支/会话关联，再固定 PR 身份。不能只凭正文里任意链接或标题相似认领其他任务的 PR。PR URL 不需要来自专用 publish_pr 步骤。

查询失败保留链接和最后可信事实，显示未核实原因并按既有轮询自动重查；无法自动推进时统一待决策。PR 关联不要求曾有某个中心候选 SHA 的 verify/review 通过记录。worker 后续向同一 PR 推送提交时，中心继续跟踪同一 PR，不维护项目验证失效状态机。

PR 被确认关闭未合并后，可根据原会话后续输出关联新的 PR，保留旧关联历史。多个开放 PR 或归属不明确时由用户在同一待决策入口指定链接，中心仍查询真实身份，不能随机选用或重复计为交付。

完成必须依据 provider 返回的真实 merged 状态、合并时间和 merge commit；普通 closed、worker 成功、收到反馈或用户文字“已完成”都不能替代。复用唯一 TaskDelivery 事务和任务领取/版本核验；重复轮询、服务重启、迟到 worker 消息只结项一次，后继仅在该交付落盘后 Ready。

PR 已合并时即使还保留可用会话，也不把会话存活当作任务未完成。停止新任务反馈投递，保留仍在运行或待清理资源的真实记录，不伪造 worker 已退出。用户明确丢弃仍按既有未合并核验、Task.discarded 和清理规则处理；已交付事实不得被改成丢弃。

## 8. 持久化、恢复与切换

SQLite 继续是唯一业务权威。主阶段只由中心提交；Execution 保存 worker/会话关联，原会话模型保存 turn 与正文，Operation 保存开始/发送等必要外部动作。中间传输进度与失败事实不再复制成多组驱动业务的状态。删除旧步骤状态机的生产接线，不能只在 UI 合并标签而继续后台五步运行。

外部调用前保存固定意图，回执后保存结果；消息持久化后推进游标。发送超时按原请求/消息对账，不改 ID 盲重发。服务重启重接原会话、补读消息和查询已关联 PR；不重复领取任务，不重建工作区，不重复投递用户输入。平台无可靠重试依据时保留同一待决策记录的“投递未核实”事实。

自动派发与不同任务人工并行的既有策略保持；保留会话句柄不等于 worker 当前正在工作，资源占用按已观察的轮次和原操作事实计算。中心停止观察与 worker 停止必须区分；已有远端取消不支持的边界不变。

项目未发布，本任务不要求导入、兼容或自动转换旧 minimal-v1 配置和执行状态。实现固定新的配置/执行协议与持久格式版本；发现不支持的旧状态先拒绝有副作用的启动并保留原文件、绑定与外部现场，不静默覆盖。发布说明必须给出新格式初始化和旧现场人工核实边界。当前格式内的重启恢复必须验收。

本任务不会自动恢复生产项目中已经终止并关闭原 worker 的旧任务。308 项目的 17/18/19 作为下述行为用例的来源，不作为生产数据库改写或旧会话重建的授权。
