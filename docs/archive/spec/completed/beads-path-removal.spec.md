# Spec：移除 Beads 旧执行路径

任务 ID：12；任务名称：移除 Beads 旧执行路径；目标：`REFACTOR`。状态：实现与自动化验收完成；独立实现 [PR #44](https://github.com/erranliu/SteerLine/pull/44) 待合入。配套 [Plan](beads-path-removal.plan.md)。

## L1：目标与前置

硬前置：[#11 测试耗时基线与夹具精简](test-feedback.spec.md) 交付，提供用例耗时和行为映射。产品基础为[原生接入](beads-exit.spec.md)已实现的单一 native 任务权威。

删除当前仍可从内部配置、Service、worker 上下文和测试夹具进入的 Beads 旧业务路径。沿用[原生任务共同约束](../../../spec/native-task-constraints.md)及[执行架构共同约束](../../../spec/execution-architecture.spec.md)，本机 Codex 与已支持 Orca 都保留。使用当前格式的重启恢复、Operation 对账与真实 PR 合并核验继续是交付门槛。

## L2：删除范围与保留边界

- 配置只接受显式 `task_authority=native`；缺省、beads 和未知值在副作用之前拒绝，包括程序构造 Config 后直接调用服务/命令的入口。消除 `taskAuthority()` 默认返回 beads、Service 的双来源分支和 Beads 客户端调用。
- 删除用于旧整段执行的 start/finish、completion 回调及 Beads claim/close/BV 刷新路径。当前 `project_steps`、minimal-v1、原生 worker 固定上下文和 PR 提供方接口保留；不因字段名字相似误删原生流程中的步骤、结果或资源结算。
- 将原生流程仍借用的 `BeadsContext`、旧 Task 包装和命名改为来源明确的原生上下文或已有类型。仅为内部重构需要做最小转换，不增设任务来源插件接口、第二套 DTO 或长期兼容包装。
- 旧配置字段显式报错；旧 Beads 数据、未知 schema 或来源不明的外部执行只读诊断并阻止自动接管/新派发。不导入、不迁移、不静默初始化新数据库替代旧权威，不自动删除工作区或停止身份未知的执行。当前原生格式中已保留身份的 unknown 执行继续允许按现有恢复命令核验和对账，旧状态拒绝不关闭合法恢复入口。
- 此次不整体重建 SQLite schema、Runtime 投影、执行记录或控制协议。先追踪它们在当前恢复中的用途；同名重复字段仅在证明无当前消费者且不承载恢复证据时随旧路径删除。
- 更新当前 README、配置样例、操作文档及执行中的规格描述。历史验收证据保留历史含义；字符串扫描应区分主动调用、拒绝旧格式的诊断和历史记录。

## L3：测试保留与迁移

用 #11 的映射逐项分类：旧来源专属的 claim/close/结项适配测试可删除；固定身份、结果校验、无重复派发、PR 不确定状态、原进程停止核验、工作区保护、决策应用证明、槽保留等当前仍需要的行为，必须先由原生路径测试承接。

将通用 fixture 改为原生最小夹具；只检查纯校验的测试不启动整套服务。关键跨进程、SQLite 并发/崩溃、Git 和平台行为仍用真实现场验证。移除仅服务于 Beads 的 fake 分支和测试数据，不为保住旧测试继续提供生产后门。不得仅按删测试数量验收。

## L4：交接与冲突

[#13](taskgraph-modules.spec.md) 在本任务合入后拆分包，避免搬迁即将删除的代码。[#6 远程闭环](../retired/03-remote-execution-and-viewer.md)只接 native 任务权威；它可独立准备远端协议适配，但与本任务修改 Service、配置、恢复及 worker 上下文时须串行集成，后集成方验证双方契约。该共享冲突不创建新的运行时任务依赖。

#3 的原生验收可在固定版本继续执行；相关路径改动后需复核受影响项，不能借本任务自动化覆盖宣告其真实平台门槛完成。

## 验收

| 编号 | 通过条件 |
| --- | --- |
| LR1 | CLI、配置加载、直接构造服务/命令入口均无法启用 Beads；源码主动执行路径无 bd/bv、旧 claim/close 或 completion 调用 |
| LR2 | 无 Beads 安装的原生 A → B 流程、固定步骤上下文、交付释放及 local/已支持 Orca 自动化回归通过 |
| LR3 | 被移除用例有逐项理由；当前不变量映射到原生测试，故障/并发/身份断言没有随旧 fixture 消失 |
| LR4 | 旧配置、旧数据库、来源不明执行的自动接管被拒绝且现场保持；拒绝测试确认未创建替代权威、未派发、未清理资源，当前原生 unknown 恢复入口仍有效 |
| LR5 | 当前原生格式的重启、答案接受与应用区分、命令结果未知、PR 查询失败/身份漂移和交付幂等回归通过 |
| LR6 | 使用 #11 工具报告基线/最终完整耗时、删除与保留的用例；最终完整测试、静态检查、Windows/Linux 构建和 diff 检查通过 |

涉及真实平台调用语义的改动须使用隔离资源补测受影响原生验收；未改变语义的内部清理使用已有证据和对应回归，不凭测试替身扩大支持范围。
