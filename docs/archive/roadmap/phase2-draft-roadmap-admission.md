## 草稿与正式

主agent可在已授权文档范围内讨论、拆分和修改草稿、Spec/Plan及验收安排。识别的草稿任务可先分配唯一ID，纯目标可无号；编号不入图、不启动worker。固定送审快照后允许继续编辑新草稿，审核/人工集成等待不默认锁死全部规划工作区。旧方案“人先建提案/文件槽才可写、改变任务数量必须放弃重建、等待集成持全局guard”不作为本页目标。

正式任务集合由SteerLine受控创建、丢弃、归档，execution-map依据真实回执/查询同步；文档编辑不是工具操作。正式任务契约不能被草稿暗改；完成归档/未完成受控丢弃保留历史及资源。实际中心状态未知时不凭空表或旧编号派发。

## 人工事项

草稿任务从规划时分类自动/人工验收，链接任务专属acceptance，记录参与人/窗口或待安排、截止节点、阻塞范围。TaskDelivery和人工验收结果分别维护；允许后置者不阻塞无关后续，真实失败按影响进入修复。

必要前置操作记录精确对象/版本、完成条件、核验方式及所阻塞任务/动作。由系统事实或明确允许的人工作证满足，并在执行前由服务重检；不能覆盖已知自动失败、缺权限或未知执行。人工事项不自动成为执行Task/DAG等待节点。具体登记/同步/资格存储与界面在2.2推导，见[代表流程](../../acceptance/archive/superseded/phase2-planning.md)。

## 固定角色与授权

| 所有者 | 职责与边界 |
| --- | --- |
| 人 | 决定目标/范围，授权精确送审/准入内容，办理人工事项并合并PR |
| 主agent | 维护草稿、解释成果/影响；不直接写正式任务、启动worker或调用子agent |
| 审核agent | 服务独立调度，读取固定快照/前置证据，判断质量与可固定程度；不直接改正式集合 |
| SteerLine | 校验精确版本、授权、审核及资格，办理原请求准入和事实同步，保持唯一业务写链路 |

只有两个固定agent角色，不建立agent树或通用编排。必要权限/受控读写/未知轮次验证纳入实际#47接入实现，不能继承worker宽权限或依靠提示词。优先验证已有动态工具通道，具体阻塞再评估替代。

## 审核与准入边界

审核检查Spec/Plan一致、范围/依赖/验收可执行性，以及前置是否仍会改变核心模型、接口、权限或边界。结论为“合格且适合固定”“需要修改”“内容合格但前置未稳定”；后两者留草稿，记录问题或所需证据和复审条件。前置未稳定不视作写作错误，未变内容不循环全量审核。

报告绑定固定快照与前置/正式基线证据；内容或关键条件变化重新核对，不能沿旧结论暗换正文或身份。人可精确授权审核通过后准入，避免重复确认，但服务必须校验授权范围。可固定不等于可执行；契约稳定者可先准入，领取仍等待真实DAG条件。

沿原草稿ID及创建请求办理中心准入，目标执行分支必须包含与固定契约匹配的Spec/Plan。Git/SQLite/文件同步分别核实，未知或部分完成沿原ID/请求对账，不重复占号或创建。具体文档集成/版本算法在成熟Spec确定，不默认要求同内容squash拒绝或确定性index物化链。文件/工具结果核对后才认定准入。

正式加入后的派发仍沿原项目策略，审核agent不改变调度；执行/唯一交付和待人工验收事实返回规划。阶段活动和实际Task状态分别表达，未验不能填全部通过。
