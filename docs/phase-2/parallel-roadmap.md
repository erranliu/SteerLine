# 第二阶段推进边界

第二阶段交付原生 UI 与受控规划，任务范围见[主 roadmap](../roadmap/roadmap.md)，依赖见[执行图](../roadmap/execution-map.md)。每项执行仍以自己的 Spec/Plan 为准，新图登记前不从文档推断 Ready。

## 业务划分

| 范围 | 归属 | 接口边界 |
| --- | --- | --- |
| 持续 worker、统一待决策和真实 PR 交付 | #36 | #45/#50 消费，不新增任务执行状态机 |
| 规划 agent 权限/工具与受控会话 | #43/#47 | 可共用底层会话能力，规划写入 guard 与任务 worker 权限分别管理 |
| WinUI 原生输入与导航 | #44 | 页面共用组件和客户端，不各建服务生命周期 |
| 本机传输与离线查询 | #45 | 在 #36 后即可提供单会话 API；多候选未启用时明确 unsupported |
| 规划草稿、文档发布与任务创建 | #46/#48 | 任务身份、文档版本和人工确认继续由中心核验 |
| 文档/执行/规划对话/审阅页面 | #49/#50/#51/#52 | 各自领域的真实 UI，复用 Query/Command |
| 完整产品链 | #53 | 汇合四个页面及第一阶段 #42，验证交付回到规划 |

## 推进顺序

#43/#44 可独立准备。#36 → #45 后，#46 建立规划草稿权威，#44/#45 可交付 #50 执行界面。#46 后，#48 文档发布与满足权限前置的 #47 会话服务可分别准备。#44/#48 → #49/#52，#44/#47 → #51，最终与 #42 汇入 #53。

多候选及全面中心搬包不再是本机 API 的前置。不同任务可在依赖满足后独立推进，共享 Service/SQLite、UI 导航和真实宿主资源仍串行集成。前置能力尚未交付时不能用样例界面提前宣告完整功能。

## 完整产品路径

人讨论目标 → 同意编写 Spec/Plan 与预留编号 → 受控草稿 → 人审阅固定版本 → 发布文档并集成目标分支 → 中心创建 DAG → worker 实现/提交/PR 与原会话反馈 → 人合并 → 中心 TaskDelivery → 主 agent 据真实结果提出规划更新，由人确认。

这里的文档审阅、固定内容/提交核验及权限约束不属于被 #36 删除的项目代码验证。它们保留在各自规划领域；正式文档、草稿和已创建任务继续区分，目标分支集成与 Git/中心部分失败按原请求恢复。
