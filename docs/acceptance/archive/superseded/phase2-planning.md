# 2.2 Roadmap草稿、artifact与人工事项验收规划

> 2026-10-13 归档说明：本文件仅保留原方案/交付历史，不是当前执行或验收要求。旧编号不复用；当前规划仅 #91，见[execution-map](../../../roadmap/execution-map.md)。

独立节点活动，不占Task ID、不入执行DAG，不代替未来各任务专属acceptance。状态：仅规划，待验收；流程/模型/原型迭代，工程任务及精确命令待定。本页记录验收行为和代表流程，不冻结通用事项模型。

## 两个代表人工流程

**交付后验收**：规划时登记任务专属人工项/产物版本/步骤/参与窗口或待安排/截止节点与影响范围 → 任务真实交付并保留待验 → 人打开关联artifact、执行步骤 → 记录通过或失败及证据 → 同步验收汇总。允许后置项不阻塞无关任务，失败按实际影响进入修复；不得改写历史TaskDelivery或以PR合并代替验收通过。产物变更重新判断旧证据范围。

**开工前必要操作**：规划时说明对象/版本、完成条件、核验方式和所阻塞任务/动作 → 用户从指定入口办理 → 系统核实事实，或校验明确允许的精确人工作证 → 服务权威更新对应条件 → 领取/副作用前重新核验。未办/过期/目标变化不放行；已知自动失败、缺权限、未知执行不可用人工作证覆盖。操作本身不是工程Task，不新增等待节点或伪Delivery。

已有环境阻断在2.1复用；本节点设计自定义定义、办理、证据和历史。文档/execution-map汇总与中心业务资格分别核对；未来状态/同步所有者须由正式Spec明确，不让UI直接写库或复制业务权威。

## 最小验收方向

| 验收项 | 方法 | 行为与通过条件 | 状态 / 安排 |
| --- | --- | --- | --- |
| P22-A1 草稿/正式与artifact | 自动 | 没有主agent时真实读写/版本校验可用，artifact准确绑定任务/交付/文档版本；草稿不进入正式DAG | 待验；环境/命令待定 |
| P22-A2 后验收关联 | 自动 | 未验/通过/失败证据范围准确，产物变化不盲沿用旧通过；汇总不伪造Delivery | 待验；机制/命令待定 |
| P22-A3 前置资格 | 自动 | 未办/过期/错对象/迟到证据不能启动，服务执行前校验；合法完成只解除对应条件，不能覆盖未知或真实失败 | 待验；门槛所有者/命令待定 |
| P22-M1 人工后验收办理 | 人工 | 从草稿/任务/产物定位待验项，查看步骤、登记结果/证据并看到影响范围 | 待验；参与人/窗口待安排 |
| P22-M2 必要前置办理 | 人工 | 明确要做什么、为何阻塞、如何核验，办理后显示真实资格；“确认”不误导为普遍放行 | 待验；参与人/窗口待安排 |
| P22-M3 无agent闭环与签收 | 人工 | 仅人工即可维护草稿、读取关联产物并完成上述两流程；界面原型确认后按实际实现签收 | 待验；参与人/窗口待安排 |

先在原型中推导一个后验收和一个前置操作，确定最小字段/来源/版本/失败行为，再拆独立工程任务并建立各自专属验收；不预建审批链、提醒器或通用待办平台。未定步骤、环境和窗口在正式实施前补齐。节点活动不默认阻塞2.3研发，仅真实依赖的工具/资格语义是前置。原始证据临时保存，本页目前无新结果。
