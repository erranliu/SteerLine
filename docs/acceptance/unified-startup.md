## 环境与执行记录要求

1. 开始前记录实际源码 commit/dirty、Go/Node/Edge 版本、命令和起止时间；沿用 Plan 的源码调查版本不代表已经验证当前源码。
2. 实际产品调试只能先运行唯一生成器，在 `C:\SteerlineDebug` 生成全新双项目包，包级 `--simulate` 显式冻结；两个独立 SteerlineTest clone/provider，manifest 固定双 exe/hash/端口。禁止使用安装目录或复制其数据库、认证、配置。
3. `evidence/` 保存宿主/项目实例、精确 OS PID/创建时间/路径、原请求/执行/会话/turn、CLI 状态与日志、Edge screenshot/trace。当前未生成验收包，路径在实际执行时登记，不能预填不存在的现场。
4. `cleanup.json` 分别记录 Web/后端退出、每项目运行时关闭/资源结算/锁释放、本包监听和 owned 进程；外部 continue_execution 资源按实际策略另列。清理失败仍为失败，不因业务断言通过而省略。
5. 默认浏览器打开由协调器定向测试覆盖：实际 start 默认分支调用系统 opener 的记录器一次，验证当前 home 的一次性授权 URL 与失败传播；--no-open 场景不能单独证明该项。Edge 综合验证同一授权 URL 机制及真实页面，系统默认浏览器关联的实际弹出和故障窗口暂停由 UST-M1 检查，自动项不宣称已完成该人工体验。
