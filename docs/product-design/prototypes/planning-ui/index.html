长期文档结构约定
SteerLine 流程文件与项目长期资料分开管理
SteerLine 流程
文件名由 SteerLine 约定，工作流程在对应步骤读取为上下文输入。目前包含以下两份文档。
项目文档
按项目实际目录结构展示长期资料，目录和文件名均由项目维护。以下架构、并行设计及主题设计只用于演示，不是必备文档清单。
目录树根据文档在项目中的相对路径生成，可展开、收起和查看正文；项目可以使用任意目录层级和文档名称。原型展示内嵌示例，不扫描真实仓库。
更新时机
  1. 项目接入：识别流程规范及项目既有资料，调查代码后按需补齐项目文档，没有依据的部分标记待补充。
  2. 正式 Spec / Plan 生成前：按约定读取生成规范和测试规范，结合本次工作参考相关项目文档并检查覆盖范围；拟议设计不写成现有架构事实。
  3. 代码 PR 合入主分支：只更新受影响文档，多次相关变化可合并维护。
  4. 长期测试入口 / 运行能力变化：有明确规划依据后维护入口说明，候选阶段先保留待合入内容。
  5. 纯文档维护 PR：核实合入后记录覆盖版本，不再次触发自身更新。
事实文档反映实际代码；规范规则变化需要明确规划依据。生成更新不等于已同步，待合入或失败保留原正文，不回退代码交付事实。
