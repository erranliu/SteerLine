# 规划界面原型

`index.html` 是可直接用浏览器打开的单文件交互原型，无构建步骤或外部脚本依赖，长页直接滚动。用于讨论页面结构、文案和状态流转；页面内的任务、回执、文档校验结果都是演示数据，按钮不连接 SteerLine 服务或 Codex。

原型用于讨论交互，不代表已经交付的能力。2026-10-21 测试管理页已按用户确认改为只读测试记录；其契约见[测试记录 Spec](../../../spec/test-records.spec.md)、[Plan](../../../plans/test-records.plan.md)与[专属验收](../../../acceptance/test-records.md)。其他分页保留早期规划演示，以各自当前 Spec 为准；[归档界面设计](../../../archive/design/planning-ui.md)仅供历史参考。

## 本轮交互

- 规划 session 的列表、新建和历史切换只在规划工作台内部。各 session 保留独立消息和输入草稿；一级页面切换保留当前 session。
- 工作台明确关联当前草稿 Markdown / JSON。新 session 可以关联已有草稿或创建新草稿；演示 Agent 可更新正文及创建占号任务。请求正式 Spec / Plan 生成或转正只返回草稿页办理指引，对话只维护 Roadmap 草稿，不写正式文档、PR 或 Task。
- “Roadmap 草稿”按多个目录展示多份文档，并可查看成对 JSON。JSON 保存稳定 draft_id、任务编号、名称、可空 Spec 和拟议依赖；草稿任务不入 DAG，正式任务的状态从演示中心读取，不回写 JSON。
- 设置增加当前项目主分支，默认 main。转正固定草稿 / JSON / Spec 引用与目标主分支快照；后续编辑或改主分支不改变已经固定的操作。
- 转正仅从草稿页启动：固定草稿、代码与规范版本后，通过明确按钮读取规范、调查现有代码并整体规划、生成正式 Spec + Plan，再复核测试 / 依赖并拓扑排序。缺 Spec 的草稿可以生成；规范缺失 / 读取失败、关键需求矛盾、未正式入图的外部依赖或依赖环阻止继续。审阅生成正文与 execution-map 差异，经确认后模拟提文档 PR、合并并创建正式 DAG。
- 支持演示“文档已合并、部分任务已入图”中断。继续原转正流程沿用原快照、PR 和任务编号；既有任务不重复创建，尚未入图的任务仍显示草稿身份。
- DAG 提供图 / execution-map 双视图，执行清单关联多份来源草稿。Task 真实演示交付后单独刷新清单同步状态，保留同步中 / 失败 / 重试；全部关联任务交付并同步后才允许将 Markdown 与 JSON 成对归档。
- 一级导航底部“设置 → 执行”独立管理全局默认候选参数，依次选择执行路径、机器、Agent、模型和推理强度，再显式保存。此处不展示任务派发或并行数量，也不选择预先成组的方案。
- 本机 Codex 路径固定为本机与 Codex；Orca 路径先选择本机或远端电脑 A，再按该机器返回的能力选择 Agent、模型和推理强度。可选项来源标为 Orca 返回或本机预检测配置，均为演示能力；切换上级清空受影响的下级选择，未完整选择不能保存或启动。远端机器/演示型号不证明真实接入支持。
- 当前项目自动派发开关放在 DAG 页头。未执行任务可从 DAG “手动启动”首次创建一个候选，预填已保存的全局默认参数，本次调整不改全局默认。
- 自动派发为尚无候选的就绪任务启动一个默认候选，不补位，不使用手动并行数量。关闭不停止运行中的候选。
- 只有“执行与待处理”中已执行且未合并的任务提供“新增并行候选”入口。任务面板仅展示本次新增数量，每个候选分别按路径、机器、Agent、模型和推理强度依次选择；不同候选的未提交选择保持独立。完全相同的参数组合按现有候选约束拒绝。DAG 对已有执行只提供查看执行入口，未执行/已合并任务不展示新增按钮。已有候选保留冻结参数，受阻/已交付任务禁用启动。
- 执行页按任务汇总，候选卡片切换独立输出、问题与回答草稿。输出每 1.5 秒模拟追加，支持跟随、暂停、滚动阅读、新输出提示及断线/重连。
- 实时输出工具栏按原执行路径提供“在 Codex / Orca 中查看对话”。本机 Codex 定位原 thread / 工作区，Orca 路径定位原机器 / terminal；即使 Orca 使用 Codex Agent，也通过 Orca 打开。点击显示绑定当前 Task / 候选 / Execution / Attempt / Turn 的演示目标，不启动真实工具。离线或缺失绑定时禁用，每个候选的定位回执独立保留。
- 候选可以演示本轮完成、中心核实 PR 合并、不可撤销放弃及停止待核实。交付后其他候选保留实际演示状态，后继依赖按交付释放。
- 一级“验收管理”按 Task / 固定 Plan 分组，显示自动 / 人工、前置 / 后置、阻塞性质和精确影响范围，支持通过 / 失败 / 待人工 / 环境与时点 / 正在阻塞筛选、查看 Plan 计划与任务专属结果记录。Plan 未关联时不推断为全部通过。
- 人工登记要求参与人、实际操作说明和证据；失败及后续通过分别保留。自动项缺环境不能改为人工，定向自动检查由演示入口产生结果；通过计数匹配固定 Plan 版本、候选 / turn / 交付构建，旧目标结果只留历史。观察断线时保留原自动操作，重连查询原结果，不另发检查。
- 前置项目验收暂停后续派发，现有执行继续；任务前置验收仅阻塞对应启动。手动 / 自动派发均检查门槛。DAG 仅显示正在生效的阻塞与办理链接；未到时点、非阻塞待验项不进入 DAG 阻塞提示。
- 项目交付检查独立于任务代码合并事实。后置项目交付门槛在检查交付时生效，不回退 TaskDelivery；非阻塞后置项继续待验，草稿归档后仍在验收管理中保留。
- 验收管理提供“验收项 / 调试环境”视图，页头始终可以创建调试环境，任务派发门槛不阻止此独立准备操作。项目设置维护公共调试根目录，默认 `C:\SteerLineDebug\DemoProject`；环境以 `dev-短SHA-YYYYMMDD-HHmmss` 命名，同秒同提交重复创建追加序号，每个环境独立目录、数据库、配置与端口。
- 创建来源是当前项目主分支，或未合并任务的指定候选提交。没有可用提交的候选不能创建。确认时固定完整 SHA、来源、根目录与准备身份；后续推送、合并及配置变化不改写已有环境，目录存在也不直接标为可验。准备失败继续原环境，不重新分配目录或端口。
- 环境就绪后，演示固定 Agent 为待人工项生成逐项指南，绑定固定 Plan、环境 SHA 与当前验收目标。指南包含启动、操作、预期 / 通过条件和证据要求，生成中 / 失败 / 可用分别显示。版本不适用和未到时点的人工项仍列出等待原因，指南生成不代表验收通过。
- 人工结果必须选择可用且版本适用的环境及匹配指南，自动带入环境 ID、目录、完整 SHA、来源、Plan 与指南版本和指南快照。不同环境的未提交人工说明分别保留。未合并候选结果不自动算作合并后的目标通过，要求主分支版本的项不能在候选环境登记；旧主分支环境也不自动包含后来合并的任务。
- 一级“测试管理”按测试集组织，默认展示运行记录，另有只读测试定义页签；支持名称 / ID 搜索、L1–L4 筛选，以及原始结果、复验情况、分支 / SHA、环境和日期筛选。目录不按 Task / Plan 分组。
- 记录由测试脚本产生和登记；人工命令行与 Agent 执行使用同一记录模型，可以没有任务 / 候选绑定。页面没有执行、重跑、结果修改、入口登记或环境创建按钮。
- 每次运行分别保留实际范围、原始结果、代码 SHA、工作区是否有修改、定义、环境、开始 / 结束时间和证据引用；有原候选来源时可跳转。脏工作区的历史通过不冒充固定 SHA 通过。
- “复验通过”依赖脚本显式关联前次失败。失败→再次失败→通过保留完整链；单次部分覆盖显示“部分复验通过”，跨记录 / 跨 SHA 的子集通过不能拼成完整通过；较新的失败优先，定义变化提示另行核对，无关联的后来通过不解除旧失败。筛选隐藏链中记录不改变完整链的判断。
- 汇总展示代码 / 环境 / 日期范围内的执行次数、最近原始结果、最近通过时间和失败待完整复验数；结果 / 复验筛选影响列表命中数，汇总口径明示，不混成当前项目全部通过。
- 分级解释采用当前[测试架构规范](../../../../SteerlineProjectGuideDoc/testing-architecture.md)：L1 包括快速单元和小范围集成；L4 并非全部串行。测试集 ID、命令、摘要与内容均为演示，不映射为真实入口。
- 草稿转正、执行页中的固定 L1、旧 PR 测试门槛和 Bug 自动测试仍是早期演示，本次未重构这些流程；“查看脚本测试记录”只导航，不再从测试管理运行测试。正式产品不因此新增测试通过 / PR / Delivery 门禁。


实时增量文字与工具正文是新增产品方向，当前服务仍只提供近期活动摘要、必要状态与完整最终回复。本原型不证明实时输出接口已实现；断线期间不生成或补画模拟输出。保存的设置与草稿仅在当前页面实例内有效，刷新后恢复演示数据。

JSON、文档与转正快照均为页面内演示数据。创建草稿任务不调用真实编号计数器，不写入实际 roadmap、Spec、execution-map 或数据库；PR 与合并不调用外部平台。正式生成、规范读取、代码调查及文档核对均为演示，不调用 Agent、不读写真实 Spec / Plan。内嵌规范来自仓库 SpecGuide.md，页面维护仅更新演示版本。归档模拟改变 Markdown / JSON 路径，不移动仓库文件。

## 版本蓝图演示

1. 版本蓝图是 AI 维护的文档。打开一级“版本蓝图”，切换示例文档并只读查看目标、能力范围、非目标、完成标准和未决问题。项目界面没有蓝图新建、编辑、保存和确认功能。
2. 页头“项目愿景”展示 `docs/roadmap/product-vision.md` 的内嵌快照；关闭或按 Esc 返回原蓝图，断线仍可阅读。
3. 当前不做 Roadmap / Task / PR 关联，不显示任务进度。蓝图路径明确标为示例，原型不读取 / 写入真实蓝图文件或调用 AI 维护文档。

## 长期文档演示

1. 打开“长期文档”，分为“SteerLine 流程”和“项目文档”。流程文档的文件名由 SteerLine 约定，工作过程中调用为上下文输入；目前包含 `docs/spec/SpecGuide.md`（Spec / Plan 生成规范）和 `docs/testing.md`（测试规范），分别用于正式生成与测试规划 / 执行。项目文档按项目实际目录结构展示，不固定文档名称或目录；当前架构、并行设计及主题设计仅为示例。目录树从文档相对路径生成，支持展开 / 收起和查看正文；原型使用内嵌示例，不扫描真实仓库。流程规范及部分项目正文来自本地快照，主题设计与覆盖状态为示例。
2. 查看结构约定，分别阅读流程规范的约定路径、必要内容与调用时机，以及项目文档的示例目录树和自由组织方式，并查看接入 / 正式生成前 / 代码合入 / 长期入口变化的触发说明。流程文档的查看与维护入口统一在长期文档页，选择生成规范或测试规范后可查看最新版本并维护演示内容；项目文档只读。设置中不再放置生成规范。
3. 切换正文与待合入预览，分别查看已同步、待更新、更新中、文档 PR 待合入和更新失败。失败 / 待合入保留正文及原覆盖，不伪造已同步。
4. 从执行页核实 #8 的 PR 已合并，架构 / 并行文档随演示代码事件进入维护，再形成文档 PR；Bug 代码合入同样触发相关资料。纯文档转正 PR 不触发架构事实维护。
5. 长期测试入口候选登记后，测试规范保留候选预览并等待合入；本任务代码合入后再整理主分支说明。两份流程规范的维护均在长期文档页进行，保存后显示待合入内容，原正文快照及既有生成输入保留。
6. 转正生成前按约定读取生成规范与测试规范，本次参考的项目文档快照另行标明并记入输入；文档维护不会生成执行任务。所有 AI / 覆盖 / PR 操作为页面演示，无真实维护和 Git 写入。

## 正式 Spec / Plan 生成演示

1. 在规划工作台发送“直接生成正式 Spec + Plan”，只返回草稿转正入口，正文 / JSON / DAG 不会因此成为正式文档或任务。普通细节约束仍可以写入 Roadmap 草稿。
2. 草稿页启动转正后，输入已固定但未生成。生成页只提供跳转长期文档的入口；查看本次生成规范快照、最新规范及维护均在长期文档页进行，可返回原转正流程；点击“生成 Spec + Plan”才依次执行必读规范、代码调查和整体规划、正式文档生成及核对。
3. 可演示规范读取失败，重试同一快照；SteerLine 约定的规范路径在长期文档页展示，规范缺失或读取失败不能生成。可演示关键需求矛盾，补充草稿后明确重新生成。
4. 在长期文档页选择流程规范并维护页面演示内容；当前生成结果仍用原版本，可分别查看新旧规范。显式按当前草稿 / 新规范重新生成才改变输入；已有文档 PR 不允许重新生成。
5. 切换任务 / Spec / Plan 查看正文、设计依据和测试安排。受控修改正文后保存并重新核对；审阅确认后正式文档随文档 PR 发布，合并才创建正式 DAG。入图中断继续原步骤。
6. 实际可维护规范在 [`docs/spec/SpecGuide.md`](../../../spec/SpecGuide.md)，页面规范编辑不写回仓库；全流程仍是单文件原型模拟。

## Bug 管理演示

1. 打开“Bug 管理”，同步演示 Issue；外部状态、修复阶段、PR 事实分别保留。Issue #401 手动启动后经过清晰度 / 系统性 / 范围审计、修复、验证方式判断与长期测试，自动提交已验证 PR，到“已验证 · PR 待合并”，可以模拟核实合并，体验版本 PR 记录随之同步。
2. #402 描述不清交给人工补充；补充步骤 / 实际 / 预期后显式重新审计，原记录保留。#403 需要大规模模型变更停在人工方法决策，补充文字不直接绕过审计。#406 在实施中发现范围扩大，保留部分成果交接。
3. #404 的原生输入体验需要人工验证，保留草稿 PR 与固定提交的独立环境 / Agent 指南；填写参与人、证据、实际步骤与结果。失败仍待人工，通过后取得同一提交的 L1，再自动更新为已验证 PR。
4. #405 自动测试持续失败，最多 2 轮后交给人工；旧轮次提交与失败证据保留。#409 使用长期 L3-WORKSPACE 常规环境隔离与清理场景（模拟），独立环境绑定本轮 SHA。结果在测试管理运行记录中可见。
5. 按标签开启自动修复，任务与 Bug 共用并行额度，多个 Issue 独立排队 / 执行，同一 Issue 不重复派发。关闭后已启动流程继续，未启动自动队列暂停。关闭 Issue 和 enhancement 默认不自动纳入。
6. 演示 Issue 正文更新，观察原依据保留与重新审计要求；断线时保留原修复步骤，重连继续原记录，不把未知结果当作通过。原生入口按冻结路径打开 Codex 或 Orca 的原会话目标（演示）。所有操作不访问外部 Issue，不创建真实工作区或 DAG。

## 体验版本演示

1. 打开“体验版本”，初始有 #001（目录已删除）与 #002（可体验），版本记录和 Agent 介绍均保留。选择 #001 可按原编号 / SHA / 路径重建。
2. “PR 记录”默认看主分支已合入内容；切换所有 PR 可看未合并、关闭和其他分支记录。PR #102 比 #104 更晚合入，可在 #002 后创建；早期或相同节点不可创建。创建资格按提交关系而非 PR 编号判断。
3. 创建 #003 时选择 #102 或 #119，预览固定来源、上一版基线、新增 PR 和目录。可分别模拟目录准备失败与介绍生成失败，各自重试；失败不回收编号，介绍失败不影响已准备版本启动。
4. 启动体验后先停止，才能确认删除本地目录；也可演示外部删除检测。删除后版本记录 / PR 清单 / 介绍仍存在，从 Git 重建沿用原编号 / 提交 / 路径并准备新运行数据，不恢复原数据。
5. 重新生成介绍保留历史，重建目录不改变介绍。设置中更改体验根目录只影响新版本。新版本必须比最后一条版本记录更新，即使该版目录已删除或准备失败也不回退基线。
6. 任务提交 / 更新 PR 与草稿转正文档 PR 均同步体验页记录，核实合并后更新主分支落点，可从新的主分支落点创建后续体验版。本轮操作均为页面内模拟，无真实目录或 Git / PR 写入。

## 演示路线

## 调试环境演示

1. 保存项目调试根目录，从主分支创建一个或多个环境，核对目录、固定 SHA、准备进度以及独立端口 / 数据目录；可演示准备中断后继续原环境。

3. 环境就绪后查看各人工项指南。T8-M1 允许候选验收，T7-M2 要求主分支环境；条件不符仍列出原因并禁用登记。指南生成失败可重新生成。
4. 从指南进入结果登记，核对所选环境及版本，填写实际操作、参与人和证据。切换环境保留各自说明草稿，结果保留验收时的指南快照。
5. 核实 C3 合并后，原候选结果成为历史，需匹配新目标再验；此前创建的主分支环境保持旧版本，可从更新后的主分支另建环境。

## 如何迭代

- 小幅视觉和状态调整直接修改 `index.html`，保持无构建步骤，方便审阅 Git diff。
- 新页面或流程应先更新当前 Spec/验收；本原型及[归档界面设计](../../../archive/design/planning-ui.md)不作为当前产品契约。
- 当需要可复用前端组件、独立设计系统或真实 API 联调时，再把原型升级为有构建配置的 UI 工程；届时仍由 Go 服务提供业务权威接口。
- 后续界面需要时重新规划独立 WebUI，沿公开 HTTP 接入 Go 服务，实时更新按需设计 SSE。本轮只完成 TUI 接入，不重建 WinUI 控件或把演示作为实现前置。
