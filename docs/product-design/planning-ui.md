# 规划与原生界面交互设计

状态：产品交互说明；选定范围已分别形成[独立 Spec/Plan](../spec/README.md)。技术边界见[技术架构方案](planning-architecture.md)，产品交付目标见[第二阶段愿景](../roadmap/product-vision.md)。

页面视觉与演示交互见[可交互原型](prototypes/planning-ui/index.html)，原型说明与迭代约定见[prototype README](prototypes/planning-ui/README.md)。原型只表现页面状态，不连接真实服务或 Codex。

## 草稿与审核的新交互边界

后续按[草稿审核目标](../roadmap/phase2-draft-roadmap-admission.md)增加固定版本送审和三个结论：可固定、需修改、等待前置。等待不是内容错误，页面显示影响前置/未稳定点和复审触发条件。正式任务集合、草稿和外部资源状态分别展示；主agent与审核agent不能从对话直接修改正式任务。下文是原基础交互，发布/确认页面在实施前同步新准入Spec，当前原型不宣称已支持审核。

## 核心体验

SteerLine 打开后首先是**规划工作台**：对话和输入占主要空间，用户与一个 Codex 主 agent 讨论目标、修改 roadmap、形成 Spec/Plan。左侧帮助定位项目、session 和主要视图；右侧按当前上下文展示文档差异、校验结果和相关约束。Roadmap 与任务 DAG 有独立的宽视图；执行页面接管第一阶段 viewer 的全部日常观察和操作。

每个项目有一个固定规划 worktree。用户随时可以建立**新 session**：新 Codex thread 不携带旧 session 的消息或摘要，仍看到该 worktree 当前的文件和草稿状态。旧 session 可继续浏览或恢复；同一 worktree 不允许两个 session 同时写入。新建 session 按钮旁明确显示“保留文档状态，开始空白对话”，避免误以为会重置文件。

```text
┌ 项目 / 固定规划 worktree / 服务状态 / 文档校验 / 待处理数 ────────────────────┐
│ 导航与 sessions       │ 规划对话与输入（主区域）          │ 上下文面板       │
│ 规划工作台            │ 需求讨论、工具过程、最终回复       │ 文档变更 / 差异   │
│ Roadmap              │                               │ 校验问题与跳转   │
│ 任务 DAG             │                               │ 相关约束与证据   │
│ 执行与待处理          │ 多行输入、引用文件、新 session      │                 │
└─────────────────────────────────────────────────────────────────────────┘
```

右侧面板可关闭；窗口变窄时变成可唤出的抽屉，不能挤掉输入框或隐藏待决策提示。顶部只显示当前项目与确有行动意义的状态，具体执行身份和诊断放在详情页。

## 导航与页面

| 入口 | 主要内容 | 关键动作 |
| --- | --- | --- |
| 规划工作台 | session 列表、对话、输入、当前文档草稿与校验 | 新 session、发送/中断/追加输入、打开文档差异、进入确认流程 |
| Roadmap | 目标及其版本、规划文档、关联 Spec/Plan、未确认草稿 | 按目标定位文档、查看前后差异、跳至约束和关联任务 |
| 任务 DAG | 任务列表、选中任务的上下游图、阻塞原因、规格和交付关系 | 筛选、定位任务、跳转执行/PR/Spec；不直接编辑已创建依赖 |
| 执行与待处理 | Ready、运行中、待决策、待合并、需处理、历史；选中运行的会话和证据 | 开始任务、处理决策、派发控制、查看 PR 与合并核验 |

“待处理”在全局导航与项目标题显示计数，并能从任意页面打开对应决策或未知结果。证据通过目标、任务和运行的深链接进入，不建立一套与业务状态竞争的独立时间线。

## 规划工作台

对话区区分用户输入、主 agent 的过程消息、工具活动和完整最终回复。长工具输出默认折叠；错误、权限等待和正在等待人的问题保持可见。用户读历史时不被新输出强制拉到底部，显式“跳到最新”恢复跟随。消息中的 `docs/` 路径、任务 ID 和约束引用可点击，打开右侧预览或对应页面。

输入区使用原生多行编辑，支持中文输入法、选择与撤销、粘贴、草稿自动保存、仓库文件引用和清晰的发送键提示。当前运行时可按已验证的 Codex 能力追加要求或中断。已发送输入的“编辑并重跑”遵守[产品愿景](../roadmap/product-vision.md)的对照门槛；在会话及文件行为未与 Codex App 实测一致前不显示该动作。

新 session 直接在同一 worktree 上开始，不自动清理草稿、恢复旧 Codex 上下文或创建新 worktree。顶部持续标明规划 worktree 的文档变更和校验状态。切换 session 只改变对话焦点，不能把上一 session 的未完成工具调用或草稿文字带进新输入框。

### 新 session 的起点

点击“新 session”先显示轻量确认层，列出固定 worktree、现有草稿及校验状态，并明确“继承目录状态；不继承旧对话、摘要和未发送输入”。用户可从这里打开草稿差异，再决定开始空白对话。新会话的第一轮可主动引用这些文件，但 UI 不暗中注入上一会话内容。若旧 session 正在写同一 worktree，新 session 仍可建立和阅读；输入区说明写入需等待旧轮次结束或中断，不能让两个轮次同时修改草稿。草稿输入按 session 分开保存。

输入法正在组词时，Enter 先完成组词，不发送消息；发送/换行的快捷键须在 UI 中可见并可用键盘设置调整。运行中追加要求、排队下一轮和停止当前轮次使用不同的标签及反馈，不能把“已排队”显示成 agent 已读到。

## 文档草稿与正式发布

UI 与服务查询展示的正式 `docs/roadmap/` 和 `docs/spec/` 内容始终来自一套完整、已校验的 Git 文档版本。发布期间的原始 worktree 不承诺外部无锁读取的多文件原子性；服务禁止新 agent 轮次读到逐文件更新中的目录。主 agent 对全仓只读，通过受控文档写入口将候选 Markdown 保存到同一固定 worktree 的 `docs/.steerline-drafts/`；服务预先登记每份草稿对应的正式目标路径，拒绝任意文件名、脚本、测试、二进制和目录外目标。草稿保留在 worktree 中，供新 session 继续修改，但不参与任务执行或 DAG 查询。

界面把文档流程表达为四个明确阶段：

1. **讨论与拆分**：主 agent 可以建议目标、任务边界和依赖；仅讨论不占任务 ID。
2. **同意编写规格**：用户确认拟规划的任务范围，SteerLine 预留正式任务 ID 并建立目标路径明确的草稿槽。ID 不因放弃而复用。
3. **校验与审阅**：主 agent 写候选 roadmap、Spec 和 Plan；UI 展示完整文件差异、任务关系预览、结构检查和必须由人判断的产品取舍。校验失败时给出源文件/规则跳转，不能显示为“待创建”。
4. **确认创建**：用户确认固定版本的完整文档集；SteerLine 发布正式文档并提交规划分支。若规格尚未进入执行目标分支，UI 显示规划 commit、目标分支与等待原因，说明必须保留原规划提交祖先、不能用同内容 squash/cherry-pick 代替。服务核验祖先和文件内容后创建同一批 DAG。创建意图尚未登记时可受控结束等待并转 needs_review，保留文档与占号；超时或部分完成沿原 ID/请求核实。

审阅页须并排区分**机器校验**和**人工判断**。机器校验逐文件给出目标路径、版本、具体规则和可跳转的错误位置；绿色通过仅代表结构与一致性满足自动规则。人的审阅仍要确认任务拆分、依赖、验收条件和影响范围。确认按钮绑定审阅过的草稿版本与正式基线版本；任一文件由外部编辑器或别的 session 改变后，原校验和确认立即失效，UI 显示冲突差异并要求重新审阅。

| 状态 | 页面应显示 | 可执行操作 |
| --- | --- | --- |
| 讨论中 | 目标与任务建议，尚无正式 ID | 继续讨论；同意编写规格 |
| 已预留 ID / 编写中 | 固定 ID、草稿路径、写入 session；提示弃用后 ID 不复用 | 继续草稿；放弃草稿 |
| 校验失败 | 按文件定位的错误、所依赖规则、与正式版差异 | 返回对话修正；不能确认创建 |
| 待人工审阅 | 自动检查通过、完整差异、DAG 影响和语义取舍 | 确认固定版本；返回修改 |
| 发布中 / 等待规格集成 / 结果待核实 | 原请求 ID、规划提交、目标分支、最后证据、正式文档和中心 DAG 的各自状态 | 等待保留祖先的规格集成或按原请求对账；仅 can_cancel 时可结束等待，未知创建结果不能取消 |
| needs_review | 原 publication 的确定拒绝/取消、已生效文档与保留数字 | 重新修改/校验/确认新版本，或按资格放弃；旧发布历史不撤回 |
| 已创建 / 已放弃 | 文档提交、任务身份与回执，或保留的已弃用 ID | 查看 DAG/证据；新需求另起草稿 |

放弃草稿不删除已经预留的任务 ID 记录，也不修改已创建任务。正式文档发布途中若服务中断，审阅页保留待核实状态和原请求身份；恢复前不能展示“创建成功”。

只修改产品方向而不创建任务时仍走草稿、差异、校验和人工确认，但没有 ID 预留或 DAG 创建。`docs/roadmap/` 的活动任务必须遵守[roadmap 文档规则](../roadmap/readme.md)；`docs/spec/` 的执行文档必须是任务独立 Spec + Plan。现有 `roadmap_task_id.py check`、链接和身份校验属于自动门槛，依赖是否合理、验收是否可执行仍需要用户审阅。嗅探器、测试和实现需求在此阶段只能形成待执行任务的 Spec/Plan，由 SteerLine worker 执行。

## Roadmap、DAG 与约束查看

Roadmap 页以目标和文档为主线，保留原 Markdown 的可读全文，也提供目标摘要、关联 Spec/Plan、版本和未确认差异。点击目标可以在右侧打开相关约束：项目 `AGENTS.md`、[roadmap 规则](../roadmap/readme.md)、[Spec 索引与规则](../spec/README.md)、架构及控制台约束。约束面板引用原文件与位置，不能维护一份会过期的复制文本。

DAG 页默认同时给出可搜索的任务列表和所选任务一层上下游；需要时扩展深度。节点标注状态、阻塞原因和交付证据；被丢弃的前置及其后继阻塞仍可查看。大型图按现有产品查询接口分页或标明截断，接口归属见[代码架构](../architecture/current-code-architecture.md)，不把不完整图显示成全图，也不提供直接拖边修改依赖。任务详情通往 Spec、Plan、运行、决策、PR 和合并核验。

拟规划任务可以在文档审阅页预览依赖变化，但只有中心已创建任务进入正式 DAG 图。Roadmap 和 DAG 均标明各自的文档版本或中心快照版本；不能用虚线草稿节点混入正式任务而不说明来源。

## 替代第一阶段 viewer

“执行与待处理”页复用第一阶段的统一 Query/Command 和会话模型。列表按 Ready、运行中、待决策、待合并、需处理、历史筛选；详情显示 Task / WorkflowRun / Execution / Attempt 的准确身份、阶段、能力、最后采样时间和可用动作原因。消息按真实轮次组织，过程可折叠，最终回复完整可读；缺口、失败和未解决问题不能因折叠消失。具体语义沿用[会话设计](conversation-events.md)、[Activity](activity.md)与[决策反馈](decisions.md)，读取当前产品 Query/Command。

操作反馈分开显示“已提交、服务已接受、已执行、被拒绝、结果待核实”。发送前保存完整原信封；重连先查询原结果，服务明确 command_not_found 时可用原 ID/内容/版本幂等补交，已有记录只对账，不生成新命令或重放外部动作。决策卡片绑定原问题和 attempt，分别展示答案保存、平台接收、轮次开始及应用证明。Windows UI 关闭不停止服务或 worker；服务关闭时保留历史和离线诊断，不依缓存 Ready 发命令。

### 结果待核实时的详情

当命令回执丢失、服务失联或外部动作结果不明，选中运行的详情顶部使用持久警示区展示：原请求/Operation ID、精确 Task/Execution/Attempt、最后可信阶段及采样时间、仍可能存在的本机 worker 与资源。主操作是“查询原请求”；若自动对账仍无结论，显示已有的人工核实入口和所需证据。期间禁用会生成新执行、再次回答或释放资源的按钮，并在原位置写明原因。重新连接只更新同一个操作的进度，不清除警示或替换目标。本机停止能力未验证或状态不明时，不显示可执行的停止动作；远端不属于当前界面交付范围。

## UI 验收情景

- 同一项目连续建立两个新 session：第二个会话不含第一个的对话上下文，却可读取第一个留下的文档草稿；两个会话不能并发写同一规划 worktree。
- 主 agent 尝试写仓库代码、`docs/` 外文件或任意脚本/测试文件：服务与执行沙箱拒绝；正式 roadmap/spec 无半成品，界面展示具体原因。
- 用户要求做嗅探器或测试：主 agent 产出符合规则的任务 Spec/Plan 草稿，确认创建后才由 SteerLine 派发 worker。
- 一个任务批次的草稿缺 Spec、Plan、任务 ID、依赖或链接不一致：审阅页定位错误，“确认创建”不可执行；修复后同一草稿版本重新校验。
- 切换项目、关闭并重开 UI、服务断线、命令回执丢失：对话、草稿、文档差异与执行历史可恢复；不重复创建任务或提交决策。
- 从 DAG 的阻塞任务进入执行详情，查看待决策、原轮次输出、PR 和真实合并核验；再返回原任务位置，不丢筛选与阅读位置。
- 新 session 建立前看见当前草稿与写锁；建立后保留文件、清空对话和输入草稿。旧 session 写入未结束时，新 session 不产生并发文件修改。
- 已预留 ID 的草稿放弃后 ID 不复用；待审草稿被外部修改时原确认失效；发布结果未知时按原请求对账并禁止再次创建。
- 执行命令回执丢失时，详情保留原目标和最后可信证据；“查询原请求”不能变成新启动或再次回答。
