## 2.2 草稿、artifact与人工事项

流程、模型与原型仍迭代。没有主agent也能人工维护草稿、查看精确关联文档/成果、办理任务后验收及启动前必要操作。草稿/送审快照/正式任务各自明确来源和版本；修改草稿不直接改DAG。

先推导两条代表流程：任务交付后打开待验项与产物、按步骤登记结果/证据；任务开工前查看具体必须操作、办理后由服务核验对应条件。验收结果不等于TaskDelivery；前置操作完成不等于所有启动条件满足。失败、过期、错对象和未知执行需清楚显示实际影响，不能用通用确认覆盖。

人工项显示参与人/窗口或待安排、截止节点和实际阻塞范围；允许后验收不锁住无关任务。artifact以真实任务/交付/文档版本定位，缺失关联如实显示。具体编辑器、布局、登记命令、状态/存储和授权留到原型成熟时固定，不提前搭通用artifact/待办/审批/提醒平台。

## 2.3 主agent接入

以下会话与工具内容仅保留旧原型设想，未来需要时重新规划，不表示2.2已有交付或仍在安排接入任务。原设想的主agent仅Codex，固定审核角色由服务调度；模型建议不是正式准入或任务启动，权限仍需实际接入验证。

固定送审快照后允许继续编辑新草稿，报告/授权绑定原快照；需修改或等待前置的内容留草稿。审核和人工集成等待不默认锁住全部草稿。新session/历史/草稿输入、中断、审批和固定审核界面在实际能力与原型确认后定稿；不提供未证实的已发送输入编辑重跑。
