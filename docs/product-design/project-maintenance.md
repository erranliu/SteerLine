# 项目更新与候选版本维护

当前流程：**检查远端 → 查看差距 → 同步本地 → 显式准备材料与测试安排 → 项目就绪 → 创建新候选**。维护更新最新材料，候选始终使用各自冻结版本；远端刷新不依赖本地快进成功。

2026-11-05 已接入[显式准备与异步处理](../../SteerlineFlow/testing/acceptance/project-maintenance-preparation.md)，2026-11-06 已接入[项目统一就绪门槛](../../SteerlineFlow/testing/acceptance/project-readiness.md)；这些增量尚未据此宣称部署安装版或人工体验验收通过。基础范围见[收敛 Spec](../../SteerlineFlow/spec/project-maintenance-simplification.spec.md)、[Plan](../../SteerlineFlow/plans/project-maintenance-simplification.plan.md)及[专属验收](../../SteerlineFlow/testing/acceptance/project-maintenance-simplification.md)。

## 版本与所有者

| 事实 | 含义与所有者 |
| --- | --- |
| 远端基线 | 最近成功 fetch 的配置 remote/目标分支 commit；保留检查结果和时间 |
| 本地基线 | 项目主工作区实际分支/HEAD 及与远端关系，不代表候选工作区 |
| 最新材料 | 同一远端快照中任务原路径的正文/摘要，不改任务身份、目标或 DAG |
| 生成测试安排 | 完整 Plan、规范、清单与规则版本对应的原 Generation 结果，由项目库保存 |
| 候选版本 | 预留时固定的契约、base、材料摘要、生成来源及完整测试快照，终生不变 |
| 任务交付 | 所选候选原 PR 实时核实合并后，原事务写唯一 TaskDelivery |

新鲜度按关联路径/内容及规范/清单比较，commit、时间和候选编号只是来源。生成输入未变可复用原有效结果，其他关联材料变化仍会使候选过期。文本换行按既有归一化规则比较，原 blob、请求和报告保留真实字节与摘要。不再以首候选快照约束该任务全部后续候选。

## 远端观察与本地更新

宿主装载、每五分钟及手动检查执行有界 fetch，合并在途读取。实际新建候选前 fresh fetch；原请求已预留则只返回原事实。失败保留最后成功观察与时间，但当前资格为未就绪。

展示实际 remote/分支、提交标题/SHA/作者时间及两侧差距，检查时间另列，按用户本地时区展示。PR 关联允许无、多条或失败；失败仅影响附加信息，不阻断 Git。当前 provider 支持 Gitea 和已配置的 GitHub 命令查询，其他能力明确诊断。

只有主工作区落后且可安全快进时提供一键更新。点击重新 fetch，固定目标与预期 HEAD，按原写入/工作区锁核对仓库身份、配置分支、干净状态、无进行中 Git 操作及可达关系。忽略文件不计脏，会覆盖的未跟踪文件不得放行；真正写入仍受 Git 锁保护，完成后核对实际 HEAD。

条件变化拒绝旧操作；写入/回执未知只核实原目标，不换新目标重做。领先、分叉、脏、错分支/游离 HEAD、其他 worktree 占用、锁、历史改写或网络/认证问题分别提示人工处理。不自动 merge/rebase/stash/reset/切分支/push，不改候选工作区。

## 显式准备与生成

项目维护列出所有 open/in_progress 任务。无记录显示“待准备”，仍可登记准备；无成功远端观察也可登记，由后台重新检查。请求与固定任务范围在同一事务保存，独立 worker 执行逐任务读取/校验和原生成观察，不在项目 actor 上等待模型，也不占任务观察的五秒预算或数据库长事务。

按固定提交读取原路径的 Spec、Plan、common、acceptance，以及 environment-project.json 声明的测试规范和唯一正式清单。缺文件、改名、非普通文件、UTF-8/大小/严格格式错误显示具体问题，由作者走正常 Git/PR 修复；不猜路径、不重写任务或 DAG。

仅显式准备范围可登记新生成。GET、轮询、远端检查、保存生成方案及任务启动均不隐式生成；未完成任务首次无安排，或完整 Plan/规范/清单/规则输入变化时才需生成，同 Plan 同输入复用。commit 前进或旁置 JSON 变化不制造循环；已完成/放弃任务不为新材料生成或重开。

生成复用 read_only 的 generate/1，每次一个 Plan，只选择已有测试 ID 并展开完整定义，不编测试程序或改 Plan。优先项目显式生成 profile，否则只能采用合格的默认本地 Codex profile；默认 Orca 或配置不足时要求明确设置，不猜模型或降低权限。提交/profile/权限与原请求冻结，后续保存配置不改已受理输入。

校验成功的安排保存在项目库，候选消费完整快照；不要求人工确认、应用或提交 .tests.json，该文件不再是运行权威。空安排仅接受 Plan 明确无需自动测试。缺失、生成中、失败、未知、取消或配置不合格均不能使项目就绪。

失败不随 tick/重启自动重试；用户新点准备或重试才登记新请求，仍须原调用终态/资源资格允许。未知只查原号；重启接续已登记范围、提交、profile 和原意图。新输入可跳过旧未受理需求，但已受理/未知的原生成保留查询与停止义务，迟到结果只归原输入。任务关闭撤销未提交需求，不误停其他任务共享的生成。

## 项目统一就绪与候选冻结

项目主状态只有“已就绪/未就绪”，查询与实际启动共用[后端资格](../../internal/app/project_readiness.go)：

1. 主工作区位于配置分支、干净、无进行中 Git 操作，HEAD 与已核实远端目标一致。
2. **全部 open/in_progress 任务**均有当前提交有效材料、完整安排及未取消的成功生成；已交付/放弃任务不计入。
3. 新候选另核验原 Task、authority、图、前置实际 Delivery 包含于本次 base，以及执行/资源资格。开发者环境跳过设置不绕过项目门槛。
4. 预留前再核验统一资格，事务内重核材料/生成及任务/图/目标，原子保存候选快照和 submit 意图；已知远端变化要求重评估，不在事务中联网。

手动 start_task、start_candidate 和自动派发均适用。未就绪返回 project_not_ready、原因与维护入口，零候选/submit；失败点击不变成隐式后台队列。就绪只表示材料和安排可用，不表示任务测试通过。

原请求已经预留则返回原候选，拒绝/未知不升级输入。新候选可用新的 base/契约，不要求旧 base 仍为新目标祖先；原前置/身份/资源约束不变。远端观察和准备都不自动创建候选，Task 关闭/放弃后不新建。

界面使用 maintenance 响应的 readiness 或只读 /maintenance/readiness；任务页、启动拒绝与自动派发展示同一资格。普通轮询保留当前主状态，查询失败/断线按未就绪，详情给出同步、准备、生成、取消和重试入口。原候选重放、恢复、反馈、继续、发布及交付沿原资格，不受新建门槛替代。

## 过期保留与测试进度

关联材料与候选快照不同即显示“已过期 · 保留候选”，无需等新候选；只变代码且材料相同不标文档过期，最新编号也不保证最新材料。新鲜度是 SteerLine 投影，独立于 participation、Runner workflow 和资源状态。

过期不自动退出、不停止原执行，不撤销原反馈/继续/发布/交付；保留原工作区、材料/测试快照、日志和 PR。旧版本不占当前材料版本五个参与名额，实际运行的旧资源仍有 owner 并计入原准入/占用。

当前测试进度读取**各候选原 Run/input 的公开快照**，按冻结定义展示，不通过旧 collect 关联或跨 Run 搬运结果。材料过期不改写原进度或让历史证据冒充最新版通过；当前读失败保留历史并标待核实。字段与结算统一归[运行时测试进度](../integration/runtime-progress.md)。

文档页面提供候选执行版本、最新版本及固定两侧的完整文件差异，包括新增/修改/删除与测试安排；大文件分页，不把截断当完整。最新材料无效显示原因，原版本仍可读。

## PR 完成任务

**过期候选的 PR 合入仍可完成同一任务。** 按该候选自己的固定契约、发布目标、Run/PR 和实时合并证据校验，不比较最新材料摘要，不等待最新版生成/执行或当前测试通过。

显式退出、StopRequested、任务放弃、身份不符、PR 未合并/未知等原拒绝条件仍适用。多候选同时核实只写一次 TaskDelivery，在同一事务关闭 Task、释放后继并保留全部候选停止义务；不能遗漏旧版本或未知资源。交付展示实际采用的候选/材料，后续材料更新不重开任务，原停止结算继续。完整交付边界见[生命周期](worker-lifecycle.md)。

## Runner 输入与范围

开发流程传固定 base 工作区内真实相对路径；SteerLine 保存原契约、材料摘要及系统测试快照，不接管 Runner 原生执行。当前 generate 使用固定仓库提交与文件路径，**不再使用 inline 材料**，输出须核实同一来源。

候选完整安排通过公开 workflow 上下文和原文件通道冻结在 submit，保留原执行提示与规则边界，不向业务仓库写虚拟文档或旁置安排。缺固定协议材料、路径/来源或公开能力时拒绝，不降级旧正文/文件模式；原号重放不重新组合。当前接线见[生成实现](../../internal/testmanagement/generation.go)和[候选测试输入](../../internal/app/test_documents.go)，固定提示词维护归[治理规则](../prompt-governance.md)。

项目添加/预纳管仍为[后续方案](project-onboarding.md)，本流程不虚构 Task 或替代完整 PS 核验。材料合入正常 PR 即接受，不设产品内第二次内容批准。人工体验与未验边界按上述专属验收判断；旧人工采用/应用流程及精简前正文从[历史证据入口](../../SteerlineFlow/archive/design/runner-reliability-history.md#第五批整理来源)追溯，不作为当前操作规则。
