# 项目更新与候选版本维护

状态：2026-10-21 已按用户确认方案实施，仍未部署安装环境。交付范围见[收敛 Spec](../spec/project-maintenance-simplification.spec.md)、[Plan](../plans/project-maintenance-simplification.plan.md)，验证结果及未验边界归[专属验收](../acceptance/project-maintenance-simplification.md)。上一批人工确认/应用及任务级冻结已替换；旧版本证据保留在[原验收](../acceptance/project-maintenance.md)。

## 一条用户流程

已纳管项目使用：检查远端 → 查看提交/PR及本地差距 → 必要时更新本地 → 文档自动更新、测试自动生成 → 创建使用最新材料的新候选。远端材料刷新不依赖本地快进成功。任务首次执行与后续新候选采用相同版本准备规则；没有维护模式、材料来源选择或逐任务人工确认。

项目添加/预纳管仍后置，仅复用窄文件/格式检查，不在本批新增登记、全套PS核验或虚构Task。仓库由作者维护Spec、Plan、测试规范、清单和实际程序，正常PR合入即接受相应材料，无产品内第二次批准。

## 版本与所有者

| 事实 | 唯一含义及所有者 |
| --- | --- |
| 远端基线 | 最近成功fetch的配置remote/目标分支commit；项目维护保存检查成功/失败及来源 |
| 本地基线 | 配置项目主工作区的实际分支/HEAD及相对远端的可达关系；不代表候选工作区 |
| 最新任务材料 | 同一远端快照中任务原关联路径的实际正文/摘要；自动刷新，不改任务目标/身份/DAG |
| 生成测试安排 | 同一完整Plan、测试规范、清单及规则版本对应的原Generation结果；项目库持有，不写旁置文件 |
| 候选执行版本 | 候选预留时固定的完整契约、base、材料摘要、生成来源和测试快照；该候选终生不变 |
| 任务交付 | 所选候选的原绑定PR实时核实合并后，由原事务写唯一TaskDelivery；材料是否过期不改变资格 |

版本按实际文件路径/内容与规范/清单比较，commit和时间只是来源。生成输入摘要仅覆盖完整Plan、规范、清单及规则版本；其他关联文档变化使旧候选过期，但可复用仍适用的生成结果。换行按现有文本归一化规则比较新鲜度，原blob/请求/报告仍保存真实字节及摘要。

不再有一个约束全任务候选的共同base/执行契约。项目actor/store持有材料和候选事实；网络读取与模型调用不占数据库长事务，原Generation/submit/停止意图持久化先于调用，不新增作业框架或另一套Runner状态机。

## 远端观察、提交与本地更新

宿主装载后、每五分钟和用户显式检查取得远端观察，合并在途读取、有界fetch。每次真正新建候选都fresh fetch，不用五分钟缓存冒充当前；原请求已预留时只查原事实。失败保留最后成功观察及时间，明确当前待核实，不能据旧成功启动新候选或宣称当前测试通过。

远端命名为origin/main等实际目标，显示提交时间、标题、短SHA和提交详情；检查时间另列。PR从provider实际关联查询，允许无PR、多PR或查询失败；失败只影响附加信息，不封锁Git/候选。提交日志可分页看目标历史、落后/领先两侧提交，展示作者、提交时间、标题及可获得的提交/PR链接；用户本地时区展示。

本地按可达性显示已同步、落后N、领先N、双方分叉（各N）或无法判断。仅落后且可安全快进时提供一键更新，点击后重新fetch固定本次目标、保存原请求/预期HEAD，按原项目写入和Git/worktree锁核对仓库身份、当前分支、干净状态、无进行中Git操作及目标可达关系后执行快进，结果核对实际HEAD。忽略文件不计脏；会被覆盖的未跟踪文件不得放行。

执行前发现HEAD、分支、文件或目标条件变化则拒绝旧条件，说明重新检查/人工处理；实际写入与回执未知时只核实固定原目标，不按新目标重做。Git标准锁/工作区保护仍须在真正写入时生效，不能只依赖检查前快照。正常API回执、重启和重复请求绑定同一项目/实例/目标及原意图。

领先、分叉、脏工作区、错分支/游离HEAD、分支被其他worktree占用、锁、Git进行中、目标删除/历史改写或认证/网络失败分别说明原因和人工处理位置。不自动merge/rebase/stash/reset/切分支/push，不改候选工作区；失败不丢本地文件或伪造同步完成。历史改写需人工处理本地主仓库；新候选仍基于本次核实的远端目标检查任务前置，旧候选不被换base。

## 自动材料与生成

任务原路径上的Spec、Plan、common、acceptance自动刷新到远端最新版本并重算摘要，无人工内容批准。路径缺失/改名、普通文件/UTF-8/大小/严格格式不合格列为具体问题，转作者正常Git流程修复；不猜新路径、不更改仓库/分支/任务依赖。

未完成任务的Plan首次无结果，或Plan、测试规范、完整清单内容改变，自动登记生成；同一Plan同输入复用有效结果，多个任务可引用，commit前进或旁置JSON变化不触发循环。规范/清单固定使用docs/testing.md与docs/testing/test-list.json。已完成/放弃任务不再为新材料发起生成，不自动重开。

生成复用read_only的generate/1，每次只处理一个Plan，只选择清单已有ID并展开完整定义，不编写测试程序或改Plan。项目显式测试生成profile优先，否则只可采用项目默认且合格的本地Codex profile；默认Orca或缺配置时显示一次性设置，不猜模型/降低权限。profile、权限和原请求按调用冻结，改配置不改变已受理请求。

结果校验成功即保存在项目库供候选使用，不要求用户审阅、应用或提交.tests.json；该文件退出运行权威和新启动前置。空结果仅在Plan明确无需自动测试时接受，不设人工勾选。必要文件/定义缺失、生成中、失败、未知或profile不合格阻断相关新候选，旧候选不受影响；清单/计划语义质量仍由正常作者/PR审查负责。

宿主按已确认的自动策略为一个新输入持久化唯一初始意图；页面GET/轮询只读。相同版本失败不随tick或重启重试。明确失败用户可点“重试生成”，仍须原调用终态/资源资格允许；未知只查原号。重启接续已有意图和结算，不另造首次请求。

连续更新时未受理的旧输入可跳过；已受理/未知的旧生成保留原输入、查询与停止义务，不能被新版本覆盖。同Plan的新版本在原资源资格允许后处理；旧结果晚到只归旧输入，不使最新版本就绪。任务关闭时撤销未提交需求，已受理按原事实结算；共享给其他任务的结果/请求不随单任务关闭误停。

## 候选级冻结与原请求

每次start_task/start_candidate或自动派发统一：

1. 原请求已预留则返回原候选；否则读取当前任务/图/目标并fresh fetch。
2. 在同一commit读取全部任务引用、规范/清单，核对对应生成输入/完整结果及前置真实Delivery包含于本次base；不要求本地主仓库HEAD相等。
3. 必要材料或生成未就绪直接返回原因，零候选/submit；用户在就绪后再次创建，不把失败点击变成后台隐式候选排队。
4. 项目库事务重核Task/authority/graph、目标及实际材料/生成摘要，原子固定该候选快照、编号及submit意图；已知远端前进返回重新评估，不在事务中联网。
5. 预留即冻结，Runner拒绝/未知也不升级原请求。新候选可绑定新的base/契约，不读取Task首候选快照，不要求旧base仍包含于新目标；原前置/身份/资源资格仍核验。

新候选创建须经原显式入口；观察文档变化只更新材料和生成测试，不自动开新候选。原候选后续反馈/继续/发布使用自己的冻结输入，不能由最新Plan偷偷替换。Task关闭/放弃后不新建候选。

## 过期保留与关联测试

最新材料与候选快照内容不同即显示“已过期 · 保留候选”，不必等新候选出现。只变代码且关联材料相同不标文档过期；候选编号最新也不自动等于材料最新。多个候选绑定同一最新材料版本时均可分别关联测试，结果仍不能跨Run借用。

新鲜度是SteerLine材料投影，独立于参与资格、Runner workflow和资源状态。过期不自动置abandoned、不停止原执行、不撤销正常反馈/继续/发布/交付；用户显式停止参与及真正停止仍沿原入口。原工作区、文档/测试快照、日志、PR全部保留。

过期候选的当前测试关联禁用，不再发起新collect。已经在途/未知的原collect只按原号核实，晚到证据可存原候选历史，不计当前统计；历史安排、结果、日志仍可读。最新候选也必须满足Run/input_digest、测试定义、环境、干净且同被测commit、真实日志来源等既有规则；没有自动搬运旧结果的入口。远端读取失败标记“当前性待核实”，保留历史但不宣称当前通过。

候选提供执行文档、最新文档和按文件完整差异，含新增/修改/删除与测试安排；大文件可分页，绑定两侧固定来源，不混版本、不以截断当完整。最新材料无效显示具体问题，原版本仍可读。过期保留记录不占当前材料版本的五个参与名额；仍在运行的实际旧资源继续按原准入/占用规则计算，不伪造停止或让未知资源失去owner。

## PR完成任务

用户确认：**过期候选PR合入仍可完成同一任务**。过期不是退出，不要求该候选当前测试可用/通过，也不等待最新版生成/执行。交付校验所选候选自己的契约/发布目标、原Run/PR与实时合并证据，不与任务最新材料摘要比较。

显式退出、StopRequested、任务已放弃、身份错配、PR未合并/未知等原拒绝条件保持。多个版本PR同时核实只写一次TaskDelivery，沿原事务关闭Task、释放后继并保存全部候选停止义务；不能因部分候选过期/未知遗漏停止。交付后显示采用的实际候选和材料版本，不伪称最新版已执行。任务关闭后最新材料变化不重开，停止/资源结算继续原规则。

## 界面与当前缺口

默认项目维护只提供检查、更新本地、提交日志和具体问题；任务自动显示最新文档及测试生成状态，候选显示执行版本、当前性、差异和测试历史。异常才提供配置生成profile、重试生成或人工处理指引，不要求用户操作模式、路径、生成ID、人工采用/确认/apply。

已删除旧apply/手工确认/旁置安排运行旁路，CLI/API/Web统一消费上述规则；原查询、停止与技术详情可沿既有记录保留，不新增另一套工作区生成流程。项目准备提示词、debug-template及测试指南同步删除要求安排入仓库的前置。未发布产品直接调整当前格式，不迁移旧库或修改已安装活动现场。

上述流程已接线；提交PR关联支持Gitea及已配置GitHub命令provider，其他自定义provider显示能力不可用诊断。人工体验签收待安排，自动项按专属验收的实际证据判定。计划/结果见本页开头链接。Worker的节点/异常/验证差异统一登记在[生命周期](worker-lifecycle.md#项目基线与材料维护2026-10-21)，本页不另立Runner状态机。

## Runner当前文档契约

最新Runner开发流程只接收固定base worktree内的真实相对路径：Spec、Plan、common、acceptance及测试规范/清单。SteerLine保留自己的候选契约、原始正文/摘要及系统测试快照；不要求Runner复制这些文档。生成workflow继续使用其正式inline材料输入。

系统测试安排通过公开workflow提示元数据组合到原submit的实施/代码审计执行提示，不再传steerline-test-plan.json或steerline-testing.md虚拟文档，不向工作区/仓库写文件。组合保留所选Runner默认正文或用户自定义正文，不改报告/发布指令、审计结果协议、模型和权限。完整组合提示与测试快照一同不可变保存；原号重放不重新组合。缺少公开执行模板时明确拒绝新候选，不降级到旧构建/旧文件应用。当前配置profile摘要与派发后的实际input_digest分别表达。

按最新主干4d11148构建和验证，实际范围见专属验收的路径适配增量；此前017e410记录仅为历史固定版本证明。
