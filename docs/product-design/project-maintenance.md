# 项目基线与材料维护

状态：2026-10-21 当前实现规则；实际通过/待验以专属验收为准。交付范围见 [Spec](../spec/project-maintenance.spec.md)、[Plan](../plans/project-maintenance.plan.md)，结果及本次审查归[专属验收](../acceptance/project-maintenance.md)。本页是三种入口的统一规则正文。

## 版本及职责

以规范 Git common-dir、配置的 repository/remote/目标分支识别项目，区分三个事实：

| 事实 | 含义 |
| --- | --- |
| 远端观察 | 最近一次成功 fetch 得到的完整目标 commit、时间和目标身份；失败时只显示上次观察 |
| 材料依据 | 指定范围的输入/输出摘要、规则版本、机器检查及必要人工确认；可复核到某个远端 commit，不用一个全局布尔值封锁所有任务 |
| 执行固定版本 | Task 首次候选预留时固定的共同 base、完整执行契约和测试快照；后续候选及原请求重放共用 |

“最新”指首次启动本次成功 fetch 所得 commit。冻结前已观察到新的目标 commit 时重新评估，不用旧观察提交；冻结后远端继续前进不改变原执行，不承诺远端与本地数据库跨系统原子提交。

Go 应用层编排，项目运行时是已配置项目材料确认/生成记录/Task 的唯一写者，相关准备依据与首次冻结在同一项目库内重核。后台网络读取不占数据库事务，结果交还原项目 owner。核心规则不依赖 SQL/HTTP/Web；Runner 只承担既有 generate/1 和原执行/资源管理。维护清单是规则结果的投影，复用原 Generation 及应用回执，不另建通用作业引擎、第二套 outbox 或 Agent 运行时。

## 一条维护流程，三个入口

共用流程：取得输入快照 → 评估影响 → 人工核对或显式生成 → 审阅/应用 → 复核远端已提交材料。不需要生成/写文件的检查直接跳过这些动作。

| 入口 | 范围选择 | 共用部分与边界 |
| --- | --- | --- |
| 初始化准备 | 当前支持的公共材料，以及明确选入的已有 Plan；没有 Plan 时不造示例 | 调用相同输入读取、规则、校验和结果投影；预纳管仅人工准备/只读核验，不建项目库或启动 Runner |
| 基线更新 | 上次观察与新远端 commit 的变化，找出受影响材料 | 按未启动任务绑定的 Plan 检查同一完整输入摘要；缺基准时全范围检查，缺失或变化均计入 |
| 局部更新 | 指定材料或一个 Plan，补齐其上游并标出下游待办 | 使用同一规则；不要求执行无关项，局部成功不冒充全项目就绪 |

本批交付初始化模式的服务适配及无建库调用测试；未纳管项目的正式 Web/CLI 候选、持久记录及登记仍归[项目添加方案](project-management.md)。不为复用名义提前实现完整纳管流程。已配置项目可直接维护，不等待添加 UI。

正式就绪及启动只读取远端固定 commit；局部准备允许未提交工作区草稿，保存基准 HEAD、实际输入字节/摘要和来源。两种来源交给相同规则/生成器；草稿不冒充 Git blob，也不计远端就绪。先在服务内读取稳定快照再评估，不能将逐文件变化中的内容拼成已核验输入。

## 首版材料与影响规则

代码内维护固定规则，不开放任意命令、hooks、插件或可配置生成 DAG。

| 材料 | 必要检查与处理 |
| --- | --- |
| 公共测试规范与清单 | 固定 docs/testing.md、docs/testing/test-list.json，普通文件/UTF-8/限额及严格清单格式；原文和清单由用户维护 |
| Task 的 Spec/Plan/common/acceptance refs | 复用原 Task 文档的规范路径、精确 blob 和摘要检查；路径/内容变化需原任务确认，不自动改任务目标 |
| Plan 测试安排 | 同目录 .tests.json；校验唯一测试 ID。输入是完整 Plan、测试规范及完整清单，唯一生成器只选择 ID，不生成测试程序或 Plan 正文 |
| 初始化结构检查 | 复用上述读取/校验，列出当前材料缺项；完整角色清单、Markdown 链接核验及 PS-01–PS-07 纳管门槛仍由项目添加批次落实，并复用此公共基础 |

本批不把尚未实现的 .steerline/project.json 或全仓文档结构作为 Task 新启动前置，不收紧现有文档映射。未来添加流程的 testing 角色需适配现有固定路径；扩展定位另行设计。

安排的新鲜度按生成器实际读取的三个完整输入及规则版本判断；不另做“只比较所选测试定义”的优化。任一输入改变，相关安排列为待复核；可以重新生成，也可以审阅现有安排后明确采用，不能强制调用模型。新合入材料无依据时同样可人工核对采用。输入/输出的归属和摘要由服务读取，不能提交一个 passed 布尔值放行。

仅源码、测试入口、构建或未知路径变化而上述材料输入未变时，显示“测试适用性建议核对”，不宣称语义覆盖已证明，也不因此阻断所有 Task 或每次后继启动。材料实际缺失/无效、输入变化而相关安排尚未复核、任务正文变化未确认才是必要待办；只阻断相关首次启动。测试内容变更仍应按项目规范同步清单/安排，由正常代码审查负责语义质量。

生成输出不作为其自身输入；按已知材料角色区分 .tests.json 与源码变化。全部依赖摘要一致可沿用到新 commit，新增远端 commit 本身不要求重新生成。人工采用或生成依据绑定一个 Plan 及实际输入/输出，不因另一 Plan 的待办而失效。

依赖比较对 UTF-8 文本统一 CRLF 为 LF，避免工作区换行转换导致草稿提交后永远无法采用；原 Runner 输入正文、Task Git blob SHA、目标原字节和应用回执仍保存/核对各自真实字节，不用归一化摘要代替原请求身份或写入条件。其他内容变更必须重新核对。

## 远端观察与本地更新

在线配置项目由宿主装载后及每五分钟检查，支持手动检查，按 common-dir/目标合并在途读取，有界超时；首次启动必须取得本次成功 fetch，不用五分钟缓存替代。检查只更新远端跟踪 ref/观察，不改本地分支、工作区或启动模型。记录失败原因、目标删除/非快进及最后成功时间，不弹窗循环或无限重试。

首版只提示用户通过正常 Git 流程 pull/处理脏工作区、分叉或历史改写，不实现 SteerLine 的同步按钮/CLI。用户更新后重新检查；不自动 merge/rebase、reset、stash、切分支或推送。目标身份变化使未应用结果和材料依据需重核，不能借 Task 材料确认把任务换到另一 repository/remote/目标分支。

准备固定一次输入。期间远端前进只提示，不改写原生成请求或无限追赶。重新检查时核对新增影响；全部实际输入/输出仍相同时可沿用。启动从远端 blob 固定版本，不要求本地 HEAD 与远端完全一致，无关本地修改不冒充新材料。

## 生成及应用控制

维护清单可有多项，首版每次显式生成仅处理一个 Plan、一次 Runner generate/1、一个目标文件；显示输入来源、文件和 profile，不建设批量模型调度或多文件应用事务。准备授权只覆盖这个固定输入，缺规范/清单时先人工准备；只读检查无需 profile/Runner 就绪。

复用原 Generation 持久记录和唯一 Runner 请求，先存意图再调用；结果经格式/ID/限额校验后成为待审阅内容，不自动写文件。一次操作不自动重试；明确拒绝，或原调用已终态且资源/停止义务允许时，用户才可为失败项创建新尝试。unknown、仅超时或取消未结算不算明确失败；重用原请求只能查询，不能换 ID 偷重发。

用户审阅差异后，单文件应用命令固定原生成/输出摘要、当前本地 HEAD/分支、输入及目标原字节条件，先保存原应用意图再原子替换。Git 来源的准备也须记录应用现场；本地输入不对应所生成版本时提示先更新，不把远端内容直接覆盖到不匹配工作区。拒绝越界/symlink/reparse/进行中 Git 操作及相对已审阅条件的新修改；允许准备时已有且未变的草稿。

预览返回服务计算的 review_digest，覆盖项目/原生成/目标路径、输出真实摘要、当前 HEAD/分支、实际输入及目标原字节条件。应用提交该摘要及 expected generation revision，服务重新读取并比对，不仅比较输出摘要；预览查询只计算，不产生写入授权或自动确认。HEAD 或输入在审阅后改变使旧摘要/原应用命令失效；重新评估后若归一化输入仍相同，可重新审阅、用新摘要和新应用请求复用原输出，不改原 Runner 请求或调用模型。目标改变也必须展示新差异。多项逐项应用，各自记录成功/冲突，不提供批量事务/回滚/继续机制。

取消与应用意图在原 owner 下串行裁决：取消先提交则禁止应用；应用意图先提交表示该单文件动作已受理，原在途写入可完成，取消不能承诺撤销它，只核实未写/已写/冲突并保留事实。丢回执/重启后的查询不补写；未取消时用户可显式重用原应用命令在条件仍成立时完成原动作，不重新生成。取消已提交后，不得用旧应用号开始尚未发生的写入，需要重新审阅并显式发起新操作。

取消阻止未开始生成，已受理/未知生成沿原 ID 保存停止义务，迟到结果不可自动应用。原 Run、未绑定/迟到接受和资源结算复用共享 Runner 围栏；结果成功、停止受理、资源已结算分别显示。没有预纳管生成路径，不为其增加假项目身份或独立恢复。

生成、应用、提交/合入和远端材料就绪分别显示。用户正常提交/push/PR 合入，重新 fetch 后用远端真实 blob 核对输入/输出和新增影响；摘要一致才能采用，不自动发布或创建 Task。模型空结果不自动替换；用户审阅并明确确认“无需自动测试”且 Plan 有说明时，允许有效空安排。

## Task 材料更新与首次启动冻结

Task 沿用 Task version，保存固定 repository/remote/目标分支及最近确认的材料路径/内容。首次预留前可显式 CAS 确认材料变化；该入口不能修改目标身份、依赖、任务范围或交付。确认比对路径和正文摘要，不因确认引用的旧 commit 号与新基线不同就要求人工重确认；执行时重新构造同 commit 的全部 refs，保留其原确认来源。首次执行固定另一份完整执行契约，区分“最近确认内容摘要”与“执行契约摘要”，不新增任务修订编号或历史迁移。

首次启动（自动派发、手动及 CLI/API 共用）：

1. 已有原请求预留时只返回/对账原事实，不重新取最新版本。
2. 读取 Task/version、图、目标及最近确认依据，成功 fetch 并取得目标完整 commit。失败阻断本次新启动，原执行查询/反馈不受影响。
3. 在该 commit 读取 Spec、Plan、common/acceptance refs、测试规范、清单和该 Plan 安排；解析全部 Git 引用为同一 commit，核验实际摘要、该范围材料依据及前置 Delivery 已进入 base。只有任务正文/引用等必要内容变化才要求重新确认；源码适用性提示、无关 Plan 或未实现的纳管结构不作为全局门禁。
4. 同一项目库事务重核 Task/authority/graph、配置目标和本次实际消费的材料确认摘要/版本，原子固定唯一 Task 执行快照、共同 base、测试快照、首候选和完整提交意图。无关 Plan、重复检查时间或纯 UI 观察刷新不制造 CAS 冲突。若事务前已知目标 commit 改变，返回重新评估；不在事务中 fetch/调用模型。

准备阻断包含必要文件缺失/无效、实际材料输入改变未复核、Task 材料未确认；合法空测试安排允许，不要求测试已经通过，不增加 PR/Delivery 测试门禁。快照只含原任务材料和实际所选测试，不混入其他 Plan。

首次预留即冻结，即使提交拒绝/未知、候选退出也不解除。后续候选先读取同一 Task 执行快照，不能重新解析最新材料；仍按原执行配置/图/前置与目标祖先关系规则核验，目标历史改写导致原 base 不在目标分支时明确阻断新候选，不换 base。原请求重放不受新基线/材料待办影响，不表示离线就可新建候选或绕过 Runner 资格。现有反馈/恢复、报告、PR/Delivery 不重写。换基线创建新任务，首版无重开或跨基线轮次。

## 界面与生命周期

顶部显示基线状态和最后检查时间；“公共材料已就绪”和各 Plan 待办/适用性提示分开。一个维护面板提供检查、Git 更新提示、范围清单、单项生成/差异/应用、人工采用及待提交/合入；面板列出本任务材料待办并可选择对应任务审阅；启动错误提示到项目维护核对。切项目/断线不转移原授权或隐式继续。

沿 [worker-lifecycle](worker-lifecycle.md) W01/W02、E01/E03–E07、V01/V03/V06–V08 整合，不增加 Runner 节点或恢复权。生成、应用和启动授权独立；后台/查询/重启均零自动生成/应用/启动。实现直接调整当前格式，不提供旧数据/协议迁移或回退。
