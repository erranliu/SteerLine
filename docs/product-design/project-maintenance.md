# 项目更新与候选版本维护

当前流程：**检查远端 → 查看差距 → 同步本地 → 读取 Git 材料与测试安排 → 项目就绪 → 创建新候选**。维护更新最新材料，候选始终使用各自冻结版本；远端刷新不依赖本地快进成功。

2026-11-05 已接入[显式准备与异步处理](../../SteerlineFlow/testing/acceptance/project-maintenance-preparation.md)，2026-11-06 已接入[项目统一就绪门槛](../../SteerlineFlow/testing/acceptance/project-readiness.md)；这些增量尚未据此宣称部署安装版或人工体验验收通过。基础范围见[收敛 Spec](../../SteerlineFlow/spec/project-maintenance-simplification.spec.md)、[Plan](../../SteerlineFlow/plans/project-maintenance-simplification.plan.md)及[专属验收](../../SteerlineFlow/testing/acceptance/project-maintenance-simplification.md)。

## 版本与所有者

| 事实 | 含义与所有者 |
| --- | --- |
| 远端基线 | 最近成功 fetch 的配置 remote/目标分支 commit；保留检查结果和时间 |
| 本地基线 | 项目主工作区实际分支/HEAD 及与远端关系，不代表候选工作区 |
| 最新材料 | 同一远端快照中任务原路径的正文/摘要，不改任务身份、目标或 DAG |
| 测试安排 | Plan 同名 `.tests.json` 的有序 ID，从同提交正式清单展开；Git 是唯一安排权威 |
| 候选版本 | 预留时固定的契约、base、材料摘要、Git 来源及完整测试快照，终生不变 |
| 任务交付 | 所选候选原 PR 实时核实合并后，原事务写唯一 TaskDelivery |

新鲜度按关联路径/内容及规范/清单比较，commit、时间和候选编号只是来源。仅代码提交推进或未选清单项变化不使安排过期；选择或所选完整定义变化使用新快照，其他关联材料沿原摘要判断。文本换行按既有归一化规则比较，原 blob、请求和报告保留真实字节与摘要。不再以首候选快照约束该任务全部后续候选。

## 远端观察与本地更新

宿主装载、每五分钟及手动检查执行有界 fetch，合并在途读取。实际新建候选前 fresh fetch；原请求已预留则只返回原事实。失败保留最后成功观察与时间，但当前资格为未就绪。

展示实际 remote/分支、提交标题/SHA/作者时间及两侧差距，检查时间另列，按用户本地时区展示。PR 关联允许无、多条或失败；失败仅影响附加信息，不阻断 Git。当前 provider 支持 Gitea 和已配置的 GitHub 命令查询，其他能力明确诊断。

只有主工作区落后且可安全快进时提供一键更新。点击重新 fetch，固定目标与预期 HEAD，按原写入/工作区锁核对仓库身份、配置分支、干净状态、无进行中 Git 操作及可达关系。忽略文件不计脏，会覆盖的未跟踪文件不得放行；真正写入仍受 Git 锁保护，完成后核对实际 HEAD。

条件变化拒绝旧操作；写入/回执未知只核实原目标，不换新目标重做。领先、分叉、脏、错分支/游离 HEAD、其他 worktree 占用、锁、历史改写或网络/认证问题分别提示人工处理。不自动 merge/rebase/stash/reset/切分支/push，不改候选工作区。

## Git 材料与测试安排

Spec、Plan、同名 `.tests.json` 与专属验收材料在 roadmap 转正时同批生成、审阅并随同一文档 PR 发布。语义选择由模型在材料阶段完成；Plan 写映射、原因、时点及特殊准备，JSON 只保存有序唯一 ID，命令/环境/断言引用项目入口定位的正式清单。外部编写材料也采用同一约定。

项目检查/更新后，由原维护后台有限读取当前提交的任务材料与安排。只读查询消费保存的投影，启动前再次核对基线和资格；没有独立准备、生成、重试、取消或测试生成 profile 操作，不写入 Git、不运行模型。

缺文件、非法格式、重复/未知 ID 或来源错误按文件诊断；通过正常 Git/PR 修复，不自动补文件或借旧结果放行。空安排要求 Plan 明确说明无需自动测试及原因，页面显示未安排，不作为测试通过。

材料缓存从 Git 读取覆盖，候选使用各自冻结的提交、Plan 路径、项目入口、所选完整定义及摘要。JSON 路径直接从 Plan 推导；不增加来源对象、独立安排数据库权威或人工采用入口。完整清单沿原提交追溯，新鲜度只纳入选择与所选定义，不纳入未选条目。

## 项目统一就绪与候选冻结

项目主状态只有“已就绪/未就绪”，查询与实际启动共用[后端资格](../../internal/app/project_readiness.go)：

1. 主工作区位于配置分支、干净、无进行中 Git 操作，HEAD 与已核实远端目标一致。
2. **全部 open/in_progress 任务**均有当前提交有效材料、有效 Git 安排及完整快照；已交付/放弃任务不计入。唯一例外是已入图 Roadmap 后继缺少同批前置声明将新增的测试，且仍被有效未交付前置阻塞：其它材料、现有清单、协议和 writer 均核实后，投影为 waiting_tests，不阻塞提供者启动。声明与当前实际图的祖先关系必须同时匹配；未声明、已丢弃/交付不一致、提供者已交付但缺定义的情况仍阻断。
3. 新候选另核验原 Task、authority、图、前置实际 Delivery 包含于本次 base，以及执行/资源资格。开发者环境跳过设置不绕过项目门槛。
4. 预留前再核验统一资格，事务内重核材料/快照及任务/图/目标，原子保存候选快照和 submit 意图；已知远端变化要求重评估，不在事务中联网。

手动 start_task、start_candidate 和自动派发均适用。未就绪返回 project_not_ready、原因与维护入口，零候选/submit；失败点击不变成隐式后台队列。就绪只表示材料和安排可用，不表示任务测试通过。

waiting_tests 不表示该后继可启动。当前任务自身必须有 ready 材料与真实完整测试快照；前置交付后，在最新固定提交严格读取同提交 .tests.json 和正式清单，缺定义仍失败，不沿用规划声明充当执行定义。

原请求已经预留则返回原候选，拒绝/未知不升级输入。新候选可用新的 base/契约，不要求旧 base 仍为新目标祖先；原前置/身份/资源约束不变。远端观察和准备都不自动创建候选，Task 关闭/放弃后不新建。

界面使用 maintenance 响应的 readiness 或只读 /maintenance/readiness；任务页、启动拒绝与自动派发展示同一资格。普通轮询保留当前主状态，查询失败/断线按未就绪，详情给出同步状态、Git 来源和具体材料错误。原候选重放、恢复、反馈、继续、发布及交付沿原资格，不受新建门槛替代。

## 过期保留与测试进度

关联材料与候选快照不同即显示“已过期 · 保留候选”，无需等新候选；只变代码且材料相同不标文档过期，最新编号也不保证最新材料。新鲜度是 SteerLine 投影，独立于 participation、Runner workflow 和资源状态。

过期不自动退出、不停止原执行，不撤销原反馈/继续/发布/交付；保留原工作区、材料/测试快照、日志和 PR。旧版本不占当前材料版本五个参与名额，实际运行的旧资源仍有 owner 并计入原准入/占用。

当前测试进度读取**各候选原 Run/input 的公开快照**，按冻结定义展示，不通过旧 collect 关联或跨 Run 搬运结果。材料过期不改写原进度或让历史证据冒充最新版通过；当前读失败保留历史并标待核实。字段与结算统一归[运行时测试进度](../integration/runtime-progress.md)。

文档页面提供候选执行版本、最新版本及固定两侧的完整文件差异，包括新增/修改/删除与测试安排；大文件分页，不把截断当完整。最新材料无效显示原因，原版本仍可读。

## PR 完成任务

**过期候选的 PR 合入仍可完成同一任务。** 按该候选自己的固定契约、发布目标、Run/PR 和实时合并证据校验，不比较最新材料摘要，不等待最新版执行或当前测试通过。

显式退出、StopRequested、任务放弃、身份不符、PR 未合并/未知等原拒绝条件仍适用。多候选同时核实只写一次 TaskDelivery，在同一事务关闭 Task、释放后继并保留全部候选停止义务；不能遗漏旧版本或未知资源。交付展示实际采用的候选/材料，后续材料更新不重开任务，原停止结算继续。完整交付边界见[生命周期](runner-lifecycle.md)。

## Runner 输入与范围

开发流程传固定 base 工作区内真实相对路径；SteerLine 保存原契约、材料摘要及系统测试快照，不接管 Runner 原生执行。roadmap generate 使用固定仓库提交与文件路径，**不再使用 inline 材料**，输出须核实同一来源。

候选完整安排通过公开 workflow 上下文和原文件通道冻结在 submit，保留原执行提示与规则边界，不向业务仓库写虚拟文档或旁置安排。缺固定协议材料、路径/来源或公开能力时拒绝，不降级旧正文/文件模式；原号重放不重新组合。当前接线见[Git 安排读取](../../internal/projectmaintenance/rules.go)和[候选测试输入](../../internal/app/test_documents.go)，固定提示词维护归[治理规则](../prompt-governance.md)。

项目添加/预纳管仍为[后续方案](project-onboarding.md)，本流程不虚构 Task 或替代完整 PS 核验。材料合入正常 PR 即接受，不设产品内第二次内容批准。人工体验与未验边界按上述专属验收判断；旧人工采用/应用流程及精简前正文从[历史证据入口](../../SteerlineFlow/archive/design/runner-reliability-history.md#第五批整理来源)追溯，不作为当前操作规则。
