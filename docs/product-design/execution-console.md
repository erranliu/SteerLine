# 执行控制台设计与操作

本文维护当前 CLI/TUI 执行控制台的布局、目标选择和操作方式，支持范围为本地 Codex 与本机 Orca。产品规则分别由[数据模型](data-model.md)、[决策与反馈](decisions.md)和[会话事件](conversation-events.md)维护；拟议原生界面见[规划与界面设计](planning-ui.md)。操作与键位以 [model_keys.go](../../internal/console/model_keys.go) 和[界面帮助](../../internal/console/view.go)的当前实现为准。

## 打开与连接

运行 `steerline console` 默认枚举 `<STEERLINE_HOME>/etc/*.json` 项目，并加载该 home 的 execution.json。`steerline console -config <path>` 打开明确项目，`-run-id <run-id|task-id>` 定位已有运行。Windows console.bat 和 `steerline projects` 菜单进入同一客户端；服务窗口由用户独立启动，生命周期及停服确认见[整体架构](../architecture.md#生命周期反馈与恢复)。

界面显示所连接的项目、服务实例、所选 Task/WorkflowRun/Execution/Attempt、冻结方案和实际能力。离线读取标明采样时间，Ready 缓存不成为领取许可。配置版本不同、实例未知或目标资格不满足时，写操作显示具体原因并拒绝；界面禁用按钮不代替服务校验。已提交、平台接受、服务操作执行和业务交付分别展示。

## 主界面与候选

宽屏左侧是任务列表，右上是所选候选、冻结方案、执行状态、环境阻断和 PR，右下是运行摘要与反馈。没有问题时右下显示最近最多十条规范活动短摘要；有问题时在原位置编辑和提交。窄屏按焦点切换列表与右侧区域，答案仍在主界面编辑，完整身份与资源定位通过只读详情展开。

每 Task 一条主行，当前及历史候选按稳定 WorkflowRun 身份选择。新增候选由人选择另一套冻结方案；允许范围、宽松开始检查、放弃和唯一交付由[候选规则](data-model.md#人工候选实验)决定。放弃需要明确确认，退出实验与 worker 停止事实分别显示；历史 PR、落选资源和未核实执行保持可定位。

正文、答案草稿、请求回执和后台读取归属项目、Task、WorkflowRun、Execution/session 及原 Decision。切候选先保存原草稿；晚到响应不改选候选、不打开另一项目的输入。原候选暂时不在快照中时显示原因，不静默改选其他候选。问题或版本变化不会把旧草稿重定向新轮次。

## 反馈与结果

待处理问题展示完整问题、选项、上下文和准确目标。Tab 在列表、选项和文字输入间循环；预选选项不会提交，Enter 在文字输入中换行，F2 明确提交原答案，F8 阅读完整背景/身份。紧凑布局中，焦点仍在列表时 F2 先回到原草稿，核对后再次提交。答案保存、送达和轮次事实按[反馈契约](decisions.md)显示；服务操作、候选放弃和宿主环境动作保持各自语义。

右下摘要不承担完整过程时间线、工具正文或轮次折叠。最终业务回复从规范会话记录自动分块读完并校验原候选、正文修订和摘要，再在简单只读入口展示；默认最新已识别业务回复，可选择历史回复。准备轮、未知阶段、普通摘要和终端静默不冒充 final。正文缺失、截断或采集缺口明确显示，过程诊断由原生会话及取证材料承接。细节见[会话读取与控制台展示](conversation-events.md#console-presentation)。

## 操作速查

| 上下文 / 键位 | 操作 |
| --- | --- |
| 主界面：←/→、Tab、↑/↓、PgUp/PgDn | 切项目、切焦点、选择或滚动；编辑时 Tab 循环列表/选项/文字 |
| 主界面：Enter / d | 有待交互问题时 Enter 打开反馈；其他情况阅读只读详情，d 阅读完整详情 |
| F6/F7（或主界面的 { / }） | 显式切换当前/历史候选，保留原草稿 |
| b / z | 选择不同方案新增候选 / 经确认不可撤销退出实验 |
| s | 打开预设执行方案列表；方案页 Enter 明确确认开始，Esc 取消 |
| a、Enter、F2、F8 | 在右下回复；输入中换行；明确提交；阅读完整背景/身份 |
| f / [ / ] | 阅读最终回复 / 选择上一条或下一条历史业务回复 |
| v / u | 历史决策 / 只读执行核验 |
| Ctrl+E / Ctrl+O | 核对原环境 / 定位原终端，须满足原身份和实际能力 |
| 1–7 | 全部、Ready、进行中、待决策、待合并、需处理、历史筛选 |
| m / x | 手动/自动派发切换 / 确认后请求停止中心服务 |
| Esc、?、q | 返回或保留未提交草稿；帮助；只退出控制台 |

详细行为随键位上下文变化，以界面当前提示为准。错误、部分提交、未知回执和恢复限制不能通过快捷键绕过；两种本机后端的实际恢复能力分别展示。

## 重开、关系与诊断

窗口操作记录仅保存项目绑定、候选/Decision 草稿和原请求身份；重开重置阅读布局，查询未知请求而不重发。损坏或不支持记录保留现场并阻止该窗口新外发，允许只读核实；多窗口独立锁定自己的记录。持久字段与格式由[会话设计](conversation-events.md#console-presentation)维护，不恢复已退役的阅读锚点或折叠状态。

任务详情展示阻塞原因、Spec 和交付定位；完整固定引用保留在中心契约。关系查询使用 `steerline task graph -config <path> -task-id <id> -direction upstream -depth 3`，导出使用 `steerline task export -config <path> -format json -output <path>`；覆盖已有导出需显式 `-overwrite`。详情、PR 与资源位置是定位线索，完成仍由中心核验真实 TaskDelivery。

配置与冻结权限见[执行方案](execution-profiles.md)，服务/数据库和工作区事实见[数据模型](data-model.md)。本页不维护 PR 变更或人工验收日志；验收结论保持在 validation，原生未测能力不能从文档或兄弟候选成功推定。
