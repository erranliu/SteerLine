# 执行控制台设计与操作

本文维护当前 CLI/TUI 执行控制台的布局、目标选择和操作方式，支持范围为本地 Codex 与本机 Orca。产品规则分别由[数据模型](data-model.md)、[决策与反馈](decisions.md)和[会话事件](conversation-events.md)维护；拟议原生界面见[规划与界面设计](planning-ui.md)。操作与键位以 [model_keys.go](../../internal/console/model_keys.go) 和[界面帮助](../../internal/console/view.go)的当前实现为准。

## 打开与连接

运行 `steerline console` 默认枚举 `<STEERLINE_HOME>/etc/*.json` 项目，并加载该 home 的 execution.json。`steerline console -config <path>` 打开明确项目，`-run-id <run-id|task-id>` 定位已有运行。Windows console.bat 进入同一客户端；服务窗口由用户独立启动，生命周期及停服确认见[整体架构](../architecture.md#生命周期反馈与恢复)。

界面显示所连接的项目、服务实例、所选 Task/WorkflowRun/Execution/Attempt、冻结方案和实际能力。离线读取标明采样时间，Ready 缓存不成为领取许可。配置版本不同、实例未知或目标资格不满足时，写操作显示具体原因并拒绝；界面禁用按钮不代替服务校验。已提交、平台接受、服务操作执行和业务交付分别展示。

## 主界面与候选

2026-10-13 当前精简：列表每 Task 一行，以固定 ID/任务提示/候选数量/标题列对齐；任务提示综合 Task、所有候选的工作流/执行状态、恢复与 PR 查询事实，只显示中文结果，不随所选候选切换；Task 已关闭/丢弃优先，其次正常候选等待合并、待决策、进行中、等待外部、启动中、待核验、阻塞、失败；任何正常候选已在 await_merge/waiting_external 时显示“等待合并”，其他候选失败不遮住它；候选数量统计同一快照中该 Task 的全部 WorkflowRun（含已结束候选），没有候选时显示 0；明确阻塞事实显示“阻塞”，不把所有 open 推断为阻塞。8 筛选阻塞任务，列表显示当前序号/总数；长标题和摘要省略，完整原值在详情。右上只显示 task_status/workflow_stage，隐藏 workflow_status/execution_status；详情保留全部原始字段，中文与颜色只按字段和确切枚举映射；未知原值保留，详情长值换行。右下优先原问题/回执、三行结果预览，固定显示当前流程/状态；变化只显示 workflow_stage 流程阶段或 workflow_status 流程状态，一条一种信息，阶段变化时只显示流程变化，阶段不变才显示状态变化，最新在上、最多五条可见消息。技术字段变化及其他活动移到 d 原始详情，turn ID 不进入默认区；原记录仍完整保留。短屏概览放入可滚动右下，原操作校验保持。见[Spec](../spec/console-flow-state-readability.spec.md)、[验收](../acceptance/console-flow-state-readability.md)。

宽屏左侧是任务摘要列表，右上是所选候选、冻结方案、原始状态、阻塞原因、PR 与下一步；右下承接方案选择、停服确认、回答、核验摘要、流程/状态变化和有界结果预览。普通 Enter 转到右下或激活当前问题，详细阅读才切页。窄屏按焦点切换列表与右侧区域，所有编辑/选择仍属于同一主界面；完整身份与资源定位通过只读详情展开。

活动窗口用双线边框与 ▶ 表示，失焦列表仍保留选中行；选项高亮和输入光标分别表示键盘目标。状态使用语义颜色/加粗，遵守终端颜色能力与 NO_COLOR，TERM=dumb 使用 ASCII 焦点框。新问题、异常和迟到回执不抢焦点或自动打开编辑器。短屏优先保留原目标、关键原因/问题、选项/输入、预览及提交/取消提示；目标或必要核对信息被截断时禁止发送。

每 Task 一条主行，当前及历史候选按稳定 WorkflowRun 身份选择。新增候选由人选择另一套冻结方案；允许范围、宽松开始检查和唯一交付由[候选规则](data-model.md#人工候选实验)决定。产品不提供单候选放弃操作；历史 PR、落选资源和未核实执行保持可定位。

正文、答案草稿、请求回执和后台读取归属项目、Task、WorkflowRun、Execution/Attempt/session 及原 Decision。切目标先保存原草稿，保存失败不切换；临时方案选择/确认取消，晚到响应不改选候选或打开输入。原候选暂时不在快照中时显示原因，不静默改选。问题或版本变化不会把旧草稿重定向新轮次。方案选择绑定原 Task/候选、服务及相关版本，选中方案 ID/摘要须与实际请求一致，变化后重新选择。

## 反馈与结果

待处理问题显示原问题、声明选项、当前选项说明和准确目标；长内容明确截断，通过 F8 完整阅读。Tab/Shift+Tab 在列表、选项和文字输入间循环，选项只是预选；选项焦点 Enter 转输入，输入焦点 Enter 换行，F2 是唯一答案提交键。紧凑布局的列表焦点下，F2 先返回原草稿预览，再次显式 F2 才提交。答案保存、送达和轮次事实按[反馈契约](decisions.md)显示；未决/失败/未知回执与问题/动态共存，不被新终态回执遮住。编辑、方案选择、确认和核验模式互斥；退出核验后拒绝其迟到结果。

已核实 PR 的停止轮次默认显示“待合并”和人工合并提示，不展示默认继续问题，也不计为待交互；Enter 只转到右下。需要追加修改时按 a 打开自由文字草稿，填写非空反馈后 F2 明确提交，继续原会话；取消草稿仍保持待合并。

右下不承担完整过程时间线、工具正文或轮次折叠。当前运行/新轮次优先于上一轮结果；主界面只显示已采集规范 final 的有界预览，完整及历史正文按需阅读。通用 Summary、准备轮、未知阶段、工具输出或终端静默不冒充 final，worker 自报测试不冒充独立验收通过。索引失败/空记录清除旧预览，采集 gap 即使有有效正文也明确显示。正文读取、完整性与大小边界由[会话契约](conversation-events.md#console-presentation)维护。

详情/F8 独占阅读按键，不向主界面分派开始、停服、环境动作或答案提交。F8 返回保留原模式/目标/焦点，重新核对相关版本；滚动有界，不能从全文阅读直接确认隐藏操作。u 在右下展示原只读核验结论、采样和下一步，过期报告不能证明当前资格，F8 才按需展开完整报告。

## 操作速查

| 上下文 / 键位 | 操作 |
| --- | --- |
| 主界面：←/→、Tab、↑/↓、PgUp/PgDn | 切项目、切焦点、选择或滚动；编辑时 Tab 循环列表/选项/文字 |
| 主界面：Enter / d | Enter 到右下或激活原问题；d 阅读完整详情 |
| F6/F7（或主界面的 { / }） | 显式切换当前/历史候选，保留原草稿 |
| b | 右下选择不同方案新增候选 |
| s | 右下选择预设方案；核对 Task、方案、能力及版本后 Enter 确认开始，Esc 取消 |
| a、Enter、F2、F8 | 在右下回复；输入中换行；明确提交；阅读完整背景/身份 |
| f / [ / ] | 按需完整最终回复 / 仅在最终回复阅读区选择历史回复 |
| v / u | 历史决策 / 右下只读核验摘要，F8 完整报告 |
| r | 列表焦点刷新项目；核验焦点重读原报告 |
| Ctrl+E / Ctrl+O | 核对原环境 / 定位原终端，须满足原身份和实际能力 |
| Ctrl+N | 为所选本机 Codex 候选打开独立 Codex CLI 窗口，连接原 app-server 实时查看 |
| 1–7 | 全部、Ready、进行中、待决策、待合并、需处理、历史筛选 |
| m / x | 手动/自动派发切换 / 确认后请求停止中心服务 |
| Esc、?、q | 返回或保留未提交草稿；帮助；只退出控制台 |

详细行为随键位上下文变化，以界面当前提示为准。开始/停服仅在原目标及核对信息可见时显式 Enter；列表焦点的 Enter 只返回原操作区，y 不确认。错误、部分提交、未知回执和恢复限制不能通过快捷键绕过；两种本机后端的实际恢复能力分别展示。

Windows 本机 Codex 候选开始原生执行轮次后，可在主界面或详情阅读中按 Ctrl+N。入口从数据库核对所选 WorkflowRun、Execution、Attempt、session 和 generation，使用该候选冻结方案中的 Codex 可执行路径，检查原 app-server 进程与实时会话工作目录，再以 `codex resume --remote <原 endpoint> --cd <原工作目录> <原 session>` 打开独立终端；打开时不附带新提示词，不创建新业务轮次。无需存在环境阻断。空会话尚无可恢复历史、原进程退出、身份变化或实时查询失败时显示原因。首次进入未信任工作目录时，CLI 可能展示其原生目录信任提示。

CLI 窗口用于查看原会话的过程及实时输出。它是 Codex 的交互界面，仍可输入命令；任务回复、继续、停止和交付应通过 SteerLine 操作，以便中心记录命令及业务事实。控制台的“已打开”表示 Windows 成功创建窗口，CLI 后续连接失败由原生窗口显示。退出 CLI 查看窗口与停止中心服务分别操作；原 worker 仍由服务管理。此入口目前仅支持 Windows 本机 Codex，Orca 与远端候选继续使用各自的原生工具。

## 重开、关系与诊断

窗口操作记录仅保存项目绑定、候选/Decision 草稿和原请求身份；重开重置阅读布局，查询未知请求而不重发。损坏或不支持记录保留现场并阻止该窗口新外发，允许只读核实；多窗口独立锁定自己的记录。持久字段与格式由[会话设计](conversation-events.md#console-presentation)维护，不恢复已退役的阅读锚点或折叠状态。

任务详情展示阻塞原因、Spec 和交付定位；完整固定引用保留在中心契约。关系查询使用 `steerline task graph -config <path> -cursor <cursor> -limit 100`；首屏省略 cursor。每屏保留同一采样的节点、内部边与截断边界，不能将分页当完整图。基本 JSON 可由调用者重定向保存。详情、PR 与资源位置是定位线索，完成仍由中心核验真实 TaskDelivery。

配置与冻结权限见[执行方案](execution-profiles.md)，服务/数据库和工作区事实见[数据模型](data-model.md)。本页不维护 PR 变更或人工验收日志；验收结论保持在 validation，原生未测能力不能从文档或兄弟候选成功推定。

Task 丢弃和获胜/落选后，PR、工作区和分支保留，需人工在提供方/目标原生工具处置。详情保留历史路径或原生 ID、分支、PR 及采样时间；保留策略不证明资源现在存在。原执行停止/未知状态单独显示，资源人工处置不构成业务阻塞。Task 丢弃不提交 Delivery、不解锁后继；closed 后不再监控该任务任何候选的 PR 状态，保留关闭时最后已知事实；Task 丢弃后的合并核实仍按任务丢弃规则处理。

## 步骤与原执行事实

同一产品快照显示 `flow_ref/workflow_stage/workflow_status` 及三个步骤的结果绑定。implement 执行 final 是正文；report 的结构化说明与原执行终态分开，源失败显示“执行失败，报告已生成”。publish 不展示虚构报告轮，await_merge 仍无必答 Continue。报告的原生权限保证缺口据实展示；活动正文、颜色和焦点规则沿既有入口。
