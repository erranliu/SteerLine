# 异步活动中心

统一活动中心展示当前项目的异步工作。顶部常驻入口与连接状态并列，打开右侧抽屉；原检测、维护、准备、执行页继续负责业务操作。首期包含环境检测、用户显式主分支检查、测试准备批次和任务候选。后台轮询和内部检查不逐次创建活动。

## 职责和状态

统一层是观察机制。领域 owner 决定提交、执行、超时、恢复、停止及资源结算，并持久保存原请求和结果。`GET /activities` 仅从本地数据库获取来源事实，不访问 Git/Runner、不对账请求、不写业务记录，不依赖页面是否打开。没有统一活动调度器、任务队列或第二套执行状态机。

活动身份由项目、来源、源 ID 编码。候选 ID 与 RunID 分开，同 Task 的多个候选独立显示；准备批次保存自己的业务结果快照及原生成关联，新批次不覆盖历史。业务失败但关联生成未结算时，活动仍为等待，保留失败摘要；全部结算后才进入活动终态。未知原操作结果不能被一次新查询推断为完成。

展示状态为 queued/running/waiting/succeeded/failed/cancelled。`needs_attention` 是按来源当前引用、精确 Material/Generation 关联和有效候选参与关系计算的提示，和进行中/最近结束可以重叠。历史问题不重新成为当前待答，其他输入或候选的成功不清掉无关失败。

测试生成已受理但原 Runner 为 blocked 或 manual_intervention_required 时，生成模型提供只读的需处理判断。项目维护与活动中心使用同一判断；仅有受阻生成时显示等待处理，其他生成仍在运行时同时显示运行与需处理提示。原 accepted、批次生命周期及资源结算保持原义；维护页 attention 是 running 的子集，只影响展示。原停止未结算时禁用重试，资格沿用原 owner 检查。

响应的 `sampled_at` 仅代表此次数据库采样。`source_observed_at` 来自原 owner 成功取证；缺失为 unverified、超过一分钟为 stale、已知观察错误为 unavailable，均不改变业务结果。环境 owner 将独立 observation_diagnostic 与成功时间分别保存在原 Record；恢复只清除观察错误及其遗留诊断，保留无关业务事实。测试准备使用所有未结算子生成的最旧成功观察，任一缺失则无法确认整体新鲜度；本地 worker tick 不能替代外部观察。终态记录作为最终快照不要求持续心跳。测试计量只展示现有分母与已确认通过数量，不生成百分比，false 保持未完成含义。

## API 与持久事实

`storage/ports.AsyncActivityReader` 提供中性来源事实与有界读取；SQLite 每个来源使用单条 SELECT 读取自身及关联，产品 query 纯映射，App 静态注册四来源并提供项目读取路由。纯 query 不导入业务 service 或 SQLite，不持有任何执行方法。最终集合由 `MatchesAsyncActivity` 解释；SQL 只能粗筛超集，四来源真实 SQLite 组合契约阻止静默丢掉最终匹配项。

观察使用最多 2 个连接的独立 mode=ro/query_only 池，失败不回退业务连接，随原 store 关闭；每来源并行采样的总 context 预算为 1 秒，包含连接等待/SQL/解码投影检查。仍共享文件/WAL/CPU，不声称物理资源隔离。

列表支持 ongoing/attention/recent，默认每页 50、最大 200；最近结束最多 50。游标限定项目、实例和筛选，静态集合翻页不漏不重，不承诺跨请求的多来源冻结快照。每次来源窗口最多 500 行并受载荷预算约束；无法证明完整计数时返回未知/部分结果，不以零代替失败。`request_ids` 每批最多 100，精确关联查询独立于列表筛选和分页。抽屉使用 `mode=links` 专用模式，只读关联，不读取摘要/列表或返回计数/游标，禁止混用 filter/cursor/limit。

schema 41 的 `preparation_batches` 保存每个批次，settings 只指向当前批次；`preparation_associations` 在初次生成登记事务中保存原 Task/Inputs/Generation，早于外部提交。批次失败、替换或重开数据库后仍可观察原生成。`source_observations` 是独立的成功时间/错误元数据，不更新业务 revision，不参与执行决策。失败保留成功时间并关联已提交业务版本，保存失败不能写入尚未提交的尝试版本；关闭取消不写伪错误，预算超时可用最多 100ms 的独立上下文尽力保存诊断，不重试外部动作。项目未发布，拒绝旧库，不新增迁移分支。

## 界面与交互

项目顶部入口零活动也显示，分别表达正式计数、临时提交和未知结果。桌面抽屉宽度至多 440px，覆盖右侧而不推挤业务布局；原页面其余部分仍可交互。640px 及以下为全宽模态，遮罩、背景 inert、滚动锁与焦点限制同步启用。关闭/Escape 返回入口，成功导航后移交页面焦点；导航保护取消时保留抽屉。

抽屉提供进行中、需处理、最近结束筛选、加载更多、历史摘要及原详情导航，不提供停止/重试/回答。新活动和轮询不会自动打开、切筛选或抢焦点。关闭仅降低只读轮询频率，页面隐藏时暂停观察；原流程继续推进。观察失败保留最后有效卡片及确认时间。

打开状态和按 home/项目的筛选偏好保存在 keyed Workspace 外；查询、游标和临时项绑定 home/项目/实例。切项目或实例保留打开状态，清空旧范围数据再读；离开项目或换 home 关闭。列表分页与 request ID 关联查询分别管理，新增 journal 请求不会重置已加载页。只读合并原本地首次启动等待项、journal 和正式关联；未发送本地项不承诺刷新恢复，旧实例未匹配请求只保留原回执历史。

## 接入新来源

先确定活动单位、稳定原 ID、原请求关联、业务结果与资源结算边界；原 owner 补齐必要持久事实和观察时间。随后扩展中性有界读取、静态注册与纯映射，定义未知状态、提醒相关性和原详情导航。验证没有 UI 仍推进、GET 零副作用、部分故障、分页、重启和跨范围隔离。原页面迁移成统一投影另行安排，不要求一次性替换。

本功能与数据库审计摘要流 [Activity](activity.md) 职责不同。成果约束见 [Spec](../../SteerlineFlow/spec/async-activity-center.spec.md)，实施与验证安排见 [Plan](../../SteerlineFlow/plans/async-activity-center.plan.md)，实际通过、失败和未验范围见[专属验收](../../SteerlineFlow/testing/acceptance/async-activity-center.md)。本期未部署。
