# 异步活动中心

统一活动中心展示当前项目的异步工作。顶部常驻入口与连接状态并列，打开右侧抽屉。各业务页继续负责发起和处理操作。后台轮询和内部检查不逐次创建活动。

| 活动来源 | 来源标识 | 展示的工作 |
| --- | --- | --- |
| 环境检测 | `environment_detection` | 项目环境检测及各轮执行结果 |
| 显式主分支检查 | `baseline_check` | 用户发起的主分支更新检查及原命令结果 |
| 任务候选 | `task_candidate` | 候选参与、对应 Run 的执行与收尾、交付和测试进度 |
| Roadmap | `roadmap` | 草稿解析、文档生成、发布和正式入图 |
| 对话续作提示词建议 | `main_agent_advisory` | 针对原对话生成后续提示词建议的状态和结果 |

## 职责和状态

统一层是观察机制。领域 owner 决定提交、执行、超时、恢复、停止及资源结算，并持久保存原请求和结果。`GET /activities` 仅从本地数据库获取来源事实，不访问 Git/Runner、不对账请求、不写业务记录，不依赖页面是否打开。没有统一活动调度器、任务队列或第二套执行状态机。

活动身份由项目、来源、源 ID 编码。候选 ID 与 Run ID 分开，同 Task 的多个候选独立显示。候选仍有待核实的停止义务或原操作时，活动显示等待并保留此前的业务摘要。Roadmap 发布和入图按各自的原请求展示进展。

展示状态为 queued/running/waiting/succeeded/failed/cancelled。`needs_attention` 按各来源的当前关联和业务状态判断，例如仍在参与的候选等待回答、Roadmap 解析完成待确认，或当前对话的建议已生成或受阻。需处理可与进行中或最近结束重叠。

响应的 `sampled_at` 代表本次数据库采样。`source_observed_at` 表示来源最近一次成功观察。对非终态活动，缺失为 unverified，超过一分钟为 stale，已知观察错误为 unavailable。业务结果独立记录，终态记录作为最终快照展示。候选测试进度使用候选已保存的进度数据，显示已通过数量和总数，尚未通过的项计入未完成。

## API 与持久事实

`storage/ports.AsyncActivityReader` 提供中性来源事实与有界读取。SQLite 按来源查询记录及其关联，产品 query 将注册的五个来源映射为活动并由 `MatchesAsyncActivity` 判定最终匹配项。SQL 负责预筛，项目读取路由通过该只读接口获取结果。

观察使用最多 2 个连接的独立 mode=ro/query_only 池，失败不回退业务连接，随原 store 关闭；每来源并行采样的总 context 预算为 1 秒，包含连接等待/SQL/解码投影检查。仍共享文件/WAL/CPU，不声称物理资源隔离。

列表支持 ongoing/attention/recent，默认每页 50、最大 200；最近结束最多 50。游标限定项目、实例和筛选，静态集合翻页不漏不重，不承诺跨请求的多来源冻结快照。每次来源窗口最多 500 行并受载荷预算约束；无法证明完整计数时返回未知/部分结果，不以零代替失败。`request_ids` 每批最多 100，精确关联查询独立于列表筛选和分页。抽屉使用 `mode=links` 专用模式，只读关联，不读取摘要/列表或返回计数/游标，禁止混用 filter/cursor/limit。

`source_observations` 按项目、来源和源 ID 保存独立的观察信息。观察失败时保留上次成功时间，诊断关联已提交的业务版本。活动状态及执行资格仍由原业务记录决定。

## 界面与交互

### 独立阅读页

项目导航及抽屉的“打开独立页”进入 `/projects/:projectID/activities`，通过稳定 activity ID 定位摘要。桌面列表与阅读区并列，窄屏分层返回；不在独立页提交回答、停止或重试。

独立页默认仅查本地活动和有界预览。进行中/需处理仅定时更新首屏，已加载后续页不自动重取；history 显式分页，不受 recent 的 50 项总上限限制，无周期/focus/reconnect 自动重取。缺权威结束时间的终态仍参与分页，进入空值桶，以原创建时间及稳定来源 ID 排序；不借生成完成时间充当入图结束时间。

选中活动或摘要深链接不查询交互。展开“已记录交互”才取一页索引，加载更多/刷新均为显式动作；进行中只检查轻量版本标记，变化提示不推进分页。正文逐条展开、逐段继续读取；短正文已完整包含于预览时免查询。正文没有轮询，原引用校验与最多 32 MiB、空闲 5 分钟淘汰的应用级内存缓存避免每段重复读取全文。

已记录交互只投影原持久用户输入、部分已保存问题上下文、verified final 及领域生成结果。缺原 Attempt/turn 的输入标为“轮次未记录”，不以当前 Projection 补绑；工具和内部事件不进入阅读索引。最近可读样本仅为最佳努力观察，tool/null 不替换原 assistant 文本或时间，不采集完整聊天档案。业务执行与原生会话仍由原 owner/Runner 管理。契约和实际验证见[独立页 Spec](../../SteerlineFlow/spec/activity-reading-page.spec.md)及[专属验收](../../SteerlineFlow/testing/acceptance/activity-reading-page.md)。

项目顶部入口零活动也显示，分别表达正式计数、临时提交和未知结果。桌面抽屉宽度至多 440px，覆盖右侧而不推挤业务布局；原页面其余部分仍可交互。640px 及以下为全宽模态，遮罩、背景 inert、滚动锁与焦点限制同步启用。关闭/Escape 返回入口，成功导航后移交页面焦点；导航保护取消时保留抽屉。

抽屉提供进行中、需处理、最近结束筛选、加载更多、历史摘要及原详情导航，不提供停止/重试/回答。新活动和轮询不会自动打开、切筛选或抢焦点。关闭仅降低只读轮询频率，页面隐藏时暂停观察；原流程继续推进。观察失败保留最后有效卡片及确认时间。

打开状态和按 home/项目的筛选偏好保存在 keyed Workspace 外；查询、游标和临时项绑定 home/项目/实例。切项目或实例保留打开状态，清空旧范围数据再读；离开项目或换 home 关闭。列表分页与 request ID 关联查询分别管理，新增 journal 请求不会重置已加载页。只读合并原本地首次启动等待项、journal 和正式关联；未发送本地项不承诺刷新恢复，旧实例未匹配请求只保留原回执历史。

### 执行定位与页面关系

活动卡片、Roadmap 结果、检测详情和历史、候选执行及操作回执统一提供直接可用的“复制执行信息”。复制正文只保留可读操作名称、相关请求/业务记录/Task/Runner Run/Attempt ID 及短说明；相同请求与记录 ID 合并，未创建和待核实分别表达，不附带配置、路径、输入正文或日志。复制失败时就地给出同一份正文供手动复制。

活动是查找入口，业务页负责解释结果。Roadmap 历史选择只复制所选解析/文档生成的原绑定；具体澄清问题和诊断直接放在所选结果区。检测历史可进入指定检测详情，复制使用该记录的原 Run/Attempt。任务执行页合并原有两种复制按钮，继续提供过程、final 和原生查看入口。

`execution_ref` 是原持久事实的只读 ID 投影。Roadmap 发布/入图/恢复活动引用自身原请求，不将先前文档生成的 Run 当作本次运行；详情通过 `record` 与 `request_id` 联合定位。主分支检查跳回维护区域时也携带原请求。指定操作读取 `/commands/{request_id}` 并核对项目及目标/结果记录关联，展示原回执；当前业务状态仍由原查询负责。操作回执的“查看对应记录”沿同一规则定位；候选启动使用原请求对应的候选 ID。所有复制和详情查询均不提交或恢复业务。

## 接入新来源

先确定活动单位、稳定原 ID、原请求关联、业务结果与资源结算边界；原 owner 补齐必要持久事实和观察时间。随后扩展中性有界读取、静态注册与纯映射，定义未知状态、提醒相关性和原详情导航。验证没有 UI 仍推进、GET 零副作用、部分故障、分页、重启和跨范围隔离。原页面迁移成统一投影另行安排，不要求一次性替换。

本功能与数据库审计摘要流 [Activity](execution-observability.md#流程与状态活动) 职责不同。成果约束见 [Spec](../../SteerlineFlow/spec/async-activity-center.spec.md)，实施与验证安排见 [Plan](../../SteerlineFlow/plans/async-activity-center.plan.md)，实际通过、失败和未验范围见[专属验收](../../SteerlineFlow/testing/acceptance/async-activity-center.md)。本期未部署。
