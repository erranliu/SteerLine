# 人工核验

人工核验让核验人在项目页面运行候选成果、逐项记录观察，并关闭待办。负责人仍在 PR 平台决定何时切换 Ready 和合并。SteerLine 按平台证实的合并结算任务交付，核验结论和待办状态独立保存。

## Plan 与草稿 PR

需要真人操作或观察时，Plan 引用核验项 ID 并说明理由。同目录的 `<name>.manual-checks.json` 保存项目自己的启动入口、操作步骤与可观察的通过条件。生成 Plan 时可以同批生成 JSON，也可以人工编写。候选准备从固定 Plan 提交读取同名文件，保存原路径、提交、文件 SHA-256 及配置。文件缺失表示无需人工核验，存在但校验失败会阻断候选准备。修改核验要求需更新 Plan 并创建新候选。

| 字段 | 内容 |
| --- | --- |
| `version` | 必填整数 `1`。 |
| `launch.program` | 系统可执行文件名，或以 `./` 开头的仓库内相对路径。 |
| `launch.args` | 必填字符串数组，允许空数组。可以用显式解释器和脚本参数表达项目特有的准备及启动步骤。 |
| `launch.cwd` | 可选仓库相对工作目录，默认 `.`。 |
| `launch.url` | 可选回环 HTTP 预览地址，端口写为 `${PORT}`，参数中也须使用该占位符。 |
| `checks` | 按顺序执行的核验项，每项包含唯一 `id`、`title`、有序 `steps` 和 `expected`。 |

格式限制与逐字段规则见[人工核验 JSON 契约](../../SteerlineFlow/spec/manual-verification.spec.md#1-plan-伴随文件)。

SteerLine 在受理候选前核对 Runner 与 PR 平台的草稿发布能力，把草稿意图随原发布输入冻结。Runner 执行发布前步骤后提交、推送并直接创建草稿 PR。平台确认原 PR 身份、分支、完整 Head SHA 和草稿状态后，SteerLine 才建立待办。待办按候选 PR 管理，发布与合并均可先于人工核验完成。当前本机启动链路支持已绑定的 GitHub PR。

## 选择核验来源

| PR 状态 | 可用来源 |
| --- | --- |
| 开放中 | **PR 位置**。使用当前 PR Head。PR 更新后，新 Head 的核验进度从待核验开始，旧结果保留。 |
| 已合入 | **PR 位置**。使用平台在合入时确认的 PR Head，即源分支提交。 |
| 已合入 | **远端 Head**。每次启动时读取原 PR 远端目标分支的最新提交，例如 PR 目标为 `release` 时读取远端 `refs/heads/release`。页面显示该次启动实际固定的完整 SHA。 |
| 未合入而关闭，或合入前退出参与 | 待办归档，保留历史、日志和资源清理入口。 |

合入后，尚未关闭的待办继续显示。选择远端 Head 后，该次现场和结论始终归属于启动时固定的提交。远端后续更新时，再次启动即可核验新版本。

## 启动和清理

1. 核验人检查页面显示的冻结命令和选定来源，点击启动。服务端按冻结的候选 PR 身份核对平台状态，解析选定提交并保存启动尝试。
2. 服务端从绑定远端拉取 Git 对象，核实完整 SHA 后创建 detached worktree。解析与拉取之间若分支发生变化且无法证明选定提交，本次启动失败。工作目录及仓库内程序均限制在核验 worktree 内。候选自身的开发现场由 Runner 管理。
3. 宿主从冻结的 `program`、`args`、`cwd` 启动本机受管进程。预览端口由宿主分配，`${PORT}` 在参数和 URL 中使用相同值。程序以本机用户权限运行，采用精简环境。页面展示实际启动参数、进程状态、日志和就绪后的回环预览入口。每个候选、来源及 SHA 同时最多一个在途启动。
4. 页面可停止原进程，确认停止后可移除对应 worktree。移除遇到本机修改时保留现场并显示 Git 的诊断。关页面或关闭待办后，已有进程仍可从详情停止，日志和核验历史继续可查。

## 记录结论与关闭

核验人在成功启动的现场逐项记录通过或失败。失败必填实际表现或复现信息，可附证据链接。保存时服务端确认 worktree 的完整 SHA 及受跟踪文件，并记录来源、SHA、核验项、原启动、冻结配置摘要、操作者和 UTC 时间。同一来源与提交下，以每项最后一次记录为当前结论。即使两个来源恰好解析为同一个 SHA，其核验结果也分别保存。

选定来源及 SHA 下的每一项都有结论后，核验人可以点击 **标记核验完成并关闭**。通过和失败都计为已记录，关闭保存来源、SHA、操作者和时间。默认待办列表隐藏已关闭项，可通过 **显示已关闭或已归档的待办** 找回，也可重新打开已关闭项，继续补充或改用另一来源。开放 PR 的 Head 更新时，原关闭状态随旧 Head 失效，待办回到列表。

关闭操作仅作用于 SteerLine 核验待办。Ready、PR 合并及任务交付仍按原项目流程办理。协议与验证入口见[本机客户端协议](local-client-protocol.md)和[专属验收](../../SteerlineFlow/testing/acceptance/manual-verification.md)。
