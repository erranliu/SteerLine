# 架构规划约束

适用于双链路控制台、中心状态机、远程执行，以及后续并行执行、共享服务和移动端的规划。本页直接保留仍适用的边界，后续执行要求落实到各任务自己的Spec；源码归属与支持范围需要核实时按需查 [当前架构](../architecture/current-code-architecture.md)，不沿历史Spec逐层追读。

## 第一阶段平台范围

第一阶段统一只交付和验收本地 Codex 与本机 Orca。远程准入、派发、反馈、恢复、取消及本机/远端混合流程暂移出一期，也不列作一期阻塞或待补验；后续另行规划。保留既有远端代码、协议定义及历史证据，不将它们声明为当前支持或完成条件。Git remote 和托管 PR 发布仍属于本机交付链。

## 长期双执行路径

local Codex 与 Orca 均长期正式支持。backend、agent、execution target 和协议版本分开；未来远端扩展也不能把本地路径用作远程故障的隐式替代。Orca terminal v2 与 supervised 可采用不同协议实现，共用业务边界和契约测试。

## 业务权威与执行边界

SteerLine 负责任务领取、工作区与 worker 关联、五个主阶段、完整反馈送达、原会话重接、PR 关联和真实合并结项。worker 负责实现、提交、创建 PR；测试、修复、审查由任务 Spec/Plan 约定。中心不再维护项目五步编排、检查清单、修复轮次或脏目录门槛。UI/CLI 使用同一 Query/Command，复用唯一业务写者。

中心停止监督与取消执行分开；本机路径的生命周期策略明确表达。

## 身份与扩展

Task、WorkflowRun、Execution、会话/轮次、用户消息和外部平台身份分别保留归属。任务领取与结项属于任务级；agent、工作区、输出和反馈属于具体会话。业务步骤不构成worker分派状态机。每个WorkflowRun 只有一条持续 worker 会话；后续多候选扩展为一个 Task 下多个独立 WorkflowRun，不为同一候选的反馈重建 worker，中心仍只记录一个 TaskDelivery。

历史操作固定到派发时的目标及代次，配置变化和迟到消息不能重定向原执行。完成由中心按选用结果和真实交付核验。

## 原生任务与人工处置边界

原生任务复用中心状态机与 SQLite，任务 DAG 决定任务间资格，WorkflowRun/Execution 管理持续会话及交付。创建任务与加入 DAG 为同一事务，交付契约随创建固定；未交付任务只能通过受控命令追加前置，事务核验身份、版本和无环关系，保留原固定契约。PR 合并前可受控丢弃，但不释放后继或抹去执行事实。已合并 PR 的任务不可丢弃或补前置。新规划改变固定交付范围或要移除旧前置时，须重新规划受影响任务，不能用普通反馈或追加边改写旧契约。

用户可通过 Codex 分析并人工处置任务与成果，系统不承诺自动修复任意人工改动。当前格式重启先核验原请求及执行事实；仍存活的原会话可接回观察，已终止的本地 worker 由用户明确选择后在新 Attempt 继续。原 thread 无法核实时，新会话也必须明确选择。关系视图和UI均不成为业务写者；未核实原执行或其他写者时保留未知状态，不自动创建替代worker。

## 后续远端设计边界

以下仅保留后续设计约束，不纳入一期交付或验收：远端只需 Orca、agent 和仓库工具，不要求部署 SteerLine 服务或共享中心磁盘；远端路径属于其目标，不能当作本机文件。远端失联也不能自动改投本机；必须独立规划其权限、原身份和恢复/取消能力。

## 未发布版本的兼容策略

SteerLine 目前是未发布版本。默认不要求兼容先前开发版本的数据、数据库结构、配置或 SteerLine 自身协议；只有具体 Spec 明确列为交付要求时才保留兼容。上线前不为旧 runtime、旧数据库或 Beads 历史建设迁移和回退流程。检测到不支持的旧状态时阻止有副作用操作，不能通过静默重建掩盖可能仍在运行的外部执行。Orca 等外部平台只启用已实测的版本与能力。

## 证据与恢复

外部动作的意图、回执和不确定性可恢复；超时不能证明没有副作用，不能盲目重派。消息内容先持久化，再推进游标或确认接收。平台能力以具体版本/目标的原生证据为准。

当前格式内的重启、故障对账和数据完整性仍需验证。共享部署与多进程演进继续保持事务或等价并发控制，不改变固定身份、原请求对账和唯一交付。
