# 二期草稿 Roadmap 与审核准入目标

目标标识：`PHASE2-DRAFT-ROADMAP-ADMISSION`。

二期逐步实现主agent维护草稿、独立审核agent检查内容与成熟度、SteerLine受控纳入正式roadmap的流程。一期认为roadmap和任务契约由外部稳定提供，只交付人工方案实验与执行，不等待本目标。

本文是目标级规划，不创建具体Spec/Plan、审核任务、任务ID或运行时DAG边。当前 #43–#53提供原能力/协议/规划/UI基础；新增审核门槛尚未包含在其固定Spec中，受影响范围在实施前正式对齐，不通过一段目标文档隐式扩大任务。

## 文档与 DAG 的对应

roadmap.md 是主 agent 与人讨论和修改的草稿；execution-map.md 是已经进入中心 Task DAG 的正式任务映射。日常执行只从后者选任务，核对真实项目、Task 状态/版本、固定契约和依赖；两张表不要求相同集合。原有编号或 Spec/Plan 可以留作草稿材料，不自动准入。

本次正式表先清空且未核对中心 DAG，不能据此宣称中心为空或取消已有 Task。后续准入/变更完成后沿真实回执及当前 DAG 同步；空表、证据未知或文件与 DAG 不一致时不从草稿派发。新增二期自动审核流程仍是待交付目标。

## 草稿与正式任务边界

草稿roadmap允许主agent讨论、拆分、修改Spec/Plan及依赖建议；这些变化不立即占正式任务编号、不冻结执行契约、不启动worker。草稿可引用已知正式任务和前置结果，但不能反向修改正式任务。新草稿默认使用临时标签；既有占号和候选文档保留其身份，不表示已准入。

正式roadmap是SteerLine面对的单一可执行任务集合。任务成员、状态和DAG继续由中心受控写链路维护；正式文档及其版本表达与任务一致的内容，不构成另一条任意写入入口。具体Git版本/文档发布/ID映射方式留给后续Spec，不在本目标里承诺跨Git和SQLite原子事务。

加入正式集合必须经过授权、固定内容、审核与机械校验。完成移出为归档，未完成移出为受控丢弃；历史、交付与资源事实保留。已固定任务范围改变通过受控替换处理，不能因为草稿删除一行就取消执行。

## 固定角色与授权

| 所有者 | 职责 | 权限边界 |
| --- | --- | --- |
| 人 | 决定目标、授权送审/正式准入范围、处理分歧并合并成果PR | 授权绑定精确批次与内容，不用模糊对话作为命令 |
| 主agent | 相对自由维护草稿，解释执行成果与待审问题 | 不写正式任务、不启动worker、不调用子agent或审核调度工具 |
| 审核agent | 读取固定快照、正式任务及前置证据，给出内容质量与成熟度结论 | 由服务独立调度；不直接编辑正式roadmap或替主agent执行任务 |
| SteerLine | 校验授权/快照/审核归属与前值，办理正式加入、执行、丢弃与归档 | 唯一受控写链路；agent的文字不是直接入图许可 |

只增加两个固定角色，不建立agent树、动态协作协议或通用编排平台。主agent仍以二期Codex能力为基础；审核协议及其权限必须在实际接入时验证，不能直接继承任务worker的宽权限。规划/审核来源不伪造Task、Workflow或Execution身份。

人的送审可以按后续明确策略同时授权“这批固定内容审核通过后纳入正式集合”，避免重复确认；权限必须由服务记录和校验。正式纳入之后是否自动开始仍由原派发模式决定，审核agent不能改变派发策略。

## 审核质量与可固定程度

审核既检查Spec/Plan一致性、范围、依赖和验收可执行性，也检查前置是否还会影响核心模型、接口、权限、任务边界或验收。把“可以固定”与“可以执行”分开：契约稳定但前置未交付的任务可先进入正式roadmap，领取仍等待DAG条件；关键前置尚未确定时继续留草稿。

| 结论 | 处理 |
| --- | --- |
| 合格且适合固定 | 通过服务机械校验和授权后准入 |
| 内容需要修改 | 留草稿，主agent按明确问题修订 |
| 内容基本合格但前置未稳定 | 留草稿，记录影响前置、未稳定点、所需证据和复审条件 |

等待前置不视为Spec写作错误，不反复要求主agent重写。复审优先由相关前置交付/契约稳定、草稿实质变化或人的请求触发；未变化草稿不反复全量审核。该触发机制由二期实现，不在本次创建定时任务。

## 送审与正式准入

1. SteerLine固定送审批次的内容摘要、Spec/Plan、依赖和正式基线/证据版本。审核读取快照，草稿仍可继续编辑。
2. 审核报告绑定该快照和来源身份。草稿新版本、关键前置变化或正式基线变动不能沿用旧结论，按影响重新校验或复审。
3. 准入前执行机械身份/路径/依赖/版本校验，核对人的授权和审核结论。任务ID及内容映射若需要改变，不得把未经复核的新正文当作原审核内容；具体分配时点在正式Spec中固定。
4. SteerLine通过现有任务创建用例固定契约、依赖及回执进入DAG，核对当前 DAG 后同步 execution-map.md，只执行正式清单内且满足中心资格的任务。未知或丢失回执按原请求对账，不重复创建。
5. 任务执行和唯一交付回传规划。主agent继续修改草稿，正式任务的加入和移出保持受控，审核结论不等同于任务完成。

保留原请求幂等、精确身份、当前格式恢复和原生权限证据。自由草稿编辑不承担所有正式发布约束；复杂性集中在固定送审与正式准入边界，不为每次讨论创建发布状态机。
