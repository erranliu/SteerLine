# 控制台规划约束

适用于执行控制台、会话展示和人工介入的后续规划。本页保留当前产品边界；后续任务把所需要求写入自己的Spec，不以已交付控制台/会话Spec作为通用必读前置。

## 服务与操作

UI 生命周期与服务、worker 分离；浏览和关闭 UI 不启动或取消任务。任务操作由服务核验，界面显示准确目标、请求身份和真实结果；已提交、已接受、已执行不混同。后端能力和业务资格同时满足时才允许操作。

Windows 服务由用户从固定入口打开的可见服务窗口承载，窗口可最小化；控制台只是独立客户端。离线时显示 `window-required` 和固定入口，不由客户端代启后台进程；服务窗口关闭会结束服务。连接异常或存活未知时保留原实例并显示诊断，显式停服须核验 applied 回执、原进程退出和锁释放。Linux detached 路径按其平台能力展示。

## 会话与按需阅读

进度消息 commentary、最终回复 final_answer、轮次结束、执行结果和业务完成分别表达。local 与 Orca 使用同一会话读模型；真实协议无法提供的阶段/轮次不能靠文本或静默时间猜测。

三窗主界面保留最近最多10条规范活动、内嵌操作和有界 final 预览；完整最终回复、问题背景、历史决策与诊断按需阅读。过程时间线、工具正文、轮次折叠和跨重启阅读位置已退役，不因布局优化恢复；错误、缺口和未解决问题保持可见。新轮次动态优先于旧结果与已终态回执，详情按键不得触发隐藏操作。具体行为见[主界面体验 Spec](../spec/console-primary-workspace.spec.md)。

## 统一待决策与反馈

持续worker流程中，未完成且停下需要人工输入的执行统一进入待决策。选项、任意文字及选项加备注使用同一个反馈入口，完整发送到原 worker 会话。保存、送达和轮次开始是传输事实，不要求 agent 回传应用证明，也不展示未经证实的“已落实”。错误、部分提交和连接未知作为原因信息展示，不再各自对应专用重试/恢复按钮。服务操作、明确丢弃和宿主登录/授权入口保留其各自语义。

两条执行路径的实际能力可以不同，不能通过隐式重启或跨后端替换伪造同等恢复能力；概要和布局压缩不能隐藏待处理决策。

## 人工候选实验

每 Task 一条主行，主界面按稳定 WorkflowRun ID 选择当前及历史候选；正文、草稿、请求和本次临时阅读上下文隔离到 Task/WorkflowRun/Execution/session。不同方案冻结配置逐个新增，5个只做开始检查，无硬名额/预留/队列/自动补位。合并前不可撤销放弃仅退出实验，worker 停止独立核实；已知合并后禁止放弃。环境 blocker 与原业务 Decision 分别展示，解除后仍需人工重新提交草稿。获胜只依据唯一 TaskDelivery，历史 PR 和落选资源保留定位。当前键位为 F6/F7（或 `{` / `}`）选择、a/Enter 输入、F8 背景/身份、F2 提交、`b` 新增、`z` 放弃；#38 CC5 已由用户人工确认通过，见[人工确认记录](../validation/candidate-interaction-ux/manual-acceptance-20261004.md)。
