# 控制台规划约束

适用于执行控制台、会话展示和人工介入的后续规划。此文不承担具体执行契约。

## 服务与操作

UI 生命周期与服务、worker 分离；浏览和关闭 UI 不启动或取消任务。任务操作由服务核验，界面显示准确目标、请求身份和真实结果；已提交、已接受、已执行不混同。后端能力和业务资格同时满足时才允许操作。

落地规格：[服务生命周期](../spec/pr-03-service-lifecycle.spec.md)、[双后端契约](../spec/pr-04a-execution-backends.spec.md)、[控制台](../spec/pr-04-console.spec.md)。

## 会话与折叠

进度消息 commentary、最终回复 final_answer、轮次结束、执行结果和业务完成分别表达。local 与 Orca 使用同一会话读模型；真实协议无法提供的阶段/轮次不能靠文本或静默时间猜测。

过程可以折叠，明确轮次结束后自动收起一次；最终回复完整可读。手动展开、阅读位置和历史消息保持稳定。折叠是 UI 视图状态，不修改业务状态或删除日志；错误、缺口和未解决问题保持可见。

落地规格：[会话事件](../spec/pr-04b-conversation-events.spec.md)、[控制台](../spec/pr-04-console.spec.md)。

## 决策与恢复

答案保存、服务接受、平台接受、轮次开始和答案应用分开记录。已接受输入不证明问题已经解决；恢复必须绑定原问题、attempt、执行身份和固定答案。业务回答与宿主登录/授权提示分开。

两条执行路径的实际能力可以不同，不能通过隐式重启或跨后端替换伪造同等恢复能力；折叠不能隐藏待处理决策。

落地规格：[人工决策与恢复](../spec/pr-05-intervention.spec.md)。
