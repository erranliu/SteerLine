# 第一阶段安装与运行交付

第一阶段以 #36 的持续 worker 流程为基线：中心负责启动、原会话反馈、主阶段和真实 PR 交付；worker 的测试、修复、审查要求来自任务 Spec/Plan。活动任务及前置见[主 roadmap](roadmap.md)和[执行依赖](execution-map.md)。

一期假定roadmap和任务契约由外部规划稳定提供。草稿roadmap、主agent、审核成熟度与正式准入机制留在二期，见[二期目标](phase2-draft-roadmap-admission.md)。近期运行范围改为单安装版与独立源码调试路径，完整 stable/dev 版本管理及提升延后。

## 当前平台范围

第一阶段统一只交付和验收本地 Codex 与本机 Orca。远程准入、派发、反馈、恢复、取消及本机/远端混合流程暂移出一期，也不列作一期阻塞或待补验；后续另行规划。保留既有远端代码、协议定义及历史证据，不将它们声明为当前支持或完成条件。Git remote 和托管 PR 发布仍属于本机交付链。

## 已具备基础与剩余交付

持续 worker、本机候选实验、独立原会话反馈、唯一真实交付及候选 TUI 已具备。实验默认一个候选，人工按不同冻结配置逐个新增；五个只做宽松开始检查，合并前放弃立即退出实验，资源停止事实独立，合并后拒绝放弃。中心保持唯一交付，人比较和选择成果。

#83 提供最小本机共存：日常安装 exe 不被源码 build 覆盖；调试入口显式绑定工作树 exe、独立 home/config，并让服务、控制台、CLI 及子进程继续使用同一套实际路径。显式状态/工作区路径不能指回安装版；调试默认使用独立测试 clone，沿用同仓库单写锁。诊断显示实际路径与构建来源，不建立版本选择系统。

#42 汇合本机候选与 #83：精确安装产物上的两条本机依赖链、固定 exe/home 连续 24 小时且交付至少五个真实任务、源码调试共存，以及同一安装构建的当前格式等待合并重启。已有 L2/L3 按构建和接线影响复用；短时 E2E 不替代安装入口和长期运行证明，不重复完整上游矩阵。

#40/#41 保留原身份与待重定草案，不作为一期/二期前置。频繁更新长期运行安装版、保留空闲会话/待合并 PR/未发送反馈，或外部发布产生明确维护需求时再规划。届时复核实际状态格式及 #83 已具备能力，不直接启动旧草案。

## 与第二阶段的关系

近期产品路线优先 #45 本机 API，再由 #44/#45 交付 #50 执行与待处理界面。#43 先验证规划权限/工具能力，#44 提供原生输入基座；草稿/审核/准入在实施前按二期方向细化。第二阶段最终 #53 汇合四页面及单安装版 #42；#42 的 24 小时不成为 API/UI 研发前置，#40/#41 不在该最终链。

## 状态与交付边界

采用各任务明确的新协议/状态格式；不保留旧步骤流程、schema 5 专项迁移或双摘要回退。当前格式同构建重启、原消息对账和真实 TaskDelivery 仍须通过。验收安装构建保持干净 commit 与固定 SHA-256；这与 worker 项目文件状态分别处理。

人工更新先核实并结算外部执行，再停中心、替换安装产物和启动；停止监督不等于停止 worker。当前不承诺跨构建接管活动状态，不迁移或清空旧格式数据。

仓库规划不修改中心已固定契约或 DAG。执行前核对 Task 的 commit/摘要/依赖；旧版本契约须先受控替换并同步消费者身份，延后任务的运行时处置须取得回执，不能凭文档改边解除阻塞。
