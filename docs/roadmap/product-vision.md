# SteerLine 产品愿景

## 产品定义

SteerLine 是一款带有研究性质的开发工具，长期远景是通往**工程 AGI**：让 AI 最终能够自主开发复杂软件项目，包括普通人需要长期借助 AI 协助才能完成的项目。下面四个交付节点是通往这一目标的阶段；第四版仍只实现有限自主推进。

当前产品形态以 roadmap 为中心：把选定的产品目标转为有依赖的任务，协调本机 Codex 或 Orca 远端执行，完成验证、审查和提 PR，并记录真实交付结果。人决定产品取舍、处理超出授权的事项，并负责合并 PR；SteerLine 核验合并后才认定交付完成。任务创建时即进入 DAG，规格和依赖随之固定；PR 合并前可受控丢弃任务，后续规划不能暗中改写已创建的任务。

具体底层能力与实施顺序见[主 roadmap](roadmap.md)。本文件只定义四个产品交付节点。

## 交付节点

### 1. Codex 规划，SteerLine 执行

人在 Codex 中规划和维护 roadmap；项目 skill 将选定范围连同任务 ID 整理为 Spec/Plan 与任务 DAG，提交给 SteerLine 校验并创建入图。SteerLine 只接收并执行任务：支持本机 Codex 和 Orca 远端、人工接手执行决策、验证与审查、提 PR、核验人工合并并释放后继任务。交付结果由人带回 Codex 继续规划。此版不提供 SteerLine 内的 roadmap 规划或 Roadmap UI。

**交付判定：**一组有依赖的任务经 skill 创建入图后完成执行、人工决策、提 PR、人工合并和合并核验；本机与 Orca 远端各自通过执行链路验收。

### 2. 人与主 agent 受控推进 roadmap

Roadmap 规划进入 SteerLine。人通过与主 agent 交互确定目标、审阅规划与变更，并确认任务创建和执行决策。Roadmap UI 稳定查看和管理目标、Spec/Plan、任务 DAG、运行、决策、PR 与交付证据，保留版本和关联。主 agent 提建议、生成草稿并解释影响；没有人的确认，不自行推进新的规划或创建任务。

**交付判定：**人能在 UI 中与主 agent 完成一次从目标讨论、确认创建 DAG、执行到人工合并 PR 和更新 roadmap 的完整闭环，并追溯相关 artifact。

### 3. 正式可发布产品

第二版能力达到正式发布标准：可重复安装和接入项目，明确平台与后端支持范围，提供用户文档、故障诊断及可复现的端到端和恢复验收。重启和外部动作结果不确定时，任务、规划、决策与交付证据保持一致，不重复派发或错误结项。正式发布后的升级策略在该阶段确定；上线前不建设旧版本数据迁移。roadmap 仍由人受控推进。

**交付判定：**新用户可按文档完成完整闭环；当前版本的服务重启可保留任务、待处理事项和交付证据。

### 4. 主 agent 有限自主推进 roadmap

人预先设定目标、授权范围和资源边界后，主 agent 可在范围内选择下一步、维护规划、创建任务并监督执行。它先处理有充分依据且已获授权的 worker 问题；遇到产品取舍、权限、证据不足或越界情况，就暂停受影响的推进，向人说明原因并等待决策。人可随时暂停或接手；PR 仍由人合并。自主动作及答案都保留依据、版本和回执。

**交付判定：**主 agent 能独立推进授权范围内的任务，在需要人决策时准确停下并恢复；重启后不重复操作，未授权范围不推进。
