# Roadmap 目录说明

本目录维护随项目进度持续更新的后续规划，包括长期计划、下一阶段计划，以及规划所需的长期约束和局部系统约束。

SteerLine 现阶段的产品目标是：以 roadmap 为核心的自动化软件开发系统。规划、规格、执行和交付反馈形成持续推进的过程，本目录先明确这一过程的文档边界。

## 文档组织

- [product-vision.md](product-vision.md) 描述从当前版本出发的后续产品目标和计划。不限定颗粒度，可以是一句话目标，也可以是具体版本交付计划、功能设计或技术选型；可选链接产品设计文档，不要求列执行约束、Spec 链接或排定执行依赖。
- [roadmap.md](roadmap.md) 是近期与后续推进的主入口，承接从产品方向中选出的目标，描述范围、优先顺序与关键前置，链接具体 Spec。
- [execution-map.md](execution-map.md) 描述已进入 roadmap 的目标之间的依赖、接口交接、共享修改范围、冲突和并行条件。目标一进入 roadmap 就加入关系表，不等到形成 Spec 或开始执行。
- Roadmap 可以由多个文档组成，主文档负责组织和链接。
- 长期约束、局部系统约束通常放在独立文档中，主文档只链接相关约束，不重复展开。
- 主文档不维护文档形成、提交、PR 创建或合并情况，不设置这些状态列、提交 SHA、合并清单或基线核对记录。规划内容的增删体现项目进展，无需记录维护动作本身。

## 从产品计划到执行

```text
product-vision.md
  → 选出目标并移入 roadmap.md，同时建立 execution-map.md 关系
  → 形成 docs/spec/ 下的 Spec 或 Spec + Plan
  → 按 Spec 实现、验证和交付
  → 根据实际结果收缩剩余规划、调整依赖，再选择后续目标
```

- 产品计划持续以当前版本为起点；不是固定不变的远期宣言，也不积累已经完成的版本历史。
- 选定推进范围时，将其具体内容移入 roadmap，避免两处维护相同交付清单。较大目标只移出选中的部分，产品文档保留剩余范围；后续仍需依赖的总目标可以保留必要概述。
- Roadmap 中的目标使用稳定标识，关系表按目标而非 Spec 文件建模。一个目标可以拆成多个 Spec，一个 Spec 也可覆盖多个目标；拆分时保持可追踪的映射，不因文件改名重建目标身份。
- 关系表中区分“Spec 已固定的要求”和“规划假设/待确定项”；有 Spec 时链接相关章节，没有 Spec 时直接表达待确定的边界，不维护文档形成状态。
- 关系至少区分硬前置、接口前置和共享修改冲突，并分别说明开工条件、合并/集成条件。未知依赖不代表允许并行；代码文件不重叠也不能证明协议、业务状态或平台资源互不影响。
- 关系表中的并行建议不自动改变既有 Spec 的串行要求。决定调整执行安排时，将职责、接口、前置和验收条件落实到所有受影响 Spec，再按新契约执行。

## 与 Spec 的关系

- Roadmap 不能直接作为执行依据。执行前，必须将相应内容落实为 `docs/spec/` 下的 Spec，或 Spec + Plan。
- 已经形成 Spec 的规划项必须附对应 Spec 链接，必要时附 Plan 链接；链接用于定位执行契约，不维护文档形成过程或合入状态。
- 具体执行 Spec 和 Plan 不得引用或依赖本目录文档，也不能通过其他说明文档间接依赖这里的执行要求。执行所需的约束、范围、依赖和验收条件必须完整落实到 Spec 体系中。
- Roadmap 后续变化不会自动修改执行要求；需要改变执行要求时，同步修订对应 Spec/Plan。执行范围以明确选定的 Spec/Plan 为准。
- 引用方向为本目录指向 Spec/Plan。产品计划、关系表和约束文档都不能成为绕过 Spec 的执行入口；关系摘要与 Spec 不一致时先核对并修订，不凭摘要放宽门槛。

## 随项目进度维护

- 每个 PR 合入时，主文档都必须同步反映合入后的剩余规划。维护动作随对应 PR 完成：删除已完成范围，调整剩余目标、依赖、顺序和相关规格链接。
- 主文档只表达规划本身的变化。纯文档整理或不影响剩余规划的改动，核对规划仍然适用即可，不添加“文档已形成”“某 PR 已合入”或仅表示已核对的记录，也不再发起用于登记这次维护的循环更新。
- 已通过 PR 合入完成的规划内容移出 roadmap；部分完成的只保留剩余范围。
- 已完成内容仍被后续步骤依赖时，仅保留必要的依赖信息，并明确依赖它的后续步骤。依赖结束后删除。
- 产品计划中的具体范围移入主 roadmap 后，不再两处重复维护。形成 Spec 后，roadmap 仍保留未交付目标的摘要、关系和规格链接，不复制执行细节；目标交付后再移除相应规划条目和关系，仍有消费者的仅保留必要交接信息。共同方向与约束在仍有后续适用范围时保留。
- 长期或局部约束在仍约束后续工作期间保留；失效或不再被后续工作依赖时删除。这些文档同样不承担执行历史记录职责。
- Roadmap 只保留未完成规划及后续工作仍需依赖的已完成信息，不设置归档或回退机制。
