# 迁移实现审计（2026-09-29）

审计依据为项目 AGENTS.md 和迁移 Spec，重点检查并行、原生身份、SQLite 持久化与当前格式恢复。

## 已修复

| 问题 | 修复与验证 |
| --- | --- |
| 第二轮启动途中重启会读取上一轮 Command/turn；Command ID 曾临时写入原生 turn 字段 | 待启动 Command 优先按自己的原生回执恢复；没有回执保持未知。新增回执存在/丢失两种恢复测试，确认不改写上一轮日志。 |
| 重放 `turn/started` 会拒绝已消费的 Command，或误把运行中答案标为接受 | 统一处理原生启动证据；重复事件保留待答状态，只在首次开始新轮次时接受结束后反馈。 |
| 定时恢复会与尚未完成的异步启动竞争；运行期间的慢重接占用中心处理循环 | 跟踪本进程正在执行的启动/恢复操作；启动恢复仍完成一轮有界核验，运行期间重接通过后台操作回传中心。测试覆盖启动竞争、慢连接与取消。 |
| 保存后继续修改旧 Execution/Workflow 指针，导致 SQLite 丢失轮次或队列更新 | 在保存边界重新取得权威记录；上一条答案先保存送达状态，再切换下一题。数据库回归断言原 Decision 已接受、队列已消费。 |
| 事件失败未确认，观察器一直等待；迟到答复可能修改终态任务 | 所有事件处理出口确认成功或失败；状态保存成功后才确认事件；失效观察器和终态任务拒绝迟到结果。 |
| RPC 超时不能中断阻塞写入，握手也可能忽略取消 | 请求取消关闭所属连接，写入有界；用阻塞连接验证取消会释放操作。 |
| 连接中断被提示为“本轮已结束”，并生成无法投递的普通反馈 | 未核实的原生 turn 保留未知状态，避免创建结束后反馈；重接确认活动后恢复运行状态。 |
| 多题提示遗漏 question ID 与各题选项，长问题被截断 | 使用已有 Decision 上下文展示完整题目、ID、选项和说明；无法完整展示的请求明确拒绝。 |

## 验证与限制

新增定向测试通过，包括真实 SQLite 持久化和 loopback WebSocket 故障注入；测试不依赖 Windows 子进程脱离 Job Object。另用进程内 mock app-server 驱动真实 Service 连续完成两个 turn，核对每轮 Command、原生 turn、停止状态及原 thread 的持久化；它不替代 detached 子进程生命周期验收。修复后的 `go test ./... -count=1` 全量通过（核心包约 395 秒），后补的 Service 两轮测试单独通过；`go vet ./...`、Windows/Linux 构建及 `git diff --check` 通过。汇总见 [验收状态](status.md)。

当前环境 `CGO_ENABLED=0` 且未找到 gcc/clang，未能运行 Go race detector。原生双任务/问答/同 thread 反馈的真机协议探针沿用[已有证据](probe-2026-09-29.md)；SteerLine 服务退出后跨 Job Object 存活的完整验收仍未完成，本次审计不将其标为通过。
