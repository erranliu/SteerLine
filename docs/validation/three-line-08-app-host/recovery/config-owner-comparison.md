# F1 configuration owner comparison

## Result

The initial ownership move had one real non-empty-requirements regression: it never committed a claim/frozen profile for an otherwise valid selected profile. That blanket “no requirements field changed” conclusion was wrong and is superseded by the evidence below. The repair restores the base behavior: evaluate requirements, bind that evaluation to the selected profile and freeze it before the final strict check/commit. The fixed profile version remains `6`; `FixedExecutionProfile` keeps its existing fields and JSON shape. The app profile port resolves the same profile ID and accepted project/global config digest before a claim.
