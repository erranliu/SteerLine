# 人工并行启动任务 Plan

## 实施步骤

1. 将服务的单个 `worker`/`active` 和当前执行配置改为按 WorkflowRun 定位的活动执行集合。中心仍串行处理状态转换与控制请求；worker 观察结果携带 Run/Attempt 身份回到中心。运行配置从已冻结的 ExecutionProfile 重建，不依赖“当前项目配置”。
2. 让人工 `start_task` 的控制预检、候选查询和原生任务领取跳过项目级执行占用判断。保留同任务 CAS、DAG 前置、暂停、模式、能力、固定契约及配置核验。自动派发继续使用单活动判断。
3. 将步骤完成、回答决策、重试、丢弃清理、资源释放、PR 轮询和服务关闭改为按目标运行定位 worker 与配置。每个运行独立刷新状态；项目级控制操作仍一次一个，且完成回执写入后才受理下一个。
4. 重启时对所有未结算运行逐一做原身份恢复。为不可重接的运行保留未知状态和外部身份；不能用全局 `CurrentTask` 代表多运行的恢复依据。
5. 调整控制台 Ready/启动许可及服务状态展示。人工模式显示活动任务数量和每个运行，不用单槽忙阻止其他 Ready 项；自动模式清楚显示等待现有运行结算。
6. 用隔离原生项目验收两个与三个不同任务并行、不同配置、并发领取 CAS、跨任务事件隔离、决策与未知状态、重启、停止以及自动串行。执行受影响包测试、`go vet` 和 Windows 构建后再替换运行版。

## 发布顺序

先在隔离测试项目验证并行执行及重启；当前生产 SteerLine 任务结算后再更新服务二进制。发布时关闭旧服务、保存当前格式状态备份、替换二进制并启动新服务。对正在运行的外部执行不得通过删除状态或强制重领绕过恢复门槛。
