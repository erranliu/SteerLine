# 主 Agent：给定上下文中的后续对话提示词建议

状态：目标契约，分阶段实施中。用户于 2026-11-09 授权先交付模块重构 Draft PR，严格边界不变，生产建议生成保持阻断。本草稿不声明完整功能交付。调查基线为 SteerLine `e9ee368f753322145457f1730b2309a68d566f83`，原实现及原测试见[历史验收](../testing/acceptance/main-agent-materials.md)。

当前阶段完成独立 contract/core、宿主本地异步记录、只读详情与活动投影，删除原答案/材料发布能力。原生零工具及排除隐式上下文未通过，故代码不装配任何模型或 Runner 提交客户端；模型偏好仅保存。首批来源适配器只认明确的两类原因码，实际生产方是否持续提供这些码仍未验证。完整自动生成、真实来源、失败时部分材料展示及人工体验仍以专属验收的未完成项为准。后续开放生成须另行补齐 Runner 能力与真实验证，不由配置开关启用。

## 1. 目标与唯一产物

**本次核心目标是建立清楚、可独立验证的模块边界；功能只做验证该边界所需的最小接入。** 交付重点是独立输入/输出协议、依赖方向、状态与资源所有权，以及零工具约束。自动异步生成、查看/复制及活动中心接入构成最小闭环，不以完善主 Agent 产品工作台为目标。

实施取舍按以下顺序：先把核心与宿主、Runner、业务状态和 Web 分开，再把一个明确来源接进现有链路。能由现有业务事实、队列、生命周期、查询和活动来源承担的职责直接复用；不为将来扩展提前建设框架。模块边界未满足时，增加界面或更多场景不算完成。

主 Agent 接收调用方明确提供的相关上下文，生成**一段供继续对话使用的提示词建议**。用户可以采用、修改或忽略；这些行为，以及提示词被交给谁、随后做什么，全部在主 Agent 模块之外。

宿主拿到明确的待处理状态后，自动冻结相关上下文、登记并异步生成建议，无需用户先打开页面或点击生成。这里的“自动处理”只到提示词生成和推理资源结算；不自动采用、修改或执行提示词。主 Agent 核心不监听项目状态、不发现问题，由外部场景 owner 决定何时需要建议。

主 Agent 的唯一业务产物是非空 UTF-8 字符串 `prompt`。它可以有自然段或条目，但仍是一份可编辑的提示词正文。没有另一份分析报告、问题列表、执行计划、Spec/Plan 新正文、结构化答案、动作提案或工具调用产物。材料不足时，把需要补充、核实或讨论的内容写进这段提示词；不发起材料获取或自动追问轮次。

例如给定“Spec 要求空输入报错，执行者询问是否返回默认值”的上下文，可建议：

> 请依据已提供的 Spec 核实空输入行为，说明现有要求是否已经足够明确；如果仍存在歧义，请列出需要我确认的具体问题，先继续讨论。

这段文字不代表已回答原问题、批准改需求或授权执行。

## 3. 独立模块与稳定协议

### 3.1 业务协议

协议标识为 `steerline-main-agent/advisory-v1`，能力固定为 `advisory`。这是明确的当前能力身份，不是可以切换为自主执行的设置。未知协议或能力值拒绝。

请求只包含以下业务字段；外层宿主仍负责鉴权、项目/实例路由及生成状态：

| 字段 | 含义 |
| --- | --- |
| `protocol` | 固定为上述标识 |
| `request_id` | 调用方生成的不可变请求 ID，沿现有 32 位小写十六进制规范 |
| `capability` | 固定 `advisory` |
| `context.goal` | 希望这段提示词帮助继续讨论什么；非空 |
| `context.user_input` | 用户本次补充，允许为空 |
| `context.materials[]` | 已选定并提供完整正文的材料；每项包含唯一 `id`、`label`、`body`，可带来源展示 `source` 和 `revision` |

`source/revision` 是供理解来源的描述，不是文件读取、链接访问或资源解析指令。核心不要求 Candidate、Run、仓库路径、Spec/Plan 路径或 question；候选入口将所需事实转为材料正文。上下文以本次提供值为准，不自动读取历史。用户确需继续生成时，外部调用方显式提供新的完整上下文并使用新请求 ID。

成功结果业务字段为 `protocol`、`request_id`、`prompt`。运输或存储可以有宿主生成状态、诊断和来源校验信息，但不把这些元数据伪装成另一份建议产物，也不向前端返回内部 Runner Request/Projection/BuildPin。

输入上下文序列化后最多 1 MiB，最多 64 项材料；输出提示词最多 16 KiB，均按 UTF-8 字节计算，空白输出拒绝。重复材料 ID、非法 UTF-8、未知字段、超限均明确拒绝，不静默截断、压缩或替换材料。详情应能查看本次提供的材料及缺失/超限原因，不增加生成前材料编辑器，不为满足限制自主挑选另一些材料。

### 3.2 依赖与归属

- `internal/mainagent/contract` 拥有上述 DTO 和版本约束，只依赖标准库；不混入 Runner、SQLite、HTTP 或候选模型。
- `internal/mainagent` 拥有输入约束、固定提示词材料的同包组装调用及输出校验；通过宿主接收推理文本。不得依赖 app、Runner、数据库、Git、网络、进程、工具、MCP 或任务命令接口。
- 宿主适配器负责读取允许的业务事实、冻结完整输入、调用现有共享 Runner 推理基础设施、保存原请求和来源、取消及结算。核心接收的上下文不包含用于回调读取的对象、闭包或 resolver。
- SQLite 负责原子写入、唯一性和预期 revision 竞争检查；业务状态由唯一生成 owner 判断。宿主不得随意修改核心产物或按当前上下文重建原请求。
- 共享模型配置、预算和资源停止沿[生命周期规则](../../docs/product-design/worker-lifecycle.md)。模型生成的启动/观察/取消属于宿主基础设施，不是主 Agent 对外业务执行能力。

实现可共用进程和数据库；不要求微服务、独立数据库、消息总线、插件框架或泛化动作协议。

本轮不提供模块内多轮讨论、Web 提示词编辑器/草稿管理、材料选择/编辑器、补充信息重新生成入口、独立历史工作台、通用事项中心或自动采用/执行。用户复制到外部后如何修改与使用，不增加本模块状态。协议可接受调用方明确提供的新请求，但不因此要求本次交付新的 Web/CLI 发起流程。

### 3.3 自动触发与事项身份（宿主协议）

外部业务 owner 提供持久的 `AdviceNeeded` 事实，最少包含项目、`source_kind/source_id`、稳定 `occurrence_id`、来源版本、原因、是否仍需处理，以及用于构建本次上下文的明确事实。首批原因只包括 `requirements_unclear` 和 `requirements_conflict`；这是调用方已标明的处理需要，不是主 Agent 生成的分类。候选原问题可携带原 Question/Attempt 身份，材料问题可使用原 owner 的稳定问题 ID。

`AdviceNeeded` 是对已有业务状态的窄输入投影，不是新建的通用事项系统。首批只实现一个候选材料问题来源适配器，复用原 owner 的记录和问题身份；来源缺少明确原因时，仅补该来源必要字段。不增加新的问题注册中心、来源插件或跨模块事件基础设施。

当前原生 Question 及活动的通用 `needs_attention` 不保证包含上述业务分类。对尚未标记类型的普通待答、审批、环境/配置错误或未知运行异常，不根据文案猜测原因或调用模型分类。生产方须显式提供这两类事实才能接入；本阶段不新增通用异常扫描器。此输入协议及首批生产接线必须实际补齐，不能只提供一个无人调用的事件接口就算完成。

宿主以 `(project, source_kind, source_id, occurrence_id, advisory-v1)` 为自动请求唯一键，原子保存生成记录和原请求关联，早于模型提交。同一事项的重复通知、轮询、观察时间/普通 revision 更新和实例重启均返回原记录；同一 ID 的不同内容不得覆盖原快照。来源版本用于固定依据，不单独作为自动重生键。真正的新事项使用新 occurrence；调用方另行提供的新请求须有独立身份，不因此新增用户重新生成流程。

来源事实持久后、生成登记前崩溃，宿主可重新消费同一事实并依唯一键登记一次；登记但尚未尝试提交的 queued 可恢复首次提交。已经开始或提交结果未知的请求只核实原请求，不再次投递模型。已完成、失败或用户取消的同一事项不因重启或重复通知自动重开。所有生成共用现有预算和队列。

上下文准备属于异步工作的阶段：先有稳定的原业务事实和生成记录，再读取限定材料并冻结本次完整上下文；缺失或超限明确失败，不遗漏活动。能力缺失同样保存本次诊断、零模型提交。失败后保留诊断并继续使用原业务处理入口，不自动重试；本轮不增加专用重试/重新生成界面。

源事项在首次模型提交前已不需处理时取消排队工作；已提交则请求停止原推理并结算，不改原任务。已经完成的建议保留为历史，其原上下文不升级为当前值。来源变化、建议完成和用户查看都不会替原业务 owner 清除问题。

## 4. 给定上下文与零工具的硬边界

模型每轮只能接收平台明确组装的固定行为规则、本次上下文及本次冻结的模型设置。以下均不允许：

- 主动读文件、遍历/搜索仓库、联网、调用 shell、调用业务 API、使用 MCP/Apps、skills、hooks 或子 Agent。
- 隐式附加项目仓库、宿主 AGENTS/个人项目指令、用户文件或先前会话记忆；外部路径、URL 和材料中的指令不触发访问。
- 让模型自行打开固定规则文件、私有上下文文件或固定 Git 快照；这些正文必须由宿主先读入明确上下文。
- 输出后自动再检索、调用另一轮模型、补报、修复、自动重试，或由失败路径改走有工具模式。

“零工具”由 Runner/原生执行配置强制实现，不能仅依靠提示词、只读权限、空工作目录、工具事件未出现，或事后拒收结果来证明。若显式模式不能关闭原生工具或排除应用侧隐式材料注入，新业务输入必须阻断。已有未知推理只核实原请求。

当前已调查的 Runner 文档 `docs/workflows/generate.md` 明确允许原生只读工具，且不承诺单目录读取隔离；SteerLine 当前 `GenerateInput` 也没有上述保证字段。因此**当前 generate/1 的 read_only、仓库 paths 和 file 材料都不能作为本 Spec 的能力证明**。必须先补齐并发布公开的“给定上下文、无工具”能力及可验证配置；SteerLine 不直连模型绕开 Runner。

固定提示词仍从 `internal/prompts/*.md`、`materials/*.md` 读取并由同包组装，缺失阻断，无行为规则 inline 兜底。本次用户明确要求改变读取者：由宿主读取固定文件，完整规则和动态上下文作为正式文本输入传给模型；不是运行时因文件失败回退 inline。实施时在[提示词治理](../../docs/prompt-governance.md)增加仅此模式适用的规则，保留其他生成流程的仓库/file 材料边界。

## 5. 输出、界面与外部行为

输出应直接可作为下一次对话的用户提示词使用，围绕本次 goal 和材料提出清楚的继续讨论要求。缺事实、存在冲突或目标过大时，正文引导下一次对话先澄清；不得编造项目事实、宣称外部操作已完成或把材料文字当成执行授权。

### 5.1 候选详情中的使用面板

名称为“后续对话提示词建议”。默认显示源事项及正在排队、准备上下文、生成、收尾或完成的状态；没有要求用户先点击“生成”才能处理的前置。自动生成不等待用户预览批准，详情如实展示系统本次已使用的固定 goal 和完整上下文。

上下文区展示原候选已绑定材料、原问题、已核实 final、必要测试安排/输入事实等本次提供项，可展开全文，显示来源/版本和缺失项。不扫描全仓、不遍历其他任务、不调用模型选材料。自动触发后的新版本不悄悄替换原输入；用户查看历史时明确原事项及当时依据。

结果区只读显示一段提示词，提供复制；用户在外部修改和使用。本轮不建设 Web 编辑草稿、恢复原文或采用状态。源事项已解除不禁止查看/复制历史建议，也不沿用原问题 can_reply 或候选可写资格控制这些只读操作。已有记录按源事项定位，不另做历史管理页面。

页面关闭、路由切换、浏览器退出均不取消已登记工作。保留现有宿主推理取消能力，仅显式取消才取消本次推理；断网/未知时查询原请求，不把查询当重新生成。切换项目、候选或记录时按原 ID 隔离结果，迟到响应不能覆盖另一记录。

没有自动投递、采用确认、采用状态、外部执行进度或完成回传，也没有“提交澄清回答”“创建材料 PR”“执行建议”按钮或隐藏 API。模型和权限能力不可用时显示诊断，保留原业务入口。

### 5.2 Web 与宿主接口

自动接收 `AdviceNeeded` 是内部业务写入口，不由活动 GET、浏览器轮询或页面 effect 调用。本轮 Web 只接入只读结果与已有取消/原请求查询；不另开通手动建议生成命令。

| 接口用途 | 固定边界 |
| --- | --- |
| 生成列表及精确详情 | 按项目、候选/源事项及 request ID 读取持久记录；详情包含本次上下文快照、生成状态、唯一原始 prompt 及必要诊断，返回显式 DTO，不返回 Runner 内部记录 |
| 内部建议生成入口 | 来源适配器提供完整 advisory-v1 请求；宿主核验作用域和来源、原样冻结并异步推进，不借用原问题回答资格；不为本轮增加手动 Web 写入口 |
| `main_agent_cancel` | 绑定原生成 request ID 和展示版本，只取消该推理，不停止原候选 |
| 原请求查询 | 用原 request ID 沿既有回执查询，不重建请求、不重复提交；已受理不等于提示词生成成功 |

详情展示实际已使用的快照，不在查询时重建当前材料。来源自称已核实时，宿主须验证其正文/版本确属本作用域；调用方原有的用户补充标为用户提供内容，不伪造仓库权威。活动导航和列表筛选不构造新快照或创建工作。

### 5.3 活动中心来源

按[活动中心](../../docs/product-design/async-activities.md)注册 `source=main_agent_advisory`、`kind=prompt_suggestion`。一个持久生成记录是一项正式活动；身份由项目、来源和原生成 ID 决定，不含实例或当前 Runner Run ID。自动触发无需浏览器 journal 即可发现，同一次自动事项不重复建卡；沿活动原 request links 协议关联原请求，不新增本用途的浏览器提交占位流程。

| 来源事实 | 活动状态和提示 |
| --- | --- |
| 已登记，等待预算或准备上下文 | queued/running，阶段说明实际工作 |
| 模型已提交，正在生成 | running |
| 原提交/观察未知、正在取消或结果已出但资源未结算 | waiting，保留原因，不宣布活动结束 |
| 唯一提示词已核实且资源全部结算 | succeeded，含义仅为“提示词建议已生成” |
| 生成/上下文/能力失败且资源结算，或明确未提交 | failed，保存本次失败，不自动重开 |
| 显式取消或源事项解除，且原资源结算 | cancelled；已完成的历史建议不改写为取消 |

`needs_attention` 由当前源事项是否仍需处理及本次生成事实推导：建议已生成但原事项未解除、或生成失败需要用户处理时为 true；源事项解除后为 false。排队/正常生成不因原事项待处理就额外制造新的处理动作。成功与需处理可以重叠，表示“建议可查看，原事项仍待处理”，不等同于要求用户确认采用。未匹配当前源事项的历史失败不重新提醒。

持久记录保存原请求、源事项/候选引用、业务结果、资源结算及观察时间，沿原 owner 路径更新。活动源通过中性有界读端口和纯投影接入，沿用现有列表、分页、计数、request links、部分故障和观察新鲜度约束；不维护第二份活动状态表。`GET /activities`、列表和详情观察均不调用模型、Git 或 Runner 对账，不修改原业务。

卡片点击定位候选详情中的确切建议记录，不重开生成，不自动打开抽屉或抢焦点；抽屉不增加生成、取消或执行按钮。刷新、无页面、切项目/实例、来源部分故障和重新打开页面均能按原持久事实观察。生成成功不表示原任务已解阻，活动结束也不解除原问题。

## 6. 未来能力扩展

未来自主探索或执行必须有单独 Spec，明确新的能力身份、上下文/工具范围、授权、动作 owner、停止恢复和验收，再更新协议与接线。`advisory-v1` 始终保持只产出提示词；模型返回值、提示词文本、设置编辑或模型升级均不能扩权。

本次仅保留协议版本、明确输入和单一产物的结构；不预留可启用的工具表、执行模式开关、任意 action 字段或 executor 注册器。不兼容 PR475 的多字段结果和动作协议。
