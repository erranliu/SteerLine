## 目标与范围

调用方单次指令仅保留当前动作、必读材料引用、少量本轮参数、结果提交位置和简短完成要求。完整测试安排、写入器源码、报告格式、环境要求、原Markdown、确认规划及历史失败由真实可读的固定材料承载，Agent先读取再执行。

本次不建设统一workflow/提示词供应预算；用户回答单独遵守已确认的2000个UTF-8字节限制。使用Runner公开文件/固定快照读取能力；2026-10-29用户授权解决308快照上限，增加公开 generate.repository.paths 明确文件选择，不新建私有传输、临时服务、通用材料分发框架或第二条模型执行链路。无法通过现有能力提供材料的流程保持准备不足，不声称全部流程已可无条件切换。

不修改Runner原生输入、粘贴、提交、启动确认或重试，不改变其现有workflow/正文覆盖契约。原Task18、构建、旧请求/Run/输入/接受pin/报告保持原样，业务复验继续等待；不恢复旧现场、定时任务，不创建子代理，不发送跨会话消息，不合并或部署。

### CPC-D01：任务指令与执行材料分离

指令只表达做什么、先读哪些文件、少量本轮参数、结果写到哪里及简短完成要求。任务ID、阶段和必要来源定位可保留；完整安排/定义/note、源码函数、协议/JSON样例、原始规划文本、历史报告和长规则不得由程序自动展开；用户直接回答按CPC-D06单独处理。

不得把这些正文移入另一个最终仍被展开的inline字段，或用JSON转义、Base64、代码围栏、多次消息隐藏传送。结构化控制请求、原数据保存及结果schema仍各归原契约；一旦被渲染成模型可见的长文字，也须按材料处理，不成为豁免入口。

### CPC-D02：材料真实可达，来源固定

准备阶段核实每项必读引用：Agent能通过现有工具读取完整内容，文件属于本次固定checkout或现有只读快照，版本/摘要与原请求一致，读取权限成立。调用方本机文件存在不等于远端或generate Agent可读。

仓库材料从固定Git提交提供；安排、确认结果或原始输入若不属于该提交，必须保留独立来源和原始字节，不能用同名但不同内容的快照文件替代。完整材料、来源核对和关联台账由程序及既有原请求保存，不重复塞进指令。

Agent必须先读取该步骤的必需材料。manifest或准备核验只证明可用，不证明实际阅读；真实验收须分别核对可达性、读取行为和结果正确性，不以一句“已阅读”放行。

### CPC-D03：缺材料阻断，不回退内联

文件缺失、版本不符、不可访问或现有能力没有正式读取渠道时，不发起依赖它的模型输入，沿原准备失败入口返回具体缺项和原因。不得回退大段inline、自动摘要、下载、补发多条输入或新增模型回合绕过。

缺少或不同源的writer须先完成正式项目准备。用户或另行明确授权的正常Git流程可交付材料，本次不自动修改业务仓库、创建材料提交/PR或向旧工作区注入文件。系统生成安排、临时草稿、非快照原文同样需要真实供给；没有入口就是准备缺口，不得用假路径宣称支持。

### CPC-D04：测试完整性和步骤权限不变

完整FrozenTestPlan、definition/note/顺序/来源/digest、进度字段、API和原存储核验保留。安排文件是原冻结数据的精确可核验呈现，不是第二套可编辑安排。Agent从固定安排、Plan、规范及清单读取全部要求，不重新选项、不增删ID、换命令或降低通过标准。

执行协议和writer由文件提供，仍须逐ID核对真实入口、开始/重跑清零，仅在实际非零、无失败/意外跳过、原报告/输入/清理全部通过后完成，禁止事后手填。新请求删除缺helper时内联源码的路径。同源核对仅允许CRLF/LF差异，不做其它空白折叠或只查文件名。

实施/审计与发布/只读报告按原权限划分。发布步骤不得获得写测试进度的指令，不借读取材料修改结果或补通过。

### CPC-D05：生成与环境流程读取完整材料

测试安排生成读取原Plan、规范和完整清单，保留两处必跑取并集、影响追加、空选择例外和原结果schema。Roadmap读取原Markdown、任务图、来源映射、确认规划和规范；解析 schema 仅定义字段结构，不再用原文行枚举夹带材料，原文逐字摘录仍由结果核验约束。保留完整文件集、固定来源及调查引用，不以摘要替代原规划。

环境规则、报告字段、脚本和前轮失败记录均通过必读材料提供。外层document/script/gaps schema没有定义环境Report内部结构，内部字段和语义必须留在正式材料中。prepare/publish短指令只指定阶段，从原文档、初始结果JSON和原报告取资料；完整L2、PR授权、未知结果和清理规则不变。

本修订替代“原始材料继续完整inline”及“前轮报告压成指令内摘要”的方案。原报告和全部通过/失败/incomplete/unknown、清理事实完整保存并可读，不用摘要替代证据。

### CPC-D06：用户内容和原请求身份不变

用户回答保留既有回复通道，按实际UTF-8字节校验完整回答（多问题答案合计），上限2000字节。未超限时，原文、问题/选项、多问题答案、来源版本和操作身份保持原样；超限在投递前明确拒绝并返回实际字节数和上限。不截断、不摘要、不拆成多条、不转文件，也不将路径冒充答案。本次不支持超限用户回答，不扩展回复接口或材料传递方式。

新规则只用于新操作。已持久化输入的观察、恢复和重启沿原冻结请求，不重新渲染、覆盖、重发或为旧现场补文件。保留CAS和不可变输入校验，不新增旧数据迁移、双写、回退或第二套权威。

### CPC-D07：明确供给缺口与验收范围

逐流程登记现有读取能力、必读材料、实际位置/版本、执行条件及准备不足原因。“材料缺失被正确阻断”不等于流程完整执行通过；材料供给、实际读取和结果核验须分别满足。

以相同输入比较短指令和材料组成，确认没有正文内联或换字段搬运。缺文件、错版本、错误主机或不可读等反例须在投递前拒绝；完整安排、原报告、原答案和授权不变。不设任意体积比例，不以静态减量或受控读取代替真实模型/发布/投递资格。

## 2026-10-29 L4 修复边界

生成快照的可选 paths 是原提交内精确普通文件清单，非目录或通配符；4096文件/64MiB/1MiB manifest 上限按实际选择执行，不自动扩大或回退整仓。测试安排生成选择原Plan、规范和完整清单；环境生成选择实际核实的完整规则、上下文、项目声明与依赖。Roadmap解析选择其完整输入；需要调查源码的文档生成保留整仓模式，不能因材料选择丢失相关源码。原commit/root tree及逐文件blob/SHA256/size保持，返回manifest须精确匹配显式清单。

远端L4使用本任务独立的真实项目克隆，通过正常Git提交准备同源规则、writer及固定安排；不改原脚本、程序、测试定义和标准，不注入旧工作区。前轮报告只进入原结果文件的初始JSON，不渲染进指令；执行Agent先完整读取，最终报告字段和原停止/封存流程保持。未知PR/未清理资源仍阻断下一轮。旧持久化请求不重新构造。

原脚本可在最终文件保留只读 previous 元数据；解析器只在与该轮已持久化初始结果文件逐值一致时接受，并剥离为原 Report 领域对象。其他未知字段、身份/字段/完整L2/PR/停止/清理标准继续严格校验，不引入报告兼容读取或可编辑历史副本。
