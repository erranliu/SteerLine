# Spec：本机安装与调试路径隔离

任务 ID：83；任务名称：本机安装与调试路径隔离；目标：`PHASE1-RUNTIME`。配套 [Plan](../plans/local-runtime-isolation.plan.md)及[专属验收](../testing/acceptance/local-runtime-isolation.md)。状态：已纳入执行规划、待中心准入及实现/验收，一个独立实现 PR 交付。

## 范围与前置

无未完成硬前置。复用现有安装、启动器、服务发现、实例核验和仓库单写锁，遵守[第一阶段共同约束](phase1-delivery-constraints.md)。Windows 交付一个本机安装版本及一个源码调试入口；Linux 保持编译通过，不作为原生安装验收。

安装目录持有日常使用的二进制，源码工作树的 build 只更新自己的产物。调试入口显式绑定调试 exe、独立绝对 home 和项目配置，缺少必要路径时失败，不能回落到日常安装目录或 PATH。复用现有入口和产品用例，不新增 channel、不可变版本库、selection、dev select、提升、自动更新、迁移或回滚机制。#40/#41 延后，不作为本任务前置或部分交付结果。

## 路径与状态

安装版的服务、控制台和 CLI 使用安装目录中的 exe/home；调试版使用本工作树的实际构建 exe 和专用 home。调试入口用局部进程环境传递 STEERLINE_HOME，不修改用户或机器的全局环境。console 启动服务、项目选择 re-exec 及其他产品子进程必须继续使用本次选定的 exe/home，不能转去调试 home 下不存在或过期的 bin/steerline.exe。

配置、execution profile、SQLite、日志、服务发现/控制文件及工作区分别归属各自 home。调试入口提供日常安装 home（默认现有安装根）和调试 home，以规范绝对路径核对两者不重叠；显式 run_dir/worktree_root 必须落在本调试 home 内，不允许复制安装配置后仍写入安装状态。目录别名按现有规范路径能力解析。已有服务实例/项目/config 核验继续生效，错误目标在写命令前拒绝；不为本任务新增跨构建客户端兼容协议。

调试使用独立测试 clone，不复制安装版任务库作为可派发来源。同仓库跨 home 的原单写锁保持；同一 clone 的 linked worktree 共用 Git common directory，不视为两个独立可并行管理的测试仓库。可复用本机后端认证来源，但可写 worker 状态、终端、会话及资源仍绑定本次执行身份，不要求再建账号或独立认证系统。

服务启动日志及控制台诊断显示实际 exe、规范 home、项目/配置与构建源码 commit、dirty 标志；构建信息未知时明确显示未知，不伪造版本。构建信息只用于定位，不成为版本选择系统。[一期验收活动](../testing/acceptance/phase1.md) 用二进制 SHA-256 固定验收产物。

## 维护边界

本任务不提供跨构建接管活动任务的保证。调试构建前先停止使用该调试产物的进程；日常安装版可继续运行。人工更新安装版须先核实并结算原外部执行，再停止中心、替换安装产物和启动；停止中心本身不等于停止 worker。当前构建/当前格式的服务重启仍保留任务、原请求、原会话和 PR 事实，不重复派发。不支持的格式保留原数据并拒绝，不能自动迁移或清库。

## 验收

| 编号 | 通过条件 |
| --- | --- |
| LI1 | 两个独立测试 clone、不同 home 的安装版与调试版同时运行；配置、状态、日志、服务发现和写命令不串线 |
| LI2 | 调试 build、停启及入口重复生成不改安装 exe 摘要、原服务实例或任务事实；调试服务/控制台/CLI 及子进程使用实际调试 exe/home |
| LI3 | 缺少调试路径、home 重叠、显式状态/工作区越出调试 home 拒绝；同仓库跨 home 第二写者被原锁拒绝；误连实例的写命令仍被拒绝 |
| LI4 | Windows 中文/空格路径及无关 cwd 可启动并显示准确身份；维护说明区分中心停服、外部执行结算、同构建重启和人工更新 |

使用真实 Windows 进程、Git、SQLite 与受控后端完成一次最小共存场景，无模型请求；原始证据保存于本次临时目录，最小摘要与待验状态记录于专属acceptance。安装与调试入口缺陷由本任务修复；业务交付、当前格式恢复及 24 小时运行由 [一期验收活动](../testing/acceptance/phase1.md) 组合验收。
