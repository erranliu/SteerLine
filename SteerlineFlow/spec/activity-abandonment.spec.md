# 活动中心放弃活动 Spec

## 1. 目标与范围

用户可以在活动中心放弃一条正式活动，让它退出当前跟进视图并进入历史。原记录、命令回执和已有的对话或结果仍可按原身份查看。六类来源均须接入，原业务页也须识别放弃状态，刷新、重连或服务重启后不恢复旧卡片。

首版覆盖已有正式 `activity_id` 的记录，包括业务已结束但仍列在「需处理」的记录。只有前端占位或尚未关联正式活动的提交待确认项，继续沿原请求核实。范围限于下表六类及其现有活动单位，单条操作，无批量放弃、撤销或主动删除资源。

## 2. 现状与统一契约

当前活动中心按六类来源读取各自持久事实。列表筛选和计数以业务终态、`needs_attention` 为依据，SQL 还有来源预筛。独立页通过同一稳定 ID 读取原记录，抽屉会合并请求关联与本地占位。沿用这些入口，增加独立的归档事实。 [活动中心设计](../../docs/product-design/async-activities.md) · [SQL 预筛与排序](../../internal/storage/sqlite/async_activities.go) · [临时项与正式关联](../../web/src/features/activities/model.ts)

- **入口与确认。** 抽屉卡片与独立页活动详情统一提供「放弃活动」，适用于尚未放弃且处于「进行中」或「需处理」的正式活动。确认框指明活动和处理范围，并按来源说明是否请求停止、是否继续核实。已打开的确认可在原活动自然结束后完成。已归档项展示「已放弃」及放弃时间。
- **身份与回执。** 沿用项目命令信封及原请求回执，校验当前项目、实例和目标来源，按「项目 + 来源 + 源记录 ID」持久保存首次 `abandoned_at`。重复请求、重复点击或跨窗口操作复用已有归档结果和停止意图。业务观察版本变化时，以提交时的原业务事实判断是否仍须停止。放弃结果未知时先查原请求。同实例确认找不到回执且未收到过响应时，可通过现有请求对账机制再次提交同一信封。只有确认持久生效后才移走当前项。明确失败时保留卡片并显示原因。
- **归档与停止。** 对下表要求停止的分支，归档成功须同时具有原业务已持久受理的停止意图、已有同一目标的停止义务，或已证实无需停止的事实。保存归档与所需停止意图须具备一致的提交结果，避免只归档却丢失停止责任，或提交失败后重复发停止。向原执行投递停止须在所需意图落盘之后，投递和结算沿原业务流程推进，归档无需等 Runner 退出。若提交时该活动恰好自然结束且已结算，按无需停止归档。仍在停止或核实中的事实应在历史详情及指定的原业务入口可见。 [Runner 调用生命周期](../../docs/product-design/runner-lifecycle.md)
- **列表、计数与深链接。** 放弃项退出「进行中」「需处理」和相应计数，按放弃时间进入抽屉「最近结束」及独立页「历史」，沿用现有分页与最近结束条数上限。SQL 预筛、排序、游标和列表/计数投影使用同一归档规则。业务 `state`、`finished_at`、诊断和已结算事实保留原义。晚到结果更新原记录，归档归属及排序时间保持稳定。保留原活动 ID、原请求关联、原详情和已有阅读入口。已关联请求继续识别为正式活动，避免旧分页、旧轮询或本地 journal 将它重新显示为待确认项。确认放弃后刷新同一项目范围内的列表、计数、详情和相关业务视图，焦点移到仍可用的列表控件。
- **业务门禁。** 各业务页按精确记录退出当前展示，保留原业务定义的互斥、结算、就绪、交付和权限规则。仍占用名额或阻塞新操作时，在对应入口显示原因并链接到原记录。保留的核实动作指向已有原请求、Run、PR 或入图回执。访问历史、详情或普通轮询继续沿各自的只读契约。放弃不附加删除工作区、会话、分支、PR、文件或日志的操作。

## 3. 六类活动的适配

| 来源与放弃单位 | 如何退出当前界面 | 首版停止策略 | 保留的核实入口 |
| --- | --- | --- | --- |
| 环境检测 `environment_detection`，整次检测，含原有轮次 | 从环境页收起这次检测的进度、等待提示和当前操作区。环境的真实就绪状态、诊断和发起资格照常显示。指定检测仍可从历史打开。 | 未结算时请求现有 `environment_stop`，由原 owner 取消尚未投递的轮次，或核实并停止原 Run。已结算直接归档。 | 保留指定检测详情、各轮诊断及原启动和停止回执。同目标仍被旧检测占用时，在发起入口给出原因并链接该详情。 [环境停止与观察](../../internal/environmentadaptation/service.go) |
| 显式主分支检查 `baseline_check`，一条 `maintenance_check` 原请求 | 收起「项目状态」中这条请求的正在检查、完成或失败反馈。页面继续显示项目基线、同步和就绪事实，其他请求的反馈独立展示。 | 让原检查完成。 | 保留「项目状态」按请求 ID 定位的原回执。仍在途或结果未知且影响再次检查或更新时，就近提示并链接原请求。 [项目状态页面](../../web/src/features/project-maintenance/project-maintenance.tsx) |
| 任务候选 `task_candidate`，一个候选 | 从执行页默认跟进列表和当前选择移出该候选，关闭它的主动反馈和待答提示。保留任务真实状态、其他候选，以及通过指定候选详情访问原操作的能力。同一 Task 的其他候选不受影响。 | 仅归档跟进视图。保留原参与和交付资格，不发 `stop_candidate` 或 Runner stop。「停止参与」仍由用户在候选详情显式执行，并遵守最后一个参与候选等原限制。 | 保留指定候选详情、原启动/答复/停止回执、原待答问题、原 Run 和 PR 核实。任务确实仍待人工处理时，任务页可链接到该候选，默认跟进列表不重新加入它。 [候选停止入口](../../web/src/features/runs/stop-candidate.tsx) · [候选停止与交付](../../docs/product-design/runner-lifecycle.md) |
| Roadmap `roadmap`，一条正式 Roadmap 记录 | 将该记录移出 Roadmap 默认当前选择，收起其草稿确认、文档审阅和当前进度区。一次归档覆盖该记录下各轮或各任务的生成工作以及关联请求。其他解析或文档记录仍按各自 ID 展示，选下一条当前记录时继续遵守原来源和流程资格。历史可精确打开原记录。 | 对目标记录中仍未结算且可停止的解析或文档生成，走现有 `roadmap_stop`，由原 owner 处理未投递和已投递的内容工作。已结算内容直接归档。已提交的发布、合并观察或入图走原流程，不因放弃撤销或重发。 | 保留原记录及生成、停止、发布和入图回执。发布待确认、已发布待合并、已合并待入图或入图结果未知时，Roadmap 页面保留指向指定记录的入口，继续提供原有核实和获准后续动作。原在途工作仍阻塞新操作时，就近显示实际原因。 [当前记录选择](../../web/src/features/roadmaps/workflow.ts) · [Roadmap 原操作](../../internal/app/roadmaps.go) |
| 对话续作提示词建议 `main_agent_advisory`，一个建议请求 | 从候选回答区收起该建议的进度、结果和自动填入。保留原候选问题及手写或已编辑的答复草稿。如果当前答复框仍是这条建议的未编辑自动填入内容，清除该内容。迟到建议不再填入，同一问题继续沿原去重规则。 | 生成尚未结算时走 `main_agent_cancel`，取消未投递生成或停止已投递的原建议 Run。原候选照常运行。已结算建议直接归档。 | 保留精确建议历史、原建议和取消回执、已有结果的查看与复制。原候选问题继续在回答区可见并可按原资格作答。 [续作建议和回答区](../../docs/product-design/main-agent.md) |
| 重构与维护 `refactoring`，整条维护行动 | 从维护页当前行动区退出该行动，收起进度和待答区，保留行动历史、报告和成果。启动区域继续按项目真实在途名额显示可用性。 | 行动仍活跃且可停止时走 `refactoring_stop`，撤销后续投递并按原责任停止当前只读决策或可写执行。已停止、已交付或已结算的阻断行动直接归档。放弃不触发「结束并交付」。 | 保留指定行动详情、原停止及运行结算、原发布结果和 PR 核实入口。项目名额仍被占用时链接原行动。用户从原行动详情显式发起的交付或冲突处理继续受原业务资格控制。 [维护停止、恢复与交付](refactoring-maintenance.spec.md) |

## 4. 通过条件

| 编号 | 通过条件 |
| --- | --- |
| AA-01 | 六类正式活动均能从抽屉或独立页发起放弃。覆盖「进行中」和「需处理」，包括已结束仍需处理的活动。临时占位没有放弃入口。取消确认零写入，离线、项目切换或陈旧实例不会改到其他目标。 |
| AA-02 | 归档成功后，两处活动界面的进行中、需处理列表及计数同步变化，最近结束和历史按放弃时间分页。覆盖原先非终态的 SQL 预筛、已加载的旧页、原请求链接及迟到业务结果。刷新、重启和重复请求后仍只有一条同身份的历史记录。 |
| AA-03 | 主分支检查与候选归档不触发停止。候选参与、兄弟候选、现有交付及最后一个候选保护按原语义工作。续作建议放弃后不能迟到填入或覆盖手写草稿。 |
| AA-04 | 对环境检测、Roadmap 内容、建议生成及维护行动，分别覆盖未投递、已投递、原提交未知、已有停止意图及已结算。需要停止时只保存一份原停止意图，停止回执丢失后沿原请求核实。已归档可与停止待核实同时展示，原业务名额及门禁待真实结算后按原规则变化。 |
| AA-05 | 六个原页面刷新后按表退出当前展示，其他记录和真实门禁仍可见。指定历史可追溯到同一原记录、回执和已有对话。Roadmap 发布与入图待核实、维护发布或停止未知、环境检测未结算、原候选待答等入口能定位原对象。归档与历史读取不触发额外清理、重发或替代运行。 |

验证安排随实现 Plan 确定，按[测试指南](../testing.md)选择覆盖，实际结果登记在任务专属验收文档。
