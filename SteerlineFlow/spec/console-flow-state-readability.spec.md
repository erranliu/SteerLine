# Spec：任务列表与流程状态可读性

> 2026-10-15 TUI 退役：本文保留原交付/验收事实，TUI 专属操作和未验项不再适用，不记为通过。共享后台/API 要求继续归原记录；当前范围见 [TUI 退役](tui-retirement.spec.md)。

2026-10-13 用户修订：完整移除单候选放弃功能（控制台、CLI、API、服务端及专用状态字段）；任务级丢弃和唯一交付保留。控制台任务提示只显示中文状态，并增加全部执行候选数量列。下文涉及单候选放弃或旧列表列布局的历史要求不再适用；历史操作设计见[归档](../archive/design/execution-console.md)。

本次命名增量以[状态命名 Spec](state-naming.spec.md)为准：候选快照与活动的业务字段改为 workflow_stage/workflow_status，内部领域步骤保持；原布局和事件事务保持；当前主干阶段变化只显示流程消息，阶段不变才显示状态消息，字段改名不恢复旧双消息规则。

用户直接授权的普通开发，接续[原始状态保留](console-worker-state.spec.md)。配套 [Plan](../plans/console-flow-state-readability.plan.md)、[专属验收](../testing/acceptance/console-flow-state-readability.md)。不改变任务或 worker 状态机，不改变原始记录格式及操作资格。

任务列表默认每 Task 一行，固定 ID、任务提示、标题三列，按终端显示宽度处理中文、emoji 与 ANSI 样式；标题及过长摘要省略，完整原值在所选详情中保留。状态提示基于原字段和事实：已有执行优先采用其 TaskStatus，未执行采用 TaskDetail.Status；open 有明确未满足前置或启动阻塞时显示“阻塞 · open”，没有事实的 open 不猜成阻塞；新鲜 Ready 候选显示“可开始”，缓存明确标注；已有 worker 的业务 blocked 或环境阻断也显示阻塞。终态任务不被历史 worker 失败改成阻塞。列表显示当前序号/总数，8 增加阻塞筛选，刷新保留原选择、焦点及固定行高，不按状态变化重排。右上对齐 task_status、step_id、status、execution_status，展示原阻塞原因及前置 ID；长原值换行，中文仍为字段/确切值固定映射。

运行与反馈保留问题、回执和结果预览的原优先级，变化仅投影两个信息：流程来自 step_id，状态来自业务 status。每条消息含时间及一种变化；两者同时变化拆成两条同时间消息，最新在上。状态消息以目标 step_id 作为当前流程上下文，流程不变不重复箭头；状态变更原因紧随对应消息，默认短摘要，详情保留全文。顶部一行显示当前流程/状态，窄屏可换行，即使没有变化也可读；默认最多五条可见消息。已在当前状态消息中展示的同一原诊断不重复占用右上概览。

execution_status、resource_status、current_turn_id、input_version、恢复和环境字段不进入默认变化列表，不合并成另一个状态。仅技术字段变化不制造主视图消息。所有原字段继续持久化，d 的只读详情保留最近原始技术变化、原始诊断及当前字段。其他活动短摘要也移到详情；不修改原日志查询或历史记录。

RecentActivity 在原项目/WorkflowRun/Execution/Attempt 及同读事务、原 1 MiB 预算下读取：最近五条流程/状态变化、最近五条原始变化、最近十条其他活动，事件去重并按原 EventID 排序；预算优先流程/状态变化。UI 缓存最多十条原始变化，默认投影再限制五条消息；技术变化和工具事件不能挤掉可读历史。保留身份、迟到、重复刷新、离线采样、采集缺口和损坏记录诊断规则。不新增表、迁移或兼容路径。

最小验收 CRD-A1–A4 见专属文档。仅现有隔离渲染和 SQLite 夹具，不启动真实模型或安装版。
