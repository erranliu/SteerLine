## 1. 目标与取舍

环境准备单元继续是**项目 × 运行机 × 执行链路**。模型及思考强度属于操作参数，不形成独立环境；沿用原 environment_key、项目身份、当前资格引用及候选准入事务，不另建环境注册或资格系统。

职责收敛为：**项目定义运行要求并自行完成检测闭环；SteerLine 提供调用与结果规范，负责调用、执行生命周期及最终结果消费。** SteerLine 知道接口位置、目标与来源，不理解项目内部怎样判断就绪。环境检测不读取或执行项目测试，不消费测试安排、进度和报告，不编排构建验收或 PR 发布。

代价是环境 ready 的业务正确性由项目负责。SteerLine 保证结果归属、时效依据及执行结算可靠，不把项目自报结论宣传为平台独立证明。项目漏检或少声明依赖属于项目接口缺陷；平台无法自动发现全部缺陷。

## 2. 操作对象与边界

### 2.1 平台、项目与未来适配

| 归属 | 负责内容 |
| --- | --- |
| 受管理项目 | 环境要求、检测及诊断方法、检查集合、工具/SDK/版本/服务/权限、失败处理和自有资源清理；维护一个可调用的检测入口并给出最终 ready/not_ready |
| SteerLine | 项目/环境定位、调用接口安全校验、冻结来源和输入、Runner 请求与原身份对账、停止/超时/封存、结果信封校验、资格引用/失效、展示及任务准入 |
| Runner | 已公布的执行通道、运行观察、原执行的停止和结果封存；SteerLine 按公开契约调用，不接管其内部状态机 |
| 初始化适配功能（未来） | 据通用指导和真实项目生成配套接口，并在生成侧完成自检闭环；不进入日常检测链，本轮不实现 |

项目自行定义工具、权限和服务的最小可用性检查；不检测执行链路，不根据 adapter、环境键或目标名称改变标准。平台不要求 environment.md 声明 required_checks/gaps，不读取项目测试清单或 PR 身份；环境入口不以项目测试、构建验收或发布结果授予资格。

平台自身执行链路的能力、受理身份、进程是否停止、结果是否封存仍由平台/Runner 核验；项目返回 ready 不能替代这些事实。项目自有资源与 Runner 持有资源各自收尾，项目不得通过报告声明 Runner 已停止。环境检测活动不产生 TaskDelivery；正常业务任务的测试安排与发布规则保持自身职责，不随本稿取消。

### 2.2 平台材料的交付

通用指导和平台固定行为材料归 SteerLine 维护。**受管理项目不复制、提交、同步或逐字匹配 SteerLine 的提示词、指导和执行规则。** 项目只实现公开调用/结果契约；接口版本不等于某版提示词正文摘要。

确需模型读取平台完整材料时，仍通过执行侧实际可读、不可变且可追溯的文件交付，不内联长规则。该交付由 SteerLine/Runner 负责，记录采用版本与摘要；摘要核验针对平台交付的材料，不针对项目仓库中的副本。现有通道能否同时提供平台材料和项目快照须在接线前验证；能力不足是平台调用能力缺口，不能要求项目预提交副本、input/context 或把规则夹进 schema 兜底。

日常环境检测不依赖生成指导、生成模型、生成记录或项目初始化状态。结构化检测请求只包含既定入口和关联事实。项目脚本负责诊断和写入 ready 结果。

## 3. 项目接口与最终结果

### 3.1 沿用文档和入口，不增加文件层

统一使用 `SteerlineFlow/environment.md` 及项目选定的 `SteerlineFlow/scripts/verify-environment.ps1` 或 `.sh`；所有目标读取同一份材料。文档正文供项目解释要求、准备方式和诊断，SteerLine 可原样展示，不将自然语言解析为通过条件。只保留一个机器段，作为调用描述；不新建输入文件、检查注册表、报告插件或依赖发现服务。

调用描述使用 manifest version 6，唯一字段为 `version`、`script`、`interpreter`、`dependencies`、`requirements`。`script` 限项目公共入口文件名，解释器仍为 powershell.exe 或 bash。`requirements` 必填，为项目定义的非秘密字符串映射，可为空；最多64项，名称最多64字节，以 ASCII 字母数字开头、仅含字母数字/点/下划线/连字符，值非空、最多256个 UTF-8 字节且不含换行或 NUL。项目脚本读取该映射或显式要求配置作为要求权威，不能依赖未纳入依据的说明正文。`dependencies` 只声明检测实际使用的辅助程序及工具/SDK、权限、服务要求配置，可为空；它用于固定来源、存在性校验和失效判断，平台不解释文件业务含义。不为少量版本字段把整份业务依赖文件纳入依据；项目可在开发测试中核对最小要求与源配置一致性。

不再要求 `validation_base`、`required_checks`、`gaps`，也不由平台从机器段决定是否可开始业务检测。标准未知、依赖服务不可达等业务事实由项目入口输出 not_ready；调用描述格式错误、脚本/声明文件缺失或接口不受支持则属于调用准备失败，不启动 Runner。

沿用 regular Git blob、UTF-8/大小边界、重复 JSON 键和未知字段拒绝、唯一有限相对路径限制。拒绝穿越、绝对路径、符号链接、通配符和旧 environments/ 目录依赖；脚本/机器段自动计入，说明正文不计入，脚本/文档不得在 dependencies 重复列出；不接受把平台规则副本或生成指导作为资格依赖。声明不得用目录扫描或运行后发现的路径改绑本次依据。

环境资格与项目测试完全独立。环境入口不读取测试定义、安排、进度或报告，不执行项目测试、构建验收或 PR 发布。业务文档、Spec/Plan、roadmap、测试清单及其程序/报告不进入 dependencies；这些材料的新增、修改或删除不使环境资格失效。项目测试保留自己的安排和验收流程。平台不为此增加测试路径黑名单、依赖分类器或第二套门禁。

### 3.2 一次调用、项目闭环

SteerLine 冻结项目源提交，校验调用描述、入口及声明文件，按所选执行方案在目标环境调用入口一次。通过结构化检测请求和结果文件通道提供必要关联事实；目标事实只含允许公开的定位信息，秘密保留原执行配置边界，不生成需提交的 context。

最小调用约定固定为：工作目录是执行机上已登记的项目 checkout 根；PowerShell 项目调用 `powershell.exe -NoProfile -NonInteractive -File <script>`，Bash 项目调用 `bash <script>`，script 是经校验的仓库相对路径，按参数数组传递，不拼接 shell 命令，不再传 Phase。唯一结果定位通道为 Runner 提供的绝对路径环境变量 `STEERLINE_RESULT_FILE`；项目先读取该文件的预置身份/调用事实，保留这些字段，完成后原子替换同一文件。不新增输入文件、自由参数或跨来源规则前置。

脚本退出 0 表示调用正常返回，可携带 ready=true 或 false；非零退出表示调用异常，仍可保留已写完的负报告。正常调用结算要求 Runner 对原执行公布 status=completed 及已核实的脚本成功退出；failed/cancelled/unknown/unreported 或无可信终态均不准入。入口须把业务失败写成负报告，不能要求 Agent 重写结论。R0 必须核验该终态及结果通道在无平台发布步骤时可用，未公开的能力不假定存在。

项目入口从读取自身要求到执行、诊断、内部收尾及最终结果写入自行闭环。平台不再拆成 tty/tty-failure/prepare/publish，不按业务步骤派 Agent，不根据 checks 或 PR 状态选择重试/修复分支。不因项目返回 not_ready 自动再调用三轮；后续检测由新的明确操作发起。原请求受理未知只能对账原请求，禁止重发入口。

入口必须能在该目标尚未 ready 时启动，不能要求先取得环境资格、创建业务 Task 或完成初始化生成才允许检测。项目检测入口应能与该目标上已经启动的普通任务并行，检测使用既有 checkout 和独立的仓库外临时资源。已有普通任务不阻拦检测。同一 home 内同目标未结算的检测继续串行。启动检测保留原执行能力和授权校验，普通 Task 仍按原资格及新候选准入规则启动。缺解释器、链路不可启动或无结果通道应如实阻断，不转为推测的业务检测结果。

### 3.3 最小结果信封

沿用 Runner 的原结果文件/停止后一次封存通道，不新增回调、外部上传 API 或第二种结果所有者。平台预置身份及未完成文件，项目入口保留身份，仅写入完成标志、ready 布尔值、人可读 message 及可选 details；按原子写入规则在返回前完成，不由 Agent 手填业务结果。结果可以超出是否 ready，平台可读取、保存和展示项目给出的原因与明细，但不负责复核。

当前结果为 version 3，固定字段如下；该版本是调用/消费契约版本，不承诺兼容旧 report2。

| 字段 | 含义及来源 |
| --- | --- |
| version | 固定结果契约版本 |
| project_identity / environment_key | 调用方提供的项目与完整目标身份，项目原样回传 |
| activity_id / round | 原活动及本次调用序号；本版一次检测一次调用，不新增业务多轮 |
| call_context | 固定为 adapter 和 target（kind/environment）；调用方预置、项目原样回传，无自由扩展参数 |
| source_commit / inputs_digest | 原固定提交与本次资格依据摘要，由调用方计算并冻结，项目原样回传 |
| completed / ready | 初始均 false；最终 completed=true，ready=true 或 false；completed 不表示检测通过 |
| message | 必填的就绪说明或未就绪原因；ready=false 必须可读地说明失败/未验证原因，原因未知也须如实说明，不含凭据 |
| details（可选） | 项目自定 JSON 明细，例如检查结果、错误摘要或证据定位；不规定内部业务结构，整体沿用报告大小/UTF-8 限额 |

平台严格核验信封结构、类型、版本、全部关联字段和原请求一致性；details 内部只作为有界 JSON 数据保存/安全展示，不复核业务检查、日志或证据，不自动访问证据链接，不增加平台专用解析器。ready 是项目结论的唯一消费字段，平台不从 message/details、工具退出码或 Agent 回复重新推导或覆盖它；平台的信封/生命周期失败只阻断资格，不回写项目结论。可解析的最终 not_ready 即项目检测负结果；非零退出可保留该负结果。ready=true 还须原调用取得 Runner 已核实的原生成功终态、原执行停止且结果封存；不以日志文字补足终态，失败/未知调用不得放行。

最终报告缺失、completed=false、身份错配、非法 ready 或停止/封存未知，均不能获得资格；分别保留调用/生命周期诊断，不冒称项目已完成检测并判失败。平台即使收到合法 ready=true，执行仍存活或停止待核实时也只展示待结算，不能准入。项目声明其自有收尾未完成时必须 ready=false。

## 4. 结果绑定、当前引用与失效

### 4.1 绑定与不可改写

活动在产生 Runner 副作用前冻结项目身份、environment_key、完整原执行/请求、source_commit、调用描述/脚本/依赖摘要、调用/结果契约版本和 inputs_digest。结果只能消费到原活动，不接受无对应活动的布尔值，也不能以当前配置重建旧请求。

当前资格仍是原项目 × 环境键的一条 Current 引用，包含 activity_id 和 revision。新检测以 expected_current_revision 事务受理并切换引用，旧资格立即不再用于新准入；本次失败、取消或未知不能回退旧成功。运行中再次开始沿原占用规则拒绝。主动失效更新同一 revision；迟到成功只能补充原活动历史，不能撤销失效、覆盖新引用或恢复被撤回的资格。

冻结材料不等于可以延后选为 Current。开始检测在原目标占用和基线观察门禁内复核冻结提交后才事务切换引用；观察尚未结束或已发布另一基线时拒绝本次开始，避免旧来源在撤销扫描之后成为 Current。

查询、派发预检及候选事务共用同一个 Qualify 判定：已处理当前观察到的基线变更、当前引用未撤销、原活动合法 ready 且已结算、当前依据可核验且与原 inputs_digest 相同。候选预留在原事务边界再次比较引用 revision 和依据，防止预检后改材料或撤销仍被放行；不新增平行资格缓存或 ready 开关。

### 4.2 依据只按显式声明计算

inputs_digest 覆盖解析并规范化的 manifest6（requirements、入口、解释器、排序的 dependencies）、入口脚本、全部显式 dependencies 的路径及 blob 摘要、原环境非模型执行上下文、下述全部固定稳定调用字段，以及会改变调用/结果解释的接口契约版本。说明正文、JSON 排版/键序和依赖列表顺序不计入摘要；依赖与脚本仍按完整字节计算。缺失、不可读或超限时不复用资格。原检测冻结 manifest、各文件摘要，脚本摘要从同一映射投影，不重复持久保存；查询、预检及原观察 owner 据此给出要求新增/移除/旧值→新值、入口/解释器变化或具体脚本/依赖路径，不回读历史提交。原因最多列八项及剩余数量，人工失效原因保持原文。当前资格依据不同提示重新检测；当前资格有效但候选固定来源不同时，按“候选 → 当前”展示差异并提示更新候选来源，不以重新检测当前材料作为修复建议。

稳定调用字段封闭为 `project_identity`、`environment_key`、`call_context.adapter`、`call_context.target.kind`、`call_context.target.environment`（本机为空）。这些字段全部计入资格摘要，不按项目代码是否使用或业务含义筛选，不传模型、发布目标或自由参数。非模型执行上下文仍由原规范函数派生；activity_id、round、source_commit、inputs_digest 自身、Current revision、Run/request ID、时间戳及本次临时结果文件路径只作信封/执行绑定，不计入资格摘要，避免自引用和每次调用必然失效。相同声明材料/稳定上下文、不同调用身份或无关源提交应算出相同摘要；信封各字段仍逐项对原活动核验。

平台不从 import、工具栈或源码扫描推导依赖。项目只声明影响环境要求与检测行为的运行配置及辅助程序；检测过程中发现需变更声明，须按项目正常 Git 流程采用后新开检测，不能改写原冻结依据。漏声明导致错误复用由项目负责。

源提交始终绑定本次实际执行及原报告，但不把整个 commit SHA 无条件纳入资格摘要。主分支从 A 变到 B，若全部声明依据和调用上下文相同，可以继续使用绑定 A 的结果；报告仍保留 A，不伪造为 B。反之任何声明依据变化均须重新检测，不因项目仍自报 ready 或模型相同而复用。平台不保证自动识别未声明的动态机器变化。

### 4.3 失效规则

确认的材料变化必须持久撤销：原项目维护/环境观察 owner 在处理已核实主分支观察时，将当前引用的依据与该固定提交完整重算；发现合法依据摘要不同，或 Git 已确认声明文件被删除/变为非法类型/调用描述已失效时，使用原 Current 事务按预期 revision 标记 invalidated 并递增 revision。撤销只作用于所观察的 activity_id/revision，竞争失败后重读，不覆盖新检测。观察与候选新准入串行经过原 owner；尚未处理完已知新基线观察时不开放准入。

A→B 的差异一旦被确认并撤销，即使后续 B→A 回退到原字节，旧成功仍不能恢复，须新检测；同一批观察中只核验到最终 A、从未确认中间 B 时，不承诺检测全部未观察提交。纯网络/命令超时或暂时读失败只能暂阻断，不能当作已确认变更撤销，恢复后可按当前引用核验；查询仍只读，不承担持久撤销写入。

| 变化或状态 | 当前资格处理 |
| --- | --- |
| 机器段有效要求、入口、声明依赖、固定稳定字段或接口语义版本变化 | 确认变化后持久撤销 Current；回退原字节也不恢复，须新检测；暂时读取失败只阻断 |
| 项目公共机器段有效要求、入口或声明依赖变化 | 使用该公共依据的各目标资格分别失效；单目标检测失败或人工撤销仅影响该目标 |
| 项目身份或非模型执行上下文变化 | 不复用原项目/原键资格，新身份或新键须检测 |
| 人工标记失效、目标工具/凭据/服务变化已被用户知晓 | 用原失效操作立即撤销，重新检测；不建平台探测器或新定时系统 |
| 开始新检测、当前检测 not_ready/异常/取消/未知 | 当前不放行；旧成功只留历史，不兜底 |
| 仅模型/思考强度、profile 名称、生成历史/指导、平台提示词措辞变化 | 不单独失效；若实际改变接口语义，须显式换接口版本或撤销后重验 |
| 说明正文、JSON 排版/键序、依赖顺序及未声明的其他源码变更 | 不自动失效；项目对声明完整性负责 |
| 纯查询暂时读不到依据 | 显示无法核验且暂不放行，不凭查询改写原封存报告；恢复可读后按当前引用重算 |

不新增 TTL、签名认证、能力协商或多版本注册框架。项目的动态环境变化靠项目检测和原人工失效/重新检测操作处理；平台升级不要求同步提示词正文。真正不兼容的接口变化可明确要求项目更新调用描述/入口，未发布阶段不做旧格式迁移或回退。

## 5. 生命周期与界面

遵循 [Runner 调用生命周期](../../docs/product-design/runner-lifecycle.md) 的原身份、受理未知、停止、重启恢复和迟到事实边界。本稿撤销其中环境业务检测的多阶段编排和项目检查裁决，保留通用执行与封存义务。断连不等于结束，结果未知不补发；超时请求停止原 Run，停止及结果封存核实前保留未知，应用重启继续对账原身份。项目内部重试由项目入口自行约束，不取得重发平台活动的权限。

取消后重启限原 Runner 构建和目录。worker 启动前通过公开查询取得原 Run/原提交请求及最新 revision；无驻留写者时用 Runner 持原写者租约的只读 inspect，不读其私有数据库、不启动执行、不证明资源已结算。仅此冷查询确认原提交从未受理时可结束未提交活动；暖查询缺失仍保留未知。必要 stop 以原身份在 worker 启动前受理；原 stop 未明确拒绝不得改写，明确拒绝须先持久记录并保留历史后才能重建。已永久 Closed 的原 Run 不另注入 stop，由 Runner 结算既有停止；平台仍等待原停止及封存。迟到 final 和重复控制不能替换已受理的 stop。跨构建不接管、不迁移，明确阻断。

界面沿用“项目 / 运行机 / 链路”与共用方案列表；模型只作为调用参数。详情显示项目说明/入口、来源、最近最终结论、项目 message/可选 details、平台结算状态及原日志。失败原因首屏可读，明细可展开且不因缺项目格式插件而隐藏；不把业务明细转为平台检查进度或二次判定。主要操作仅“开始检测/重新检测”“停止原活动”“标记失效”；不显示平台生成/更新环境材料、按检查步骤解锁或协议同步按钮。材料未适配时给出指导位置和调用诊断，不能隐式生成、调查或补装。

保留既有六阶段的展示框架，ready/not_ready 以统一资格判定为准；“尚未检测、项目未就绪、调用失败、停止/结果未知、已失效”在原因中区分。项目业务细节按项目原文展示，不强制六项检查/L2/PR 栏目。查询失败不可用历史通过缓存冒充当前就绪。

材料/状态查询只读，不能 fetch、运行入口或修改失效状态。历史按环境筛选后取最近20条，移除 profile 后仍可按原活动查询/停止。切换环境丢弃操作草稿的旧目标，忽略迟到响应，命令仍复核环境键及 revision。

移除日常 environment_generate 及其平台生成页面/新请求路径，不为旧命令保留兼容别名；未来初始化不借此恢复日常生成职责。现有任务测试来源/生成和普通添加项目不因本稿改成环境适配器。旧活动/数据库按未发布项目规则换代，不通过自动取消、清库、部署或旧格式兼容处理安装现场。

## 6. 初始化与日常更新

通用指导是 SteerLine 提供的规范。用户或项目自己的开发流程根据指导维护环境要求、检测入口和声明，项目自行验证。SteerLine 日常只调用已采用接口，不调查项目、不验证生成过程、也不把“生成自检成功”当成 ready。

未来项目初始化适配在生成侧读取指导、真实项目和明确目标，一次形成配套草稿，自检并修复接口格式、声明完整性、正常/负向/启动失败与收尾行为，交付自检结论和未验证项；不要求目标先 ready，不先提交协议/input/context，也不把自检步骤搬进平台日常检测。真实检测得到 not_ready 可以是正确的自检结果，不因未配齐工具而强造 ready。整体审阅并正常 Git 采用后才进入日常调用。

日常要求变化由项目配套更新文档、入口及声明并完成自身验证，经 Git 采用后由既定依据规则失效，重新检测即可；不通过 SteerLine 发起生成或内置审计。初始化 API、自动适配、生成修复循环和提交/纳管都留未来，当前不实现、不自动触发。

## 7. 与既有规范和实现的差异

本稿保留[原页面对象](runtime-environment-ui.spec.md)、[环境键/准入事务](project-environment-readiness.spec.md)及通用生命周期；取代[原适配规格](project-environment-adaptation.spec.md)与[发布能力规格](environment-publication-scope.spec.md)中“平台解析项目检查、强制完整L2/TTY/PR、分阶段调用并裁决”的环境条款。项目原测试和发布检查只在其任务流程中保留，不进入环境入口；平台不继续依赖旧业务报告结构。

实现已同步提示词治理、路径/产品设计和旧规范导航的现行表述，不能让旧协议副本要求通过另一文档重新成为前置。`internal/prompts/materials` 仍是平台固定规则所有者，但日常请求不读取受管理项目的同源副本；平台材料交付不得改为长正文 inline。本轮已移除旧生成/阶段编排及协议副本前置，结构化请求只调用项目入口一次；原任务测试协议、writer 与发布行为保持各自职责。

已授权的通用 execute/1 与原 result_file 承载一次项目调用，工作区、可信 final、原停止与封存沿原 owner；Runner 不新增环境业务知识。旧 Runner 的 development 发布组合不作为检测兜底。不得假定未公布的工作流/跨来源文件能力，不能用空 PR、假发布成功或修改项目检测要求绕过；不足时列平台调用能力缺口并在实施前补齐具体接线计划，不擅自建设新 Runner 框架。
