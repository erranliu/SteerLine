# Roadmap 草稿任务与依赖审阅

2026-11-09，用户要求为 Roadmap 草稿确认页改善依赖可读性，并授权审计、修订后实施。普通开发，不占任务号、不纳入 execution-map、不启动 roadmap-runner；实际实现与验证状态见专属验收。

## 1. 问题与目标

当前页面将任务正文、草稿原有依赖、Runner 拟议依赖和变化理由放进四列长表。依赖不变时重复显示相同内容，用户需要跨行追踪前置，难以发现分叉、汇合、独立分支和真正调整的关系。

本次将确认区域改为“局部依赖预览图 + 依赖变更清单 + 按需任务详情”。用户先判断整体结构，再检查变化和依据，最后沿现有入口确认整批规划。图直接由已保存的解析结果派生，无需再次调用模型或创建正式任务。

相关基线：[Roadmap 转正契约](roadmap-promotion.spec.md)、[Roadmap 页面](../../web/src/features/roadmaps/roadmaps.tsx)、[流程选择](../../web/src/features/roadmaps/workflow.ts)、[正式任务 DAG](../../web/src/features/tasks/dag.tsx)、[依赖校验及别名解析](../../internal/roadmap/model/model.go)。调查源码为 `eed86e1355b14d07521c85483c511bd2e625f585`。

## 2. 范围与权威

- 修改 Roadmap 页任务与依赖审阅区域，以及确认按钮中用于说明对象的文案。保留原草稿阅读、文档编辑、生成、发布、入图和原请求核实流程。
- 使用当前选中 `RoadmapRecord` 的 `analysis.tasks`、`analysis.questions`、`analysis.overlap`、`existing`、`source`、`id/revision`；不额外请求实时正式图来拼接该快照。
- 复用已安装的 React Flow，图只读、可平移缩放和适配画布；不支持拖拽连线、增删依赖、修改任务或逐边批准。
- 不改 HTTP/Runner 契约、数据库、解析规则、固定提示词、模型输出、确认摘要算法或 Task 编号时机。预览不产生正式任务、执行状态或启动资格。
- 现有后端继续负责引用、别名、环和确认资格校验。前端的投影、差异与布局不是第二套业务准入，也不写回解析结果。

## 3. 用户可见行为

### 3.1 总览与信息层次

依赖区标题使用“任务与依赖”，显著标明“局部依赖预览，尚未正式入图”；历史记录使用“历史规划快照”，已入图记录使用“入图前规划快照”并提供原正式 DAG 入口，不将保存的规划展示成实时正式图。

默认显示 Runner 拟议关系。顶部汇总规划条目数（区分新增与关联已有）、拟议直接依赖数、新增/移除依赖数、待澄清问题数。条目数来自全部 `analysis.tasks`，不能用去重后的图节点数代替。数字为依赖事实，不使用“可执行”“已就绪”等状态。

当前流程栏保留原操作和状态，采用普通文档流，不再整块吸顶遮住依赖画布。确认入口的业务位置及含义保持。

待澄清问题保持在确认区域直接可见；依赖不变也不隐藏问题。`overlap` 原文保留在“重叠检查与解析依据”折叠区，默认不让长路径、commit、tree 或保留理由占据总览。该区可查看本记录来源路径、固定来源提交、原文摘要以及完整重叠说明；不解析 `overlap` 自由文本来猜测结构或结论。

### 3.2 预览节点、连线与布局

- 新任务显示完整内部代号和最多两行任务标题；原完整标题在可键盘访问的任务清单及选择详情直接显示，不依赖悬停。正式任务显示 `#ID` 与快照标题，明确标记“已有正式任务”，使用不同节点样式并同时提供文字区分。
- 图包含全部规划条目，以及原始/拟议依赖直接引用的正式任务；未被关联或引用的已有正式任务不进入图。孤立任务仍显示。已有任务之间没有在本分析中表达的关系不补画，也不递归展开完整正式 DAG。
- 连线始终为“前置 → 后继”，画面常驻方向说明。只画保存的直接依赖，不做传递约简或补画间接边；不能将同层节点之间的视觉顺序解释为依赖。
- 提供“Runner 建议 / 草稿原始 / 差异”三种视图。节点集合及位置在同一记录的三种视图间保持稳定；原始视图展示原始边，建议视图展示拟议边，差异视图展示两者并集。仅原始关系引用的正式节点标注“仅原始引用”，在建议视图保留位置但不冒充拟议前置。
- 差异视图分别标识“保留 / 新增 / 移除”，使用文字图例及线型/颜色共同区分。移除边仍可选中查看，不参与拟议拓扑分层。两套关系的并集可能成环，不能把差异视图当成一个可执行 DAG。
- 默认按拟议依赖从左到右简单分层，同层稳定排序；不增加交叉优化算法或布局依赖。正常轮询不打乱节点位置或重置缩放。原始关系可能成环或包含逆向边，按保存关系显示并说明，不删边伪装成 DAG。
- 图中本地身份与正式身份分开编码，如 `local:<key>`、`formal:<id>`，内部代号 `8` 不等于正式 `#8`。`existing_task_id` 明确关联已有任务的条目投影到同一个正式节点，展示其内部别名，并保留独立的规划条目详情；不能画成另一个待新建任务。

### 3.3 依赖差异与依据

原始和拟议依赖先按身份解析为边集合，再比较：`保留 = 原始 ∩ 拟议`，`新增 = 拟议 − 原始`，`移除 = 原始 − 拟议`。比较忽略输入顺序及重复引用，但不改写记录中的数组和原始正文。

后端只对拟议引用做正式别名归一化，原始引用保留原貌。前端比较时须把指向已有关联条目的本地引用解析为对应正式身份：例如原始引用本地 `foundation`，且该条目关联正式 `#8`，拟议引用正式 `#8` 时应判为保留。不能把别名转换误报为删除加新增。

图下方默认只列变更，按后继任务分组，显示新增/移除的直接前置及该任务完整 `reason`。零变更明确显示“依赖未调整”；不逐项重复“保留原依赖”。该清单只表示依赖变化，不代表任务目标、范围与验收内容已经审阅。

另提供完整任务清单，逐项显示内部代号/正式关联、标题和拟议直接前置。清单不受“仅变更”影响，无变化任务和孤立任务仍能被选中并审阅。已有正式任务链接沿当前项目的既有 DAG 路由打开；普通选择节点不自动跳走。

### 3.4 选择与详情

选中节点高亮其直接前置、直接后继及连线，其余关系降低强调但不消失。图、任务清单、变更条目只共用一个选中任务；点击连线选中后继任务，其详情按“前置 → 后继、保留/新增/移除”列出相关直接依赖和任务理由。无需独立边详情、边选中状态或额外抽屉。保留边没有额外理由时不编造说明。

新增/关联规划条目的详情完整保留：内部代号来源、标题、目标、范围、约束、通过条件、原文依据、原始与拟议直接依赖、变化理由、已有正式关联。仅被引用的正式节点只显示快照中可得的身份、标题及原 DAG 链接，不推断交付或实时状态。原始依赖文字保留，便于核对别名归一化前的引用。

图使用审阅区全部宽度，详情统一位于图下，避免侧栏压缩画布；长标题不撑高图节点。全部任务及依赖均可经键盘操作清单获得同等信息，不要求依赖鼠标命中画布节点或细线。沿现有主题变量实现对比度和焦点显示，新增区域在 320px、768px、1440px 宽度可用，清单及详情的长代号/标题换行，操作区和清单不撑出页面；图可在自身画布平移缩放。

### 3.5 快照与确认

- 新视图严格跟随现有 `record/analysis` 选择；从项目、实例、草稿、记录或记录修订切换时，重置视图为建议图并清空失效选择。相同记录版本和关系仅轮询刷新时保留用户选择及画布视角。
- 当前与历史数据不得交叉拼接。历史加载中、无记录、无分析时展示明确空态，不能暂借上一条记录的图。来源变化沿现有 LF/CRLF 比较规则提示原快照过期，仍可查看原图，但保留原确认禁用条件。
- 确认按钮说明“确认本次任务与依赖（N 项）”，N 为本次规划条目数，并在总览区分新增与已有任务关联。按钮确认整个拟议规划，与当前图视图、所选节点或变更筛选无关；原始/差异视图不能成为另一个提交内容。
- 沿现有 `roadmap_confirm` 命令提交所审阅记录的 `id` 与 `revision`，不提交前端生成的图/边集或新摘要。离线、历史、读取错误、非 review、过期、待澄清等既有禁用和服务端拒绝语义保持。

## 4. 验收要求

| ID | 最小通过条件 |
| --- | --- |
| RDR-A01 | 分叉/汇合/独立任务、正式引用和已有关联均完整显示；方向准确、身份无碰撞、同一正式身份不重复建点；未引用的正式任务不混入。 |
| RDR-A02 | 三视图边集合、计数和新增/移除/保留正确；顺序/重复/别名归一化不产生假差异；差异并集成环不破坏拟议布局，不漏边。 |
| RDR-A03 | 默认变更清单简洁，零变化有说明；完整任务清单、任务详情及直接边明细可达，原文和理由可核对；仅有正式引用时不补造事实。 |
| RDR-A04 | 切换和轮询遵循快照规则；历史、来源变化、离线、待澄清及读取失败不误确认；点击确认仍只提交当前整批拟议规划的原 id/revision。 |
| RDR-A05 | 实际浏览器中图、选择高亮、三视图、缩放适配、长文字和宽窄屏可用；键盘通过清单访问同等信息，无新页面横向溢出和运行错误。 |
| RDR-A06 | 打开/切换/选择/缩放预览零业务写操作；不新增模型调用、正式图读取、任务创建或执行；生产构建及选定回归通过。 |
