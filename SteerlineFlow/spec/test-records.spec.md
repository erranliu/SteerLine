# Git 测试历史 Spec

日期：2026-10-23。用户已确认并授权普通开发，不纳入 roadmap。配套 [Plan](../plans/test-records.plan.md)、[本次验收](../testing/acceptance/git-test-records.md)。本方案取代原数据库登记和显式复验方案；[旧验收](../testing/acceptance/test-records.md)仅保留原版本事实。

## 目标与整合

L1–L4 历史的唯一来源为主分支 Git 中的 `SteerlineFlow/testing/records/<完整受测 SHA>.json`。每个提交独立文件，随代码 PR 合入，删除文件即可清理可见历史，Git 保留追溯。不同受测提交不修改同一个历史文件。

复用 cmd/test-feedback 的实际执行、冻结定义和 managed 报告；增加仓库侧 record 子命令，读取原报告后生成简洁历史。internal/testmanagement 负责格式校验、导出和查询投影，internal/app 复用项目维护核实的主分支 commit 与普通 Git blob 读取，Web 沿原只读测试页简化展示。

删除项目记录 SQLite 表、登记命令/API/客户端、登记回执和 Runner 历史投影。数据库 schema 从 29 切至 30，不迁移、兼容、双读或回退。候选 PlanTests、Runner 原始 artifacts 和证据归属校验保留，不从简洁历史文件取得交付证明。

## 文件与生产流程

```json
{
  "runs": [
    {
      "at": "2026-10-23T08:30:00Z",
      "results": [
        {"test_id": "l1.minimum", "level": "L1", "environment": "isolated", "status": "passed"}
      ]
    }
  ]
}
```

SHA 由文件名给出；每次执行一个 run，at 为该次报告的最晚结束时间（UTC RFC3339），results 每个已登记完整测试项一条。只保存 test_id、当时 level、environment、status 和可选 note；状态限 passed/failed/incomplete。不复制定义、命令、仓库绝对路径、分支、PR、日志、摘要和复验关系。清单继续由 test-list.json 维护；历史页的定义页明确是当前主分支定义。

流程：提交代码 → 测试入口输出实际报告 → `go run ./cmd/test-feedback record -report-dir <本次报告绝对目录>` → 提交 JSON，随同一个 PR 合入。文件名是实际受测 SHA，不是包含记录的提交号；rebase/squash 后仍保留原 SHA，不冒充新提交受测。

一个目录只能含同仓库、同源码提交、同次执行的报告。只接受执行前后固定、干净、未变的源码和完整登记项；记录目录自身变更不计源码脏。脏/未知/变动源码、定向子集和 build-only 的报告留在本地，不能生成固定 SHA 历史。实际通过条件继续由原执行器负责，零匹配/跳过/缺必要执行证据不计通过。

同 SHA 补测增加 run，原失败保留；同目录重复导出不重复追加，相同时间不同结果拒绝。仓库侧写入原子发布，同目录并发写者明确失败而不丢结果；不自动提交、push、创建 PR 或连接 SteerLine。完整日志留在原报告目录。

## 读取与页面

只读取项目维护已核实主分支 commit 下的普通 Git 文件；未提交/仅本地分支的文件不进入页面。按主分支 commit 缓存一次完整解析结果，commit 改变整体替换；缓存只在内存，不入数据库。文件名、JSON、时间、结果和唯一性严格校验；无记录目录为空，有坏 JSON 明确报错，不悄悄漏掉坏文件或回退旧缓存。

按测试项、级别、环境、原始结果、受测 SHA 和日期过滤；按 at 倒序、计算出的稳定 ID 排序分页。游标绑定项目、过滤器与主分支 commit，基线改变后拒绝旧游标并提示刷新。删除文件后列表和详情均不再返回原记录。

页面显示原始结果、时间、受测 SHA、级别/环境、备注和仓库相对文件路径；不显示数据库登记、来源候选、显式复验链或日志上传。汇总原始执行次数、原始失败次数、最近结果和最近通过；后续通过不会自动解决之前失败，历史通过不代表当前分支通过。历史中已不在当前清单的 ID 仍可浏览，标明仅有历史结果。清单无效与历史查询分别诊断。

## 验收要求

| ID | 自动通过条件 |
| --- | --- |
| GTR-A01 | 简洁 JSON 校验、完整固定源码导出、失败保留、重复导出及冲突拒绝正确；无应用/数据库依赖 |
| GTR-A02 | 真实 Git 证明未提交文件不可见、固定主分支读取、坏文件报错、删除移除、目录缺失为空、旧清单 ID 可查 |
| GTR-A03 | 过滤/分页/游标隔离、只读 HTTP 及前端原始结果/当前定义展示正确；原候选证据校验回归通过 |
| GTR-A04 | 新隔离模拟包中实际脚本失败→提交修正→通过→导出并合入本地受控主分支，API/浏览器可读，删文件清理可见历史；停止和资源结算完整 |

GTR-M01：页面密度人工体验可后置，不阻塞代码与自动验证。
