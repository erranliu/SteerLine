## 3. 测试集与报告

### 3.1 目录

复用 `SteerlineFlow/testing/test-list.json` 的稳定 ID，界面称“测试集”，可以代表一个整体入口。六个必需字段和可选 note 不变。目录从项目维护已核实的主分支 commit 读取，展示路径、commit 与观察时间；定义版本使用原规范化摘要，不另设人工版本号。

目录不可用时显示诊断，历史记录仍可查。目录列表合并记录里出现过的旧 ID，标“当前清单未登记”，历史详情用原快照；不引入独立历史目录管理。环境来自项目数据，不硬编码本仓枚举。

### 3.2 扩展原 Report

沿现有 `managed-<test_id>.json`，每份只属于一个测试集、一个实际环境。一条记录就是这次入口实际运行，不要求 Task/Candidate/Runner。`id` 为开始执行时产生的 32 位小写十六进制随机记录 ID；真正重跑使用新 ID，补登记沿用原 ID。一次命令运行多个入口时分别产生报告，不新增跨入口批次对象。

保留原 `sequence/selection/environment/definitions/before_commit/after_commit/before_clean/after_clean/results` 语义，增加以下必要内容：

| 内容 | 规则 |
| --- | --- |
| started_at / finished_at | UTC RFC3339，同一报告内结束不早于开始；不以不同机器的时钟判断复验先后 |
| 定义快照、实际命令、分支 | 在测试开始前冻结定义/摘要、选择和命令，结束后只补结果和后置 Git 观察；不在结束时读取已变更的清单充当当次定义 |
| 源码信息 | 保留前后完整 SHA/clean；Git 无法读取明确 unknown，detached 分支可空 |
| rerun_of | 可空，引用同项目、同测试集的一条已登记报告 ID；数据由脚本给出 |
| 证据清单 | 原相对引用、文件长度/摘要；未生成、过大或不可读取可声明缺失及原因 |

测试入口仍负责实际断言与完整性。不能报告子项的入口只有整体结果；已有执行器能报告稳定场景时才保留实际选择和逐项结果，不为本次页面强制新增 `expected_scope` 注册表或范围摘要协议。新增可运行场景仍按项目现有分级登记规则维护。

`selection/results` 仍表示清单 ID，不悄悄改作内部用例 ID。可逐项报告的入口可附可选 scope（本次是否覆盖入口完整范围、实际项 ID 及逐项结果），内容来自原执行器的冻结选择/枚举；缺少该能力时按整体项处理。只有实际报告了原失败项，才能按这些 ID 判断部分或完整复验，不能从名称/日志猜出覆盖。

原始结果为 passed/failed/incomplete：有实际断言失败优先为失败；无失败但前置、中断、清理或必要执行证据不完整为未完成；只有实际选择全部满足通过条件才通过。仅编译、零匹配、零退出码或 Agent 自述不能代替通过。子集报告须显著标“部分范围”，不冒充完整测试集。

原始结果与来源/证据适用性分开。脏工作区、Git unknown、前后 commit 变化、服务未取得必要证据均保留记录和诊断，不能作为固定 SHA 的通过证明；无报告不伪造失败。不建设脏文件指纹、全程源码监视或新的防篡改证明。

## 4. 登记与已有 Runner 接线

### 4.1 公开入口

脚本始终保存本地报告和原日志；有 `-record-project <项目ID>` 时在测试结束后调用统一 register 用例。沿原 `STEERLINE_HOME`/本包 CLI 发现规则选择 home，不新增 record-home/-home 参数或另一套发现机制；无目标明确提示仅保存本地，不猜测项目。

```powershell
# STEERLINE_HOME 按原 CLI 约定指向目标 home
steerline tests register -project <项目ID> -report-dir <本次报告绝对目录>
# 多入口时显式指定需要复验的测试集，其余仍为独立运行
# test-feedback 新参数：-rerun-of 'test_id=前次报告ID[,test_id=前次报告ID]'
```

register 只读指定目录内的报告和声明证据，不执行测试。CLI 通过既有认证应用/项目命令通道逐条提交；可由本项目 test-feedback 或其他项目脚本调用。新增命令独立校验参数，不沿用生成/停止命令的必填请求号和材料参数。命令请求号按原 CommandEnvelope 生成/保存；业务去重用项目+报告 ID，不能混用传输请求号。

项目目标由调用方显式选择，来源仓库沿现有项目 repository 识别/校验，不发明第二套 Git URL 归一化。Runner 来源必须核验原绑定，普通脚本记录明确标“脚本报告”，不能凭填写来源字段升级为 Runner 证明。

### 4.2 有界登记及缺证据记录

CLI 只读取声明的目录内普通文件，拒绝路径穿越/绝对引用/链接越界。服务接收内容，不按用户给的任意路径读取文件。复用现有 1 MiB 命令预算：每次提交一份报告（原始 JSON 至多 128 KiB）及一份必要 summary（原始字节至多 512 KiB），JSON/base64 编码后的完整信封仍须不超过 1 MiB；不扩大通用协议预算，不新增分片、上传会话或通用附件服务。

报告本身无效/超限、身份冲突或已上传字节摘要不符则拒绝。summary 缺失/超限时报告仍可登记，证据状态为“不可用”并显示原因/原引用；原始失败与未完成不能因没有完整日志而消失。不能把引用当作已核验证据，不静默截断冒充原文件，证据不可用的通过不计复验通过。原完整日志留在本次 out；其他文件仅保留引用。登记重放可补充原报告已声明且摘要匹配的 summary，不修改原报告、原始结果或证据声明。

登记阶段未上传/无法取得 summary 与测试执行时缺必要证据分开：前者保留脚本报告的原始结果并标“证据未核实”，后者由生产者如实报告 incomplete。不得为了登记成功把原始失败改成未完成，或把执行未完成改成通过。

控制台和独立 registration.json 按报告 ID 记录已登记/失败/未知、目标与诊断。多个报告分别成功或失败，不要求整目录事务。测试退出码保持原意；standalone register 有拒绝/未知项时返回非零并列明。离线后显式补登记原目录，不重跑测试。本地登记日志在发送前保存未知状态，显式补登按尝试追加并保留原回执。原请求对账只读取并核验该记录及完整原输入，不依赖 UI 历史详情或重新提交；临时存储/传输失败保持未知。没有后台发送器、自动补测或常驻 worker。

### 4.3 所有权与去重

`internal/testmanagement` 统一报告校验、项目登记和历史查询；SQLite 每条报告原子保存规范化内容/摘要、索引及已接收的必要 summary。同项目+报告 ID、相同报告/声明摘要重放幂等；内容冲突拒绝。证据可用性、已核验来源属于附属观察，不改原始报告。首次登记、后续证据补齐和来源核验均须事务性更新，不能半写后称已核验。

Runner 保留原公开 artifact 收集和 Candidate/Run Evidence 所有权；在原持久化已核验证据后，把同一份解析报告交给项目记录登记。重复观察/重启通过原报告 ID 重放幂等，不增加发件箱或新 worker。CLI 与 Runner 先后登记同一报告只出现一条；从 Runner 取得的 summary 仍受原 artifacts 的限制/校验，不能为 CLI 的附带 summary 限制放宽原候选规则。

项目记录的 summary 存取统一受 512 KiB 限制，超过时只显示原引用/不可用原因。Runner 原 Evidence 中更大的合格 artifact 仍按原规则保留和供 PlanTests 核验，不因页面预算被截断或删除。

原 PlanTests 继续读原 EvidenceView，复用扩展后的报告解析，不改读项目记录表。项目记录投影暂时不可用不得吞掉原已核验候选证据。原 Evidence 存储维护已投影 artifact 数量（复用其只追加、不可变的 artifacts 集合），现有项目 tick 有界读取尚未投影的已保存 Evidence 并幂等登记，成功才推进该数量；包括已交付/已放弃候选，不依赖其继续满足原 Runner 观察筛选或 Runner 仍在线。只有 artifacts 增加才需再次投影，单纯 Git 观察时间更新不触发重复投影。此处只处理本服务已有证据，不重新采集、不建 outbox/新 worker；结构冲突返回明确诊断，不标投影成功；单个坏候选不阻断其他候选，同批显式父子报告不依赖枚举顺序。

原候选 Git 新鲜度、固定 Plan/定义、Run/输入及必要证据规则不放宽；独立记录不因 SHA 相同自动算作候选证明。查询不导入报告，也不扫描临时目录/私有文件。

## 5. 显式复验：只认一次完整匹配的后继报告

脚本通过 test_id→前次报告 ID 的映射填写 rerun_of；未映射的测试集为独立运行。父记录必须已登记且同项目/测试集，引用不可改；新 ID 引用既有记录，不允许自引用，也不需要建立可编辑复验图。未登记父报告时先补登记父报告；不设后台等待/自动绑定。

复验顺序来自引用，时间仅用于展示。新 SHA 允许，定义、环境和验证范围必须可比。原始失败始终保留失败结果，复验进展按其显式后继中最新的一份报告判断：

| 展示 | 条件 |
| --- | --- |
| 失败待复验 | 没有后继，或最新后继失败/未完成、必要证据不可用 |
| 部分复验通过 | 最新后继通过，但只覆盖原失败范围的一部分 |
| 复验通过 | 最新一份后继报告在同定义/环境下，完整覆盖原失败范围且必要证据齐全；源码状态如实标注，不另加提交/clean 门槛 |
| 定义/环境变化，待另行核对 | 后继不可比，不能因此解除原失败 |

**不把多份子集或不同 SHA 的通过拼成一次完整复验。** 每次部分通过仍在历史可见；需要完整复验时让脚本实际运行原失败范围。不能逐项报告的整体测试集必须完整重跑。同一线性链以最后后继为准，较新的失败/未完成不被旧通过掩盖；无关联通过不解除失败。

多个分叉保留各条报告及父链接，分别展示；原失败标“多次复验，分别查看”并继续计待完整复验，不合并分叉证据或建立人工裁决/关闭流程。筛选隐藏链中记录不改变判断。历史通过记录只说明那一次，不宣称当前分支通过或证明修改与通过的因果关系。脏工作区/未知源码也可展示“复验通过 · 源码未固定”，不能宣称固定 SHA 已验证；本页不为日常脚本验证增加必须先提交代码的条件。原候选 PlanTests 的 clean/固定版本规则仍仅用于其原用途。

原失败行的复验进展同时标明对应复验报告 ID 和其源码状态；不能只显示原失败提交的 clean 标记，让脏工作区复验看起来像干净提交通过。

## 6. 页面与查询

侧栏新增 `/projects/:project_id/tests`，按原型的搜索/级别→测试集列表→运行记录/定义展示。目录不按 Task/Plan 分组；报告保留可选来源，核验可定位时跳原候选，不能定位则说明。原 PlanTests 只补深链接。

公开只读路径：`/tests/catalogue`、`/tests/records`、`/tests/records/:record_id` 和该记录的 `/evidence`。证据接口只返回本记录已接收的 summary 或明确不可用，不接受任意路径。列表返回报告摘要，详情按需取原定义/结果、父子记录和 summary；只读接口不创建命令或登记。

筛选：名称/ID、L1–L4、原始结果、复验情况、分支/SHA、环境、日期，可组合/清除。日期按界面显示时区转换 UTC，逆序报错。无清单、坏清单、无记录、无命中、查询失败分别呈现；目录失败不阻断历史查询。

记录按 started_at 倒序、record_id 稳定次序分页。复用现有游标方式，首屏携带记录入库序号上界，后续页和复验关系查询均使用同一上界；新报告/证据补齐/来源核验提示刷新，刷新后采用当前事实。不保存查询会话或全库快照，不承诺冻结可更新的证据观察。游标校验项目/筛选，不能用另一项目或筛选的游标。复验详情能读取完整关联记录，不限于当前列表页。

汇总针对所选测试集+代码/环境/日期范围，显示次数、最近原始结果、最近原始通过时间、失败待完整复验数；结果/复验筛选只控制列表命中，口径明示。部分、缺证据、定义变化和分叉仍待完整复验，同链每次失败分别计数，不称为 Bug 数。最近原始通过要同时标是否部分/脏/缺证据，不用单个绿灯宣称当前版本全部通过。

缓存键复用 home/项目/实例隔离，URL 保存测试集/记录定位和筛选；隐藏页停轮询，离线保留最后观察/时间，查询失败不假装空或新通过；迟到响应不改新项目。日志仅通过受控接口显示，不打开 file:// 或执行命令。
