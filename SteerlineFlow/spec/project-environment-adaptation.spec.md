## 1. 目标与所有权

SteerLine 根据项目 Git 内的准备文档，通过 Runner 指挥远端 Agent 准备、排障并使用其原生工具执行固定验收脚本。脚本分别写进度文件和结果文件，Runner 回传原始字节，SteerLine 校验项目标准。通过且原 Run 收尾核实后允许该项目在该远端配置上启动任务；预算耗尽仍有任何必需项欠缺时禁止启动，展示环境未就绪项及原因。不推断这台远端可以执行哪些任务。

| 所有者 | 职责 |
| --- | --- |
| 项目 | 维护准备文档、验收脚本、正式 L2 定义和完整 PR 要求；脚本执行并报告硬标准 |
| SteerLine | 上游生成提示词、材料固定、适配轮次和重试预算、结果校验、二态就绪与新任务准入、页面及历史 |
| Runner | 既有远端 Run、原执行身份/权限/工作区、原请求查询和停止；独立 progress-file/result-file 的来源绑定、字节校验及最后快照 |

Runner 不解析环境适配文档或文件内容，不判断 L2、PR 或环境就绪，不执行本功能的准备—验收—修复业务循环。SteerLine 不自行操作远端终端、读取 Runner 私有库或用本机代跑远端脚本。不要求远端无模型命令、artifacts 扩展、新通用 workflow、独立 context 或文件平台。

## 3. 二态执行资格

以“项目身份 × 远端执行配置”为范围，执行资格只有 `ready`（环境已就绪）和 `not_ready`（环境未就绪）。绑定配置ID及execution摘要；共享占用键仅用已公开的adapter+target.kind+target.environment，不发现主机/归并别名。远端重建或环境名改指机器后须显式重新适配，不承诺自动识别未公开的主机替换。不同项目/配置不自动共用通过结果。

未适配、材料缺失/无效、适配中、失败、取消、超时、结果未核实和预算耗尽均为 not_ready；流程进度单独显示，不成为第三种资格。启动新适配时先撤销原 ready。分项结果用于排障，不生成能力标签、任务分类或自动改投建议。

所有使用该远端配置的新任务/新候选入口共用门槛：在实际预留与保存提交意图前校验 ready 及适用依据，事务内复核，失效则零新派发。原请求重放先返回原事实；原候选结果读取、停止、既有交付不受此门槛阻断，不借适配强行中断或重开业务任务。本机执行不纳入本期门槛。适配和生成操作本身不依赖 ready，避免循环前置。

同home仅增加按公开目标键的窄准入占用对象：适配开始时核对已登记项目活动Run/未知写操作，拒绝与其并发；持有适配占用时阻止同键的新候选。各项目原持久记录是事实来源，启动先重建占用再开放新作业；不借用Runner服务启停锁或生成队列，不建调度平台、主机发现、跨库事务或全机锁。跨home/外部工具不在互斥保证内，占用不新增第三种环境资格。

## 4. 项目材料与稳定生成

项目固定入口为 `SteerlineFlow/environment.md` 与 `scripts/verify-environment.ps1` 或 `scripts/verify-environment.sh`，按项目目标平台选定一种入口。文档包含一个固定机器段，只声明版本、相对脚本路径、解释器、预先存在的验证base及有限的依赖文件路径；不从散文猜命令，不做全仓影响分析。两件材料由同一次生成形成配套内容，经正常审阅和 Git 流程维护，在同一正式提交固定后才能用于适配。首版不建设任意语言脚本框架或多文件应用事务。

SteerLine内置版本化上游提示词；环境模块独立构造generate输入、解析两份材料和缺口，只复用Runner客户端及home生成配额。不得向Plan专用GenerationService加入环境kind分支、改变其.tests.json/测试清单语义或提炼通用文档框架。生成不要求待适配远端就绪，输出可预览/导出，经正常Git审阅入库，不自动合入或恢复旧apply服务。

提示词输入为实际项目源码/相关入口、测试规范及完整清单、构建与依赖/服务/配置说明、Git/PR provider 与发布/审核要求、已有两份材料；维护时附相关适配失败事实。需要的文件缺失或超出本次材料范围时明确列缺口，不假装读过。提示词和实际输入/输出保存来源和摘要，生成结果不证明环境通过。

上游提示词必须稳定落实：

- 以完整 L2 + 完整 PR 为唯一环境就绪标准，复用已有真实测试入口与正式清单；不要求全部 L3、Full 或全部 L4。
- 准备文档覆盖工具、依赖、服务、配置、非秘密凭据引用、可持久复用的准备方式、常见故障及需人工处理项；不得依赖仅当前 Agent shell 有效的临时状态。
- Agent使用原生工具执行固定脚本prepare/publish阶段；prepare验证完整L2，publish唯一负责完整PR及最终报告。prepare失败立即写失败报告，原实现阶段报告阻断，不能进入PR。不得由Agent手写成功、删减L2、接受零匹配/跳过或改成模拟。
- 固定验证base由项目预先维护，Runner实际head按轮隔离；PR只在publish阶段创建一次，未知先查原PR。脚本清理自己创建的临时资源，保留固定base、Runner仍持有的工作区及预期安装成果；不绕过必需检查/审核。
- 信息不足或脚本/测试存在缺陷时报告缺口；运行期 Agent 不得改写固定验收标准以取得成功。

首次使用、L2/依赖/PR 流程变化或适配发现材料错误时提供生成/更新入口；日常维护走正常 Git 审阅，不因普通代码提交全量重生成，不增加后台自动模型审计。必要变更的适用性由维护与代码审阅负责，不承诺程序理解任意源码语义。

## 5. 硬验收标准及最小结果

完整 L2 指项目正式清单中当前全部 L2 登记项，不使用 Task 的选测安排，不按配置裁剪必需项；空清单或未实现入口不算通过。L2 自身规定的受控环境可以保留，但另行要求的完整 PR 必须真实执行。项目既有 PR 前置要求（如 L1）照常执行，不额外扩展为全部 L3/Full/L4。

完整 PR 指专属验证改动 → 项目要求的检查/测试 → commit/push → 创建 PR → 必需检查/审核 → 实际合并 → 合并事实核验与本次临时资源清理。验证 PR 合入专属验证 base，不合入业务主分支，不产生 TaskDelivery 或释放业务后继。隔离分支仍须覆盖项目真实规则；检查未触发、审核缺失或规则无法覆盖时未就绪，不能关闭 PR 冒充合并或绕过保护规则。

两个文件均由 Runner 分配、初始化并注入，调用方和脚本不得自选远端路径。脚本通过环境变量使用它们；同目录临时文件完整刷新后原子替换。只写单份小报告，完整日志留在远端，失败摘要不能含凭据。

| 通道 | 内容与消费规则 |
| --- | --- |
| `progress_file` / `STEERLINE_PROGRESS_FILE` / `progress-file` | 展示进度；初始声明本轮全部 L2 ID 与 PR 字段为未完成，开始/重跑先重置。由实际测试/脚本更新，不改变既有普通候选的布尔协议；进度全绿不代表就绪 |
| `result_file` / `STEERLINE_RESULT_FILE` / `result-file` | 脚本生成最终 JSON 报告。初始化为本轮 `completed=false`，成功或明确失败后原子发布 `completed=true` 的完整报告；completed 仅表示报告结束，不表示通过。每轮独立 Run 和初始内容，旧报告不能复用 |

progress持续观察，result只在原执行结束且生产者停止后封存一次，查询不读取远端文件。两份快照分别核验contract、原Run、base64/长度/SHA256，不能比较两通道版本或拼接内容。result仅接受disabled/pending/closed、version=0/1；version=1只能是closed且包含完整字节，真实空文件仍为version=1；closed且version=0必须有失败diagnostic，没有内容。result沿公开64KiB上限，超限/缺失/格式错误保持未就绪，不退回progress、Agent final、stdout或artifacts。封存成功或失败后都保存原事实，同一Run不等待新版本、不重采、不resume刷新；字节校验可复用，不共用progress观察生命周期。

结果内容由 SteerLine 单独定义和校验，不进入 Runner schema：版本、本次活动/轮次、受测提交和固定脚本摘要、completed、实际 L2 ID 集合与各项 `test_id/status/message`、同一 PR 的 URL/base/head/必需检查与审核结论/merged/merge_commit、本次脚本资源清理结论及失败原因。项状态沿用 passed/failed/incomplete，空必需项或未执行不能填通过。业务格式可先在本仓固定，不依赖新增命令或进程接口。

通过要求：先依据原Run的既有流程状态发起停止并核实收尾，再取得closed/version=1的唯一封存报告；其本轮关联完整、L2集合与预期完全一致且全部passed、完整PR及脚本资源清理通过才置ready。脚本必须在返回前原子写完最终报告。pr_ready仅触发停止，不证明通过；不能等待运行中的result来决定停止。无法确认最终内容、停止或资源状态仍未就绪。普通Runner命令accepted、进度全绿、completed=true、文件摘要或Agent总结都不能单独置ready。

这里的硬标准是固定项目脚本所作断言。Runner 证明回传内容来自绑定文件并保持字节完整性，不提供脚本独立进程退出证明，也不证明生产者未伪造；报告中的退出码如有也是脚本记录。准备文档禁止 Agent 改标准或手写结论，不将 SHA256/双文件解释为防同权限恶意写入的安全证明。

脚本、测试定义与本次受测源码固定；Agent 只能进行准备文档允许的环境和工作区初始化，不靠修改受测实现取得通过。执行在原远端实际身份/权限下，不依赖当前 shell 临时状态，不混同准备权限与业务权限。最终必须有一轮完整 L2 + PR 成功，不跨轮拼接通过项。

## 6. 有界修复与原请求恢复

默认总计三轮：首次准备/验收一次，最多两次修复重试。首版固定此预算，不增加多维预算或策略编辑器。开始动作包含此范围的有界后继授权；先持久固定材料、execution、预算及本轮原 submit，再调用 Runner。每轮独立 Run，使用相同固定标准和前轮失败事实，复用远端已安装成果/缓存并重新执行必要工作区初始化。Agent 自行排障不另计轮次；正式轮预留时占用一次预算，重复请求不重复计数，重启不重置。

流程为：Agent准备并执行固定脚本→观察progress和原Run→到pr_ready、完成/明确失败、取消或期限到达时沿原入口停止→核实原Run结束及result封存→全部通过才ready，否则明确失败且资源允许时进入下一轮。waiting_input和单个turn结束不触发停止或通过。脚本L2失败可以不进入PR，后续发布覆写必须如实报告阻断，不创建PR。达到三轮仍失败则停止自动后继，保留not_ready、未通过项、尝试历史和人工处理建议。显式“重新适配”创建新活动及新预算，不能抹去原失败。

开始前指定一个正的单轮总超时，对三轮保持一致；轮次开始时固定截止时间，覆盖 Agent 准备、自行排障、脚本及 PR 检查/审核等待。SteerLine 观察期限并沿原 Run stop 入口收尾，不依赖远端无模型命令超时。到期即停止本轮、保留未就绪；已确认失败/取消且原写者及外部 PR 操作已核实后才可用剩余预算重试。超时不重置、暂停或偷偷延长预算，不增加全局/Token/费用预算系统。

沿用[生命周期](../../docs/product-design/worker-lifecycle.md)与[服务换代恢复](service-generation-recovery.spec.md)的原请求、围栏和停止规则；本功能新增的仅是SteerLine持久保存的有界业务修复授权。submit/stop或PR结果未知时只核对原请求/原PR。停止后pending或查询暂不可读可继续查询原持久记录；closed/version=0为最终采集失败，保留并展示diagnostic，不等待同一Run刷新、不授权Agent重跑。只在原Run及外部PR资源安全条件满足后使用剩余三轮预算新建Run；无法核实则未就绪并暂停后继。重启保留原Run、封存事实、轮次和截止时间，仅已证明未发送且原授权仍有效的后继可首次发送；不自动重发未知输入或生成替代身份。

一范围只允许一个未结算适配活动；停止通过 Runner 原 Run 入口，取消后不再新建修复轮。停止受理不冒充进程结束；未知原操作或残留写者未核实前不得新开活动/补验。必需人工凭据、审核或项目缺陷无法在预算内解决时按实报告，不降低标准。

已确认在原implement阶段停止且没有PR及外部PR未知事实的取消/超时，可以结算取消或在剩余预算内新建轮次；缺报告仍不能通过。其他缺报告/PR未核实活动保留not_ready及人工处理原因，不提供手动改判ready。原stop明确拒绝时保留旧请求，再按新revision发起停止；未知stop只查询原请求。

## 7. 适用性与页面

ready仅比较项目/配置/execution、两份材料、正式L2定义/入口、机器段有限依赖文件与公开PR设置/固定验证base。文件按实际字节记录摘要，缺失阻断，不发现主机、猜关键文件或分析全仓语义。明确输入变化/已报告环境故障使其失效；普通提交不机械失效，远端重建由用户显式重新适配。不增加TTL或全机监控。

项目环境页按远端配置列出二态、进度（第几轮/共三轮、截止时间）、未就绪项与原因、L2/PR/清理报告及 Run 收尾事实和历史；分别显示“进度”与“验收结果”，不把文件观察状态当业务资格。提供生成/更新材料、开始适配、停止和显式重新适配入口。沿既有项目 HTTP 命令、Query 和可见页面轮询，不增加专用 SSE。双文件是两个 Runner 汇报通道，与项目生成的准备文档/脚本两份 Git 材料不是同一概念。

首版列表显示最近20条活动，按原ID查询完整轮次/文件/生成结果，完整历史仍保留在项目库。Agent回复和原Run说明仅供排障，不作为验收报告；长回复显示有标记的节选。公开HTTP动作及输入输出见[本地客户端协议](../../docs/product-design/local-client-protocol.md)。

现有环境检查的通用基础能力、原历史及原操作读取/收尾保留；本期远端项目级 L2/PR 准入统一使用适配结果，不把旧 check/v1 报告转换为 ready，不为旧数据回填或新增兼容旁路。

环境生成和适配Run分别列入现有具体生命周期入口：启动原请求/Run核验、兼容构建接管、service-start前stop outbox、应用/项目关闭、离线verify-stopped、调试reset与项目状态清理。复用既有逐类型登记方式补本类型，不增加通用registry；未结算原操作阻止破坏性清理，不能因不属于Candidate或旧Generation而漏掉。
