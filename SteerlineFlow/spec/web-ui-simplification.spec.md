日期：2026-11-10。状态：已按用户后续授权实施，自动验证通过；独立代码审计发现已修复并复核。用户要求大幅简化 WebUI，减少调试信息，保留直观进度变化。配套 [Plan](../plans/web-ui-simplification.plan.md)、[测试安排](../plans/web-ui-simplification.tests.json)和[专属验收记录](../testing/acceptance/web-ui-simplification.md)。普通开发，不分配 Task ID，不修改 roadmap，不部署安装现场；实际通过情况及未验边界只登记专属验收。

## 1. 目标与边界

日常页面围绕四个问题组织：当前做到哪一步、最近有什么变化、需要用户处理什么、结果是什么。技术标识由现有“复制执行信息”承担定位用途；默认页面不再铺开多层执行状态、内部回执和来源信息。

本次覆盖执行与待处理页、任务 DAG/列表及任务详情、Roadmap、项目运行环境、活动中心、项目维护摘要、全局栏和用量费用摘要。保留现有导航和深色视觉体系，不合并业务模块、不重做执行方案及配置编辑器；配置页的有效参数和测试管理页的定义、运行、历史、报告能力不因本次精简而删除。

本次只改变信息层级、显示文案和布局，不新增后端 API、数据库状态、Runner 契约、执行链路或通用展示配置框架。不引入“普通/专家模式”开关，不新增调试信息面板，不为旧版界面或开发数据提供兼容路径。

业务权威及 W01–W18、E01–E07、V01–V08 沿用 [Runner 调用生命周期](../../docs/product-design/runner-lifecycle.md)。等待按 [Runner 等待规则](runner-wait-retry.spec.md)，测试按 [运行时测试进度](runtime-test-progress.spec.md)，参与退出按 [候选停止规则](candidate-stop.spec.md)及[可靠性边界](candidate-stop-reliability.spec.md)。本次没有新的重试、恢复、交付或停止规则。

## 3. 信息取舍规则

| 信息 | 处理要求 |
| --- | --- |
| 任务编号、标题、候选编号、方案名称、当前阶段、参与状态 | 保留，用户仍能区分任务和并行候选 |
| Run/Execution/Attempt/Turn/请求/实例 ID、revision、digest、审计源命令及结果标识 | 从普通页面、展开的业务明细和全局栏移除独立字段展示；现有复制按钮保留已有字段 |
| 工作区绝对路径、执行分支、Workflow 标识/版本、请求模型和推理参数、冻结材料清单 | 从执行详情移除；方案参数在原配置页维护，不为精简新增查看入口 |
| 图版本、Task 版本、测试进度版本、采集传输技术状态、内部 Runner 事件、原始命令回执 | 移除面向用户的技术展示；后台数据、版本校验、原请求保存及对账不删除 |
| Spec/Plan/验收正文、执行与最新文档差异、测试命令与检查要求、审查问题及证据 | 业务内容保留，按需展开或切换查看 |
| 发布目标仓库/分支/文件路径与发布前后内容、任务依赖、材料变化提示 | 属于用户决策依据，保留，不能按“技术信息”统一删除 |
| 重复正常说明、实现归属说明、固定免责声明 | 移除或压缩；影响当前判断的限定词保留，例如“估算”“部分”“上次已知”“未核实” |
| 阻塞、拒绝、失败、未知、离线、材料过期、停止未核实 | 默认展示简明原因和适用的处理入口；补充上下文可展开 |

“复制执行信息”当前只复制定位字段，不包含所有诊断、路径和执行参数。本 Spec 不要求补齐这些内容，也不以复制按钮替代用户当下需要知道的失败原因。错误或业务正文中自然包含路径、提交引用或原始状态时不做盲目删改；删除对象是专门用于调试的字段和面板。

同一事实在同一详情区域只设一个主要展示位置，不在标题、交付、PR、告警等处重复长篇解释。不同请求的历史结果、当前执行事实和任务交付不能为了去重而合成一个状态。活动中心保留跨页摘要，不能代替原页面的实时进度、问题或操作。

## 4. 执行详情

### 4.1 当前进度与操作

标题保留任务名称、候选编号和冻结方案名称。当前进度区集中展示当前阶段、执行/参与的简短状态及必要的异常标记；不再同时铺开 `workflow_stage`、`workflow_status`、`execution_status` 等原始字段。运行中仍可同时显示“待回答”或“需处理”，不能用单一主状态吞掉独立事项，候选筛选及计数继续沿现有语义。

阶段来源为原候选公开投影的当前步骤/阶段及对应活动，不解析 Agent 正文猜阶段。已知阶段使用简明中文名称；只有现有事实足以确定实际阶段顺序及已完成阶段时才显示阶段条。当前接口仅给当前步骤、缺少顺序或完成证据时，展示“当前阶段＋近期阶段变化”，不为了实现固定的“准备→实现→测试→审查→交付”条而新增协议、猜测完成或假设阶段不能回退。未识别阶段显示“执行中，阶段待核实”等明确文本，不空白，也不标为失败。

“停止参与”“在 Codex/Orca 中查看”“复制执行信息”等原操作保留；冲突解决等操作按当前资格出现。没有能力的动作不能仅通过改版获得可用状态。需要用户回答或恢复核验时，在当前进度下方、动态和长结果之前直接显示问题/原因及原操作入口；非阻塞问题明确标为可稍后回答。

准备等待默认保留：排队/查询/退避/耗尽的区别、已等待多久、实际尝试次数、可核实时的下次读取倒计时。没有可信采样基准不显示伪计时；陈旧状态暂停确定性倒计时；倒计时到零只提示等待 Runner 更新，不判定失败、不发起输入或恢复。操作 ID、预算明细等调试字段不再形成等待详情面板。

### 4.2 最近动态

将最后一条消息和近期活动整合到一个“最近动态”区域：默认展示最新消息预览、其观察时间/相对时间，以及最多五条非内部活动。消息预览最多六行，有内容被截断时提供展开完整正文入口；活动默认显示时间和简短标题，详细正文按条展开。

超过五条的已返回活动提供“更多活动”入口，展开当前接口实际返回的其余记录。该入口不承诺完整历史，不新增全量日志或分页协议；内部 `runner_event` 不再单独提供技术事件列表。消息与活动是两种来源，不根据正文相似度去重，不把消息生成成阶段事件。

相对时间以来源观察时间计算，不把每次 GET 成功当作新的业务进展。无新消息不是卡住；无业务活动显示简短空状态，不能以内部事件条数冒充业务推进。读取失败保留最后可见内容并标为上次已知。

### 4.3 测试与审查

默认保留真实的“测试通过数/总数、未完成数”，有分母时可用分段条表达。展开后可查看逐项状态、原命令及检查要求，不默认铺开整张测试清单。布尔 false 只能表示未完成，不能拆成失败、运行中或尚未开始；没有安排、未安排自动测试、查询失败和历史关联不可用分别表述，不能用 0/0 或绿色满条伪装通过。重跑清零、历史结果、材料过期和同步异常仍可直观看到。

审查默认汇总已采集结果中的修复数量和遗留问题数量，并区分各轮/各步骤；多轮修复数不直接相加成“去重问题总数”。缺少完整结果时显示未核实，不默认零问题。遗留问题和审查失败摘要直接可见，逐项问题、修复说明及验证证据按需展开。删除结果来源 ID、命令 ID、输入版本、digest 及前后 Git 哈希等技术来源块。

文档入口合并为紧凑的“任务文档”入口，保留原执行版本、最新内容与差异查看能力。材料过期/当前性未知的提示留在默认视图；可与测试区同源提示合并一次，但不能隐藏它对当前测试关联的影响，也不能暗示旧候选已自动停止或失去交付资格。

### 4.4 交付结果与用量

合并交付摘要中的 PR 观察和页尾 PR 面板，原 PR 只设一个主要链接与状态展示位置。可区分“PR 已就绪”“待合并”“已合并，交付待核实”“任务已交付”；不能把原生执行成功、最终回复完整、PR 合并、TaskDelivery 和资源停止合成一个“完成”。来自不同观察来源且尚未一致的事实显示待核实，不通过改版选择较乐观结果。

已观察的 PR 状态保留“上次核实于”的紧凑时间或相对时间，明确是缓存观察；页面刷新不表示已重新查询外部 PR。PR 查询错误直接提示当前状态待核实。

运行中交付区域保持紧凑，已有最终回复仍可主动查看；原执行结束后，结果区优先展开当前 Execution/Attempt 最近取得的最终回复，其余已取得回复按需展开。当前接口的正文列表没有逐条 Turn 标识，必须标为“回复历史，包含先前轮次”，不能按列表位置把最近一条宣布为本轮结果；只有已有公开事实能够确认归属时才使用“本轮”标签。未核实/正文不完整时明确标记；本轮结果未核实时，即使有旧回复也保留该提示，最终回复缺失时不能用最近消息替代。不新增完整性或历史读取接口，不靠解析正文推断轮次。

停止参与后显示“已停止参与，底层执行可能仍在运行”；确有资源停止待核实、结算失败或未结束时保留摘要。只有原证明支持时才显示资源已停止，不把候选退出或会话关闭当作证明。

用量与费用保持单行“估算费用＋Token”摘要，原明细继续折叠。未计价、部分计价、覆盖不完整及旧估算不能伪装为完整账单。删除日常摘要里的技术版本和冗长解释；估算范围、假设及价格明细仍在原费用明细中可查，不在本次重做计费配置。

## 6. 进度真实性、交互与布局

1. 不显示推算的任务总百分比、完成 ETA、队列排名或“无消息即卡住”。只对有真实分母的测试/准备项显示计数和比例；阶段不是等权任务，不转换成总进度百分比。
2. 保留待回答、阻塞、失败、未知、准备等待、资源停止和材料当前性等相互独立事实。一般运行摘要可以简短，影响下一步的事项不能只靠颜色、图标、悬停或复制文本表达。
3. 对同一来源、同一事项的重复告警可合并；不同请求、不同来源和业务失败/观察失败保持区分。正文不丢失，必要补充详情可展开；没有可安全概括的原因时展示原原因，而非用“出错了”替换。
4. 离线或读取失败时保留缓存并标“上次已知/待核实”，显示最后可信观察时间；不因移除刷新时间行而丢失陈旧提示。观察错误不宣布执行失败，不取消实际工作，不能因折叠或关闭详情发送停止。
5. 所有业务操作沿用原能力、资格、版本、原请求持久化及对账，查询/重开页面/倒计时不生成新输入。项目、实例、Task、候选、Execution/Attempt、问题草稿和历史记录继续隔离，旧响应不得覆盖新选择。
6. 除第 4.4 节结束后优先展示结果的区域外，按需详情默认收起；直接打开、刷新或切换到已结束候选时，结果区在该身份的首个有效终态快照后默认展开。用户主动选择展开/收起后，同身份普通轮询不得覆盖选择或抢焦点；身份切换时按新对象初始化，不得带入旧对象正文。沿用现有可见性与查询缓存策略，不因视觉合并重复挂载查询、增加轮询频率或补充后台日志查询。
7. 桌面布局将当前阶段、重要操作、待处理事项和最新动态置于技术明细原位置之前。375/800/1440px 宽度及收起导航状态均可操作，无页面级横向溢出；长路径、正文、测试命令允许在自身区域换行或横向滚动。
8. 状态同时有可读文字，操作与展开入口支持键盘和可见焦点；进度变化不抢焦点，适度播报，不每秒朗读倒计时。沿用已有减弱动画偏好，不用持续动画伪装真实进展。
