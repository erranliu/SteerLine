# Spec：候选停止参与与终态处理收敛

2026-10-14 用户直接授权的普通开发需求。状态：已实现，最小自动验收已通过；人工复验待定，结果见专属验收。不新增 roadmap 任务，不修改 execution-map。

配套[实现 Plan](../plans/candidate-stop.plan.md)与[专属验收规划](../testing/acceptance/candidate-stop.md)。接续[候选连续创建与失败留档](../plans/candidate-start-retention.plan.md)，保留立即显示新候选、最多五个参与候选和编号不复用的规则。

本 Spec 定义新的 `stop_candidate` 功能，替代先前移除单候选操作的需求中与本功能冲突的要求；不恢复旧 `abandon_candidate`、`AbandonNativeCandidate` 或旧状态字段作为兼容接口。现行产品文档及既有验收记录仍描述其对应版本，实施时同步更新。

## 目标与边界

控制台和服务器提供停止指定候选参与的操作。人工停止、明确启动失败与已有候选终态使用同一套参与判定、停止声明和事实接收规则，移除现有已结束候选的专用恢复与生命周期执行通路，不并行保留新旧两套结束后处理。

停止参与取消中心对该候选的后续业务推进和交付资格，保留候选、编号和原执行事实。不停止 worker，不关闭会话或 PR，不删除工作区、分支、文件或其他资源。原 worker 可能继续其已经开始的工作。

停止资格和停止声明不以 Task 状态、版本、领取、依赖或 TaskDelivery 为条件，也不修改这些记录。Task ID 只用于定位归属和统计同一任务的参与候选；既有数据库完整性检查及提交后的只读快照继续沿用，不新增任务准入条件。Task 的派发、反馈和交付资格仍由各自任务入口校验；候选参与资格不得通过 Task 状态推导。Task 转为 closed/discarded 不自动批量写候选停止状态，也不触发已结束候选的专用处理路径。

## 单一参与判定与停止事实

参与资格只读取持久化 WorkflowRun 自身：`completed`、`abandoned` 为不参与，其余现有合法流程状态为参与。不另建参与状态表、参与布尔值或另一套参与状态机。控制台、数量上限、调度、反馈、交付和恢复使用同一判定契约；Task 状态不进入该判定。

准备中、运行中、等待输入、等待合并、阻塞以及执行效果未知的候选都计入参与数量。明确启动失败经统一停止声明进入 `abandoned` 后不计入；人工可以停止执行状态未知的候选，其资源事实仍保持未知。

统一停止声明将 WorkflowRun 写为 `abandoned`，并保存固定停止时间、原因和操作者。原因至少区分 `manual` 与 `startup_failed`；自动来源明确记录系统操作者。原请求身份及请求内容由既有 Command/回执日志保存，停止事实与命令结果同事务提交。首次停止事实固定，后续事件和重复请求不得重写时间、原因或操作者。

停止保留最后的真实业务阶段及其输入/结果历史。`start.failed` 可继续表示启动失败阶段及诊断，不要求删除或替换；参与资格只由 WorkflowRun 状态决定，不能按该阶段另走一套结束后处理。中心未派发的准备意图和业务输入保留原记录，并失去外发资格，不伪造已经执行或已经停止的回执。

候选自己的真实完成仍使用现有 `completed` 终态；它与 `abandoned` 共用后续参与门禁和事实接收规则。唯一交付的验证、事务和已冻结证据保持原契约，不把候选停止请求解释成完成或交付。

## 服务器操作与原子约束

新增 `stop_candidate` 控制动作、能力声明、严格请求校验及控制台 HTTP 客户端/服务端接线。请求绑定项目/仓库、正确服务实例、Task ID、WorkflowRun ID、候选当前版本和独立 request ID。停止请求的 request ID 与目标候选 Run ID 各自保留，不用停止请求创建新候选或分配编号。

服务器不要求任务处于 in_progress、服务处于 manual 派发、派发未暂停、worker 空闲、原进程已退出或 PR 可查询；操作不包含任何 Git、PR provider 或 worker 外部检查。通用请求身份和服务版本检查可以沿用现有控制协议，但不增加 Task 版本或图版本作为停止条件。

受理后，在同一个数据库写事务内完成：

1. 优先按原 request ID 核实并重放已经提交的相同请求；同 ID 的内容或目标不同则拒绝。
2. 校验目标归属、候选版本及候选自身状态。已终态候选返回明确的已结束结果，不改写原终态事实。
3. 从权威记录重新统计同任务的参与候选。人工停止的目标必须仍参与，且停止后至少保留一个参与候选；历史失败、已停止和已完成的候选不能充当剩余参与候选。
4. 使用统一停止声明保存终态、固定停止事实、命令结果和对应事件，提交成功后才发布成功回执及新快照。

两个客户端同时停止最后两个参与候选时，最多一个事务成功；另一个因仅剩一个参与候选被拒绝。创建与停止的数量检查都在写事务中完成，不能只依赖控制台按钮或操作前快照。

人工停止的最后一个保护不适用于自动启动失败：确切失败仍保存为历史并释放名额，不能为维持数量把失败候选伪装为参与。身份不明、结果未知、环境阻塞或仍可能运行不等于自动启动失败；只有明确的失败事实可以走自动来源。

## 统一门禁与事实接收

参与判定必须覆盖准备结果应用、准备/启动派发、后续阶段、反馈、恢复、PR 查询和唯一交付写入。停止提交后，不再为该候选发起新的工作区准备、会话准备、输入、下一阶段、PR 轮询或交付。交付写事务必须再次校验所选候选未停止，防止停止与交付竞争时用旧快照完成任务。

以中心把动作交给适配器的派发边界区分待派发与在途：尚未派发的意图失去执行资格；停止前已经派发的动作可能返回真实结果，停止不撤销外部事实。停止提交与实际派发必须有确定先后，不能检查参与状态后仍在停止提交之后交出新动作；复用现有执行串行化机制落实，不新增独立调度框架。晚到准备结果不得重新激活候选、推进到启动或补派发后续步骤。

所有收到的 worker 事件、输出和生命周期回执保留原绑定校验、去重及事实入库。对已停止候选，仅更新可由原回执证明的执行/资源事实、历史输出和原操作结果；不改变候选终态，不恢复业务资格，不制造新 Command、Attempt、执行身份或会话。已交付候选的冻结证据不得被晚到消息改写。

停止后的事实接收不新派发 `Execute`、可能重新实施副作用的 `Reconcile`、业务输入、完成报告、原生结果确认/ack、停止执行/观察、清理或文件删除。既有传输协议接收消息所需的确认沿用原通道，不因此补发业务或生命周期动作。没有新事实时保留最后采样和不确定性，不能把 Execution/资源状态强行写成 stopped、成功或已释放。

已经连接的只读观察通道可以继续接收原执行事实；在途结果携带的原观察对象只能用于同一事实接收，不授权新的资源或业务动作。正常传输与本地句柄的释放不得因候选停止而调用外部停止或资源清理。服务重启后跳过已停止候选，不为它创建观察器、主动重连、轮询、恢复或补结算。

移除 `resumeRetiredCandidate`、`finishRetiredCandidate` 等专用结束后恢复/完成流程，并移除 `retiredResourceAction` 及各处结束候选可继续外发资源动作的例外。原 `applyRetiredLifecycleReceipt`、`recordRetiredWorkerEvent` 中必要的绑定校验和记录能力收敛到既有事件/回执入库流程；活动和终态复用事实写入，终态不推进业务。允许保留不同消息类型的解析入口，不另建通用事实引擎或重写适配器体系；不得仅更名后保留一条人工停止路径和一条旧 retired 路径。

原 `failReservedStart` 等明确启动失败入口调用同一停止声明；不得直接另写一套终态或恢复逻辑。明确的任务交付、停服和资源管理操作保留自身授权边界，不由候选停止或通用终态处理隐式触发。

## 历史、名额、编号与 PR

停止后立即释放一个参与名额；准备中及未被停止的未知执行继续计入，最多五个参与候选。名额描述业务参与资格，不承诺最多五个物理 worker；停止不清理资源，实际存活 worker 可能更多。

停止不删除候选或修改 `CandidateNumber`。新候选在创建事务内从同任务全部持久化历史的最大编号加一，历史包括已停止、启动失败和已完成候选；不复用、不压缩、不按当前列表位置编号。控制台待创建展示以确认后的权威编号为准，不重写旧编号。

准备期停止可以保留尚未取得基线、会话或环境证据的原记录；历史读取和重启加载不得要求为这些记录补齐外部证据。已经固定的共同基线继续覆盖历史并用于后续候选，不能因为原候选停止而换基线；没有取得基线的停止历史不伪造基线，也不阻止其余候选首次固定基线。

停止候选的 PR、合并事实及分支身份保持历史记录；不自动关闭 PR，不让其后来的输出或合并触发候选复活或 TaskDelivery。本功能不改变新增候选时既有的历史 PR 核验规则；候选停止本身无需查询 PR，新增候选等显式操作仍执行各自核验。原 PR 唯一绑定、固定共同基线和真实目标 Git 事实仍覆盖相应历史，不能把停止当成外部 PR 已关闭、未合并或资源已消失。

## 控制台

新增 F9“停止当前候选”，进入现有右下确认区。确认显示 Task ID、固定候选编号、执行方案和目标身份，并明确显示：停止参与、保留历史和资源、当前 worker 可能继续运行。Enter 明确提交，Esc 取消；保存原答案草稿失败时不切换操作或提交。

操作只允许服务器已经确认存在、身份和版本可核实的参与候选。控制台仅有提交中的本地占位候选时，不发送停止请求；提示等待服务器确认。最后一个保护的计数只采用服务器已持久化的参与候选，本地占位不能充当另一个参与候选；只剩一个时显示不可用原因，最终资格由服务器事务裁决。已终态候选显示停止原因或完成事实。Task 状态、派发模式和原执行是否空闲不作为按钮资格条件。

提交前持久化原 request ID 和固定目标，提交期间显示正在停止，未收到成功不能假定已停止或释放名额。结果不明时查询原请求，不更换 ID 重发。晚到、重复或错误目标回执不能改写其他候选、重新编号或抢用户当前选择。

停止成功后，若用户仍选择该目标，基于最新权威快照切到编号最大的剩余参与候选，并按现有切换规则清空当前展示的旧正文、问题、活动、详情/滚动和异步读取缓存。若用户期间已切换则保持其选择；剩余候选暂不可核实时保留原目标并提示刷新，不凭旧快照猜选或重新创建候选。

已停止候选仍可通过 F6/F7 选回只读查看历史。默认区明确显示“已停止参与”或“启动失败历史”、固定原因及“资源保留”；执行/资源状态按原事实独立展示，未更新时显示最后采样/未核实。停止后的问题和答案仅作历史，反馈、恢复和继续等业务操作不可用。

## 最小验证与交付范围

自动项 CST-A1～A6 见[专属验收](../testing/acceptance/candidate-stop.md)：服务器事务/幂等/任务状态独立、最后一个与并发保护、名额/编号、无外部动作及统一事实处理、重启读取与停止不恢复、控制台确认/身份/选择，以及停止与交付竞争和共同基线。复用现有隔离 Go、Git、SQLite、受控适配器和控制台夹具；只补覆盖上述契约所需的最小用例或驱动。

相关旧单候选退出测试若仍引用已删除接口，改为新 `stop_candidate` 契约或移除已失效的旧断言；不能通过恢复旧接口或资源清理流程来通过测试。后续实现 Plan 必须按验收项明确实际场景、命令、环境、时点和证据位置；本 Spec 不要求 Full、真实模型或真实 PR 验收。

本次只规划控制台与服务器/现有 HTTP 客户端所需操作，不额外增加独立 CLI 子命令，不新增旧库迁移、旧协议兼容或候选重新参与入口。人工界面复验可后置，窗口和已验/待验事实只登记在专属验收文档。
