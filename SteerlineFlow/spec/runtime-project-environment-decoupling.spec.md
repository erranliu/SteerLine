# Spec：运行环境与项目运行环境最小解耦

2026-11-02，已按用户授权实施；所选自动验证及独立代码审核通过，范围与原失败见专属验收。代码基线 `6f1edde1dbc9bb950d579a4cbe1dca67301c778b`。[Plan](../plans/runtime-project-environment-decoupling.plan.md) · [专属验收](../testing/acceptance/runtime-project-environment-decoupling.md)。普通开发，不进入 roadmap。

## 1. 成果与范围

运行环境是运行机与运行链路的组合，由 SteerLine 的全局执行配置和原生能力探测获得；项目运行环境是项目在该组合及具体执行上下文上的适配与检测结果。未选择项目、没有注册项目、项目未提供任何接入材料或项目启动失败，都不妨碍获得运行环境配置和执行平台能力探测。

本轮主要调整底层归属、依赖方向和查询组装，复用已有全局配置页、探测入口及项目检测闭环。运行环境检测限于现有只读配置/能力查询：可定位的目标、链路、Agent/模型目录、版本与已公布能力及查询错误；不新增模型执行探针，也不宣称目录查询成功已证明执行、停止和封存全过程可用。实际执行仍由原 Runner 生命周期核验。

本稿实施后，仅替代[项目检测 Spec](project-environment-workflow.spec.md)与[界面 Spec](runtime-environment-ui.spec.md)中把运行环境本身归属项目、混称全局探测与项目资格的部分。项目自有入口、manifest4/version3、显式依赖、资格摘要、Current、统一 Qualify 和原 Run 生命周期继续沿用。旧验收只证明各自固定版本。

## 2. 最小对象与身份

| 对象 | 来源和身份 | 归属 |
| --- | --- | --- |
| 运行环境 | 当前 home 下的 `adapter + target(kind/environment)` 配置目标；本机由当前运行主机定位，远端 environment 保留配置中的 selector 原值 | 全局配置/探测 |
| 执行方案 | 原 profile，引用上述目标并携带 Agent、模型、权限、启动程序等执行参数 | 原 `execution.json` |
| 项目运行环境检测上下文 | 项目身份 + 原 `environment_key`；该键仍由非模型 execution 上下文计算，区分会影响项目检测的 Agent/权限/启动配置 | 项目 |

运行环境是现有目标的值对象，不新增持久 ID、注册表、机器配置文件或 CRUD。配置中的运行环境由 profiles 按目标归组；可发现的未配置远端仍沿原目录入口返回，不自动落盘或生成 profile。不要求在全球范围识别同一物理机器，也不增加重命名/换绑协议。

原 Orca selector 可为 ID 或唯一名称，本轮不解析为新的规范身份、不合并别名；不同 selector 不保证被识别为同一物理机器。目录新选择沿原入口采用返回的 ID，显示名仅作标签，不用展示名称改写已保存目标、项目键或占用键。

同一运行机与链路上的多个 Agent/profile 共属一个运行环境；它们的能力查询和项目资格不因此共享。`environment_key` 继续表示项目检测上下文，不再用它命名全局运行环境。保留该算法及既有项目材料路径，是保留其仍然成立的语义；不增加旧数据读取、迁移或键映射。

目标识别/校验与分组的纯规则归 `internal/executionconfig`；从 `environmentadaptation/model` 移走现有 `Target` 所承载的中性规则，更新消费者并删除原实现，不保留转发包装。`Context/Key`、材料路径、结果信封和资格判定仍归项目检测模型。运行环境规则不导入项目检测、项目 Config、SQLite 或任务模型。

## 3. 配置、探测与项目检测

### 3.1 全局配置和探测

开发链路的能力组合试样，以及 Web 新建方案或在无匹配模板时构造的开发链路参数，必须显式提供公共 schema 要求的 `access_mode: full_access`，不能因试样缺少必填字段误报不支持，也不能生成无法保存的开发方案。真实保存配置仍必须显式声明权限，后端不补默认值、不放宽校验。 Web 移除权限下拉及过时的默认/沙箱选项，静态说明开发执行使用完全访问；开发方案的新建、链路切换和显式工作流切换在现有构造入口写入权限，能力试样也统一初始化一次。只读内容方案的普通编辑继续保留 read_only，生成/对话契约不变。

- `execution.json` 仍是唯一人工保存的执行配置。沿现有 Snapshot 增加由 profiles 派生的 `environments` 只读分组，每项仅含 `adapter`、`target`、`profile_ids`；不包含项目身份、材料、活动或 ready。所有合法 workflow 的 profile 均参与全局分组，项目检测继续仅消费其支持的方案。
- 复用 `/api/web/execution-config` 和其 `/discover`、`/validate`、`/status`，不新建环境 API。配置读取、校验与全局分组不连接项目端口、不解析项目 Git 身份、不读取项目库或环境材料。Runner schema/能力仍由现有离线元数据入口提供，不为探测启动共享 Runner 服务或业务 Run。所有元数据子进程显式使用当前应用 home 作为 cwd，不继承启动 Web 的项目目录；不使用进程级 `os.Chdir`。
- `discovery.Manager` 继续由 Web 持有，原生查询只接受全局目标与查询参数。提供 `profile_id` 时必须找到该方案，并校验查询的 adapter/target 和所选 Agent 与之相符；不存在或错配明确报错，不能静默用默认程序探测另一条链路。profile 只用于绑定目标、Agent 和原查询实际支持的参数，不承诺还原其全部执行配置。Codex 沿现有元数据程序查询，Orca 沿当前本机 runtime/已配对远端的目录 RPC 查询，不执行 profile 的 transport/agent_launch。原不带 profile 的目录查询保留其原生默认上下文；profile 内的 provider、权限、启动参数等未被目录查询验证的上下文仍明确 `context_unverified`，不为验证这些字段增加执行或连接路径。
- 分组不聚合出“整个运行环境 ready”。查询结果沿原 `context_key` 绑定实际使用的查询输入和当前可观察身份，例如程序、目标、Agent、本机 runtime 或配对信息；这些已观察输入不同不得串用成功。未用于目录查询的 transport/agent_launch 不据此宣称被验证，也不为其建立执行上下文摘要。远端 runtime 重启若未通过新查询观察到，不能保证立即发现；继续用原显式刷新及 freshness 表达缓存，不增加每次命中前的 RPC。复用原缓存、取消、超时和并发，不增加持久探测活动或后台扫描。
- 探测信息区分成功、不可用、不支持、过期及查询错误，显示来源和时间；成功仅针对该查询范围。全局配置缺失/非法可阻断读取，但诊断必须指向全局配置，不能要求项目先接入。安装程序、登录/配对、修改 PATH 或凭据不属于本轮。

全局分组对应已保存配置及原 `saved_digest`，项目继续使用启动时冻结的配置；保存未重启不把新列表当作已加载事实，沿原待重启门槛处理。分组按原 profile 首次出现顺序输出，不重排配置。同一目标下的 profile 顺序保持；Runner 元数据读取失败单独表达，不删除已能从合法配置识别的目标。

元数据程序的解析、文件取证和启动也不得依赖父 cwd：绝对程序路径直接使用，含目录的相对程序路径明确查询不支持；裸程序名只在绝对 PATH 目录项中沿原生扩展名规则解析，不搜索 cwd、相对或空 PATH 项，不修改进程 PATH。取证和启动使用同一条已解析绝对路径。这仅限定目录查询，不改保存的 profile 或项目执行路径语义，也不新增通用路径解析器。

### 3.2 项目检测

项目选用原 profile，从中性目标规则取得运行环境，再按原非模型上下文读取项目材料。项目查询先组装目标/方案信息，再独立计算项目资格；某项材料缺失或源提交无法读取时，仍返回该运行环境及方案，附项目未接入或无法核验原因，不能将整份配置查询变成失败或空列表。

无入口材料显示“项目尚未接入检测”，不启动项目检测；入口、依赖或来源不合法继续按原规则阻断。具备材料后仍只调用项目入口一次，消费其 ready/not_ready、message/details。项目需要的 SDK、许可证、服务或权限由项目自行检测；环境入口及资格依据不涉及项目测试、构建验收、业务文档或 PR 发布。

两个项目共享全局配置与能力信息，分别保存项目活动和资格。项目 A 缺材料或未就绪不影响项目 B，也不改写全局探测。全局目录暂时不可查询不改写项目封存报告，不撤销 Current，也不能连带封死停止原活动的操作。

## 4. 准入与生命周期

不新增全局 Current、持久 ready、资格版本、全局环境数据库或“全局检测通过后才允许项目检测”的门禁。

任务准入继续由后端原执行配置/Runner 能力校验与项目 Qualify 共同负责；Web 的目录数据及缓存不成为准入证据。实际链路不能启动仍由原执行路径报告，不能用目录成功补足；项目 ready 也不能替代平台能力、身份和生命周期核验。

原项目 `inputs_digest`、Current revision、材料变更持久失效、候选事务复核与目标占用规则保持。中性目标规则移动后，跨项目、同目标不同上下文的占用仍沿原范围判定；不得误缩到 profile 或扩大到整台机器。原请求未知只对账原身份，停止、封存及同构建恢复遵循[Worker 生命周期](../../docs/product-design/worker-lifecycle.md)。本轮无新增执行节点、重试、恢复或停止授权。

## 5. 页面最小适配

全局 `/settings/execution-configs` 继续承担配置和能力探测，利用原运行机分组展示运行机/链路及探测状态，无需项目即可进入；不新建运行环境管理页、导航体系或编辑器。

已保存列表直接消费全局 Snapshot 的目标分组，删除被替代的前端目标归组算法，避免两份规则；项目页保留其按检测上下文归组的卡片，因为它表达的是独立资格。

项目 `/projects/:project/environment` 保留路由、卡片、开始/停止/失效、历史与任务返回，仅将标题、导航、摘要和相关阻断文案明确为“项目运行环境”。材料缺失标为项目未接入，并提供现有全局执行配置入口；项目页面不新增一套全局探测按钮或编辑表单。

前端区分全局探测与项目资格的数据类型和查询作用域：前者按 home/配置/目标/Agent，后者继续按 home/项目/实例/检测上下文。项目切换不污染资格，目标/配置切换后迟到探测不覆盖新选择。现有保存冲突、待重启、未保存草稿及错误缓存表达保持。

编辑页为探测选择已保存 profile 时，必须比较完整目标（含远端 environment），不能只匹配 adapter/target.kind/Agent。新建或切换目标后没有对应已保存方案时，沿原不带 profile 的默认目录查询并显示范围；不将旧方案探测结果标成新草稿的实际执行验证。

## 6. 验收条件

| ID | 可验证成果 |
| --- | --- |
| RPE-A01 | 合法全局配置下，零注册项目、项目加载失败及项目零接入材料均可经产品入口读取运行环境和探测；没有项目 Git/库/材料调用，也无新 Run/Task；元数据程序解析/取证不依赖项目 cwd，子进程 cwd 固定为 home |
| RPE-A02 | 目标识别/分组只有中性 owner；同目标多 Agent/模型共属一组，目标或链路不同则分组不同；项目原环境键、依据和占用语义保持 |
| RPE-A03 | 全局配置读取/校验/探测复用原入口；指定方案缺失或目标/Agent 错配明确失败；不同实际查询输入/已观察身份不串缓存，未验证执行参数及未观察远端重启的缓存边界如实呈现，不扩目录 RPC |
| RPE-A04 | 项目材料错误不吞掉运行环境/方案；未接入、项目 not_ready、平台查询失败分别呈现；两项目资格独立，项目检测仍自行闭环 |
| RPE-A05 | 准入继续使用后端原平台校验与项目 Qualify；目录成功不能放行未就绪项目，目录失败不改封存报告/Current，不阻止原活动停止；失效/迟到/占用及候选事务反例通过 |
| RPE-A06 | 原两条页面路由可用，全局无项目可操作，项目文案明确；任务定位/返回、草稿、保存/重启和缓存隔离回归通过 |
| RPE-A07 | 无新增配置文件、环境表/库、持久探测作业、资格缓存、执行工作流、兼容包装或新 Runner 协议；移除被替代的重复目标规则与相应重复测试 |

具体场景和结果归专属验收。本轮不改固定提示词、模型可见材料、调用接线或对应测试/CI；实施如触及这些范围，须先给出实际正文差异、前后字节数、业务原因和验证并经独立审核，遵循[提示词维护](../../docs/prompt-governance.md)，不能用样本更新代替批准。

## 7. 安装现场补充：配置展示不能等待项目资格（2026-11-02）

RPE-A04 同时覆盖查询迟滞：项目材料读取挂起或超时时，运行机、链路和方案仍可显示，不能只在材料读取最终返回错误后保留配置。

复用项目 `/environment/options?configuration=true` 只读投影启动时已加载的执行配置；不读项目 Git、存储、Current 或依赖，不读取尚未加载的全局保存稿。它只提供配置事实和 `unverified/not_ready`，不授予项目资格。完整 options 继续负责项目资格；前端先显示配置、允许选择，未核实前禁用新的检测/失效操作，原活动停止不受影响。显式刷新同时刷新配置和资格，初次配置查询临时失败可恢复。

没有当前检测的环境，只检查项目文档、manifest 和脚本入口并提示待准备与检测；完整依赖错误在开始检测时报告。已有 ready 的资格核验和实际检测仍读取全部显式依赖、比较原完整依据；失效、未结算及失败状态不为展示重复计算无效的依据。材料预览只返回原文、入口和诊断，不生成资格或完整依据摘要。共享 Git blob 只在单次请求按仓库、固定提交及路径复用；不新增持久缓存、作业、状态表或回退通道。

补充通过条件：将项目存储和 Git 设置为不可用时轻量配置查询仍成功；完整查询挂起时选择器仍有配置、操作不放行；初次轻量失败可显式刷新恢复；依赖缺失时待检测查询不扫描依赖，但实际检测必须失败，已有 ready 的依赖变化仍撤销资格。
