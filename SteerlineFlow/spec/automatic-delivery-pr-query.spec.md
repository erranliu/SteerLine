# 自动交付平台查询与项目 actor 解耦 Spec

SteerLine 的自动交付从候选取得原 PR 绑定，使用候选冻结的 provider 向平台查询，并以本地 SQLite 事务决定是否交付。平台等待移出项目 actor，候选观察、派发和用户控制可在查询期间继续推进。范围限于 `TickPR` 的自动交付。废弃、PR 页面诊断及 Runner 职责沿现有规则。

## 查询与提交

- 项目 actor 按当前自动交付资格和候选扫描顺序选取对象，为本次查询冻结项目实例、任务、候选、原 PR 绑定、版本和查询起点。每项目最多一项自动交付查询或待处理结果。一个轮询周期内依次处理当轮候选，送查前重读资格。重复 tick 合并，慢查询、未合入或可恢复错误处理后可继续扫描下一候选。已交付任务沿原规则退出扫描。
- 查询执行方只使用本次冻结的 provider、原 PR 和认证引用，沿用 command/Gitea 的既有超时、解析和脱敏。它返回事实或错误，SQLite 提交、既有诊断和下一项选择仍由 actor 处理。结果仅供当前实例、本次查询消费一次。结果完成后有五秒提交窗口，超过期限重新取证。查询超时与结果交接各有独立边界。
- 查询完成通过单槽位和独立唤醒交接。已通知的 stop 优先，其次处理就绪结果，再开始普通调度工作。候选观察在单个候选处理完成后可交接结果。完整合入证据可让本轮辅助观察按原上下文取消路径让出等待，避免其用满五秒后才处理证据。正在执行的候选控制仍走既有对账。证据年龄从平台返回起算，交接和让出等待均不重置时间。
- `stop_candidate` 的持久 inbox、原校验、回执和抢占机制继续生效。查询挂起时可立即处理 stop。结果就绪与 stop 通知竞争时，actor 在准入结果前先处理已通知的紧急控制。若 stop 已应用，晚到结果不能交付该候选。若通知在交付事务准入后到达，沿用现有取消和事务顺序，以已提交记录为准。原最后候选限制仍适用。停止项目时取消在途查询、丢弃未提交结果、等待自有查询退出。重启从当前持久状态重新取证。

## 交付证据的有效边界

候选全量 revision 会随 Run 投影、事件页和游标变化。自动交付查询跨越这些观察后，事务使用当时的候选重新建立绑定，并与查询前固定的依据逐项比较。全量 revision 仍供原候选写入 CAS 使用。

- 查询前固定任务、候选、认领者、任务契约、原 submit 请求及冻结输入摘要、Runner 命名空间、Run ID/input digest 和工作区/会话身份。候选 PR 继续使用现有 `BindRunnerPR` 的来源和目标要求。固定 URL、编号、provider 配置和认证引用、仓库、base/head 分支及候选已知的 PR head revision。提交时工作区、原生会话、attempt 或 generation 与取证依据不符，旧证据作废。
- 提交时在原 SQLite 事务重读任务状态和版本、authority 和图版本、候选当前参与与停止状态、受理和认领关系、契约和原绑定。比较本次取证依据，继续验证响应是同一原 PR、平台明确已合入、有有效合入时间和 commit、观测时间有效、PR 未被另一候选占用。候选撤回、停止、原输入或目标改变、任务或图版本变化均使旧证据失效。新绑定或未知事实须重新取证。
- 仅普通观察变化时，候选仍符合原资格且上述依据相同，已经取得的合入事实可以提交。Run revision、投影状态或诊断、事件页和游标的变化本身不触发重查。任务、图或原绑定持续变化时仍可能需要重新取证。禁止把查询结果改标为另一候选或为旧结果回填当前 revision。现有唯一交付、重放、图推进、后继释放和停止义务仍原子提交。废弃沿用原候选集合和严格版本检查。

控制与恢复沿[统一 worker 生命周期](../../docs/product-design/worker-lifecycle.md)。本次差异限于自动交付查询生命周期及其事务取证依据。

## 通过条件

1. command 或 Gitea 查询挂起时，观察、派发和合法 stop 仍可在释放查询前完成。每项目最多一个在途项，后续候选可得到查询机会。关停后无迟到提交或遗留查询。
2. 用可控屏障覆盖 stop 与查询结果同时就绪、stop 已应用后返回合入、交付先提交三种时序，保留原控制回执与事务结果。
3. 查询期间连续推进同一候选的 Run revision、事件和游标，在任务、图及原绑定稳定时，一次合入查询完成唯一交付。用会等待到五秒预算耗尽的辅助观察验证结果可提前交接。单独改变停止资格、认领、输入、会话、PR 或任务和图版本时，旧证据均被拒绝。
4. 未合入、来源不符、结果过期或项目重启时不产生交付。重启重新查询原 PR，已有交付按原记录重放，后继仅在交付事务成功后释放。

实施顺序和验收入口见[Plan](../plans/automatic-delivery-pr-query.plan.md)及[专项验收](../testing/acceptance/automatic-delivery-pr-query.md)。
