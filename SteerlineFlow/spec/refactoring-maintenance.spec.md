## 1. 成果与范围

提供“重构与维护”项目分页。用户选择方向、就绪配置、预算和策略后，SteerAgent 只读调查与理解反馈，生成提示词驱动 Runner 在一个受管 worktree 中分轮改善代码，最终交付一个 PR 和重构审计报告。维护默认与普通任务开发并行，每个项目同时只允许一个在途维护行动。

首版实现单方向、手动启动、三种策略、美元/时间/轮次预算、人工答复、提前交付、立即停止、停止后收尾、历史查看及手动冲突续作。多方向、在途编辑预算/策略、暂停后续轮次、定时触发、自动合并、自动监控到合并、Orca 维护组合不在本期。首批完整组合为本地 Codex；支持范围来自公开契约与本次验收，不从普通开发就绪推断。

用户不必先创建普通 Task 或手写维护 Spec/Plan。无有效改动时交付报告和结束原因，不创建空 PR。对已有行为、公共接口或其他任务范围的改变超出授权时，提出具体人工决定。

## 2. 唯一所有者与解耦

| 所有者 | 本期职责 |
| --- | --- |
| 维护业务 | 唯一行动记录、版本、预算、轮次、人工决定、项目在途名额、收尾与后台推进 |
| SteerAgent maintenance | 只读工具调查、理解反馈与收益、生成执行提示词及必要决策说明，提出问题或结束建议 |
| Runner 适配 | 固定与投递原请求，观察、来源校验、用量读取及停止责任；不自行解释工程收益 |
| Runner | 工作区与会话、所有项目写入、实现、验证、审计、修复、撤销、Git/PR 操作和报告生成 |
| 查询与页面 | 只读展示保存事实、提交原对象上的用户操作；查询不生成提示词、推进轮次或调用 Git/模型 |

维护业务独立于 Task/DAG、候选、TaskDelivery 和现有待答建议。复用 runnerclient、纯绑定校验、配置派生、价格计算和项目运行时，不泛化候选专用 runnerbridge，不增加通用 Agent 引擎。SteerAgent 的决策执行使用实际只读权限，不向其暴露项目写入或任意执行工具。人工问题、结束建议等控制说明不成为可执行动作脚本。

## 3. 启动及冻结

表单从五个长期方向中单选；补充要求可空；默认带入项目默认执行配置，不能隐式改投；默认策略“谨慎决策”；美元、分钟、轮次至少填一项，均须为有限正值，轮次为整数，默认只填 1 轮。金额使用十进制精确表达，拒绝 NaN、无穷、负数和零。

开始前沿现有项目维护资格只读核实配置远端目标分支 HEAD，要求项目已就绪、本地与远端一致；维护启动不主动 fetch 或准备项目。冻结 remote、URL、local_path、分支与完整提交、执行源及派生配置、方向、用户原文、策略、预算及规则原文。另核验本次组合的环境、Runner、模型、文件材料、结果封存与发布工具资格。缺必要能力返回具体原因，零行动执行提交；已预留原请求不升级输入。

原用户命令、行动登记及项目在途名额原子保存；每个具体 Runner 请求的完整意图在投递前落盘，保存失败零外部提交。同请求同正文返回原行动，换正文冲突；另一请求同时启动由后端仲裁，不依赖按钮禁用。未结算的决策、可写执行、未知请求和停止义务仍占行动名额。

只读决策和 execute 执行分别通过 Runner 的配置能力从所选方案明确派生，保留模型与目标的选择并固定结果；不使用对话建议的独立模型设置，也不新建维护模型配置树。新行为缺构建能力时禁用本功能，不影响原业务观察或停止。

## 4. 多轮与 Runner 来源链

一个维护轮次是同方向的一次有限重构或审计尝试，含调查、必要执行、审计与结果判断；内部修复、工具调用和结果补读不各算一轮。失败、放弃和无改动的审计尝试也计轮次。项目准备、决策生成和收尾不增加维护轮数，但运行与费用计入行动。

每次明确的项目执行使用新的 execute/1 Run。首个执行创建 worktree；后续修复、轮次、收尾和冲突处理通过 `reuse_worktree_from_run_id` 引用同一 state-dir 的最新持有者。完整 Repository（含初始 base_revision）、adapter、target 与来源一致；主线推进不改写这些冻结字段，后续 fetch/merge/rebase 由 Runner 在原 worktree 内执行。

对返回的原请求、Run、input digest、相关行动、来源 Run、`workspace_origin_run_id` 和 `workspace_identity` 进行绑定校验。接受新 execute 即更新最新持有者；即使新 Run 失败、未产生提交或被停止，也不退回“最近成功 Run”或最初 Run。接受未知时只对账本次 request_id，期间不创建另一接管。

接管前只消费 Runner 的结算与公开资格，不在平台自建 Git 清理或工作区重建。`workspace_not_settled` 保留实际待结算责任；只有确认本次申请被拒绝且没有新 Run/副作用，才可在原责任核实结算后保存新的申请意图，保留原拒绝事实且不重复计维护轮次。`workspace_already_reused`、`workspace_transferred`、`workspace_identity_unavailable`、`workspace_identity_conflict` 说明具体阻断，不猜选其他 Run、不改路径绕过。原结果未封存、物理文件写入或 parser 未结算均不能视为可复用。

SteerAgent 按实际反馈决定继续调查、生成审计/修复/撤销提示词、接受成果或请求人工。审计使用与实施独立的只读会话，依据 Runner 回传的差异、验证结果和封存证据。Runner 说明与判断相关的未提交变化，证据不足时先请求补充。结束建议可以提前收尾，不必消耗全部预算。已结算写 Run 的 Git HEAD 和干净状态由 Runner 的公开只读观察提供，只有最近 worktree 持有者的已核实 Git 事实进入当前上下文。

只读决策已停止且原结果明确为原生提问或无效 JSON 时，保留原失败和用量，在同阶段生成一次新决策。该次生成不增加维护轮次。再次出现输出失败则阻断并保留诊断，原 Run 不接收回复或重发。

业务结果以原 execute 的封存结果文件表达完成、需要补充依据或阻断及证据，宿主按本次行动/操作来源校验；模型文本不能直接改业务状态。execute/1 若因原生提问结束，沿真实失败/缺失结果交给只读决策处理，不能向旧 execute 发 reply/resume。人工决定后的下一步是明确的新 execute。

固定短指令及完整规则沿 prompts 文件与集中组装入口维护。完整材料通过正式固定文件渠道交付并记录来源、字节和摘要，缺文件或超限阻断，禁止 inline 规则兜底。决策与独立审计使用 generate.directory 的 read_only 读取原项目目录。首次 execute 才由 Runner 建立维护 worktree，后续决策通过冻结 file 材料读取 Runner 回传的成果。execute 的历史 Documents 字段引用已核实的两份真实项目规范/测试入口，仅作协议参考，不另建维护 Spec/Plan、准备模型轮次或项目规范文件。动态用户原文、轮次反馈与报告不截断、不改换行、不塞进 schema 或诊断字段。用户无需手写材料，宿主也不直接写项目。

## 5. 预算与费用口径

预算只限制新维护轮次的发起。有剩余额度即可发起下一轮，不预留下一轮或交付的完整预计成本；任一已设置预算耗尽就自动进入收尾。当前轮次的必要处理、验证、修复、独立审计、冲突处理、PR 与报告继续完成，不因预算本身等待人工、要求追加预算或硬杀执行。收尾不再增加新切片，实际消耗允许超过预算。

时间按行动实际运行区间累计，包含准备、决策、执行、验证、审计、必要排队与收尾；等待人工、显式停止和服务离线不计入，页面另列总历时。预算及消耗持久化，刷新或重启不清零。

用户已明确确认美元口径：**主会话 + 已登记内部调用的已覆盖参考费用**，始终披露未覆盖的子 Agent、工具内模型和不可观测供应商调用；不称为完整账单或全来源总成本。已明确披露的范围外来源不单独禁用美元预算。启动时美元预算另要求采集可用、配置模型明确和有效价表；保存当次价格依据、版本/摘要与匹配时点，原行动按该依据计算，不随配置刷新重算预算。

必须先固定每个 Run 的 snapshot_revision，再读完同 revision 事件页。scope 缺省按 Runner 当前契约解释为 main_session；新 scope=runner_internal 单独处理。仅 counted 且具备可信用量和配置归属的事件计价。按 Run/事件身份去重后汇总；父主会话合计、内部事件和已计算费用不能重复相加。

`run-usage.tokens/status/coverage` 继续只证明主会话；主会话计数与 Token 一致性只比较 main_session 事件。内部来源结合 call_id/call_source/source_result_id/coverage_status 和 model_call_coverage 核验，不拿内部 counted 数去比较主会话 counted_responses。未知 scope、非法计数、缺页、模型/价格缺失及 pending/uncovered 保留为费用缺口，不能算零；费用问题不改写已核实的执行结果。

已登记来源尚待采集时有界观察原事实，不执行模型重试以补费用。若仍不能确定计价范围内的新轮次资格，停止发起新轮次并自动收尾，保留不确定性；没有美元预算时费用不可用不阻止按时间或轮次推进。UI 展示累计运行时间和总历时，分别展示推进与收尾参考费用、覆盖范围及缺口。

## 6. 人工决定、停止与恢复

完全自主、激进决策、谨慎决策只影响取舍倾向，不改变权限、范围和验证要求；谨慎决策不要求逐轮批准。需要人工时保存事实、影响、推荐方案和原问题版本，在当前卡片内答复。答复绑定原行动和问题；保存后由 SteerAgent 转成后续提示词，保留原答复和实际提示词，未保存不投递。过期答复不改投，未知投递不重复发送。

“结束并交付”持久保存不再新开轮次的意图，让必要工作继续到交付。“立即停止”先撤销后续投递资格，再停止正在进行的只读决策或可写执行；迟到结果不得再触发新输入。分别展示停止受理和资源已核实停止，保留成果及“结束并交付”入口。

停止后结束并交付，在原停止、文件封存及其他责任结算后创建新的收尾 execute，复用最新工作区；不重开旧 Run、不伪装恢复原会话。未创建工作区或没有有效成果时直接报告真实结果。工作区已丢失或原停止未知则保留具体阻断，不借预算原因要求人工，也不自动新建替代工作区。

原请求、未知、输入串行、停止和构建边界沿 [Runner 调用生命周期](../../docs/product-design/runner-lifecycle.md)。新增差异只在行动授权内创建明确的后继 Run；同构建重启先恢复观察、原请求与停止责任，不自动重发旧 pending/unknown 或重新生成输入。首版核实后以“结束并交付”明确授权继续已有成果收尾。所有维护及决策 Run 纳入项目关闭、服务退出、升级排空和 reset 的原责任集合。

## 7. PR、报告与冲突续作

收尾提示词由 SteerAgent 生成，Runner 执行验证、报告、提交、推送及 PR 创建/更新。平台不直接修改项目或发布 PR；维护宿主通过只读 provider 查询核验 repo、head 分支/提交、base 与 PR 身份，再采用结果。最终报告从原 Run 的公开结果和封存结果文件读取，不能从终端片段或宿主私有目录补造成功。

报告包含目标/基线/策略、每轮接受的改动、收益证据与代价、实际验证及独立审计、失败/撤销/遗留、预算与实际消耗。报告在本页展示，并由 Runner 同步到原 PR 正文；不增加独立报告文件管理页。保存 PR 前进展、发布未知与平台核验失败分别呈现，不能因回执丢失重新创建 PR。没有改动仍有报告，未完成验证不能称为可合并。

报告注明本次收尾决策请求冻结的参考费用与采集时间。发布、发布后审计和存档使用这份原快照。收尾决定、报告/发布及晚到用量继续计入页面行动汇总，原报告版本保持原有金额、时间和覆盖范围。

交付前关注目标分支变化，由 Runner 同步并复核。冲突审计说明双方意图、解决方案、重新验证，以及收益保持/部分损失/抵消/不确定；没有文本冲突但影响重构依据时也要复核。报告绑定明确 head/base，相关变化后标待复核。

“处理冲突并更新报告”仅用于未合并、未关闭的原 PR，原子取得项目在途名额；沿原行动和最新 worktree 持有者创建新 execute，更新同一 PR 和报告版本。该操作属于已有成果收尾，不重置预算、不新开方向、不新增 PR；有其他维护在途则拒绝。保留原报告，缺失原资源时具体阻断。自动合并及持续监控不在本期。

## 8. 最小页面与产品接线

一个项目分页包含启动表单、当前行动卡片和底部历史列表。启动后表单收起为只读摘要；卡片展示方向/策略、轮次/阶段、时间/参考费用、当前工作及最近判断；展开记录可看“做什么、为什么、结果、下一步”和原提示词/反馈。人工问题、答复框和“提交决定并继续”位于同一卡片，不另建聊天或详情子页。

区分准备中、执行中、等待人工、收尾中、已停止、已交付、异常和结果待核实；仅展示真实阶段，不按文字猜进度。预算耗尽显示收尾，不显示等待充值或确认。只提供已确认的运行控制和交付后续作，按钮资格由后端提供。未知费用不显示为零，发布待核实不显示已交付。

复用应用 v2 原命令信封、版本、请求回执及操作反馈。异步活动中心增加一个维护行动来源并链接回本页，显示 SteerAgent maintenance 用途；不为每个辅助 Run 重复创建产品活动，也不把现有项目同步误归为智能维护。活动和列表 GET 只读已保存投影。

## 9. 自动验收与完成条件

全部自动项必须在[专属验收](../testing/acceptance/refactoring-maintenance.md)有证据；少量体验项单独后置。提示词资产、接线及其测试须按[治理规则](../../docs/prompt-governance.md)提供实际完整正文差异、UTF-8 字节数、业务原因、验证和独立审核，不能用黄金样本更新代替批准。
