# 活动中心独立阅读页 Spec

2026-11-10，已按审核修订后的本 Spec/Plan 实现并完成必要验证；随后独立代码审核确认的 7 项问题已修复、复核及补验。未部署、不启动 roadmap、不修改 Runner 或固定提示词；ARP-M01 人工体验待安排。初稿、审核及实际报告保留于专属验收。

对应 [Plan](../plans/activity-reading-page.plan.md)、[测试选择](../plans/activity-reading-page.tests.json)及[专属验收规划](../testing/acceptance/activity-reading-page.md)。本文是现有[活动中心](../../docs/product-design/async-activities.md)的增量设计，不将其历史测试准备来源恢复到当前产品。

## 1. 成果与范围

在当前项目新增 `/projects/:projectID/activities` 独立页，集中发现全部活动、阅读最近可读消息及按需查看已记录交互。顶部抽屉继续快速查看，在抽屉中提供“打开独立页”；项目导航也可直接进入。两入口定位同一活动身份，不复制活动业务状态。

本期活动来源为当前注册的 environment_detection、baseline_check、task_candidate、roadmap、main_agent_advisory；每个来源的实际消息能力分别展示。无消息的检查、发布、入图等活动仍显示其真实阶段与结果，不伪装为 Agent 对话。

本期不包括跨项目聚合、独立页提交回答/停止/重试、全文检索、完整原生 transcript 采集、工具日志重放、原生日志扫描或自动模型摘要。去回答、去处理和打开原生会话沿已有定位入口。后续完整原生对话能力需另行确定 Runner 公开契约，不由本期补造。

“历史对话”在本期明确指**已记录的交互**，不承诺完整原生会话。界面使用“已记录的交互”，并说明可包含已保存的用户输入、公开问题和回复结果；运行中 commentary 的连续历史只有在原公开持久事实存在时才可展示。本期不将瞬时最近消息采样积累为聊天档案。

## 3. 最新可读消息

### 3.1 定义与真实性

“最近可读消息”是本系统最后观察并核验归属的公开 assistant 文本、当前问题或已保存回复结果的有界预览。阶段/诊断是单独的“活动进展”，用户输入另有角色，均不冒称 Agent 新回复。预览显示类型、原消息/观察时间、来源及截断标志，默认两三行，正文最多 4,096 UTF-8 字节。没有消息时间时标明观察时间，数据库采样时间不能冒充消息时间。

当前 last-message 可能只返回 tool。遇到工具消息时不展示工具正文、不替换同一绑定的上一条 assistant 样本，也不更新该样本时间；没有旧样本就显示“暂无已观察到的可读消息”。本期是最佳努力观察，不承诺“原生会话最新 assistant”，也不为寻找上一条 assistant 拉取完整对话。若后续要保证此语义，需 Runner 提供按角色读取的轻量公开能力，另行规划。

只有完全相同的 Run/Attempt/session 绑定才可比较或保留样本；新 Attempt 清空旧运行的实时预览，旧内容只在有原持久依据的历史中展示。问题或新 final 可优先作为明确标注的摘要，不把不同来源时间混排为一条推定的原生消息序列。预览不能证明业务成功、资源结算、输入送达或会话完整。

### 3.2 读取与观察解耦

活动列表和摘要 GET 只读本地持久事实/快照，不调用 Runner、Git 或模型，不逐项调用业务详情。现有 owner 负责持久事实；新增消息观察作为原观察链的独立、有界只读步骤，通过只读端口消费公开 last-message，不能新增活动调度器或依赖活动页是否打开。

后台只采样有原公开定位能力的未终态 Run，每个绑定最多每 10 秒尝试一次；应用内消息读取最多 2 个并发，单次消息读取预算最多 1 秒（含等槽/公开调用/解码），不阻塞状态观察和资源收尾。限频使用最近尝试时间，成功、失败、null 和 tool 都消耗间隔；最后有效 assistant 消息时间独立保存。现有执行页选中目标可维持 3 秒按需刷新；该前台读取与后台采样共享同绑定快照、在途读取及最近尝试时间，不能两个通道重复调用。活动独立页不额外发起前台 Runner 读取。禁止为观察创建原生会话、恢复、对账业务命令或补交输入。

采样失败保留原时间与旧样本，标明陈旧/不可用；关闭应用后不承诺补齐错过的消息。无合法绑定或不支持公开读取的来源直接显示能力缺口，不发试探性请求。允许保存每个原绑定一条有界最新样本，不建立全量消息镜像库；该快照不递增业务 revision、不参与资格或恢复决策。终态停止采样，沿用最终持久结果与最后观察时间。

## 4. 页面与按需查询

### 4.1 布局与浏览

桌面为左侧活动列表、右侧所选活动阅读区。默认“进行中”，另有“需处理”和“历史”；计数未知时保留未知提示。“历史”包括全部有持久依据的终态活动：有权威结束时间者在前，按结束时间降序；缺少结束时间者进入独立空值桶，按原创建时间降序，创建时间也缺失则放桶尾；各桶同时间按来源加稳定 ID 升序。游标携带同样的桶/时间/身份排序键，显式加载更多，每页默认 50、最大 200，不受抽屉 recent 的 50 项总上限限制。已入图 Roadmap、提交前拒绝/取消且无 Projection 的候选等无结束时间记录仍可分页发现，显示“结束时间未记录”；空值桶的创建时间只作浏览排序，不能借先前生成时间充当发布/入图结束时间。未结算仍按原语义留在进行中，不为填历史改写状态；底层窗口不足以证明完整时返回部分结果，不能显示“全部加载”。

history 列表没有周期刷新或窗口重新聚焦时的自动重取，加载过的页不随列表轮询重读；手动刷新重新读取首屏并重置后续游标。进行中/需处理的周期查询仅更新明确的首屏/当前可见有界摘要范围，不自动逐页重取全部已加载结果。列表查询、摘要刷新和显式翻页共享数据/在途请求，分别设置触发条件，不能直接把现有 infinite query 的轮询设置套到所有历史页。

列表包含名称、阶段、必要进度、最近可读预览及时间。摘要更新原位替换，不以新消息重排列表或抢选中项。右侧默认仅有摘要、问题/阻断提示及“查看已记录交互”按钮。页面初次打开不自动选中第一项；深链接 `?activity=<稳定活动ID>` 可以选中摘要，但不自动展开历史。

窄屏按列表→所选摘要→展开交互分层，提供返回列表，保留选中和滚动位置；长文字换行。键盘可选择活动、展开交互及返回列表，焦点不随轮询变化。抽屉打开独立页时传原活动身份并正常移交焦点；独立页打开期间复用同一查询缓存，不能另起一组重复轮询。

### 4.2 查询触发表

| 用户/页面行为 | 允许读取 | 禁止读取 |
| --- | --- | --- |
| 进入页面、列表轮询/翻页 | 活动列表及当前页有界摘要，可一次批量读取摘要 | 所有活动的交互索引、正文、原生完整会话 |
| 选择活动、打开摘要深链接 | 所选活动必要摘要/定位元数据 | 交互历史和长正文；不因终态自动展开 |
| 点击“查看已记录交互” | 仅所选活动首个索引页：角色、类型、来源、时间、短预览、正文引用、完整性/缺口 | 后续所有页及每条完整正文 |
| 点击“加载更多交互” | 所选活动一个后续索引页 | 自动追游标到末页 |
| 展开期间发现来源变化 | 有廉价标记时只读原 revision/事件序号等变化标记，显示“有更新” | 返回/自动追加新交互、遍历旧页或正文计算变化标记 |
| 点击“刷新交互” | 所选活动一个新的索引首屏，旧页失效并重置游标；不自动读正文 | 自动恢复全部旧页，或将不同分页范围拼接 |
| 点击某条“展开正文” | 该条正文首段；超过一段提供继续读取 | 同页其他正文、该条全部后续分段 |
| 点击“继续读取正文” | 该条下一段，沿用摘要/长度/身份校验 | 其他消息正文 |
| 收起、切换活动、切项目/实例、页面隐藏或离开 | 同范围可复用内存缓存；必要的列表轻量观察依原规则 | 隐藏详情的持续刷新、新详情请求和迟到响应写入新目标 |

索引默认 50 条、最大 200 条、单页序列化预算沿用 1 MiB；短预览每条最多 512 UTF-8 字节，不在索引中携带完整请求或 final 正文。索引使用窄字段/有界预览，不逐条读完整事件正文再裁剪；既有大 JSON 的 SQL 字段提取可能仍解析所属原记录，但不能把完整载荷传入 query 或扫描全部会话来生成一页。

正文沿用 256 KiB 单段及 16 MiB 完整正文上限，超限/截断/损坏明确展示。首次显式展开某个正文，在原存储只能提供整体载荷时允许读取和验证该条全文一次；后续段复用同一不可变引用的验证结果和有界内存缓存，不能每 256 KiB 重新读/解码/哈希全文。缓存须有总字节和生命周期上限，逐请求核验原归属及版本，失效/淘汰后明确重新验证；不新增正文磁盘镜像。单次用户动作最多返回一页/一段，不自动循环拉取。较短正文已完整包含于预览时可直接阅读，无需重复查询。

展开的进行中活动最多每 5 秒检查一次轻量来源变化，且只在在线、可见、仍展开的单一选中活动启用；返回标记而非交互索引，不能推进任何分页游标。无廉价变化标记的来源仅提供显式刷新。已加载的交互和输入送达状态明确属于“本次读取快照”，变化只提示“有更新”，点击刷新后重取一个首屏，不建设跨来源增量 feed/upsert。终态历史不轮询，显式刷新才复核；正文引用不可变，正文没有轮询。缓存绑定 home/项目/实例/活动/原运行/正文版本，收起后再打开先复用缓存，仅按以上规则检查变化。首次索引展示已加载页的原顺序，不为跳到最新偷偷遍历中间页；最新进展始终可从摘要取得。

读历史时不自动追加或滚动；出现“有更新”仍保留阅读位置和原快照。用户显式刷新才重置索引首屏，加载更多时保持已读位置。失败保留旧内容、原读取时间及缺口，提供局部刷新，不将读取失败记为活动失败。

## 5. 已记录交互的投影与边界

用户 answer/feedback/message 仅从原持久请求读取可识别正文，标明本地保存、pending、unknown、accepted、rejected 等原事实；accepted 不表示 Agent 已读。自动组装的系统指令不标成用户消息。初始任务/草稿等长输入标为“任务输入/用户草稿”，默认折叠，按需取原保存版本，不能读取当前文件冒充冻结输入。

公开 question 只有原事件/原记录存在时才进入历史；已经被覆盖且没有事件依据时标为未记录。verified final、领域生成结果及当前最近消息预览保留各自类型和来源，不混用“最终回复”。工具调用、工具输出、内部事件、重试心跳及重复状态不进入阅读索引；必要诊断和待答问题常驻摘要，原技术过程仍通过已有详情查看，不新建工具日志查看器。

同一请求或公开事件按稳定来源 ID 去重；正文引用核对原 Run/Attempt/session/turn（公开事实存在时）、事件身份及摘要。不跨候选拼接；缺少原输入轮次时单独列为“轮次未记录”，不得归到当前 Attempt/turn。多轮检测和多次 Roadmap 操作按原记录分组；无跨来源因果顺序时分组展示本地记录时间/来源顺序，不能根据近似时间制造“一问一答”关系。缺时间显示“时间未记录”，不把采样时间当发送时间。

活动列表、摘要、交互索引、正文分成窄的只读契约，UI 只消费投影，不解析原 Runner/领域载荷。来源适配在产品查询/组装边界静态接入，SQLite 只提供中性有界事实；原 owner 仍拥有请求、业务状态、运行绑定和结果。新增交互投影不创建第二套执行状态机、发送权限或完整会话写库。历史 final 正文继续复用原 body 引用和校验，不复制到活动表。

## 6. 验收要求

| ID | 必须满足的成果 |
| --- | --- |
| ARP-A01 | 独立路由、抽屉入口、稳定深链接及桌面/窄屏浏览成立；现有五类活动按真实能力可发现，原操作入口精确定位 |
| ARP-A02 | 所有默认活动摘要 GET 均为本地有界读取；公开消息采样限频/并发/取消/绑定正确，不阻塞原观察；工具样本不覆盖或刷新 assistant 时间，能力缺失如实显示 |
| ARP-A03 | 请求计数证明首次进入、选择、深链接均不查交互；展开/刷新只取一页、正文只返回一段；自动检查仅返回廉价变化标记，不推进游标；关闭/切换/隐藏取消，缓存复用且无自动追页/正文轮询 |
| ARP-A04 | 用户输入、公开问题、verified final、领域结果各归原来源；角色/送达状态、缺口、截断与分组正确，工具和内部载荷不进入阅读索引，重复读取不重复消息 |
