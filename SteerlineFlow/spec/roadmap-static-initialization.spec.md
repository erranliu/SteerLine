# Roadmap 静态材料初始化闭环

2026-11-02 用户授权：补齐初始化流程，为已有 SteerlineTest 准备静态材料并提 PR，再验证草稿转正式 DAG。本增量承接 [材料自动准备](roadmap-material-preparation.spec.md)，不扩建完整项目添加/纳管。

## 行为与边界

- Roadmap 页面先展示三个固定材料的准备状态。GET 只读 HEAD 和已观察的目标分支，不 fetch、不写项目、不调用模型。工作树存在不授予固定来源就绪；只有 HEAD 和目标分支均可读、内容一致且通过现有规则/指南内容校验才就绪。规则容忍 LF/CRLF，原正文和摘要不改写。
- 提供显式“初始化静态材料”操作，复用原命令信封/请求日志及唯一 PrepareStatic owner。校验当前项目、原 HEAD、版本、严格 payload、Git 工作区及未在 merge/rebase；仅创建缺少的 parse-rules.md、document-rules.md、SpecGuide.md，保留已有指南，不覆盖不同平台规则。初始化不提交、不推送、不建 Task、不启动模型，不生成动态图/映射/确认 JSON。
- 未发布材料不能启动解析或生成文档。页面区分缺文件与“工作树已准备，待正常提交合入目标分支并更新本地”，初始化按钮不自动循环或替换原请求。
- 同项目初始化从日志登记到结果保存保持互斥；查询不能抢先结束仍在执行的初始化。重启/结果保存缺失后，只读核验原 HEAD 与本地材料：确保已满足则对账为 applied，不推断创建者；缺失、部分完成或版本变化明确结束为 rejected 并保留文件，允许用户审阅后新建显式操作。查询不重写文件、不重跑未知动作。项目 A 的未决请求不阻塞项目 B。
- 调试包新项目初始化在首次 Git 提交前调用同一 PrepareStatic；已有项目由显式入口准备并按正常 PR 发布。不会在服务启动或解析失败时偷偷补文件。
- 固定提交材料状态可缓存，键含 HEAD/已观察目标提交；每次仍检查这两个引用和工作树准备状态，不缓存短暂读取故障，版本变化失效。业务采用继续从原固定 Git 读取完整材料，不用就绪缓存替代实际来源核验。

## 验收

RI-01：初始化首提交含三份同源材料；重复准备不覆盖自定义指南；错误目标/版本/payload、Git 操作中及重定向拒绝。

RI-02：GET 零写入；未提交/未发布阻断，发布后就绪；UTF-8、大小和原错误分类不弱化；轮询不重复读取已核实固定 blob。

RI-03：真实命令日志中的初始化 pending 在完成/未开始/部分/版本变化后可只读对账，零重复文件动作、零 Task；跨项目未决不互锁。

RI-04：SteerlineTest 三份材料通过同源检查及项目 L1/L2，以独立 PR 交付；隔离使用该项目实际 sample-demo 草稿完成六任务/六依赖、十八文档、Git 发布合并和正式 DAG，原安装服务及业务任务不被测试改写，真实 Runner 正常停止结算。

实现及验证见 [Plan](../plans/roadmap-static-initialization.plan.md) 和 [验收](../testing/acceptance/roadmap-static-initialization.md)。原短提示/完整规则正文不改，接线和资产采用仍需独立审阅；不以更新黄金样本代替批准。
