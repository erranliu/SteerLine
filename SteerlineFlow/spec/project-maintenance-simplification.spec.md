# Spec：项目更新与候选版本收敛

状态：2026-10-21 用户已确认方案，已按本文实施，验证结果与未验项登记专属验收。普通开发，无 roadmap Task ID，不修改 execution-map。配套 [Plan](../plans/project-maintenance-simplification.plan.md)、[专属验收](../testing/acceptance/project-maintenance-simplification.md)；统一规则归[项目维护设计](../../docs/product-design/project-maintenance.md)，执行节点与异常规则归 [Worker 生命周期](../../docs/product-design/worker-lifecycle.md#项目基线与材料维护2026-10-21)。

## 目标与确认结论

正常流程收敛为：查看远端更新 → 必要时一键更新本地 → 自动跟随最新文档及生成测试安排 → 新建候选。用户不再选择维护模式、材料来源、Plan 路径或逐任务确认，不再为测试安排执行审阅、应用、提交 JSON 的操作。

用户最终确认：同一任务可多次修改 Plan，每个新候选都执行最新代码与材料；旧候选过期后作为保留候选，关联测试功能不可用，但继续执行和保留历史。**过期候选的 PR 合入仍可作为任务完成依据**，不能因过期、最新测试未生成或未通过而拒绝其交付。

## 行为契约

### 远端、本地和提交信息

远端基线明确命名为配置目标，例如 origin/main；最新是最近一次成功 fetch 的目标 commit。显示提交时间（用户本地时区）、标题、短 SHA、可打开的提交详情和关联 PR；检查时间与提交时间分别展示。没有 PR 与查询 PR 失败分别说明，PR 元数据失败不阻断 Git 更新或候选创建。

本地基线是配置项目主工作区的实际分支/HEAD，不是候选工作区。按 Git 可达性显示已同步、落后 N、领先 N、双方分叉或无法判断；分叉同时显示两侧数量。提交日志支持分页浏览目标分支历史，以及本地与远端之间的差异提交。每条展示作者、提交时间、标题、提交链接和可获得的 PR 链接。

一键更新只在目标分支、工作区干净、无进行中 Git 操作、可快进且锁/路径/仓库身份合格时执行。点击后重新 fetch 并固定本次目标，再做条件核验和快进；不自动合并、rebase、stash、reset、切分支或 push，不修改候选工作区。失败返回实际原因、相关路径/分支及人工处理建议；不丢弃本地修改。更新原请求在重启/丢回执后只核实实际 HEAD，不把重复请求变成追赶新目标。具体正常、异常、竞态规则统一见长期设计。

远端观察、任务文档更新不以本地快进成功为前置；本地落后本身不阻断从远端创建候选。失败时保留最后成功观察及时间，标明当前未知，不把旧缓存称为最新。

### 自动材料与测试安排

同一任务原有 Spec、Plan、common、acceptance 路径自动读取远端最新版本，重算实际摘要，无二次人工确认。目标 repository/remote/分支、任务身份、依赖和交付不随文档自动改写；缺文件、删除/改名而无法定位、格式错误明确转人工修复。

材料版本按实际文件路径、内容及测试规范/清单识别，不因无关提交、文件时间或候选编号变化而变化。生成输入仍为完整 Plan、测试规范、完整清单及规则版本：Plan 内容变化或规范/清单变化，自动为受影响未完成任务的 Plan 生成；首次没有对应结果时同样生成。同一输入复用一次有效结果，不做重复轮询调用或失败无限重试。

生成使用项目固定的测试生成 profile。优先使用显式配置，否则仅可采用项目默认且符合 generate/1 的本地 Codex profile；默认是 Orca 等不适用配置时提示一次性配置，不猜模型或降级权限。生成保存固定 profile、全部输入、原请求和来源；只选择清单已有 ID，选择后展开完整定义。合法空结果要求 Plan 明确说明无需自动测试，无额外勾选确认。

生成结果按输入版本保存在 SteerLine，校验通过即可供新候选使用；旁置 .tests.json 不再是运行权威或启动前置，不新增 Git 写入、提交或 PR。生成中、失败、未知或缺必要材料时阻断相关新候选并显示原因；不影响原候选。新版本来临后旧生成不能覆盖新版本；原未知/迟到/停止继续按原请求处理，失败的显式“重试生成”复用既有资源资格规则。

开发执行遵循当前 Runner 的工作区文档语义：Spec、Plan、common、acceptance、测试规范和清单只传固定 base 工作区内的相对路径，不要求 Runner 复制材料。系统测试快照及执行说明作为数据冻结到原请求的实施/代码审计提示，保留 Runner 发布的模板或用户自定义正文、报告及发布指令；不构造虚拟文件或写入工作区。generate/1 仍使用其公开 inline 输入。缺少必要公开提示模板时明确拒绝新候选，不回退旧构建；配置 profile 摘要和实际冻结请求摘要分别保存。

### 候选独立冻结、过期与测试

所有新候选入口均 fresh fetch，固定本次最新 base、同 commit 的全部任务引用和对应生成测试快照。事务内核对 Task/图/目标、实际材料及生成结果，保存候选快照和原提交意图；已经预留的原请求重放仍返回原候选，不能悄悄升级或重复派发。前置真实交付进入本次 base 的检查保留。

每个候选创建后冻结；新增候选不要求与旧候选同 base/契约。远端材料更新后，旧候选显示“已过期 · 保留候选”，不自动停止、不更换输入、不撤销原反馈/继续/发布资格。候选的材料新鲜度、Runner 执行状态、停止参与和资源状态分别表达；不能复用 abandoned 或资源 retained 来代表材料过期。

当前/过期按最新材料内容比较。多个候选绑定同一最新材料版本时均可独立关联测试；仅代码提交前进而材料不变不使文档过期。观察失败显示“当前性待核实”，不宣称当前测试通过，也不撤销既有交付资格。历史/已完成任务不因更新重开。

过期候选不再新增关联测试收集，已在途原收集仅按原请求核对、必要时保存为该候选历史，不进入当前统计；既有测试安排、结果、日志继续只读可查。仅最新材料候选可关联测试，并仍须满足原候选/Run、定义摘要、干净且同被测 commit、环境和日志来源等原规则。旧报告不跨候选复用；没有“把旧候选测试补绑到新 Plan”的入口。

候选详情同时提供执行文档、最新文档和完整差异查看，覆盖新增/修改/删除以及测试安排；大文件可分页/按文件展开，不能只显示截断片段却宣称完整。过期保留记录不占最新材料版本的五个候选名额；实际仍运行的旧资源继续计入原资源准入/占用，不伪造停止或无限自动开候选。

### 过期候选交付

只因材料过期保留的候选，仍按原绑定 PR 的实时、同身份、已合并证据完成同一 Task。交付核验其自身冻结契约和发布目标，不要求等于最新任务材料，也不要求当前测试可用/通过或最新生成结束。显式停止参与、Task 已放弃、身份错误、PR 未合并/未知等原拒绝规则保持。

多版本候选竞争交付仍只提交一次 TaskDelivery；任务关闭、后继释放和全部候选停止义务沿原事务提交。若旧版 PR 交付，页面注明实际采用的候选/Plan 版本；新版本未完成不得阻止这次已核实交付。任务完成后不再启动该任务的新候选/新生成；已受理的生成按原请求结算，其他任务仍引用的生成不受影响。

## 界面与范围边界

默认只展示远端/本地摘要、检查更新、更新本地、提交日志、具体问题和任务最新材料/测试状态。候选列表显示当前候选与过期保留候选，历史可折叠但可直接进入；保持停止、原执行及 PR 操作可理解。异常项才提供“配置测试生成”“重试生成”或人工处理指引。

移除正常流程中的维护模式、手填 Plan、手动确认任务/测试、生成 ID、审阅/应用/提交安排步骤；必要技术来源放详情，不要求用户操作原请求。原生 CLI/API 同样消费唯一的自动生成及候选冻结规则，删除旧 apply/人工采用的运行旁路，不保留兼容写法。

不实现任务自动重开、跨仓库/目标分支自动改绑、推断文档改名、自动修正文档/测试程序、自动 Git 发布或新的 Runner 状态机。直接调整未发布产品当前格式，无旧数据库迁移、回填或兼容要求。已有安装数据/活动候选不得用来调试或通过改库实现本方案。
