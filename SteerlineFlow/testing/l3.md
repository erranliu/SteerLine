# L3：可并行功能测试

按变更影响选择。以下均为 controlled：真实 SteerLine/Git/SQLite，公开 Runner/PR fixture，无真实模型。每项独立 home、repo、数据库、端口、provider 和证据；只复用只读构建产物，清理归创建场景。

各 ID 的完整命令及约束见 [JSON](test-list.json)，对应 package/test 见 [执行登记](../../tests/e2e/suites.json)。

```powershell
go run ./cmd/test-feedback -level=L3 -suite=<suite> -env=controlled -scenario=<ID或逗号分隔ID>
```

可跨 suite 选择，包间最多二并行；仅 runtime 包内也最多二并行，跨包时包内串行。recovery/runtime 有既有并行记录；configuration 具备独立资源并使用 `t.Parallel`，与其他 suite 的组合运行证据尚待补齐，不能据此宣称全部组合已验证。

| ID | suite | 主要断言及独有覆盖 |
| --- | --- | --- |
| `testing.runtime-progress` | testing | 固定测试字段、通过/重跑清零、非法内容和断连保留快照、重启零业务输入、独立业务 revision、不生成 managed 历史及停止清理。 |
| `configuration.execution-profiles` | configuration | 浏览器条件保存本机Orca三Agent配置、待重启门槛、正式停启、关闭Web后CLI核对adapter/target/agent/model/effort/helper，原候选不变且资源清理完整。 |
| `recovery.waiting-merge-restart` | recovery | PR 待合并时重启 SteerLine，保持原候选/Run/请求，零自动新输入、不提前释放后继；合并后唯一交付，资源清理完整。 |
| `runtime.dual-home-operation` | runtime | 两独立 home 同时在线，以不同请求 discard 不同任务；另一项目/provider 不变、无候选，实例不变，两者停止清理完整。 |
| `runtime.service-lifecycle` | runtime | 中文与空格路径、无关 cwd 下创建启动器，核对任务、宿主身份和控制；停止结算，再启动新实例保持任务事实，最终清理完整。 |
| `runtime.shared-runner-projects` | runtime | 同 home 两项目共用一个 Runner，相同产品请求号创建独立 Run；分别消费仓库/PR，整体重启保持绑定、零自动新输入，全体资源清理完整。 |

输出目录必须全新；结果、日志、清理和复验要求见 [报告约定](reports.md)。返回 [测试指南](../testing.md)。
