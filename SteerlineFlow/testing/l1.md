# L1：最小代码检查

每次代码修改后、提交 PR 前运行一个固定集 `l1.minimum`，建议整体 1 分钟内。入口：`go run ./cmd/test-feedback -level=L1`；环境 isolated，需要 Go/Git、Node 24+ 与已安装 Web 依赖。

固定范围见 [scoped.go](../../cmd/test-feedback/scoped.go)、[task_scope.go](../../cmd/test-feedback/task_scope.go) 及 [web.go](../../cmd/test-feedback/web.go)：六组 Go 覆盖任务状态/契约/依赖、公开 Runner 契约、原子写入、Windows/Linux 依赖边界、提示词正文/参数及源码约束、清单一致性；随后复用 `web/src/shared/api/client.test.ts` 和 `web/src/features/runs/state.test.ts` 两文件，验证请求封装及候选状态计算。不构建 Web、不启动浏览器；完整前端回归见 L4 `web.unit`。Go 分组默认三个 worker，可用 `-workers=1` 诊断。

前置为 Go/Git、Node 24+；先 `npm --prefix web ci`。依赖缺失明确失败，不自动联网安装或跳过 Web。原提示词用例及正文没有变更；CI 先准备 Node/npm 依赖，再运行同一完整 L1。

既有 `TestRunnerExecutionBoundary` 同时扫描真实仓库的开发者配置边界：服务、查询及辅助代码不得重新导入原始开发者配置或直接读取其字段，配置定义/校验/编辑和能力映射入口保留；源码检查覆盖全部平台与构建标签。正反例完整回归在边界 owner，L1 测试根与平台子例清单保持不变。

完整 Go owner、启动/恢复/部署、HTTP、SQLite 等专项保留在 L4 `go.full` 及相应 owner 集中，完整前端回归为 `web.unit`；不为每项新功能扩张固定 L1。冷编译可能超出建议时间，报告须记录实际总耗时。

| ID | 验证与通过条件 |
| --- | --- |
| `l1.minimum` | 固定六组 Go 与两份前端文件全部非零执行，原生报告/终态完整、断言通过、无跳过；任一组失败整体不通过。 |

输出目录必须全新；结果、日志、清理和复验要求见 [报告约定](reports.md)。返回 [测试指南](../testing.md)。
