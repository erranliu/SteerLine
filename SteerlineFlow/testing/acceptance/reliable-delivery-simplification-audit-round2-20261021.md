## 二轮补充检查

以下问题在修订期间发现并已落实约束；不是留给实现者自行猜测的前提。

| 故障窗口或简化风险 | 方案中的处理 |
| --- | --- |
| 安装进程崩溃，OS 释放锁，磁盘仍为混合包 | 首次目标写入前原子发布绑定 prepared 的 pending；所有受支持启动/写入口先查 pending 与已提交构建。最终 manifest 与移除 pending 同一次原子提交，崩溃不开放半包 |
| 普通重启覆盖旧实例记录，随后重建缺失数据库或只扫描剩余项目 | 驻留租约内先读取旧完整清单；未完成启动保留 last_complete_census，缺旧 Store 先阻断；项目移除/改绑须有正式维护证据 |
| 为防配置变化而永久固定成功安装时的全部预设 | 完整配置字节只约束 pending 期间的安装/续装；正常已提交包允许按既有规则编辑预设，Runner pin 仍须对应已安装程序 |
| 安装父进程持项目锁，等待需要同锁的新后端 | 协调器先释放仓库/run-dir 准备锁，再由新后端重新取得并生成当前 census；应用协调锁持有至启动结果确定，避免递归取锁 |
| 间隙出现 ready writer，部署复用它后才发送原 stop | 部署要求 fresh writer；owned namespace 的每次新 writer 均需本次 caller 上下文及完整停止信封，在恢复/派发/ready 前受理；外来实例冲突报告已安装但未启动 |
| 让全部保留原生资源长期持安装共享租约，使兼容接管永远无法更新 | 原生资源单纯存活不持该安装租约；其身份、原授权和冻结资源按兼容契约核验，活跃状态写者才受共享租约约束 |
| 新观察接口在分页时跳过事件，或使交付使用旧 PR 缓存 | 同一只读事务返回投影与有界页，cursor 仅消费实际事件；CAS 整页保存，交付前 PR 权威刷新保持，散列缓存移出首版 |

上述设计保证仅覆盖全部遵守新契约的受支持入口。未建立归属、没有完整清单、原程序不支持租约或有不受协调写者的现场，不启用直接离线替换；普通请求不补造归属/清单，不能以启动一次旧版来重建已经丢失的 caller 事实。

## 可行性与实施成本

按目标收集事实、Go/PowerShell 语义收口、现行文档整理仍可先做，沿现有锁及核验交付。预查询减少依赖完整绑定；命令传输收口可以独立实施；同快照观察独立后置。

直接离线恢复和续装的收益是减少人工恢复原版及重复启停，但需新增启动清单、公开安装租约、owned 启动上下文和持久 pending 阻断。这部分不能按“只删除几步校验”的成本估算，也不应捆绑为第一批简化的前置。两仓先交付前置能力，新环境留下原证据后再启用；不会为过去的无清单中断追认资格。

Worker 统一规则的[当前实现与缺口](../../../docs/product-design/worker-lifecycle.md#可靠性交付简化前置方案)已同步 W/E/V 映射和待实施状态；方案未另建 Worker 状态机，未放宽原请求、未知输入、唯一交付和停止义务。

## 本轮验证及边界

本轮执行修订文档的本地链接/锚点检查及 `git diff --check`，固定内容摘要并保存检查记录。没有运行全量测试，也没有新增生产运行测试：本轮只修改设计文本，新协议尚无可执行实现，用当前实现通过的测试不能证明未来方案。

首轮已有三个隔离 L1 基线通过，覆盖实际发送时实例变化、原关闭/结算证明、原结果补查及重启输入零补发，原日志与命令见[首轮验证记录](reliable-delivery-simplification-audit-20261021.md#本次验证)。这些是实施时应保留的历史基线，本轮没有重跑，也没有将其计作 SIM-A01–A09 通过。

后续每个实施 Plan 须把所选自动验收项映射到实际级别、场景/命令、隔离环境、时点、通过条件和专属证据。租约的真实 OS 排他性、writer 并发交接及每个崩溃窗口必须实测；在其通过前，现有核验与恢复门槛保持。
