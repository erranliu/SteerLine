# L4：可复用测试与专项

按变更影响选择，包含边界测试、无法并行的功能、真实链及单元/集成测试集。以下 E2E 的实现映射见 [suites.json](../../tests/e2e/suites.json)，环境/完整命令/约束见 [JSON](test-list.json)。

```powershell
go run ./cmd/test-feedback -level=L4 -suite=<suite> -env=<controlled或live> -scenario <ID或逗号分隔ID>
```

E2E 当前仅支持 Windows。controlled 需要 Go/Git；项目维护和测试记录还需要 Node/npm、Edge，E2E 入口自建公开 Runner 夹具。live 单项精确选择，前置按各 ID 的 JSON；目录发现不要求业务模型登录，交付/审计需要本机 Codex、固定 Runner 及 SteerlineTest GitHub 写权限，会创建并合并专属 PR。审计另设两个不同模型。测试管理真实链消耗模型、不发布 PR。

项目维护、测试记录、测试管理真实链共享源码 Web 依赖及构建目录，须串行，不能与其他 Web 安装/构建命令并发。四项 runtime 边界独享资源，可包内二并行；与项目维护同选时整个包串行。L4 包间串行，live 单项运行。

L1 复用其中最小 Go 规则及边界；e2e/runneracceptance 标签不在普通 Full 内。正式 owner 子集各自输出对应 managed，不输出 go.full 通过；未登记定向命令继续归 diagnostics。独立 Runner 专项缺输入不得 skip 通过。

边界包包含开发者配置所有权的正反例：显式配置入口与领域策略允许，服务/查询的导入、原始字段访问、辅助包、非当前平台及不启用标签源码均拒绝；测试夹具、注释与字符串不误报。复用 `go.full` 的普通包枚举，不新增 E2E 场景；只执行边界包时保留 diagnostics，不能登记为完整 go.full 通过。

环境 App 的固定声明31根（Windows执行31/其他平台30）由 [environment_scope.go](../../cmd/test-feedback/environment_scope.go) 明确维护：adaptation/decoupling/lifecycle/materials/readiness/script_windows/target/workflow 八个environment前缀文件全部24声明根，加 PM 预留拒绝、生成材料闭环和原生配置预检共三根、developer_test.go 三根及 shared_environment_test.go 一根。Windows脚本根仅Windows执行；源清单守卫始终解析全部声明并拒绝漂移。owner组没有App的-run，其他App用例保留在go.full。Runner contract五根按app/client/web三组分别执行，新增配置三操作及Web保存重验，不要求业务模型或发布。

go.http 包含 Windows 跨进程快照压力，固定发布次数、读者数和原期限不变；本机安排与其他 E2E、Full、压力任务串行，避免将并行负载下的压力窗口失败误作功能通过。本次所有原失败与独立复验分开记录，不以独立复验声称并行组合已验证。
