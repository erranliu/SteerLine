# 重构维护的自然语言执行、上下文决策与预算收尾 Plan

对应 [Spec](../spec/maintenance-conversation-budget.spec.md)。状态为已实施，验收记录含未通过项，基线 `134fd29e`。测试 ID 固定在[同名安排](maintenance-conversation-budget.tests.json)，结果记入[专属验收](../testing/acceptance/maintenance-conversation-budget.md)。

## 1. 数据与状态先行

在 `internal/refactoring/model`、SQLite、命令入口、产品 DTO 和查询中删除维护轮次和轮次预算，修订持久化契约及所有创建/查询消费者。保持当前业务 owner 和事务边界。

用原操作 ID 关联当前选定目标、起点提交、实施/修复、审计、人工答复和接受记录。将 `roundStart`、`AcceptedHead(round)`、按轮反馈与摘要改为按目标来源操作及接受操作定位。默认一个目标在首次选定时固定，重试和恢复延用。直接更新数据契约，遵循项目未发布规则。

将金额和时间资格、默认目标完成、提前结束和用量待定统一归入宿主现有派发判断，形成可继续改进或收尾交付的许可。保存收尾原因并保证收尾单向推进。在请求准备、待发和决策消费处重核，保持原请求受理未知时沿原身份核实。

## 2. 实施回执与审计接线

在 `internal/refactoring/service.go` 中按执行用途处理结果。实施/修复保存绑定 Final 原文与原生事实，删除其 JSON 解析、ID 回显和字段校验。发布及冲突仍使用原结构化回执和远端核验。

重写 `delivery.go` 的实施接受条件，基于原生绑定、成功、可信干净工作区和相对目标起点的提交变化。程序事实不从自然语言提取。增加审计 `finish` 及其无改动门禁，保证脏修改和目标内未处理提交不能被遗漏。

在 `operations.go` 中按目标关联准备对话材料，优先保留当前原任务、执行/修复原话、人工答复、公开 Git 事实和未解决事项。后续决策无执行目录访问，PR 报告继续使用已有固定 diff 通道。实施与修复不额外调用一次回执分类模型。

## 3. 固定提示词与治理

由 `internal/prompts` 修改 `maintenance-decision.md` 和 `maintenance-execute.md` 及组装参数，落实 Spec 第 6 节拟定条款。预算许可作为固定条款的选择参数，金额、时间和默认目标限制留在宿主。实施/修复改为直接呈现任务原文及必要事实，移除含行动及操作身份的 JSON 请求包装，机器定位依靠请求信封。因固定 Runner 的 Codex execute/1 单行约束，模板为单行，原任务以 JSON 字符串无损编码传入；用真实契约专项覆盖 CRLF 和结尾空格。发布和冲突用途继续沿原模板及请求组装路径。

分别审阅首个调查、后续选题、审计、JSON 格式重试、PR 评审，以及自然语言实施/修复、原发布/冲突的完整渲染样本。比较两种许可，列出正文实际差异、UTF-8 字节前后值和业务原因。更新黄金样本和守卫时保留缺文件阻断及固定材料来源断言。依[提示词治理](../../docs/prompt-governance.md)取得独立审核，审核覆盖模板、接线、材料、样本及对应测试变更。

## 4. API、CLI 与页面

新建表单预算金额和分钟均可为空，移除轮次，解释默认完成一项改进后交付。详情保留余额、未知用量和收尾原因，去掉轮次计数。CLI、HTTP 及存储测试同步覆盖空预算创建。

在 `internal/product/query/refactoring.go` 从已保存请求投影用于排查的正文、材料清单和输出约束，在维护执行对话中按操作展开。使用字段白名单屏蔽凭据和无关配置，不返回整个 Runner 配置对象。保留任务原文和执行反馈的原字节，标题明确区分出站请求与模型输入。

更新 `docs/product-design/refactoring-maintenance.md`、`docs/architecture/refactoring-maintenance.md`、`docs/integration/steerrunner.md` 及 `docs/prompt-governance.md` 的当前行为说明，用本 Spec 链接解释对旧方案的替代关系。
