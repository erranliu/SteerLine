## 1. 实施策略与依赖

先建立有界本地摘要，再接独立页，最后接按需交互与正文。默认浏览成本与完整历史大小解耦。复用当前公开 last-message 和原持久事实，不为本功能升级 Runner 协议或采集完整 transcript；若现有公开绑定不足，该来源显示缺口，不静默寻找私有替代来源。

本期“最新”是最后观察到的可读样本，不是精确的原生最新 assistant。当前工具样本无法倒查上一条 assistant，是明确限制；要改变承诺须先修订 Spec 并安排公开 Runner 能力，不能借实现便利隐式扩大范围。历史为已有持久事实的投影，不保证补齐部署前或停机期间未采集的 commentary。

| 层/位置 | 责任与最小变更 |
| --- | --- |
| `internal/product/api` | 活动 history 筛选；有界摘要、交互索引与正文引用 DTO；显式消息类型/能力/缺口，不输出内部请求载荷 |
| `internal/storage/ports`、`internal/storage/sqlite` | 扩展原活动读取和必要的批量摘要/交互读取；索引阶段不物化长正文，保存原绑定的单条最新快照；不新建统一活动业务表 |
| `internal/product/query` | 活动状态继续沿原投影；静态来源适配和只读索引合并，处理边界、预算、来源 ID、游标和完整性，不依赖业务 service 执行方法 |
| 原 owner / App 组装边界 | 原观察链可选的轻量消息采样；原绑定校验、限频、共享在途及超时；无公开定位能力就不采样，不推进业务状态 |
| `web/src/features/activities` | 抽屉/独立页共用列表查询和轻量展示；独立阅读区拆出独立的摘要、交互索引、正文查询，不复制各领域页面 |
| `web/src/shared/api`、`web/src/app` | 只读单页/单段客户端入口、路由及缓存键；不使用当前 final() 自动遍历全部页/正文的路径 |

不引入消息总线、插件发现框架、统一运行调度器、第二套原生历史数据库或默认全量全文搜索。只增加本功能必需的窄接口和静态适配，扩展动作与查询分离。

## 2. 实施步骤

### P1. 核实来源并固定最小读取契约

按 Spec 来源表核对实际字段、持久位置及归属：候选 Actions 原请求与送达状态、runner_events final、当前 question 投影、建议记录 Source.Facts 的已保存问题上下文、检测轮次、Roadmap 原输入与生成/命令结果、建议原记录。当前公开 Event 没有 question 正文；Action 缺 Attempt/session/turn 与时间，输入只能沿已保存的请求关联分组，缺失时显示“轮次未记录”，不能用当前 Projection、expected_revision 或近似时间补齐。建议问题上下文须核验项目/候选/Source.Occurrence，不推导缺失 turn。统一活动 ID 仅用于路由及查询授权，正文访问仍核验原项目/目标及精确来源绑定。

保留 `/activities` 的旧 filter 与 request_links 语义；新增 `history` 不改变抽屉 recent。独立页首选列表一次带回同页有界摘要；存储用关联查询或一次批量读取，不能循环查询每项详情。summary/preview 字段与实际业务状态分开，响应同时声明来源与正文能力。保留原来源超时/部分结果与计数未知约束。

所选活动交互索引以活动 ID、原分组及稳定来源位置为分页范围；首屏记录原事件末序号/原输入成员边界，继续翻页不混入后续新增成员。可变送达状态按每次实际读取版本标明，不承诺跨请求冻结，也不创建历史快照。原数据变化导致成员边界无法继续证明时使游标失效，提示显式刷新一个首屏，不拼旧页。

自动检查只返回不透明的来源变化标记：优先原候选/检测/Roadmap/建议记录 revision；原命令使用 command_id/status/updated_at。必须是窄字段或索引读取，不遍历 Actions、正文或全部历史计算标记；不存在廉价标记的来源只允许手动刷新。候选视图的关联建议问题上下文，通过其原事务维护的 reading_versions 读取索引版本组合；它只描述索引变化，不递增业务 revision 或建立历史增量流。不建设通用多源增量 feed、高水位更新流或状态 upsert 协议。复用 body 引用及校验规则，先固定 DTO/HTTP/存储契约，再接页面。

### P2. 增加有界最新样本与历史查询

原 owner 的运行观察链为有公开定位能力的活动提供不可变读取目标；App 注入只读消息端口，不能让活动 query 直接调用 Runner。采样复用公开 last-message，核对 Run/Attempt/session/turn 和时间/字节预算。只接受 assistant 为可读样本，tool 不替换样本。业务诊断、question、持久 final/生成结果直接来自本地原记录，保留不同类型。

在原观察链加入每绑定 10 秒尝试限频、应用内并发 2 和单次最多 1 秒的独立消息读取预算；预算含等槽、公开调用与解码，忙时跳过而不排长队，不延迟业务观察/取消/收尾。不为消息采样持有业务事务或 actor 锁。最近尝试时间与最后有效 assistant 样本时间分开，成功/失败/null/tool 都消耗间隔；相同绑定由进程内单一观察入口原子登记尝试。执行页 3 秒选择性刷新与后台 10 秒采样共享在途和尝试时间，前台任一次尝试都推迟后台下一次资格，不能两个通道各调一次。取消/超时后不得在业务观察上下文里重试；样本未变化不重复写正文。

仅保存原绑定最新一条有界样本和真实观察时间/错误，不保存历史采样序列。重启读取原快照但先核验绑定，原 Attempt 变化不沿用旧快照。消息样本写入不触发业务 revision；终态停采样，采样失败不妨碍最终结果持久化。本地只读列表/摘要不触发采样。若需要调整 SQLite schema，按项目未发布规则使用新版本，拒绝旧格式，不增加迁移、双写或兼容读取。

history 使用原业务终态与精确相关性，扩展原有有界存储窗口/游标读取，超过 50 项依旧可继续；SQL、投影合并及游标一致采用 Spec 的权威结束时间桶/空值桶/原创建时间/来源 ID 排序，不过滤缺结束时间的终态记录，不伪造完成时间。为计数完整性无法证明的情况保留原部分语义。索引读取按页获取必要短字段/正文引用；SQLite 不为做 512 字节预览反复读取所有历史大正文。若原 payload 仅有大字段，使用窄 SQL 投影或原记录的有界预览事实，不复制长正文到活动表。

### P3. 接入独立页面，默认只读摘要

新增 Spec 指定路由及抽屉链接；抽屉和独立页共用范围校验、数据键、单页读取及请求关联，展示组件独立。分页动作与定时刷新分开配置，不直接复用当前 infinite query 对全部已加载页的周期 refetch：history 无 interval、focus/reconnect 自动重取，手动刷新重置为首屏；进行中/需处理的周期查询只覆盖明确的首屏/可见有界摘要，不遍历后续页。独立页打开时停止抽屉自己的重复计时器，保留公共入口计数。查询键包含 home/项目/实例，不把旧项目 saved ref 带到新范围。

页面不自动选中首项，深链接仅选中摘要。进行中/需处理复用原规则，历史单独分页。桌面双栏、窄屏分层、返回列表和可访问焦点与新消息原位更新按 Spec 实现。问题与阻断不依赖展开交互才能看到，去处理定位原业务页。页面选择与历史展开状态分开；任何终态不能隐式打开 final。

### P4. 接入按需交互索引与正文

新增单页交互读取和单段正文读取客户端方法，复用现有摘要/长度/UTF-8 校验规则，不调用会自动追页的 final()，也不直接复用每段都全量物化的 ReadMessageBody 实现。每次展开/加载更多/刷新最多一次索引请求，每次展开正文/继续读取最多返回一段。短正文在预览内已完整时无需请求。

原 final 索引使用单页窄字段/有界预览和原正文引用，避免 NextConversationEvent 逐条 SELECT 完整 payload 再计算预览/引用的路径；必要的长度/摘要/预览元数据由原持久记录拥有者维护，不复制正文到活动表。正文在首次显式展开时最多物化该条 16 MiB 并完整校验一次；同引用后续分段复用只读 reader 注入的已验证内存缓存。缓存以 home/项目/实例/原记录/正文引用版本和摘要为键，应用内总正文缓存最多 32 MiB、空闲 5 分钟淘汰，无业务 writer/Runner 能力；每次命中先窄读核验原归属及版本，失效、缓存淘汰或超限后重新验证，不保留磁盘副本。并发同引用的首次读取去重，缓存满时淘汰而不扩容。用后端读取字节/完整解码和哈希次数验证同引用连续读多段仅一次全文校验，明确缓存失效/淘汰的重验证例外，不能以 256 KiB 响应大小替代后端成本证据。

索引首次读取仅在显式展开时启用；在线/可见/仍展开且进行中的单一选中活动可每 5 秒检查轻量来源标记，标记变化只显示“有更新”，不得追加交互或推进索引游标。用户点击刷新才读取一个新首屏，重置旧页/游标；“加载更多”仍每次只取一页。已读内容和送达状态标为本次读取快照，终态及无廉价标记来源不自动检查。收起/切换/离开时取消旧请求，旧 Promise 不得覆盖新范围。正文没有 interval，正文引用版本不变时复用缓存；新增版本不能静默覆盖正在读的旧正文。明确浏览器页面内存缓存生命周期，不额外建立 localStorage 聊天档案。

展示用户请求原角色/状态，系统输入折叠为任务输入，领域结果与 verified final 分别标记。按来源 ID 去重并只保留有原证据的轮次分隔；缺轮次、缺口/未知/截断不合并成完整对话。历史滚动位置不受摘要/变化提示影响，多页积压继续显式翻页。

### P5. 验证与文档收口

按下表完成定向契约/组件测试与专属浏览器请求计数断言，再在稳定候选完成一次选定正式回归。更新长期活动设计、执行观察/本机协议和 Web 导航说明，将“当前支持”与“完整原生会话不支持”写清楚，依据实际实现与验证结果登记状态。

## 4. 证据、前置与停止条件

本轮使用 `C:\SteerlineDebug\wt-7e9d-activity-reading` 独占 scope，各次执行新目录，原始报告不进仓库。实际受测 SHA/脏状态、命令、退出码、非零命中、报告入口和清理事实登记专属验收。已授权的隔离测试不接触安装现场。

原生绑定无法核验的来源、缺失历史正文和缺失公开问题记录必须如实呈现；伪造可读消息、默认全量历史读取或查询推进业务均为交付阻断。ARP-M01 仅体验可后置，自动失败或能力缺失不能转为人工待验。必需验证通过、确认问题闭环且最终差异覆盖后结束核验，不因写记录再重跑同范围集合。

初稿文档检查与独立文档审核保留于专属验收第 4、5 节；本轮实现、必要验证及后续独立代码审核另行登记，不覆盖原失败记录。实施阶段结束时未提交/推送；后续依用户授权创建 PR，不合并或部署。
